1. Use [] for a final, possibly empty argument pack

void receive(i32 values[]) {
    return;
}

usize pack_len<T>(T values[]) {
    return Slice.len(values);
}

void send_values() {
    receive();
    receive(1, 2, 3);
    usize empty_count = pack_len<i32>();
    usize count = pack_len(1, 2, 3);
    return;
}

The chosen spelling is T values[] in the last parameter position. It accepts zero or more same-typed arguments; it is not an ordinary Vector parameter. The caller prepares a temporary owning pack and the callee accesses it through a read-only Slice<T>-like view. No Copy-only restriction is imposed on T.

A generic empty pack still needs enough type information. Here pack_len<i32>() supplies T explicitly; an untyped empty call cannot invent an element type. The ordinary generic argument/destination inference rules continue to apply.

Design reference. These are chosen source and ownership contracts, not results from an implemented compiler or runtime. Ellipsis parameter syntax has been superseded by the name-following brackets.

2. One final pack with required ordinary parameters before it

void receive_tagged(bool enabled, i32 values[]) {
    return;
}

void send_tagged_values() {
    receive_tagged(true, 1, 2, 3);
    receive_tagged(enabled = true);
    return;
}
PropertyRule
Count and positionAt most one variadic parameter per function, and it must be last.
Repeated argument countZero or more; a nonempty pack uses ordinary positional expressions.
Ordinary prefixRequired ordinary parameters may precede it; a defaulted ordinary parameter before it is unsupported.
Named callsThe pack itself cannot be supplied by name. Ordinary prefix names retain the positional-first rule.
MutationA mut variadic binding is unsupported; the pack grants no ordinary writable or consuming element access.
Generic inferenceUnresolved empty-pack element types require sufficient ordinary inference evidence or a complete explicit type-argument list.

The named-prefix example has an empty i32 pack. Named ordinary parameters do not permit later positional arguments; use the first call form when supplying repeated positional values.

3. Copy simple values, move owners or pass references

usize count_owned(string values[]) {
    return Slice.len(values);
}

void send_owned_strings(string first, string second) {
    usize count = count_owned(first, second);
    return;
}

Each owning string moves from its source into the pack. The callee can observe the strings without consuming or replacing them. The pack remains their owner, and its still-owned elements are cleaned up when the call completes normally. A read-only callee view does not make the incoming argument a borrow or preserve the caller’s moved owner.

usize count_borrowed(&string values[]) {
    return Slice.len(values);
}

string keep_original(string original) {
    usize count = count_borrowed(&original);
    return original;
}

Here the pack element type is &string. Shared-reference values copy while their original referent permissions and lifetimes are preserved; the text owner is not moved or cloned. A pack element is a value argument: passing an existing non-Copy &mut U or MutSlice<U> handle as a bare argument moves that handle into the pack. The automatic reborrow exception for a dedicated outer &mut U or MutSlice<U> parameter does not apply merely because pack element T has that type. An explicit argument expression such as &mut owner instead creates a new loan at that expression. The read-only pack still cannot copy or extract an exclusive element capability. No owned string is silently created from a literal.

Rejected example. This intentionally violates a chosen rule.

// Rejected: the owning string was moved into the pack;
string invalid_reuse(string original) {
    usize count = count_owned(original);
    return original;
}

Rejected example. This intentionally violates a chosen rule.

// Rejected: a string_view literal cannot supply an i32 element;
void mixed_types() {
    receive(1, "two", 3);
    return;
}

Rejected example. This intentionally violates a chosen rule.

// Rejected: typed i64 is not implicitly converted to i32;
void typed_numeric_mismatch() {
    i64 wide = 2;
    receive(1, wide, 3);
    return;
}

Untyped numeric literals can match their resolved parameter context. Already typed values receive no implicit numeric conversion. Homogeneous packing is not a heterogeneous list or a foreign varargs-promotion rule.

4. The pack view cannot escape or consume its storage

Result<i32, BoundsError> first_value(i32 values[]) {
    &i32 first = Slice.at(values, 0)?;
    return Result.ok(*first);
}

Read-only Slice operations can inspect the pack. This example copies the i32 pointee and returns that value; it does not return a reference to temporary storage. An empty pack is valid, but ordinary bounds-checked access may still return an error.

Rejected example. This intentionally violates a chosen rule.

// Rejected: the temporary pack view would outlive its call;
Slice<i32> invalid_return(i32 values[]) {
    return values;
}

The view may not be returned, stored or captured in a way that survives the call. A loan to an element owned in the pack is likewise bounded by the pack’s lifetime. If an element is itself a shared reference, copying that reference can retain the original external referent lifetime; it does not make the pack slot or the pack-owned values longer lived.

Read-only access cannot replace slots, grow storage, extract non-Copy owners or manufacture exclusive element loans. Any existing synchronized interior-access contract remains a property of its element type; the pack itself grants no extra mutation capability. Use an ordinary Vector, Array, MutSlice or explicit mutable-array borrow parameter when modification or ownership consumption is required.

Existing arrays are not automatically spread into repeated arguments, and no explicit spread form is supported in the initial rule. A Slice parameter is the ordinary alternative when a caller already has a runtime-length view.

5. Use canonical types for one array parameter or return value

Written formChosen meaning
T values[] as the final parameterVariadic pack; this parameter syntax never denotes one owning Vector argument.
T values[N]Fixed Array<T, N>; as a value parameter, the array owner moves even when T is Copy.
T grid[R][C] in an ordinary declarationArray<Array<T, C>, R>, with suffixes applied from outer dimension to inner dimension.
T values[] in an ordinary declarationOwning Vector<T>; a dynamic array literal produces a fallible Result.
T grid[][] / T grid[](2) in an ordinary declarationEquivalent Vector<Vector<T>> nested dynamic storage; rows may differ in length.
Vector<T> valuesOne dynamic array value parameter. Use canonical types for returns, generic arguments and multidimensional dynamic parameters.
&Array<T, N> values / &mut Array<T, N> valuesA read or exclusive write borrow of the whole fixed array.
&Vector<T> values / &mut Vector<T> valuesA read or exclusive write borrow of the whole dynamic array.
Array<i32, 5> relay_fixed(i32 values[5]) {
    return values;
}

Vector<i32> relay_dynamic(Vector<i32> values) {
    return values;
}

void inspect_fixed(&Array<i32, 5> values) {
    return;
}

void modify_dynamic(&mut Vector<i32> values) {
    return;
}

Array owners move by default; there is no automatic pointer decay or whole-array Copy because the elements happen to be integers. The examples return ownership using the canonical Array and Vector names. A normal mutable value parameter changes the callee-owned array; an exclusive borrow changes the original owner under the established borrow rules.

Result<Vector<Vector<i32>>, CollectionError> make_dynamic_grid() {
    i32 rows[][] = [[1, 2], [3, 4, 5]]?;
    return Result.ok(rows);
}

The declaration supplies nested dynamic context, so the whole nested literal has one fallible construction Result. The canonical return type names the same owning Vector<Vector<i32>>. These allocations belong to explicit array construction, not to a variadic pack.

A suffix wraps its base element type. When that element type is a reference, the suffix describes an array of references; it is not a borrow of the whole array. Whole-array borrowing uses &Array<...> or &Vector<...>. Rank-bearing or repeated-empty-bracket parameter declarators are unsupported in the initial function grammar: write the canonical nested Vector type instead.

For ordinary declarations, parenthesized rank is a positive compile-time integer, while dynamic row lengths may change at runtime. Fixed and dynamic bracket composition follows the recursive Array/Vector mapping. Fixed literal extents are checked; dynamic [ ... ] construction requires explicit Result handling or ? in a compatible function. See Arrays and Static Arrays for the complete literal and storage contract.

6. Prepare arguments once and clean current pack owners exactly once

The caller prepares a statically counted temporary pack in its call frame. Pack storage introduces no hidden heap allocation. Copy elements copy and non-Copy owners move under their ordinary value rules, so real copy/move costs remain. Explicit argument construction, cloning or dynamic array literals keep their own allocation and error costs.

Explicit argument expressions run once, left to right in source order. Preparation tracks initialized elements. If normal error propagation exits the caller before the remaining arguments are ready, already prepared owners are cleaned up exactly once; moved source bindings are not restored. A returned Err used merely as an ordinary argument value does not itself propagate without the existing propagation operation.

enum PrepareError {
    Failed;
};

Result<string, PrepareError> prepare_second(string input, bool reject_input) {
    if (reject_input) {
        return Result.err(PrepareError.Failed);
    }
    return Result.ok(input);
}

Result<usize, PrepareError> prepare_owned_call(
    string first, string second, bool reject_second
) {
    usize count = count_owned(first, prepare_second(second, reject_second)?);
    return Result.ok(count);
}

first is moved into the prepared pack before prepare_second runs. On its error path, the input second is cleaned up by the helper, then ? exits the caller and cleans up the already prepared first. count_owned is not entered. On success it observes two owning strings and both remaining pack owners are released after that call. No earlier side effect is rolled back.

After a call completes normally, still-owned initialized pack elements are cleaned exactly once. A valid copied reference to external storage follows its original lifetime instead. Forced safety stops and external process termination gain no new cleanup guarantee. Exact physical placement, frame limits and ABI lowering must preserve these source-level obligations without a hidden heap fallback.

8. Preserve overload priorities and explicit cost boundaries

TopicContract
Zero argumentsAllowed; unresolved generic types still require valid inference or explicit complete type arguments.
OwnershipOrdinary Copy-or-move inputs; non-Copy elements are allowed and remain owned by the call-frame pack.
Access and lifetimeRead-only Slice-like access; pack views and loans of pack-owned elements cannot escape the call.
Mutation, spread and namesMutable variadic binding, explicit/automatic spread and named variadic binding are unsupported initially.
Ordinary defaults before packUnsupported in the initial rule.
Overload tieAfter existing type, literal and generic/non-generic preferences, an otherwise equal fixed-parameter candidate wins.
Remaining compiler detailsPhysical ABI, frame-size limits, backend lowering and full returned-reference notation still need implementation-level specification.

No overload families from different originating modules are pooled. If candidates are still tied after the selected priorities, the call is ambiguous. See the fixed-versus-variadic example.

Dynamic array literal construction uses CollectionError and one recursive construction Result for nested lists; inner lists do not each need their own ?. Ordinary Result-valued element expressions are not implicitly unwrapped. Remaining detailed element-cleanup ordering is separate: the pack contract does not silently select a general Array destruction order or a GPU/parallel execution model.
