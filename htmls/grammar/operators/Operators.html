1. Chosen expression rules

An expression computes a value or identifies a place in storage. A statement performs an action. Aevix keeps ordinary assignment statements separate from value expressions, while explicitly allowing prefix and postfix increment and decrement as value expressions.

This is a language design reference, not a claim that an Aevix parser, compiler, borrow checker or runtime implements these rules. Each example statement ends with a semicolon. Local binding examples assume a suitable enclosing block; module placement is not settled by this page.

  • Names follow type-first declarations: i32 value = 3;. Bindings are immutable unless mut is present.
  • int means i32; float means f64. rsn performs static inference.
  • Every normal non-void function exit has an explicit return. An error exit may be explicitly marked with postfix ?.

3. Typed operands do not silently promote

i32 left = 7;
i32 right = 3;
i32 sum = left + right;
f64 ratio = 0.5;
rsn inferred = sum + 1;

Already typed arithmetic operands must have compatible declared types. An unconstrained integer literal defaults to i32 and an unconstrained real literal to f64. A literal that has no type yet may use the surrounding type context. The result does not dynamically widen when it exceeds the type's range.

Rejected example. This block intentionally violates a chosen rule.

// Rejected: no implicit conversion from i32 to f64;
i32 number = 7;
f64 fraction = 0.5;
f64 mixed = number + fraction;

Use a documented explicit conversion API before mixed-type arithmetic. A cast operator spelling is not chosen here. Assignment and return contexts do not turn ordinary arithmetic into checked Result arithmetic.

4. Arithmetic keeps the chosen failure mode

i32 dividend = 7;
i32 divisor = 3;
i32 quotient = dividend / divisor;
i32 remainder = dividend % divisor;
i32 product = dividend * divisor;

The quotient here is 2 and the remainder is 1. Integer division uses the Integer contract of truncation toward zero. Ordinary integer arithmetic returns a scalar, diagnoses a statically guaranteed arithmetic failure, and safely stops execution on runtime failure. It never silently changes to wrapping because a release, AOT or JIT build was selected.

Recovery uses Integer.checked_* or lexical checked(...). See Checked Arithmetic for failures, evaluation boundaries and unfinished edge contracts. The exact mechanism of runtime safety termination and cleanup on that termination remains open.

5. Comparison and boolean logic

i32 low = 0;
i32 value = 5;
i32 high = 10;
bool within = low < value && value < high;
bool same = value == high;

Relational operators bind more tightly than equality operators. Comparisons still cannot form an unparenthesized chain across either level; explicitly group a comparison when using its result as another comparison operand. low < value < high is rejected; write two comparisons joined by &&. Equality does not grant ordering to a type that has no ordering contract.

Rejected example. This block intentionally violates a chosen rule.

// Rejected: chained comparisons are not an interval test;
i32 low = 0;
i32 value = 5;
i32 high = 10;
bool within = low < value < high;

Boolean logic short-circuits

bool large_ratio(bool enabled, i32 numerator, i32 denominator) {
    return enabled && ((numerator / denominator) > 1);
}

bool acceptable = large_ratio(false, 8, 0);
bool ready = !acceptable;

In this call the division is skipped because enabled is false. AND evaluates its right operand only when the left is true; OR does so only when the left is false. Both operands are still type-checked. A branch that is not evaluated does not perform arithmetic, mutation or calls.

Rejected example. This block intentionally violates a chosen rule.

// Rejected: an integer is not a boolean condition;
i32 count = 1;
bool active = count && true;

Use an explicit comparison, such as count != 0. Integer & and | perform bit operations and do not stand in for lazy boolean logic.

6. Bitwise operators and shifts

u8 flags = 0b1010;
u8 mask = 0b0010;
u8 common = flags & mask;
u8 combined = flags | mask;
u8 changed = flags ^ mask;
u8 inverted = ~flags;
bool selected = (flags & mask) != 0;

Bit operations preserve the integer width. Comparison binds more tightly than bitwise operations. Parenthesize the mask operation in (flags & mask) != 0 to test its result rather than combining an integer with a boolean.

In 0.2, both operands must be integers; their widths need not match. The shift count must be nonnegative and less than the left operand width. An invalid constant count is diagnosed and an invalid runtime count safely stops execution. Left shifts discard high bits within the original width; signed right shift propagates the sign bit and unsigned right shift inserts zero bits. Named checked-shift APIs remain design-catalog operations, not implemented alternatives.

7. Assignment, writable places and borrows

mut i32 total = 0;
i32 delta = 3;
total = delta;
total += delta;
total *= 2;

The target must be a writable place, and the stored value must match its type. Assignment and compound assignment do not yield a value for a surrounding expression. A C-style for header has a dedicated update-action slot that accepts i += 1 without turning it into a value expression.

Rejected example. This block intentionally violates a chosen rule.

// Rejected: assignment has no expression value;
mut i32 first = 0;
mut i32 second = 0;
i32 saved = (first = second);

Evaluate a target position once, then the right-hand side, then validate and store the result. If the associated arithmetic fails, no result from that failed update is stored. Borrow conflicts remain errors; assignment syntax does not authorize another simultaneous write alias. Fully specified compound-assignment interactions with user-defined places remain open.

Borrowing and dereference preserve permission

void increase(&mut i32 target) {
    (*target)++;
}

i32 apply_increase() {
    mut i32 value = 4;
    increase(&mut value);
    return value;
}

The immutable target reference binding carries an exclusive write capability, so the referent may be modified. The binding itself need not be mutable. An ordinary owner, such as value, requires mut before an exclusive loan can be created. A shared reference does not authorize writing, and dereference does not permit moving an owning non-Copy payload out of borrowed storage.

Rejected example. This block intentionally violates a chosen rule.

// Rejected: a shared read borrow does not grant write access;
void change_read_only(&i32 value) {
    (*value)++;
}

Unary & creates a loan; binary & combines integer bits. Loans obey overlapping-region and last-use checks. Existing compatible references and views pass directly to functions without automatic extra reference layers.

8. Prefix and postfix ++ / --

FormSuccessful updateReturned expression value
++valueAdd one, validate, then store.The new value of type T.
value++Add one, validate, then store.The previous value of type T.
--valueSubtract one, validate, then store.The new value of type T.
value--Subtract one, validate, then store.The previous value of type T.
mut i32 value = 4;
i32 previous = value++;
i32 current = ++value;
i32 before_decrement = value--;
i32 after_decrement = --value;

The recorded results are 4, 6, 6 and 4; the final stored value is 4. Each target position is evaluated once. These operations require a writable integer place, produce an integer value rather than a writable reference, and do not support bool, float or complex operands in the initial rule.

Overflow and unsigned underflow follow checked integer arithmetic. Validation occurs before the write. checked(value++) returns Err on failure and leaves that target unchanged; it does not produce Ok of the previous value when increment failed.

Rejected example. This block intentionally violates a chosen rule.

// Rejected: immutable integer storage cannot be incremented;
i32 value = 4;
value++;

Assignment remains statement-only even though increments are value expressions. This is an explicit language choice. Postfix increment/decrement belongs to the postfix chain; prefix forms share the unary level. Parentheses remain useful around compound targets. See the complete precedence table.

9. Ternary value selection

i32 maximum(i32 first, i32 second) {
    return (first > second) ? first : second;
}

i32 choose_score(bool selected) {
    return selected ? 10 : 20;
}

The condition must be bool. Both branches must resolve to the same value type, without silently converting an already typed operand. Only the selected branch executes. The result can initialize an immutable binding or be explicitly returned.

Rejected example. This block intentionally violates a chosen rule.

// Rejected: the two already typed branches have different types;
bool selected = true;
i32 integer_value = 10;
f64 float_value = 20.0;
rsn mixed = selected ? integer_value : float_value;

The conditional operator binds below range creation and logical OR and associates to the right. For clarity, group nesting as first ? a : (second ? b : c). Statement-form if is separate and never produces a value. Postfix error propagation and ternary selection are distinguished independently of whitespace. Use the unique complete syntactic interpretation, or require explicit parentheses when several remain; operand types do not select a parse. See question-mark parsing.

10. Precedence and evaluation order

RankOperatorsGrouping
1. () [] ? ++ --Left-to-right postfix chain; each form retains its operand/place rules.
2& &mut * + - ! ~ ++ --Right to left.
3* / %Left to right.
4+ -Left to right.
5<< >>Left to right.
6< <= > >=No unparenthesized comparison chain.
7== !=No unparenthesized comparison chain.
8&Left to right.
9^Left to right.
10|Left to right.
11&&Left to right; short-circuit.
12||Left to right; short-circuit.
13.. ..=Nonassociative; group endpoints when needed.
14condition ? first : secondRight to left; one selected branch.
i32 calculated = 2 + 3 * 4;
i32 grouped = (2 + 3) * 4;
bool allowed = (calculated > 0) && (grouped > calculated);

The first two results are 14 and 20. Parentheses override grouping. They do not alter the defined side-effect evaluation order. Assignment is outside the value precedence table.

Postfix propagation and increment/decrement bind in the postfix chain; prefix updates share the unary level. Nonassociative range creation binds below logical OR and above right-associative conditional selection. Comparisons cannot chain without explicit grouping. Parsing Rules defines mixed question marks, generic angles, range token boundaries and narrow compile-time type operands. These are chosen requirements for a future parser, not evidence of an implemented grammar.

Operands and arguments evaluate left to right once

i32 next_number(&mut i32 number) {
    return ++(*number);
}

i32 combine(i32 first, i32 second) {
    return first * 10 + second;
}

i32 observe_order() {
    mut i32 counter = 0;
    return combine(next_number(&mut counter), next_number(&mut counter));
}

observe_order returns 12: the first argument receives 1 and the second 2. Argument computations happen left to right, once each; each completed call's temporary exclusive loan ends before the next one is created. A function that retains a loan would still have to satisfy the borrow rules.

Precedence builds the expression tree. Evaluation order determines which operand work happens first. a + b * c evaluates a, then b, then c, computes the multiplication, then the addition. Short-circuit boolean operators, ternary selection and a checked failure skip work that their contracts exclude. Optimizations preserve observable values, mutations and failures.

11. Range literals create Range values

Range<int> half_open = 0..10;
Range<int> inclusive = 0..=10;
mut int total = 0;

for (int index in half_open) total += index;
for (int index in 0..10) total += index;
LiteralEquivalent constructorIncluded values
0..10Range.new(0, 10)0 through 9.
0..=10Range.closed(0, 10)0 through 10.

A range stores its endpoints and inclusion contract, not a preallocated list of all values. The existing Range reference describes supported fixed-width integers, empty ascending ranges, explicit descending/strided constructors and maximum endpoints. This literal rule does not approve floating-point ranges or new descending shorthand.

int first = 2;
int last = 6;
Range<int> segment = (first)..(last);

Range creation is nonassociative and binds below logical OR and above conditional selection. Arithmetic endpoint expressions bind first; grouping remains useful for readability. The lexer reads 0..10 as integer, range token, integer. See literal boundaries.

Open expression decisions

  • The chosen parsing requirements still need a formal grammar and executable positive/negative corpus; this is implementation work rather than an undecided source policy.
  • Broader catalog error enums and their payloads; the implemented shift contract is specified above.
  • User-defined operator overloads, indexing failures, place protocols and aggregate comparison contracts.
  • The 0.2 profile supports owned Optional propagation: Some yields its payload and None returns through a matching Optional function or explicitly typed closure. None-to-error conversion, a general cast spelling, null coalescing and if expressions remain outside this profile.
  • Safety termination, unwinding and cleanup on unrecoverable runtime arithmetic failure remain unsettled.
