1. Expressions connect the type and declaration rules

This section records the Aevix operator choices made after the data-type and declaration references. Ordinary integer arithmetic safely checks its result, explicit checked arithmetic produces Result, and postfix ? can forward an error from the current function.

Each page separates chosen syntax from open decisions and connects the operation to its type, ownership, cost and failure contract. These are language design references, not compiler execution evidence.

3. The combined model

Result<i32, IntegerError> calculate(i32 first, i32 second, i32 third) {
    i32 sum = checked(first + second)?;
    i32 value = checked(sum * third)?;
    return Result.ok(value);
}

i32 maximum(i32 first, i32 second) {
    return (first > second) ? first : second;
}

checked makes an arithmetic Result. Postfix ? extracts success or explicitly returns the error. The ternary operator chooses one same-type value. Neither form allows a function's final expression to become an implicit return.

4. Chosen rules at a glance

  • Static numeric types, contextual literals, no implicit promotion of already typed operands.
  • bool-only conditions; short-circuit AND/OR and selected-only ternary branches.
  • Left-to-right, one-time evaluation of operands, arguments and writable target positions.
  • Statement-only assignment plus explicitly supported integer ++ and -- value expressions.
  • Half-open and inclusive range literals create Range objects rather than materialized arrays.
  • Arithmetic Result failures and ? exits preserve ownership and do not roll back successful earlier effects.

Declaration examples use T name = value;, mut for ordinary writes and rsn for static inference. int = i32, float = f64, and the owning text type is lowercase string.

5. Open decisions remain visible

The precedence and parser-integration policy is chosen in Parsing Rules; a formal grammar and executable corpus remain future implementation work. Final IntegerError layout, complete shift contracts, nested checked/? effects, Optional propagation, user operator overloading and forced-stop cleanup remain open.

The existing type and declaration references describe the values, APIs and function contracts used by these grammar pages.
