1. Declare a struct and its fields

struct Point {
    public f64 x;
    public f64 y;
};

Point origin = Point { x = 0.0, y = 0.0 };
f64 horizontal = origin.x;

The type name precedes the variable name. Every field declaration and variable initialization ends in a semicolon; the complete struct declaration ends with };. A field is declared by its type and name. These examples use explicit types rather than name: Type syntax.

Point is a move type even though its f64 fields are Copy. Reading a Copy field can copy that field without transferring the whole owner. Automatic aggregate equality, ordering, or a physical representation is not implied.

2. Field visibility is private by default

struct User {
    string name;
    public i32 level;
};
Field form Access boundary Mutation permission
string name; Private to the declaring type. Visibility does not create a mutable owner or loan.
private string name; Explicit private has the same field access boundary. Normal ownership and borrowing still apply.
public i32 level; Available outside the type where the type itself is accessible. An ordinary write requires a writable place and a compatible exclusive loan.

Visibility modifiers belong to module/type declarations, not local bindings. A public field cannot expose its containing type through an inaccessible type boundary. The default visibility of every other declaration category is not specified by the field rule.

3. Initialize by field name

Point point = Point { x = 1.0, y = 2.0 };
Point reordered = Point { y = 4.0, x = 3.0 };

Each initializer key selects a declared field. Field spelling determines the destination; the written order determines expression evaluation. An initializer checks required-field completeness, duplicate keys, unknown names, type compatibility, and access permission.

Condition Selected outcome
A required field is missing. Compile-time rejection; a partially initialized safe struct is not exposed.
A field is specified more than once. Compile-time rejection.
An unknown field name is specified. Compile-time rejection.
A value has an incompatible field type. Compile-time rejection; already typed numerics do not receive implicit promotion.
The caller cannot access a specified private field. Compile-time rejection.

Rejected examples. These fragments intentionally violate separate initializer rules.

Point missing = Point { x = 1.0 }; // Invalid: y is missing.
Point duplicate = Point { x = 1.0, x = 2.0, y = 3.0 }; // Invalid: duplicate x.
Point unknown = Point { x = 1.0, y = 2.0, z = 3.0 }; // Invalid: no z field.
i32 typed_integer = 1;
Point wrong_type = Point { x = typed_integer, y = 2.0 }; // Invalid: typed i32 is not f64.

4. Initializer access is checked

A named initializer is not an escape hatch through a private field boundary. External code cannot set a private field simply by spelling its name. When required private fields must be initialized, an accessible type-internal factory can perform the initialization and return a complete owner.

Rejected external fragment. User.name is private. This function is outside the User declaration and receives an already owned string.

User invalid_external_initialization(string owned_name) {
    return User { name = owned_name, level = 1 }; // Invalid: private name.
}

The factory reference provides the selected type-internal function syntax. Field defaults remain outside the 0.2 profile; no implicit zero, empty string, or placeholder is supplied here. The planned 0.3 field shorthand abbreviates a named initializer without omitting required values or bypassing private access.

5. Evaluate initializer expressions once, left to right

struct OrderSample {
    public i32 first;
    public i32 second;
};

i32 next(&mut i32 running_count) {
    return ++(*running_count);
}

mut i32 counter = 0;
OrderSample ordered = OrderSample {
    second = next(&mut counter),
    first = next(&mut counter)
};

The written second expression runs first and produces 1; the written first expression then produces 2. Declaration order does not reorder observable initializer effects. Each completed call here returns a scalar and retains no loan, so the next call can create its own exclusive loan.

A later failure does not roll back successful earlier effects or moved inputs. Existing ownership cleanup rules govern values still owned by the evaluation. Exact diagnostics and implementation mechanics for partially constructed aggregates remain part of compiler design.

6. An ordinary field write follows owner mutability

Point fixed = Point { x = 1.0, y = 2.0 };
mut Point editable = Point { x = 1.0, y = 2.0 };
editable.x = 3.0;

An ordinary immutable owner permits reads but not direct field writes. mut provides the owner-level write permission; visibility and borrowing must still permit the access. A public field does not make an immutable instance mutable.

Rejected write. fixed is an ordinary immutable owner.

fixed.x = 3.0; // Invalid: immutable owner.

Interior synchronization types retain their own contracts. Their existence does not grant arbitrary writes to unrelated immutable fields. Per-field immutability modifiers and field defaults are not introduced here.

7. Borrow a value without moving it

Point point = Point { x = 5.0, y = 6.0 };
&Point read_view = &point;
f64 observed = (*read_view).x;

mut Point editable = Point { x = 7.0, y = 8.0 };
&mut Point write_view = &mut editable;
(*write_view).x = 9.0;

Shared loans preserve read access and exclude conflicting writes. Exclusive loans permit access through one compatible capability and exclude overlapping conflicts. An immutable binding that stores &mut Point can modify the referent; its own binding mutability concerns rebinding that reference.

The explicit dereference is intentional. Field automatic dereference is not selected by the method-call convenience rule. Loans remain bounded by their source lifetime, and proven disjoint field loans can be accepted without allowing arbitrary overlap.

8. Whole-value transfer moves by default

Point initial = Point { x = 1.0, y = 2.0 };
Point destination = initial;
f64 observed = destination.x;

destination receives the Point owner. initial is no longer available as a live value because Point has not opted into Copy. Assignment, value parameters, and returns follow the selected ownership model rather than silently deep-cloning fields.

Rejected use. The complete owner has already moved.

f64 stale = initial.x; // Invalid: initial was moved.

Adding implements Copy is a separate explicit decision for a type and is compiler-checked. Whole-value transfer does not physically promise memcpy, pointer-only movement, or a particular stack layout. Field-level partial moves and their interaction with custom cleanup remain open.

9. Keep bindings local and names unambiguous

Point point = Point { x = 1.0, y = 2.0 };
{
    f64 local_coordinate = point.x;
    f64 adjusted_coordinate = local_coordinate + 1.0;
}
f64 outside_coordinate = point.y;

A local name is available in its lexical region and descendant regions. A new variable must not hide an already visible variable, including a visible parameter. Public/private cannot decorate a local variable to widen its scope or extend its lifetime.

Rejected shadowing. The inner point would hide a visible owner.

Point point = Point { x = 1.0, y = 2.0 };
{
    Point point = Point { x = 3.0, y = 4.0 }; // Invalid: visible-variable shadowing.
}

Independent enum switch branches have their separately selected scopes; see Enums. These field and owner rules do not independently decide sibling reuse in every other declaration context.

10. Make allocation and cleanup contracts separate

A named initializer creates a concrete value. Type.new is an ordinary function whose body determines its work. Neither spelling implicitly requests Box allocation, shared ownership, a deep clone, or CPU/GPU transfer. A field initializer or called API may have its own explicit allocation and resource costs.

On a normal scope exit, currently owned initialized values are cleaned once under the established ownership rules. A transferred owner is cleaned at its destination, not again at its origin. A retained reference still needs its original backing owner to remain valid.

Operation Chosen meaning Not inferred from the spelling
Point { x = 1.0, y = 2.0 } Create a fully initialized concrete value. Heap placement, stable foreign layout, or automatic deep copy.
Point.new(1.0, 2.0) Call a declared receiverless type function. A special constructor allocation rule.
Point destination = initial; Transfer ownership for a non-Copy Point. CPU/GPU transfer or duplication.
&point Create a checked read loan. Ownership extension beyond the source lifetime.

11. Open struct policies

  • Field default expressions, alternative omitted-field mechanisms, and initialization update/spread syntax.
  • Custom destructor spelling, field cleanup ordering within aggregates, and partial-move restrictions.
  • Field automatic dereference remains outside the method-call borrowing convenience. In 0.2, field/method name collisions are rejected; distinct method signatures may overload, and accessible later-defined methods may be called without prototypes. See overloading and method calls.
  • Memory layout, alignment directives, ABI guarantees, and foreign representation annotations.
  • Automatic comparison, operator derivation, inheritance, or shared heap identity are not selected here.
  • Reference-return lifetime annotation syntax and the complete modifier grammar remain open.
