1. Build types from the established value rules

Aevix user-defined types use the same type-first declarations, static types, ownership, borrowing, visibility, and explicit returns as built-in values. A struct is a concrete value type; its name does not request a heap allocation or give it shared identity.

Confirmed design. The rules on these pages have been selected during language design. Examples are source-level specifications; no parser, runtime, benchmark, or backend execution is claimed.

3. A complete small value type

struct Point {
    public f64 x;
    public f64 y;

    public Point new(f64 initial_x, f64 initial_y) {
        return Point { x = initial_x, y = initial_y };
    }

    public f64 get_x(&Point self) {
        return (*self).x;
    }
};

Point point = Point.new(1.0, 2.0);
f64 coordinate = point.get_x();

The ordinary type function returns an initialized Point. The read method borrows the receiver and returns a Copy scalar. Point remains a move type because it does not declare implements Copy. Public fields are directly accessible, subject to mutability and borrowing.

4. Confirmed rules at a glance

Topic Selected rule Implication
Initialization Type { field = expression } Names select fields; required fields are initialized exactly once.
Field access private by default; public opt-in. Initializer access and later field access are both checked.
Mutability Immutable owner by default; explicit mut for ordinary writes. Visibility does not supply write permission.
Factories Type.new(...) is an ordinary receiverless type function. Its declared return type can be the type itself or Result.
Receivers &Type self, &mut Type self, Type self Read loan, exclusive write loan, or ordinary value transfer.
Copy implements Copy is an explicit built-in capability. All fields must be Copy; no implicit deep duplication.
Generic types struct Pair<T> and where T implements Copy The bound on T does not make Pair itself Copy.

5. Enums, interfaces, and generic types

Enums reuse the type-function and receiver model while adding explicitly selected variants and payload patterns. Generic struct, enum, and interface declarations use angle-bracket type parameters. Read the dedicated pages for their confirmed syntax; this section does not choose new interface, pattern, or constraint rules.

6. Decisions still open

  • Field default values and omitted-field initialization beyond the required-field rule.
  • Custom cleanup declarations, partial moves from types with user-defined cleanup, and the full field-projection move rules.
  • Physical layout, alignment controls, stable foreign representation, and automatic equality or other operator derivations.
  • General field automatic dereference and wrapper forwarding remain outside this profile. Method overloads, rejection of field/method name collisions, and calls to later-defined functions or methods already work in 0.2.
  • General modifier combinations remain subject to their own rules. The type header order is established: generic parameters, then implements, then where. See generic types.
