1. User-defined values move by default

struct Point {
    public i32 x;
    public i32 y;
};

Point original = Point { x = 1, y = 2 };
Point destination = original;

Point has no Copy declaration, so destination receives the owner and original cannot be used again. This default applies even when every field happens to be a Copy scalar. A compiler optimization cannot change the source-level validity of the old binding.

The same selected default applies to enums. Primitive Copy values keep their established scalar behavior; an aggregate does not automatically inherit Copy merely because it contains them.

2. Opt in with implements Copy

struct Coordinates implements Copy {
    public i32 x;
    public i32 y;
};

Coordinates first = Coordinates { x = 1, y = 2 };
Coordinates second = first;
i32 first_x = first.x;
i32 second_x = second.x;

implements Copy is the selected aggregate opt-in. Both bindings remain usable after the value copy. The declaration requests a compiler-checked built-in capability rather than an arbitrary user-defined duplication function.

Copy applies to ordinary value initialization, value arguments, value receiver calls, and value returns according to their declared modes. Read and write loan parameters still borrow; being Copy does not convert them into value arguments.

3. Check every field, including private fields

Requirement Reason
Every struct field is Copy. The whole value can be duplicated without duplicating an exclusive resource owner.
Every field of every enum variant is Copy. Copy is a static type capability, not a runtime decision based on the active tag.
Private fields and variants are included. Visibility cannot hide an unsafe duplication obligation from the compiler.
Nested aggregates meet their own Copy contract. A containing type cannot bypass another type’s move default.
Shared-reference copies preserve the source loan lifetime. Copying a reference does not create a new backing owner.

Rejected declarations. A private owned string or an exclusive reference makes the complete type non-Copy.

struct BadOwnerCopy implements Copy {
    public i32 id;
    string name; // Invalid Copy requirement: string owns its data.
};

struct BadLoanCopy implements Copy {
    &mut i32 target; // Invalid Copy requirement: exclusive loans are not Copy.
};

An empty ordinary interface with the same spelling cannot substitute for the compiler capability. A manually written deep-copy function also cannot certify Copy. Adding a non-Copy field to an explicitly Copy type must be rejected until the type contract is changed.

4. Keep value copying distinct from owner duplication

Value category Copy treatment Boundary
Established primitive Copy scalars Ordinary values copy. See the relevant primitive type contract.
&T Shared reference can be Copy. Copies point to the same referent and preserve its loan constraints.
&mut T Not Copy. Exclusive access cannot be duplicated as unrestricted aliases.
struct / enum without implements Copy Move by default. All-scalar contents do not automatically opt the aggregate in.
struct / enum with valid implements Copy Ordinary value copy is permitted. The compiler checks all fields, and all variants for an enum.
string Not Copy. Owning text is not silently deep-cloned.
Vector<T> Not Copy. The growable buffer owner is not implicitly duplicated.
Box<T> Not Copy. The unique heap owner is not implicitly duplicated even if T is Copy.

Explicit duplication APIs have their own work and failure contracts. For example, an explicit Box duplication can allocate; it is not the same operation as ordinary value Copy. This page does not introduce a universal Clone interface or final clone-method syntax.

5. Shared reference copies retain the original lifetime

struct CounterView implements Copy {
    public &i32 target;
};

i32 source = 7;
CounterView first_view = CounterView { target = &source };
CounterView second_view = first_view;
i32 observed = *(second_view.target);

The two views refer to source. Neither owns source, copies source into independent storage, or extends its lifetime. Both copies remain subject to the same source validity and conflicting-access checks.

Rejected escape. A Copy view cannot return a reference to a dead local.

CounterView invalid_view() {
    i32 local = 7;
    return CounterView { target = &local }; // Invalid: local cannot outlive this call.
}

Reference fields may carry hidden source-loan constraints even when a later type-erasure or ownership wrapper hides their concrete type. The full written lifetime-parameter and returned-reference annotation syntax remains open.

6. Receiver spelling determines the call mode

Receiver Value capability effect
&Coordinates self The call reads through a loan, regardless of Coordinates being Copy.
&mut Coordinates self The call requires exclusive write permission; Copy does not authorize aliases.
Coordinates self The ordinary value call may copy because Coordinates explicitly implements Copy.
User self for a non-Copy User The ordinary value call moves the User owner.

The automatic method-borrow convenience follows the declared reference receiver. It does not select a different receiver mode based on whether the value can be copied. Borrowed dyn views do not gain value-receiver support merely because one possible implementation is Copy.

7. An enum checks every variant

enum Direction implements Copy {
    North;
    East;
    South;
    West;
};

Direction first_direction = Direction.North;
Direction second_direction = first_direction;

The Copy declaration applies to Direction as a whole. A payload enum must check all variant fields, including private variants. A non-Copy payload anywhere prevents Copy even when the current value happens to be an empty variant.

The separately selected consuming enum switch moves a non-Copy owned enum: switch (move value) makes its original binding unusable. The exact explicit-consume treatment of Copy enum operands remains open; this page does not choose forced invalidation or ordinary copying for them. Source-level move semantics do not promise a particular physical byte-copy instruction. Read Enums for all switch modes and payload bindings.

8. A Copy bound on T does not opt in its container

struct Pair<T> where T implements Copy {
    public T first;
    public T second;
};

Pair<i32> numbers = Pair<i32> { first = 10, second = 20 };
Pair<i32> destination = numbers;

The where clause requires a Copy type argument. It does not declare Pair<T> itself Copy, so this Pair<i32> owner moves. A separately declared implements Copy opt-in is needed for a generic aggregate to copy under a valid complete field check.

Pair<string> violates the bound because owning string is non-Copy. Generic function requirements use the chosen name-following type parameters and parameter-list-following where clause; multiple function requirements repeat their subject and are separated by commas. The combined header order for a type that has both its own implements list and a where clause remains open. Read Generic Types for the selected type-parameter grammar.

9. Copy is a semantic capability, not a machine instruction promise

Copy permits value duplication without a hidden deep clone, allocation, or CPU/GPU transfer. The compiler can eliminate a proven redundant copy or choose an efficient representation while preserving observable values and ownership validity. Large Copy values can still require real data movement.

A move is also a semantic ownership transfer; physical bytes may move or be optimized away. Do not infer performance from the words Copy and move alone. Scope cleanup releases only values currently owned in that scope and does not release an owner again after transfer.

Custom cleanup declarations and their compatibility with Copy are not settled. No user-defined destructor body, duplicate finalization protocol, or exemption from borrow checks is implied by this built-in capability.

10. Required rejection and open capability policies

Condition Selected outcome
A Copy declaration contains a non-Copy field. Reject the declaration, including when the field is private.
A Copy enum contains a non-Copy payload in any variant. Reject the declaration; active-tag testing cannot rescue it.
A moved non-Copy owner is used again. Reject the later use.
A copied shared reference escapes its valid source lifetime. Reject the escape.
A Copy generic argument bound is not met. Reject the type instantiation.
  • Custom cleanup and partial-move compatibility remain open.
  • General Clone interfaces, user operator derivation, comparison derivation, and deep-copy notation remain open.
  • Physical layouts, foreign ABI representation, generic implementation strategy, and copy-cost diagnostics remain open.
  • These are source-level rejection categories, not implemented compiler diagnostic codes.
