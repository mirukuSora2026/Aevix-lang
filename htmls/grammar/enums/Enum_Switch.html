1. Choose read, modify or consume mode explicitly

HeaderModeSource after the switch
switch(event)Shared read loan.Owner retained; ordinary mutation through its read bindings is unavailable.
switch(&mut event)Exclusive modification loan.Owner retained; explicitly bound writable fields may change.
switch(move event)Explicit consuming dispatch on an owned non-Copy enum.Original source unavailable after consumption; owning fields may move into bindings.

The selector is evaluated once. Only the matching branch runs. Every case and every written default has its own independent lexical scope and ends with break;. There is no implicit fallthrough. Earlier return, loop continue, divergence and Result ? are allowed, but every written branch still ends with break;. A required break that is unreachable is not an error or warning solely for that reason. This does not establish a general unreachable-code policy. See case exits.

The move marker is approved for enum switch headers. This does not establish a general move expression anywhere in the language. Reference-source mode inference, temporary lifetimes and special treatment of Copy enums in explicit consuming switches remain open.

2. A public payload schema for the examples

public enum Event {
    Quit;
    Move {
        public i32 x;
        public i32 y;
    };
    Message {
        public string text;
    };
};

These fields are public so the free functions below may bind them. Field privacy is enforced in initializers and patterns. Event.Quit is an empty variant value, while Event.Message is only a tag-only case spelling until an owning text payload is supplied for construction.

See enum visibility and private factories for exposing a public variant while retaining private payload data.

3. Default dispatch reads and preserves the local owner

Event inspect_event(Event event) {
    mut i32 code = 0;
    switch (event) {
        case Event.Quit:
            code = 1;
            break;
        case Event.Move { i32 dx = x, i32 dy = y }:
            code = dx + dy;
            break;
        case Event.Message { &string message = &text }:
            bool empty = string.is_empty(message);
            code = empty ? 0 : 2;
            break;
    }
    return event;
}

The pattern names dx and dy are newly bound variables; x and y on the right name payload fields. The i32 fields are Copy, so their values may be copied during a read switch. A non-Copy string is instead bound as a read reference, without an owning clone.

switch(event) preserves the event owner, allowing the final explicit return to transfer it. The by-value function parameter already receives caller ownership on function entry; the switch itself does not add another move. This example distinguishes call ownership from dispatch ownership.

Read bindings cannot authorize ordinary writes to payload fields. Compatible aliases and escaping references remain governed by source provenance and lifetime.

4. Explicit and convenience read-borrow bindings are both supported

bool message_empty(Event event) {
    mut bool empty = false;
    switch (event) {
        case Event.Message { &string message = text }:
            empty = string.is_empty(message);
            break;
        case Event.Move:
            empty = false;
            break;
        case Event.Quit:
            empty = false;
            break;
    }
    return empty;
}
Pattern fragmentMeaning
i32 dx = xCopy the visible i32 field x into immutable local dx.
&string message = &textExplicitly read-borrow the visible non-Copy field text.
&string message = textSupported convenience read-borrow spelling inside an enum pattern.
&mut i32 dx = &mut xExplicit writable field borrow in an exclusive modification switch.
string message = textMove the owning field in consuming mode; no hidden clone.

A shared receiver method may explicitly select its enum referent with switch (*self); this chooses a read loan of the referent place, not a value move out of the reference. The unspecialized switch(self) source-mode inference remains open. The read convenience rule is specific to enum pattern binding. It does not add implicit read borrowing to ordinary local declarations or function arguments. A binding declaration starts with its type, and its name may not hide a visible outer local name.

5. Exclusive dispatch modifies explicitly borrowed fields

Event shift_event(Event input) {
    mut Event event = input;
    switch (&mut event) {
        case Event.Move { &mut i32 dx = &mut x, &mut i32 dy = &mut y }:
            *dx += 1;
            *dy -= 1;
            break;
        case Event.Message:
            break;
        case Event.Quit:
            break;
    }
    return event;
}

The mutable local event supplies the exclusive capability. dx and dy are explicit writable references to separate fields of the active Move payload; dereference them to modify those fields. The enum owner is retained and may be returned after the switch.

Active borrow conflicts are checked against overlapping storage. Reading an already borrowed reference directly does not insert another &. An exclusive switch does not silently expose writable references for every field.

The shorthand &mut i32 dx = x is not yet chosen. Examples use the explicit &mut field form. Replacing the active variant while field loans remain active follows ownership/overlap checks; a dedicated replacement syntax is not defined here.

6. Consuming dispatch moves owning payload fields

usize consume_message_bytes(Event event) {
    mut usize bytes = 0;
    switch (move event) {
        case Event.Message { string message = text }:
            bytes = string.byte_len(&message);
            break;
        case Event.Move:
            bytes = 0;
            break;
        case Event.Quit:
            bytes = 0;
            break;
    }
    return bytes;
}

event is an owned non-Copy value. The switch consumes it, and the original event binding is unavailable afterwards. In the Message case, the owning text field moves into message. The read length operation borrows that new owner explicitly; it does not create a text clone.

At case exit, message is cleaned up if it remains owned by that case. If a moved binding has itself been transferred to another valid owner, cleanup follows that destination instead. Remaining active payload fields that were not moved are cleaned up exactly once.

Only the active variant has live payload resources. Custom cleanup implementations and their compatibility with partial moves remain open. No example here defines a custom enum destructor.

7. Bind a subset of fields or only the variant tag

enum Envelope {
    End;
    Data {
        public string body;
        public string note;
    };
};

usize consume_body_bytes(Envelope envelope) {
    mut usize bytes = 0;
    switch (move envelope) {
        case Envelope.Data { string payload = body }:
            bytes = string.byte_len(&payload);
            break;
        case Envelope.End:
            break;
    }
    return bytes;
}

The Data pattern binds only body; note is intentionally omitted. In a consuming switch, omitted owning payloads remain part of the switch cleanup and are released exactly once. In read or modification mode, omitted fields stay with the source owner rather than being implicitly moved or cloned.

A tag-only case such as case Event.Message: is accepted even though Message has payload fields. It grants no payload access and can match a visible variant whose fields are private. In consuming mode it also leaves all unbound payload owners to cleanup.

Tag-only case syntax is not a constructor spelling: Event.Message alone is not a fully initialized payload value.

8. Each case and default has its own lexical scope

i32 move_component(Event event) {
    mut i32 component = 0;
    switch (event) {
        case Event.Move { i32 local = x }:
            component = local;
            break;
        case Event.Message:
            i32 local = 0;
            component = local;
            break;
        case Event.Quit:
            i32 local = -1;
            component = local;
            break;
    }
    return component;
}

The three local names belong to independent sibling case scopes. Reusing the name is allowed because another sibling case binding is not visible. A pattern or body binding that hides an already visible outer local is still rejected.

Pattern bindings and body locals leave their lexical scope with the branch. Owners still held there are cleaned up in reverse initialization order. Nested-block cleanup is not repeated by the terminal break.

A loan lifetime is not identical to a binding name scope. A reference may remain valid beyond the case if its source provenance and the surrounding borrow rules permit it; a reference to case-local owned storage cannot escape the storage lifetime. Do not assume every source loan must end solely because break is reached.

9. Cover every variant or provide default

i32 event_category(Event event) {
    mut i32 category = 0;
    switch (event) {
        case Event.Quit:
            category = 1;
            break;
        default:
            category = 2;
            break;
    }
    return category;
}

An enum switch must cover all variants through explicit cases or a default branch. Omitting any declared variant without default is a compile-time error. The earlier full Event switches need no default because each variant is covered.

A tag-only case covers that variant without requiring every payload field to be bound. A default covers all variants not explicitly handled, including variants added to the enum later; it therefore suppresses missing-variant diagnostics for those additions.

This coverage contract belongs to enum dispatch. It does not silently impose the same exhaustive finite-domain rule on an ordinary scalar switch. Guarded patterns and their coverage meaning remain open.

10. External switches need default for hidden variants

public enum Credential {
    Token {
        string secret;
    };
    private Internal;

    public Credential issue(string initial_secret) {
        return Credential.Token { secret = initial_secret };
    }
};

bool externally_is_token(Credential credential) {
    mut bool token = false;
    switch (credential) {
        case Credential.Token:
            token = true;
            break;
        default:
            token = false;
            break;
    }
    return token;
}

External code can tag-match public Token without binding private secret. It cannot name private Internal, so default is required to cover that hidden possibility. Privacy does not erase the variant from the enum type or from exhaustiveness checks.

Code with access inside the enum may name its private variants and may provide full explicit coverage. A default branch still has an independent lexical scope and still ends with break. It does not grant access to the hidden payload.

11. Rejected coverage, field and ownership patterns

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

void missing_variant(Event event) {
    switch (event) {
        case Event.Quit:
            break;
        case Event.Move:
            break;
    }
}

Message is uncovered and there is no default.

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

void duplicate_field(Event event) {
    switch (event) {
        case Event.Move { i32 first = x, i32 second = x }:
            break;
        default:
            break;
    }
}

A payload field cannot be bound twice in one pattern. This is distinct from reusing a local name in independent sibling cases.

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

void unknown_field(Event event) {
    switch (event) {
        case Event.Move { i32 depth = z }:
            break;
        default:
            break;
    }
}

Move declares no field z.

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

void inaccessible_field(Credential credential) {
    switch (credential) {
        case Credential.Token { &string exposed = &secret }:
            break;
        default:
            break;
    }
}

This function is outside Credential and cannot bind private secret. The public tag-only case remains allowed.

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

Event consumed_then_returned(Event event) {
    switch (move event) {
        case Event.Quit:
            break;
        case Event.Move:
            break;
        case Event.Message:
            break;
    }
    return event;
}

The owned non-Copy event was consumed. Returning the original binding afterwards violates ownership. These examples define intended compile-time rejections rather than executed diagnostics.

12. Open switch details and linked contracts

  • Guarded patterns, grouped labels, wildcard spelling and richer nested/destructuring patterns.
  • Temporary selectors, detailed lifetime rules for borrowed selectors and inference when the source expression is already a reference.
  • Implicit mutable field binding without an explicit &mut source marker.
  • Custom cleanup hooks and partial-move restrictions imposed by such hooks.
  • Exact handling of Copy enums under an explicit switch(move ...) header.
  • General unreachable-code treatment remains open beyond the chosen exception for the syntactically required terminal break. Normal return/continue/Err exits apply their ordinary cleanup; nontermination and forced stops do not gain a normal-exit guarantee.
  • General move expressions outside enum switch and full parser grammar for future type syntax.

Missing fields in a pattern are already permitted, while missing required fields in a constructor are rejected. Ordinary arithmetic failures and ? propagation keep their separate contracts. See Switch, Copy, Interfaces and Generic Types.
