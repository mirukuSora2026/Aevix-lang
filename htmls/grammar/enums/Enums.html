1. Unified variants belong to one parent type

An enum declaration introduces one named type. Empty variants represent cases without data; payload variants carry named typed fields. Values of both forms have the parent enum type. Aevix does not split empty enums and data enums into separate declaration mechanisms.

Ordinary enum values move by default. Visibility, payload initialization, Copy eligibility and interface implementation are checked against the complete declaration. These requirements are language-design contracts rather than results from an implemented compiler.

2. Declare empty and named-payload variants

public enum Event {
    Quit;
    Move {
        public i32 x;
        public i32 y;
    };
    Message {
        public string text;
    };
};

Quit is empty. Move carries two i32 fields. Message carries an owning string. Fields use the ordinary type-first declaration form. Each empty variant ends with a semicolon, each payload variant closes with };, and the whole enum also closes with };.

The declaration makes variant names public by default. Payload fields are made public explicitly here so code outside Event can initialize and bind them in the following examples. A field without public is private.

3. Initialize every required payload field

Event make_quit() {
    Event event = Event.Quit;
    return event;
}

Event make_move(i32 initial_x, i32 initial_y) {
    Event event = Event.Move { x = initial_x, y = initial_y };
    return event;
}

Event make_message(string initial_text) {
    return Event.Message { text = initial_text };
}

Event.Quit is an empty variant value. Event.Move { ... } and Event.Message { ... } are named-payload initializers. All required fields must be present and accessible from the initializer location. No default payload values are assumed.

Moving initial_text into Message transfers its ownership. No deep string clone or hidden allocation is requested by this syntax alone. Each returned value still has type Event; Event.Move is not a separately declared type.

A payload variant name alone, such as Event.Message, is not a fully constructed value. A tag-only case label is a different pattern operation documented in Enum Switch.

4. Variant access and payload access are separate

A public variant with private payload fields can be named in a tag-only case outside its type. Naming that variant does not authorize construction of inaccessible fields or binding their contents. A private variant cannot be explicitly named by external code.

Visibility never extends the lifetime of an enum value or borrowed field. A local binding still belongs to its lexical scope, and nested locals may not hide a visible outer name.

5. Use type functions to construct private payloads

public enum Credential {
    Token {
        string secret;
    };
    private Internal;

    private Credential from_secret(string initial_secret) {
        return Credential.Token { secret = initial_secret };
    }

    public Credential issue(string initial_secret) {
        return Credential.from_secret(initial_secret);
    }
};

Credential issue_credential(string initial_secret) {
    return Credential.issue(initial_secret);
}

from_secret is a private receiverless type function. issue is a public type function that uses it. Both are inside Credential and may initialize the private secret field. External code constructs a Credential through Credential.issue, while the field remains inaccessible.

The factory name is an ordinary function name. No constructor-only keyword, static storage modifier or implicit payload default is introduced. persist controls storage duration; it is not the spelling for receiverless type functions.

6. Moving an enum moves its active payload

Event relay_event(Event source) {
    Event transferred = source;
    return transferred;
}

An enum that does not implement Copy moves through ordinary value assignment, by-value parameters and returns. Its active payload follows the transferred value. An immutable binding may move; immutability forbids ordinary mutation rather than ownership transfer.

The source binding cannot be used after a move. An inactive variant has no live payload to clone or clean up. A shared read borrow or enum read switch can observe the active value without transferring the owner.

Normal scope exits clean up resources still owned locally in reverse initialization order, exactly once. Returning a moved enum gives the caller its owner; it must not also be destroyed as a local. Memory layout and custom enum cleanup hooks remain open.

7. implements Copy validates every possible variant

enum Axis implements Copy {
    X;
    Y;
    Offset {
        public i32 amount;
    };
};

Axis copy_axis(Axis source) {
    Axis duplicate = source;
    return duplicate;
}

Copy is a built-in checked capability. Every payload field of every variant must satisfy its Copy requirements, including private variants and private fields. An empty variant contributes no payload field. The check applies to the whole enum type, not only the currently active variant.

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

enum InvalidEvent implements Copy {
    Quit;
    private Message {
        string text;
    };
};

The owning string is non-Copy, so InvalidEvent cannot implement Copy even when external code cannot name Message. The compiler must not base this decision on which variant happens to be stored at runtime.

See Copy for the shared capability contract. Copy does not promise a deep clone, custom clone method, stable ABI or operator overload.

8. Enums reuse type functions and self receivers

enum Signal {
    Stop;
    Value {
        public i32 amount;
    };

    public Signal value(i32 initial_amount) {
        return Signal.Value { amount = initial_amount };
    }

    public Signal into_signal(Signal self) {
        return self;
    }
};

Signal relay_signal(i32 amount) {
    Signal signal = Signal.value(amount);
    return signal.into_signal();
}

value has no self parameter, so it is called on the type. into_signal has a by-value self parameter, so its call receives ownership of the non-Copy signal. The returned owner then moves to the caller.

The shared method forms are a value receiver T self, a read receiver &T self, and a modification receiver &mut T self. Public/private access and explicit receiver capabilities follow the same rules as structs. The appropriate active payload is accessed through a switch pattern rather than pretending all variants have the same fields.

Non-void methods explicitly return a value on normal completion. Every written case/default in an enum method switch still ends with an explicit break;, including after a permitted return, enclosing-loop continue, divergence or Result ?. The required terminal break produces neither an error nor a warning merely because an earlier exit makes it unreachable. A successful ? continues toward that break; an Err exits the function. Normal exits clean up only the regions they leave, exactly once. General unreachable-code policy and safety-stop cleanup remain separate open topics. See case exits.

9. An interface implementation covers the whole enum

An ordinary implements Interface declaration belongs to the entire enum type. Self in that interface means the parent enum. It does not mean an individual variant, and each variant does not become an independent implementer.

Enums reuse the selected interface dispatch, default method and override contracts. A method may decide its behavior from the active variant through switch, but its signature still satisfies the one enum implementation. Variant visibility does not remove private variants from this obligation.

See Interfaces for the canonical declaration and method requirements, and Generic Types for type parameter constraints. A built-in capability such as Copy also applies to the whole enum, with additional compiler validation.

interface Leveled {
    public i32 get_level(&Self self);
};

enum LevelState implements Leveled {
    Beginner;
    Experienced;

    public i32 get_level(&LevelState self) {
        mut i32 level = 0;
        switch (*self) {
            case LevelState.Beginner:
                level = 1;
                break;
            case LevelState.Experienced:
                level = 2;
                break;
        }
        return level;
    }
};

Self in Leveled maps to LevelState, so the implementation receives &LevelState self. The required method is a normal public declaration; override is reserved for replacing an inherited default implementation. The switch explicitly selects the enum referent place through *self for a read loan. It does not move the enum out of the shared reference.

10. Rejected initialization and visibility examples

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

Event incomplete_move(i32 initial_x) {
    return Event.Move { x = initial_x };
}

Move requires both x and y. There is no implicit default for the missing field.

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

Credential inaccessible_payload(string initial_secret) {
    return Credential.Token { secret = initial_secret };
}

This function is outside Credential, so it cannot initialize private secret. Use the public factory. Tag-only matching of the public Token variant is still allowed without revealing secret.

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

Event invalid_payload_value() {
    return Event.Message;
}

Message requires a payload initializer. The tag-only spelling is accepted as a case label, not as a constructor value. These examples define intended rejection, not actual compiler diagnostics.

11. Open enum decisions

  • Numeric discriminants, explicit variant numbers, memory layout, tag size, niche optimization and stable foreign ABI.
  • Automatic equality/ordering, operator derivation, automatic clone generation and custom clone conventions.
  • User-defined enum cleanup and its interaction with partial payload moves.
  • Full parser grammar, initializer defaults, overload resolution and additional constructor shorthand.
  • General move expressions outside enum switch, and special treatment of explicit switch(move ...) for Copy enums.
  • Extended pattern features, reference-source mode inference and temporary selector lifetime details; see Enum Switch.

The accepted choices on this page are independent of those open decisions. Continue with Enum Switch for ownership-aware dispatch and exhaustive pattern coverage.
