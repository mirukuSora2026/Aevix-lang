1. Files define modules; imports define access

One .avx source file defines one module. Its path under the configured source root determines its logical full module path. Imports appear at the top of a file before declarations and explicitly control the public names that the importing file may access.

This reference records the selected Aevix design. It does not claim an implemented compiler, package manager, loader, diagnostic system or filesystem resolver. Source paths shown in examples describe hypothetical modules; they are not links to files in this documentation tree.

3. A small public module and a selective consumer

EXAMPLE FILE · src/math/vector.avx · module math.vector

public struct Point {
    public f64 x;
    public f64 y;
};

public f64 dot(&Point left, &Point right) {
    return (*left).x * (*right).x + (*left).y * (*right).y;
}

public const i32 DIMENSIONS = 2;

EXAMPLE CONSUMER · imports precede declarations

import math.vector { Point, dot };

f64 horizontal_projection() {
    Point point = Point { x = 3.0, y = 4.0 };
    Point axis = Point { x = 1.0, y = 0.0 };
    return dot(&point, &axis);
}

Point and dot are public in math.vector and explicitly selected by the consumer. DIMENSIONS remains unselected in that consumer: neither its short name nor math.vector.DIMENSIONS is available through this import. A qualified spelling does not bypass selection or privacy.

4. The chosen module contract

AreaChosen rule
File mappingsrc/math/vector.avx becomes math.vector; no separate module declaration.
Source rootsrc/ by default; configurable, with configuration spelling still open.
Path spellingFull, case-sensitive module paths only; no relative imports or aliases.
VisibilityModule-level types, functions and constants are private unless explicitly public.
Wildcard importimport math.vector { * }; imports the module's public names.
AmbiguityNo explicit/wildcard/local priority; ambiguous short-name use is rejected.
Reexportpublic import names explicitly, preserving their names and original declaration identity.
Module cyclesAllowed inside one package; value initialization is a separate dependency problem.
Package cyclesRejected between packages, including packages in one workspace.
Prefix coexistencemath.vector and math.vector.ops may be independent files at the same time.

5. Keep syntax, ownership and initialization separate

Importing a declaration does not call it, copy its values, allocate a wrapper, or transfer data to a GPU. Ordinary function arguments still use the selected value and borrow rules. Imports themselves do not make a declaration Copy or grant write permission.

Modules reachable from the entry module through imports and reexports contribute all of their top-level persist declarations to pre-entry initialization. Import order is not a value-initialization schedule. See Persistent Storage for dependency ordering, runtime readiness checks and cleanup.

Source-root configuration syntax, full identifier grammar, filesystem indirection details and package version/build metadata remain open. These open details do not weaken private access, selected import restrictions or full-path collision errors.
