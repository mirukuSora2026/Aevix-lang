1. A package contains modules but has its own dependency boundary

A module is one .avx file. A package groups source modules and participates in a package dependency graph. Sharing a workspace does not merge package identities, private scopes or dependency rules.

This page records source-level package and path boundaries. It does not define a completed package manifest, registry protocol, version solver, package publishing process or workspace configuration file.

2. External modules include the actual package name

import pixel.filters;
import pixel.filters { apply };

The path identifies the filters module of an external package actually named pixel. The second line illustrates selecting a public name offered by that example module; it does not assert that a standard pixel package or implemented apply API exists.

Package identity is not replaced by a source import alias. Import aliases and selected-name aliases are not permitted. The imported path also controls qualified access: reexports do not automatically authorize the original package path.

3. Standard modules have top-level paths

import math;
import io;

Standard-library modules use paths such as math and io. There is no required std prefix. Whether std is reserved is still open, so this page neither reserves it nor promises that a user package may freely claim every spelling under it.

The lines demonstrate module path spelling, not the detailed APIs of math or io. Visibility and selected/whole-module import rules apply to public declarations supplied by the resolved module.

4. No source category wins a full-path collision

CandidatesChosen result
A project math module and the standard math module.Resolution error; no project-first or standard-first fallback.
Two available sources both provide pixel.filters.Resolution error; no dependency/source-order winner.
Different modules each expose a short name Point.Not a full-path collision; ambiguous short uses follow import lookup rules.

A full path must identify one module candidate. An explicit named import does not resolve a collision in the module path itself: the target module must be identified before its selected names can be resolved.

Do not interpret configurable source roots as a priority list that silently overrides this rule. Configuration syntax is open; the no-priority collision result is not.

5. Dependencies between packages must be acyclic

GraphChosen rule
Several modules inside one package.Declaration/import cycles may be allowed under the module rules.
Package A depends on B and B depends on A.Reject the package dependency cycle.
A depends on B, B on C, C on A.Reject the indirect package dependency cycle.
The same cyclic packages are members of one workspace.Still reject; workspace membership is not an exemption.

The package dependency graph and the module declaration graph are distinct. Supporting mutually referring source files inside a package does not legalize circular dependencies between independently identified packages.

Moving two packages into one workspace is therefore not a cycle-resolution mechanism. No package manifest syntax is needed to state this semantic constraint, and no package manager implementation is claimed.

6. Package membership does not bypass file privacy

Module-level types, functions and constants are private to their declaring file module unless public. Another module in the same package cannot import a private helper solely because it belongs to the same package. A module with a longer path prefix is also a separate boundary.

Across packages, the same public access requirement remains. A public type retains its field and payload access rules; making a declaration importable does not expose private internals or create a writable reference.

A package dependency also does not put all dependency names into scope. Each file still writes the full-path imports and explicit selections it needs.

7. Public forwarding creates only the declared public route

EXAMPLE MODULE · graphics.api

public import pixel.filters { Filter };

EXAMPLE CONSUMER

import graphics.api { Filter };

The consumer may name Filter and graphics.api.Filter. It does not gain pixel.filters.Filter without another import of the original path. The underlying declaration remains the same canonical Filter rather than a new copied type.

This example illustrates public names supplied by hypothetical modules. Their implementation files are not HTML links or newly created source artifacts. Wildcard public forwarding is forbidden, and forwarding never bypasses the source declaration's public requirement.

8. Imports also connect the pre-entry initialization target set

Starting at the entry module, follow imports and reexports to the connected modules. Every top-level persist declaration in those modules is a pre-entry initialization target, including private or otherwise unused top-level persist declarations in an included module.

Selecting one declaration does not mean only that declaration is initialized. This target-set rule is separate from which names the file may use. Allowed declaration cycles are not an execution order; confirmed value dependencies and the persistent-storage readiness rules determine initialization.

Unimported unrelated source files are not added solely because they exist in a directory. The default executable entry is main from src/main.avx. The configuration spelling for choosing another entry module and complete build configuration remain open. See Persistent Storage for the initialized target set and shutdown contracts.

9. Check identity and access before treating a name as usable

CheckBoundary
One full path resolves to several providers.Reject module resolution rather than picking a provider.
A package cycle exists.Reject even in a workspace.
Only casing differs between modules in one package.Reject the conflicting source arrangement.
A private declaration is selected from another file.Reject the selection regardless of package membership.
A consumer names an unimported original reexport path.Reject the unauthorized route.

The language does not derive initialization safety, visibility or memory layout from package location. All examples use the chosen grammar with explicit semicolons and preserve ordinary static typing.
