1. if is a statement; conditional selection is an expression

An if statement decides which statement or block executes. It does not produce a value. Aevix uses the ternary conditional operator when a condition selects a value for an initializer, argument or return expression.

The grammar requires parentheses around each if and else if condition. Conditions have type bool; numbers, pointers and Optional values do not acquire implicit truthiness.

2. Required parentheses and explicit return paths

int maximum(int left, int right) {
    if (left > right) {
        return left;
    } else {
        return right;
    }
}

The condition is evaluated once when execution reaches this if. Exactly one branch executes. else is optional for a statement-form if; when the condition is false and no else is present, execution continues after the statement.

A function returning a non-void value still needs an explicit return on every normal completion path. Selecting a branch does not itself return from the function.

3. Conditions must be bool

int clamp_negative(int value) {
    bool negative = value < 0;
    if (negative) return 0;
    return value;
}

Comparisons produce bool. Logical !, && and || work on bool operands; && and || preserve their short-circuit behavior within a condition. A numeric test must explicitly compare the number with another value.

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

void invalid_numeric_condition() {
    int count = 3;
    if (count) return;
}

The rejected condition has type int, not bool. Use an explicit condition such as count != 0.

4. Braces may be omitted for one executable statement

int normalize(int value) {
    mut int normalized = value;
    if (normalized < 0) normalized = 0;
    else normalized += 1;
    return normalized;
}

One executable statement may form a branch body without braces. Multiple statements require { ... }. This is a count of statements, not a count of source lines. Every declaration, assignment, call statement and return statement ends with a semicolon. A closing control-flow or function brace does not require an extra semicolon.

int record_positive(int value) {
    mut int adjusted = value;
    mut int changes = 0;
    if (adjusted > 0) {
        adjusted += 1;
        changes += 1;
    }
    return adjusted + changes;
}

Putting another statement on the same physical line does not add it to a braceless branch. A declaration used as a branch body requires an explicit block, even when it is the only declaration. The block supplies its lexical scope and cleanup boundary; a lone unbraced declaration is rejected.

5. else if checks alternatives in order

int sign_code(int value) {
    if (value < 0) return -1;
    else if (value == 0) return 0;
    else return 1;
}

Conditions are considered in source order until a branch is selected. Later conditions and their bodies are not evaluated after an earlier condition succeeds. Each else if has its own parenthesized bool condition; else has no condition.

An else attaches to the nearest unmatched if. In if (outer) if (inner) action(); else fallback();, the else belongs to inner. Use braces to attach it to outer. See statement parsing.

6. Use ? : when a condition selects a value

int maximum_value(int left, int right) {
    int larger = (left > right) ? left : right;
    return larger;
}
PropertyChosen rule
ConditionMust have type bool.
Alternative typesBoth alternatives have the same result type; no automatic numeric promotion of already typed values.
EvaluationEvaluate the condition, then evaluate only the selected alternative.
PrecedenceLower than arithmetic, comparison and logical operators.
AssociationNested conditional selection associates to the right.
ReturnThe conditional expression does not replace the explicit return keyword.
int sign_value(int value) {
    return (value < 0) ? -1 : ((value == 0) ? 0 : 1);
}

Parentheses around the condition are shown for readability in conditional expressions. The already chosen mandatory condition parentheses apply to if and while; they do not impose a separate mandatory-parentheses rule on ternary conditions.

7. Conditional ? and postfix Result ? are different operators

Result<int, IntegerError> select_sum(bool use_left, int left, int right) {
    int selected = use_left ? left : right;
    int sum = checked(selected + 1)?;
    return Result.ok(sum);
}

The ternary operator needs a condition and two alternatives separated by a colon. Postfix ? operates on one Result value: it extracts Ok or returns Err from the current Result-returning function. Their meanings do not depend on whitespace.

Postfix ? propagates the same error type declared by the enclosing function. It does not convert errors automatically, catch a forced safety stop inside a called function, or undo effects that have already occurred. Result construction and conditional value selection remain separate operations.

8. Only selected code runs; ownership is checked across paths

string choose_text(bool use_first, string first, string second) {
    return use_first ? first : second;
}

The selected owning string moves into the returned value. The unselected local owner is cleaned up when the function exits. Neither string is silently deep-cloned. Conditions and side effects still follow the chosen evaluation order; a skipped branch has no runtime effects.

After a conditional branch, a value may be used only if it is valid on every path that can reach that use. If one branch moved a non-Copy owner away and another retained it, an unconditional use after the branch cannot assume ownership survived.

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

string invalid_conditional_move(bool take_first, string first, string second) {
    if (take_first) {
        string moved = first;
    }
    return first;
}

The rejected return is reachable after first moved into the inner binding on one branch. A different runtime condition does not remove the compile-time ownership requirement.

9. Branches obey local scope and cleanup

A local declared inside a braced branch belongs to that branch block. It is visible inside nested blocks and unavailable after the branch block ends. Names of visible outer local bindings cannot be redeclared inside a branch. Visibility modifiers are not an escape from local scope.

int branch_scope(int input) {
    mut int output = input;
    if (input > 0) {
        int bonus = 2;
        output += bonus;
    }
    return output;
}

The bonus binding disappears at the closing branch brace. Resources still owned by that block are cleaned up in reverse initialization order. A return or Result ? inside the branch also cleans up the enclosing function scopes it leaves, while transferred return payloads follow the caller.

10. Rejected forms remain visible

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

int invalid_if_expression(int left, int right) {
    int larger = if (left > right) left else right;
    return larger;
}

Expression-form if is deliberately excluded. Use (left > right) ? left : right to produce a value.

Rejected example. This intentionally violates a chosen rule and is not valid Aevix code.

int invalid_missing_parentheses(int value) {
    if value > 0 return value;
    return 0;
}

The required parentheses around the condition are missing. These negative examples document chosen compile-time rejection rules; no compiler execution is claimed.

11. Open decisions

  • Declarations or condition-local bindings inside an if condition, including pattern binding forms.
  • Conditional expressions involving never branches, user-defined conversions, or contextual literal typing beyond existing numeric inference.
  • Additional interactions with future type syntax; the existing postfix Result ? and ternary ? : parsing rules are already chosen.

Chosen parsing rules are collected in Parsing Rules: else attaches to the nearest unmatched if; declaration bodies require an explicit block; postfix Result ? and ternary ? : use the unique complete syntactic interpretation independently of whitespace. Multiple complete interpretations require parentheses before type checking. These rules are not open decisions.

No pattern-matching if, if expression, truthiness conversion or automatic copy is introduced by this page. Continue with Loops for iteration or Switch for multiple case branches.
