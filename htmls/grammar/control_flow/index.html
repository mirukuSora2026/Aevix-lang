1. Choose a branch or repeat a statement

Aevix uses statement-form if, while, for and switch. Conditions of if and while require parentheses and a bool value. A single executable statement may omit its surrounding braces; multiple statements require a block. Physical line breaks do not decide how many statements belong to a branch or loop.

These pages record the accepted source-level design. They do not claim an implemented parser, optimizer, borrow checker or runtime. Unsettled policies are explicitly listed rather than inferred from C++, Java or another language.

Boolean decisionsConditionals

Repeated executionLoops

Multiple branchesSwitch

3. A compact tour of the chosen syntax

int maximum(int left, int right) {
    if (left > right) return left;
    else return right;
}

int sum_first_ten() {
    Range<int> indices = 0..10;
    mut int total = 0;
    for (int index in indices) total += index;
    return total;
}

4. Control flow keeps ownership and cleanup visible

A local binding is visible in its declaring scope and its nested scopes. A for header binding does not escape its loop. Visible outer names cannot be shadowed by a nested local declaration. public and private qualify module or type declarations; they do not widen the scope or lifetime of a local binding.

A normal scope exit, break, continue, return or Result propagation with postfix ? cleans up the initialized resources still owned by the scopes being left, in reverse initialization order and exactly once. A moved value follows its new owner; a borrowed referent is not destroyed merely because a reference goes out of scope.

These structured exits are distinct from a forced safety stop. Each case and default has an independent implicit local scope. Forced-stop cleanup, labels for multi-level exits and the user-defined iterator protocol remain open. Persist cleanup order is the reverse of successful initialization completion at normal shutdown. Enum Switch documents read, modification and consumption modes with exhaustive branch checking.
