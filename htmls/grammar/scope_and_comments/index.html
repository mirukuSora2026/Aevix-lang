1. Names, resources, and documentation

These references explain which local names are visible, what happens when their owning scopes end, and how ordinary block comments describe declarations. They reuse Aevix’s type-first declarations, immutable defaults, explicit borrowing, and ownership rules.

Design reference. Chosen language rules are stated directly. Open policies and recommendations are labeled separately. These examples do not claim an implemented compiler, runtime, or diagnostic system.

TopicRule
Local namesAvailable in their declaring scope and nested scopes; public/private are not local modifiers.
Visible-variable redeclarationOverlapping lexical shadowing is rejected.

BorrowingA loan grants access without taking the owner’s cleanup obligation.

4. A local resource and a documented function

/*
 * @parameter value The integer to return.
 * @return The unchanged integer.
 */
i32 documented_identity(i32 value) {
    {
        Vector<i32> scratch = Vector.new(i32);
    }
    return value;
}

The nested local owner ends before the explicit return. Its name is not exported by a comment. This design example introduces no public-local exception or custom destructor syntax.

5. Open decisions stay visible

Each case and default has an independent implicit scope and may reuse names from other branches while obeying the outer no-shadowing rule. Struct and enum field defaults and access-checked initialization are chosen. 0.2 also permits name reuse in nonoverlapping sibling blocks while retaining the no-shadowing rule. Custom cleanup syntax, fallible-cleanup enforcement and ordinary borrowed-device exit waiting versus rejection remain open. Module paths and imports now have chosen rules. No cleanup guarantee is made for an ordinary safety abort. Persistent initialization and normal shutdown have chosen rules, including waiting for tracked resource users before persist cleanup.

Deprecated-use warnings and automatic documentation parameter-name checking are recommendations, not established compiler behavior.
