1. State the goals and the chosen boundaries

Aevix aims for C++-class native performance and safety at least at the level targeted by Rust, together with approachable syntax and a unified CPU/GPU programming model. These are user-selected design goals, not comparative benchmark results, formal safety proof, or evidence of an implemented compiler.

The confirmed execution direction is ahead-of-time compilation as the baseline plus selective just-in-time compilation. Both paths must preserve the same type, ownership, error, evaluation, and cost semantics.

3. Keep ordinary source simple and explicit

i32 add(i32 first, i32 second) {
    return first + second;
}

i32 result = add(10, 20);
mut i32 accumulated = result;
accumulated += 1;

Types appear before names, bindings are immutable unless mut is present, statements end with semicolons, and a value-returning function spells return. Ordinary integer arithmetic retains its selected safety contract; compiler optimization cannot silently change that contract.

4. Confirmed direction and open mechanisms

Area Confirmed direction Still open
Compilation AOT baseline with selective JIT. Triggers, cache, installation, fallback, and deployment packaging.
Safety Static typing and ownership/borrowing guide memory and parallel safety. Compiler implementation, full unsafe/FFI boundary rules, and verification evidence.
Compute AI-native Tensor/Shape support and a unified CPU/GPU model. Kernel syntax, target scheduling, memory representation, and backend coverage.
Cost Copies, allocation contracts, and CPU/GPU transfers remain visible. Final diagnostics, profiling, and target-specific mechanisms.
Extensibility An extensible compiler can support backends such as LLVM and MLIR. Exact intermediate representations, passes, and plugin/backend interfaces.

5. Implementation evidence is a later milestone

The documentation records design choices and example syntax. Native throughput, race rejection, leak prevention, GPU execution, interoperability, and JIT optimization require their respective implementations and validation. No runnable Aevix compiler, benchmark suite, deployment package, or stable ABI is demonstrated by these HTML pages.

The detailed type catalog contains proposed standard APIs. A proposed API table does not establish that its backend, allocator, synchronization protocol, or foreign binding has been implemented.
