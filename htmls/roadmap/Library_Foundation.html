Proposal and current scope

The selected 0.3 target includes the synchronous CPU library catalog; the ten suspending Task contracts and their async machinery belong to 0.4. GPU-only Pending, device queues, kernels and transfers remain deferred. Implementation and feature-by-feature execution checks are authorized, but the complete CPU catalog is still incomplete. The published 0.2 profile remains the release boundary.

Current source modules cover explicit errors, Optional/Result transformations, Array/Slice helpers, hashed and AVL ordered collections, text/codecs, CPU shape/tensor/quantization foundations, scalar helpers and registered File/Process/path/fs/env/time operations. Compiler-bound Shared/Weak, Atomic, Mutex/RwLock and owned Task operations have scoped ownership and execution gates. These providers use explicit source calling forms and error carriers; public declaration counts do not establish every canonical signature, callback, cost or lifetime contract.

The recorded 39088693 checkpoint passed 138/138 CTest cases in 703.69 seconds on macOS ARM64. Its 526 frozen compiler/runtime/library/test/tool/data inputs and 3,797 public lifecycle declarations identify that tested snapshot. Later changes require their own evidence, and this checkpoint does not establish Linux or Windows execution or complete CPU coverage. Performance-changing optimization remains on hold pending the final Claude review.

Native resources use the selected typed native boundary foundation. The development tree now includes compiler-managed Drop, console calls, and move-only io.File and process.Child owners backed by separate typed registry identities. Known private helpers in trusted standard modules have validated signatures and closed operation bindings. This does not grant arbitrary source externs native privileges or complete the resource catalog.

Current byte and owned Task profiles

The imported bytes module provides 128 ordinary source functions and bytes.ByteError has 16 variants. The profile includes explicit LE/BE integer codecs through i128/u128, exact f16/bf16/f32/f64 representation codecs, scalar bit operations, strict binary/hex text, overlap-safe copying, fallible owning-buffer growth/slicing and strict UTF8 validation/owned adapters. Full extents and capacity are checked before mutation. UTF8 decoding can validate and then validate/copy again through string.from_utf8; it does not promise one scan or zero allocation. Native-endian codecs, lazy iterators and exact canonical Byte signatures remain separate contracts.

copy_within accepts ascending unit-step ranges. An open empty extent at buffer length and an empty copy to destination length are valid. Reversed endpoints produce ReversedRange; descending or non-unit descriptors produce NonContiguousRange, including empty descriptors. Closed endpoints must name existing elements before adding one. Source and destination checks finish before any write; overlap chooses a safe direction and no allocation occurs.

Spawned Task work uses one native thread per admitted worker. Only concrete zero-argument compiler closures with fully owned captures/results and checked transfer, transitive calls, global access and Drop effects are admitted; even static borrowed views are rejected. Every observation retains its lexical Scope loan. Task/Scope global or persist storage, nested scopes, worker-side spawn, borrowed workers, pools and detach remain unsupported in this profile. Conditional Shared/Weak/lock/Atomic transfer facts do not bypass these admission and cleanup checks.

Discarding a Task consumes observation only; Scope retains work and cleanup. Join does not flatten application Result values. ScopeError.Retry retains a closed Scope when reaping must be retried. close_admission is idempotent and does not drain; active_count includes prepared/queued/running children and is an observation scan, not a coherent instant or completion proof. scope_status exposes Open/Closing only. executor reports the selected native-thread backend, not a unique scheduler or thread identity.

Of the 59 canonical Task rows, 27 now have source candidates and 32 lack matching callable providers: 22 synchronous contracts remain targeted for 0.3, while ten Awaitable/suspending contracts belong to 0.4. Task.wait is an additional blocking source convenience outside those 59 rows. Task.id and Task.ready were added after the recorded 138-test checkpoint; their targeted evidence is separate. Matching names still require exact signature, ownership, result-carrier and cost reconciliation.

Task.ready moves a precomputed owned value into a Scope without starting a worker. It can allocate bookkeeping and result storage, returns a fallible SpawnError carrier, and consumes and cleans its by-value input on construction failure. Its initial profile rejects borrowed data and hidden Task loans. Task.id returns an opaque Copy diagnostic identity; it exposes no native handle or address and does not keep a Scope alive.

Task.cancel_token and cancel_clone return fallible CancellationError carriers; Task.cancellation returns Result<CancellationToken, TaskError> and retains notification state only, not the Task, Scope, captures, result or JIT code. request_cancel uses the distinct TaskCancelRequest carrier. Cancellation remains cooperative. deadline_after composes checked monotonic time without registering an async timer or suspending the caller.

0.3 system convenience layer

The selected 0.3 console scope includes import system; and the console functions system.print, system.println, system.printf, and system.input, system.flush, and system.log. They are not implemented in 0.2. The console IO plan also covers direct text/scalar output and output-only + composition, with explicit Result errors, full-line string input, token-based scalar input, optional log codes, and flushing. The linked page records the current contracts and target execution limits. The convenience plan retains return-only bool-to-integer adaptation, explicit Boolean conversion, field shorthand, and raw literals.

Place system above the text/bytes/convert and io foundations below as a public convenience layer. It reuses their formatting, bounded-buffer, stream, resource, and error contracts rather than adding unchecked C varargs. Mixed-type printf arguments use a checked 0.3 intrinsic; the existing homogeneous values[] variadic syntax remains unchanged. The existing resource/FFI goals and implementation order remain in force.

Representation and range inspection

Float.from_bits<T> and Float.to_bits reinterpret exact representations for f16/bf16/u16, f32/u32 and f64/u64. These compiler intrinsics do not perform arithmetic or numeric conversion, allocate, or canonicalize NaNs. Signed zero and NaN payload bits survive. They are distinct from scalar math and do not add unsupported f8 overloads. The bytes codecs read and write these representations in an explicitly selected byte order.

Range.start/end/step_magnitude/step/is_inclusive/is_descending/is_empty inspect a borrowed integer Range without consuming or advancing it. Step is an unsigned magnitude paired with direction. The imported ordering module supplies the shared Copy enum Ordering.Less/Equal/Greater and ten pure helpers, also reexported by bytes. Its canonical integer conversion uses -1/0/1 rather than enum layout; then receives already-evaluated arguments. Neither ordering nor bytes is a new primitive or automatic prelude module.

Imported scalar and Unicode profiles

The explicit floating module adds 108 source functions for f16/bf16/f32/f64 classification, signs, magnitude, adjacent values, total order and format constants. Exact representation helpers do not silently widen low-precision arithmetic or add f8. The existing math module still wraps native f32/f64 C math; host numerical behavior is not a cross-platform correctly-rounded guarantee, and lgamma still needs a thread-safe reentrant bridge.

The explicit integer module supplies 528 overloads across 48 function names and 24 constants for twelve signed/unsigned integer types through 128 bits and native widths. Checked, wrapping, saturating and overflowing arithmetic, bit operations and magnitude helpers use the source IntegerArithmeticError carrier. This is not canonical Integer namespace forwarding; wider shift/field, division-rounding, parsing/formatting and conversion contracts remain individually unresolved.

The explicit unicode module has 107 scalar/ASCII/code-unit/property/case/name functions. The Char catalog maps to two direct Core bindings, 76 source alternatives with the same return carrier and 29 with the adapted UnicodeError carrier; source alternatives do not add Char namespace methods. Fifty functions use pinned Unicode 17 data with reproducible tables and the complete upstream license. Full casing uses default isolated-scalar mappings. Property lookup does not provide whole-string normalization, grapheme/word/sentence segmentation, contextual or locale casing, collation, bidi layout or terminal width.

The explicit boolean module supplies 20 source functions for integer 0/1 and nonzero policies, eager/lazy owned selection, strict parsing, fallible text and transactional bounded output. Its BooleanError carrier differs from conceptual AllocError/BufferError signatures. These tested scalar providers broaden the usable CPU subset without completing every Boolean, Float, Integer, Char, SIMD or Tensor catalog contract.

Useful additions to the existing catalogs

  • Source spans and typed IDs for source/AST/type tables that grow.
  • Structured IO errors and explicit error mapping into compiler diagnostics. The development Error interface supports borrowed inspection; the concrete owning AnyError carrier supports Result<T, AnyError>. Neither is shipped in 0.2. Conversions remain explicit, and fallible packing preserves the original error on failure. The current AnyError owns Box<dyn Error>; packing is explicit and fallible. Inline small-error storage is not implemented. Concrete typed errors retain their payloads.
  • Bounded readers, write-all and documented partial progress after failure.
  • Lossless OS paths and environment values.
  • Temporary-output transactions with no-overwrite publication.
  • Stable content hashes distinct from randomized collection hashing.
  • Allocation-failure injection, test/fuzz helpers and deterministic fixtures.
  • Versioned AIR/cache serialization and streaming formatting writers.

API sketches

The confirmed console names and proposed signatures are documented in System console IO in 0.3. These sketches are historical contract examples, not a copyable current API reference. Current signatures and lifecycle versions are recorded in the source API inventory; broader resource and collection contracts still require individual implementations.

Result<usize, IoError> read(&mut File self, MutSlice<byte> output);
Result<usize, IoError> write(&mut File self, Slice<byte> input);
Result<unit, IoError> flush(&mut File self);
Result<ExitStatus, ProcessError> wait(&mut Child self);
Optional<&V> get(&Map<K, V> self, &K key);
Result<T, ParseError> parse_integer<T>(string_view input, u32 radix);

Borrowed-key lookup must not secretly clone a key. Iterator/callback APIs need explicit item ownership and reference lifetimes. Add associated-type machinery only if a required API cannot use the existing generic contracts.

Keep outside bootstrap requirements

The bootstrap subset determines dependency order, not a reduction of the selected synchronous CPU library target for 0.3. CPU Tensor, Quantized, synchronization, and synchronous Task APIs remain in the reviewable CPU plan; suspending Task APIs and their async machinery move to 0.4. Implementation remains authorized and incomplete; the selected synchronous catalog must be exercised before 0.3 is called complete. GPU and GPU-only Pending APIs remain outside this work; package-registry hosting is separate infrastructure.
