Scope and version boundary

Add these conveniences to the existing 0.3 roadmap. Native resources, FFI, library foundations, and the compiler subset remain required. The 0.4 compiler port and 0.5 self-hosting target are unchanged.

Planned for 0.3. These examples describe the proposed implementation target. They are not accepted-source promises for the released 0.2 profile. The boolean conversion API already appears in the design catalog; this plan schedules its implementation.

Keep type-first declarations, immutable defaults, explicit non-void returns, bool-only conditions, and the established move, borrow, and access rules.

Boolean results in integer returns

At an explicit return expression;, allow a bool value to satisfy a scalar integer return type. Encode false as 0 and true as 1. Evaluate the expression once. The comparison expression itself still has type bool.

i32 is_larger(i32 left, i32 right) {
    return left > right;
}

i32 main() {
    return 1 > 2;
}

The helper returns either 0 or 1. The main example returns 0. For a process exit status, 0 means success; this is a numeric encoding of the comparison, not a rule that a true condition means successful process termination.

ContextPlanned rule
Explicit return to a scalar integerAllow the 0/1 adaptation for signed and unsigned integers through 128 bits, isize/usize, and transparent aliases such as int.
Methods and explicitly typed closuresUse the same rule when their declared result resolves to a scalar integer.
Return to boolKeep the bool value unchanged.
Variable initialization, assignment, arguments, arithmetic, and overload matchingNo new implicit bool-to-integer conversion.
Float, byte, char, enum, SIMD, Optional, or Result destinationNo adaptation. Do not wrap a bool in Ok or map a container payload automatically.
Borrowed bool or integer conditionsNo automatic dereference for this rule and no numeric truthiness.

The source must resolve to bool under ordinary expression typing before applying this return rule. Preserve numeric literal context, generic inference, and generic-body contract checks; do not add bool compatibility to the compiler's general type-matching relation or choose a missing generic type merely to enable adaptation. A favorable concrete specialization must not make an otherwise invalid generic body legal. The rule requires no allocation, cloning, or representation reinterpretation.

The explicit spelling already available in 0.2 remains valid:

i32 main() {
    return (1 > 2) ? 1 : 0;
}

Explicit boolean conversion

Implement the existing catalog spelling Boolean.to_integer<T>(bool value) for scalar integer T. It uses the same false-to-0 and true-to-1 mapping, including outside return statements.

bool ready = true;
i32 encoded = Boolean.to_integer<i32>(ready);
rsn comparison = 1 > 2;

Here encoded is 1 and comparison remains bool. This schedules one catalog operation; it does not mark every Boolean helper as implemented. Decoding an integer into bool remains an explicit, separately specified operation.

Output composition with +

Use + to join text and printable values in system.print and system.println. A single built-in printable value may also be passed directly. Keep ordinary numeric addition and the existing left-associative precedence. Add no separator automatically.

import system;

Result<unit, system.IoError> show_count(i32 count) {
    system.println("count: " + count)?;
    system.println("sum: " + 1 + 2)?;
    system.println("sum: " + (1 + 2))?;
    return Result.ok(Unit.value());
}

The last two calls produce sum: 12 and sum: 3. This is planned output composition into borrowed formatting segments, with no required intermediate owned string. It does not introduce a general string allocation operator. See the console IO contract for supported values, evaluation, borrows, and partial-output errors.

Printing bool uses true or false; the 0/1 rule applies to integer returns and explicit conversion, not display. Owned strings are read by borrow. Built-in value support does not automatically make structs, enums, containers, or pointers printable.

Named field shorthand

Allow a local name to supply a same-named field in a named initializer. Point { x, y } means Point { x = x, y = y }.

struct Point {
    public f64 x;
    public f64 y;
};

Point make_point(f64 x, f64 y) {
    Point point = Point { x, y };
    return point;
}

The value name must exist in the current lexical scope; shorthand does not search instance fields implicitly. Apply ordinary field visibility, type, duplicate, unknown-field, and completeness checks. Evaluate fields left to right, once each. Copy fields copy and non-Copy values move under the ordinary rules; there is no automatic clone, borrow, spread, or default filling.

Apply the same shorthand to enum variant named initializers, preserving their field access rules. It does not change case-pattern binding syntax or allow name shadowing.

Raw string literals

Add raw UTF-8 literals for text containing backslashes or quotes. Their value is the same allocation-free string_view as an ordinary literal. Raw contents have no escape processing or interpolation.

string_view path = r"C:\temp\main.avx";
string_view quoted = r#"say "hello""#;
string_view pattern = r##"a "# marker"##;

Use r"...", or place 1–255 hash marks between r and the opening quote and require the same number after the closing quote. A quote without that closing delimiter stays in the contents. Multiline contents are allowed; preserve valid UTF-8 source bytes, including line-ending bytes inside the literal. No Unicode normalization is implied.

An unterminated literal or excessive delimiter count is a compile error. This is text syntax, not an OS path type, shell escaping, or a bypass for printf format checks. Creating an owning string still uses an explicit fallible constructor.

Implementation gates

  1. Implement and test the return-only adaptation without widening initialization, argument, arithmetic, condition, generic, or overload compatibility. Include all integer widths, aliases, methods, closures, and rejected wrapper/reference destinations.
  2. Implement the canonical Boolean.to_integer API with the same mapping and no hidden allocation.
  3. Lower output composition after resolving the actual system function. Preserve numeric subtrees, left-to-right evaluation, borrow lifetimes, failure before output, and the existing Result-based IO contract.
  4. Lower field shorthand into ordinary named initialization before existing visibility, completeness, move, and borrow checks. Include enum variants and partial-initialization cleanup.
  5. Extend the lexer for raw literals, byte spans, multiline diagnostics, UTF-8, line endings, and matching delimiter limits. Keep ordinary string lexing intact.
  6. Use shared acceptance, rejection, and execution cases across AOT and JIT. Freeze the approved rules before the 0.4 compiler port relies on them.
