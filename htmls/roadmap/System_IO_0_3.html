Selected scope and status

Selected 0.3 scope: an explicitly imported system module exposing print, println, printf, input, flush, and log. Calls to print and println accept text or a built-in scalar directly, and also join text and typed values with +. This adds console IO to the existing resource/FFI and library foundation goals; the output-only formatting and composition rules are specified below.

Not implemented in 0.2. The examples below target the development compiler; they are not programs accepted by the shipped 0.2 compiler. The working tree now contains compiler and runtime implementations; AOT/JIT regression tests are being completed before a 0.3 release. The contracts below distinguish this implementation from the broader library catalog.

Selected function Planned purpose Recommended result
system.print(value_or_composition) Write borrowed text, a built-in scalar, or composed segments without appending a newline. Result<unit, system.IoError>
system.println(value_or_composition) Write borrowed text, a built-in scalar, or composed segments and append a newline. Result<unit, system.IoError>
system.printf(format, values...) Write formatted output, with no automatic newline. Result<unit, system.IoError>
system.input<T = string>() Read a complete UTF-8 line for string, or one whitespace-delimited token for a supported scalar. Result<Optional<T>, system.ReadError>
system.flush() Explicitly flush standard output. Result<unit, system.IoError>
system.log(level, message, code = "") Write an info, warning, or error record to standard error. The text code is optional. Result<unit, system.IoError>

The table shows call shapes, not variadic function declarations or a new general-purpose composition type. Print and println require one value; printf and log have the separate checked forms below. User-defined printable types are not implemented.

Imports and call forms

A whole-module import system; uses qualified calls such as system.print(...) and the exported error name system.IoError. IO types are not added to the automatic prelude.

import system;

Result<unit, system.IoError> write_summary(string_view label, i32 count) {
    system.print("Summary: ")?;
    system.println(label)?;
    system.printf("%s: %d\n", label, count)?;
    return Result.ok(Unit.value());
}

This is a proposed helper returning Result. It does not change the selected i32 main() convention or make ? valid in an incompatible integer-returning main.

Selective imports retain the existing rules. In a separate file, the following form exposes only the selected names; unrelated system exports still require their own import. Name collisions use imported module-qualified paths, with no new alias or overload-merging rule.

import system { println, IoError };

Result<unit, IoError> announce() {
    println("ready")?;
    return Result.ok(Unit.value());
}

Output and errors

Recognized print and println calls accept string_view, a borrowed owning string, a built-in scalar, or the output composition described below. An owning string argument is automatically read by borrow in this output context; an explicit string.view(owner) remains valid. The same non-consuming borrow rule applies to owning string segments. No owner is moved or cloned, and neither form may retain a caller's borrow after returning. Formatting and internal buffering copies or allocations must have documented costs and failure behavior.

Output returns Result<unit, system.IoError> because writes and resource operations can fail. An Err can follow a successfully written prefix; it cannot roll back terminal output. Lower-level short writes should be handled under a documented write-all policy, without promising that a caller can blindly retry the entire message after an error.

The error module defines ReadFailed, WriteFailed, FlushFailed, Interrupted, WouldBlock, Closed, InvalidUtf8, InputTooLong, AllocationFailure, SizeOverflow, and Unsupported. Read/write failures retain an OS code and payload-byte progress when available. EOF is an Optional absence, not an OS error. The runtime does not install a process-wide signal handler: broken-pipe signals follow the host process policy and may terminate the process before a Result is returned.

Output composition with +

Recommended 0.3 semantics: inside the output argument of a recognized system.print or system.println call, a + node with a text operand joins output segments. An existing composition also counts as a text operand, so a chain can continue with more typed values. The compiler resolves the real imported declaration, including selective imports; an unrelated function named print or println receives no special behavior. This is an output-call construct, not a global string operator or an implicit scalar-to-string conversion.

The initial supported values, both as direct arguments and as composition segments, are string, string_view, the built-in signed and unsigned integers, f32/f64, bool, char, and byte. A direct value uses the same built-in formatter as a segment. Text keeps its UTF-8 bytes; integers use decimal digits, bool uses true or false, and char writes its Unicode scalar as UTF-8. A byte uses 0x followed by exactly two lowercase hexadecimal digits, keeping its display distinct from numeric u8.

Supported f32/f64 values use locale-independent shortest round-trip decimal text for their source floating format. The console specialization currently rejects f16 and bf16. Preserve the sign of negative zero; nonfinite values use nan, inf, or -inf. Do not promise to preserve a NaN payload in text. Finite formatting uses the linked C++ runtime's std::to_chars shortest-round-trip conversion. Fixed-versus-exponent spelling is not a version-stable serialization format; use a separately specified codec for stable persisted text. No arbitrary struct/interface conversion, implicit unwrap, or conversion of a Result or Optional payload is added.

Normal precedence, grouping, and left associativity remain in force. Two numeric operands still calculate a numeric result with the existing type and arithmetic-failure rules. A string elsewhere in the expression must not cause an earlier numeric subtree to be flattened into separate display values.

import system;

Result<unit, system.IoError> write_count(i32 count) {
    system.println("count: " + count)?;
    system.println(count)?;
    system.println(count + 1)?;
    system.println("sum: " + 1 + 2)?;
    system.println("sum: " + (1 + 2))?;
    system.println(1 + 2 + " apples")?;
    return Result.ok(Unit.value());
}

For a count of 5, the lines are count: 5, 5, 6, sum: 12, sum: 3, and 3 apples, in that order. The fourth line displays two integer segments; the third, fifth, and sixth first compute their numeric sum. A bool value remains logical text even when a separate return-only bool-to-integer convenience is available; see the 0.3 convenience plan.

Evaluation, ownership, and cost

Evaluate operands once, from left to right, before this output call writes its first byte. Preserve numeric subexpressions and ordinary short-circuit or conditional evaluation inside an operand. A leaf expression can have its own side effects, including another output call; those effects are not rolled back. If evaluation exits through ? or never completes, this outer call has not begun writing.

Borrow owning strings for reading and keep each text loan and temporary owner alive until the call returns. Copy scalar segment values according to their ordinary Copy rules. No implicit owner move or deep clone is performed. A later operand that tries to modify an already borrowed string is rejected by the borrow checker. For example, a composition that reads name and then calls a function requiring &mut name cannot keep both accesses alive.

import system;

Result<unit, system.IoError> show_label(&string label, i32 count) {
    system.println(*label)?;
    system.println("label: " + *label + ", count: " + count)?;
    return Result.ok(Unit.value());
}

Both calls read the existing owner through label; neither consumes it. Each text borrow remains valid through its call's write, including any internal buffering work.

The construct requires no intermediate owned string. Work still includes scalar formatting and copying bytes into the output stream. If formatting or buffering allocates, allocation and capacity failures must remain explicit in the call's Result<unit, system.IoError> contract. Do not advertise a universal allocation-free guarantee. A write failure can follow partial output, and appending println's newline is part of the same fallible call.

Acquire any call-level output lock after operand evaluation, then serialize the composed segments and newline as one call relative to other calls using the same stream API. Several calls are not one transaction, and independent OS writers are outside this promise. Output does not implicitly flush.

Boundary outside output

A composition is consumed by its recognized output call; it cannot be assigned to a variable, returned, captured, or passed to an arbitrary helper as a hidden string value. Grouping the complete composition does not turn it into an owner. Numeric + and existing type compatibility rules elsewhere stay unchanged. General owned text construction remains a separate fallible operation: the proposed string.concat and string.format APIs return Result<string, TextError>. Those catalog entries are not implemented 0.2 alternatives.

This construct does not relax printf's compile-time format requirement, change homogeneous values[] variadics, or add general user-defined operator overloading. AOT/JIT acceptance and rejection cases cover recognized declarations, composition boundaries, evaluation order, and loan lifetimes.

Checked printf without C varargs

The recommended initial printf uses familiar percent-style conversions while checking the format, argument count, and argument types at compile time. Its format should initially be a literal or supported compile-time string. The sample uses %s for a string_view, %d for i32, and %% for a literal percent; The implemented conversions are %s for text, %d for signed integers, %u for unsigned integers, %f and %g for f32/f64, %c for char, %b for bool, and %% for a literal percent. Both float conversions use shortest round-trip text; they do not promise C printf's default six fractional digits. Width, precision, length modifiers, and other conversions are rejected at compile time. Forbid unsafe conversions such as %n.

Mixed-type arguments use a checked compiler intrinsic. The string_view and i32 arguments in the example are intentionally heterogeneous. They are not an extension of the existing homogeneous i32 values[] variadic parameter syntax. The compiler checks every placeholder and value without changing that syntax or its ownership rules.

Do not lower this interface to unchecked C varargs or rely on C's default argument promotions. No implicit ownership move, deep clone, or arbitrary printable-type conversion is introduced by a format string. Invalid static formats should be compile errors; actual output/resource failures remain Result values.

Typed input, EOF, and UTF-8

input() and input<string>() return Result<Optional<string>, system.ReadError>. A string preserves every space in one line: input he ll o produces exactly that text. LF and CRLF terminators are removed; a lone CR remains text. The inner Optional distinguishes an empty line from EOF. The owned string exposes the allocation and ownership transfer.

input<i32>() and other supported scalar specializations skip leading ASCII whitespace and read one token. Three integer reads from 10 20 30 produce 10, 20, and 30. The delimiter after a token remains in the stream: a following string input can therefore read an empty remainder of that line. No automatic line skipping is added. Character input reads a single-scalar token. This is whitespace token extraction, not a promise of all C++ iostream numeric-prefix and locale behavior.

Scalar tokens use the same strict full-input conversion as T.parse(value): integers 8–128 bits and aliases, f32/f64, bool, char, and byte. Nonfinite floats and malformed or out-of-range values are errors. ReadError.Io carries an IoError; ReadError.Parse carries a ParseError. Failed input may already have consumed bytes. A malformed token is consumed so a subsequent token read can progress.

Observed input Recommended result
A line containing text followed by a terminator Ok(Some(text)), with the terminator removed.
An empty line Ok(Some("")); it is not EOF.
EOF before any bytes of another line Ok(None).
A final line without a terminator, followed by EOF Ok(Some(text)), then None on the next successful read.
Invalid UTF-8, an IO failure, a size-limit failure, or allocation failure Err(...) under the reviewed error policy.

The table uses outcome notation rather than constructor syntax; the empty-line payload is an owned empty string. The native stream boundary consumes and emits UTF-8 bytes. macOS ARM64 is locally executed; native Linux and Windows console behavior remains a target-specific gate, including Windows console code-page handling.

The implementation recognizes LF and CRLF line endings, removes their terminators, preserves a lone CR, and rejects invalid UTF-8 without replacement. Buffers cannot exceed the target ptrdiff limit. A failed read preserves its reported OS error and payload-byte progress when available; allocation or decoding failure does not rewind already consumed input.

import system;

Result<Optional<string>, system.ReadError> read_next_line() {
    return system.input();
}

Structured logging

system.log(level, message, code) accepts system.info, system.warn, or system.error, which identify the corresponding system.LogLevel variants. Omit the final text code when it is unnecessary. Logging writes to stderr and returns Result<unit, system.IoError>; the caller can propagate a write failure. It does not change the control flow into an exception.

import system;

Result<unit, system.IoError> announce() {
    system.log(system.info, "Compiler ready")?;
    system.log(system.warn, "Cache entry ignored", "W1001")?;
    system.log(system.error, "Cannot open source", "E1001")?;
    return Result.ok(Unit.value());
}

The records are [INFO] Compiler ready, [WARN W1001] Cache entry ignored, and [ERROR E1001] Cannot open source, each followed by one newline. A call holds its output lock for the complete record after evaluating and formatting its operands. Logging does not add a timestamp, color, file sink, automatic flush, or persistent error-code registry. Codes are application-supplied text. The planned 0.5 compiler diagnostics have their own versioned compiler codes and source-location model.

Buffering, flushing, and resource boundaries

Separate writing, flushing a library buffer, and releasing a resource. A successful buffered write need not mean the terminal has displayed the text. Appending a newline should not imply an undocumented flush.

Selected additional operation: an explicit system.flush() returning Result<unit, system.IoError>, particularly before waiting for input after printing a prompt. It is included in the 0.3 console implementation.

Define standard-stream ownership, redirection, and closure behavior on each supported OS. Automatic cleanup cannot guarantee a successful fallible flush. Recommend thread-safe, call-level stream serialization after operand evaluation, while leaving the relative order of racing calls unspecified; several calls do not automatically form one output transaction.

The public system surface should be a convenience layer over the reviewed text/format and io/resource facilities. It must not bypass bounded byte loans, ownership, OS error translation, or safe FFI rules. This console implementation is synchronous and does not implement GPU operations or shell execution. The approved wider CPU library work remains separate.

The current AOT path links the matching Aevix C++ runtime archive and a C++ standard library: libc++ on macOS, or libstdc++ on Linux and GNU Windows. Linux also requires pthread support. Cross-target objects may contain unresolved runtime calls; an executable needs a matching target runtime, linker, and sysroot.

Review and implementation gates

  1. Finalize direct text/scalar and composition call forms, exact result types, error categories, newline policy, and the explicit flush stage.
  2. Specify shortest-float representation ties and fixed-versus-exponent selection; test signed zero, nonfinite values, and two-digit lowercase byte output. Specify recognized imported callees, composition contexts, evaluation order, loan/temporary lifetimes, and fallible allocation without changing general numeric +.
  3. Approve the heterogeneous printf intrinsic and its checked format grammar without changing homogeneous variadics.
  4. Finish the resource/FFI, byte, UTF-8, allocation, and error foundations needed by synchronous standard streams.
  5. Test direct scalar and borrowed-owner arguments, text/scalar chains, grouped numeric sums, integer overflow, one-time evaluation, conflicting mutation, temporary cleanup, and exits before output. Reject stored compositions, unrelated same-named callees, and unsupported printable types.
  6. Implement and test empty input, empty lines, CRLF, final unterminated lines, malformed UTF-8, size limits, allocation failure, short/interrupted writes, partial output, broken pipes, redirected streams, flush errors, and concurrent calls.
  7. Verify the same language and ownership behavior in AOT and JIT on the supported targets. Only then describe these functions as implemented.

Library foundations records the wider implementation order. The 0.2 executable profile remains unchanged by this planning document.
