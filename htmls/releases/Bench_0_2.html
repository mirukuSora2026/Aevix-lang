Annotate the function you want to measure

Place @bench before a function with a body. The annotation needs no import. Run the program normally; completed calls are aggregated, and a report is written to standard error during normal process exit.

@bench i32 leaf(bool early) {
    if (early) return 7;
    return 8;
}

@bench i32 main() {
    i32 first = leaf(true);
    i32 second = leaf(false);
    return first == 7 && second == 8 ? 0 : 1;
}

The annotation also works on generic functions. Early return and error propagation through ? finish the measurement for the active call. Recursive calls are recorded individually.

@bench is source syntax, distinct from documentation comment tags. Repeating the annotation on one function is an error. Types, variables and function declarations without a body cannot be annotated.

Run and inspect

Both native AOT execution and ORC JIT execution use the measurement runtime. No separate benchmarking switch is required.

aevixc measured.avx
aevixc --jit measured.avx
aevixc measured.avx 2> bench.txt

Source checking and LLVM emission do not run the measured function. Annotations remain in the generated program when it is compiled; running the resulting program produces the report.

Labels contain logical function names and compiler identity suffixes such as leaf#42. The suffix is not a stable public identifier, and generic specializations may have separate labels. Standard output remains available for the program’s own output.

The header identifies the measurements as wall time and sampled process RSS. Memory fields can be unavailable when the operating system cannot provide a successful observation.

Wall time includes nested work

Each call is timed from its recorded entry to its recorded exit using a monotonic clock. Wall time includes waiting, scheduling and time spent in called functions. It is not a CPU-time counter.

Nested and recursive timings are inclusive. An outer call includes the time of an inner call, while the inner call also appears in its own row. Adding all rows therefore does not give total program execution time. Concurrent calls can also overlap.

@bench i32 recursive(i32 depth) {
    if (depth == 0) return 0;
    return recursive(depth - 1) + 1;
}

i32 main() {
    return recursive(3) == 3 ? 0 : 1;
}

This example records four calls to recursive. The total includes time counted at more than one recursion depth.

Memory is sampled for the whole process

The runtime samples resident memory at measured entry and exit. While calls are active, a background sampler also requests observations at an interval of about 10 milliseconds. Scheduling can delay an observation; short-lived peaks between samples can be missed.

A sample covers the entire process. It includes code, stacks, runtime bookkeeping and unrelated allocations. In JIT mode it also includes the host compiler and JIT state. These readings are neither the bytes allocated by one function nor a reserved managed heap.

Each active function receives one observation at a sampling point, regardless of its recursion depth. Nested functions active at the same instant can receive the same process-wide value. The reported mean is the arithmetic mean of observations, not a time-weighted mean.

If the sampler thread cannot start, the report says so and falls back to entry/exit observations. Platform memory queries can fail independently; unavailable observations are counted.

Measurement has a cost

Instrumentation adds timestamp reads, synchronized bookkeeping, memory queries and reporting. The profiler allocates its own metadata and may create a sampling thread. Very short functions can be dominated by this overhead.

Unannotated functions do not receive profiler entry/exit hooks. A program with no annotations does not start this profiler. Its normal compiler and runtime costs still apply.

For comparisons, use the same target, compiler settings and workload; run repeated samples and keep warm-up conditions consistent. AOT and JIT process RSS are different measurement contexts. Do not use one annotated invocation as proof of an optimization.

Normal-exit reporting. Process abort, forced termination and fatal runtime failures do not guarantee a final report. Metadata allocation limits can also leave affected calls unrecorded; the runtime prints a diagnostic when this occurs.

Checked behavior

Integration checks run annotated code through AOT and ORC JIT, covering nested calls, recursion, generic specialization, early return and Result propagation. They check report fields, call counts and the absence of active calls after normal completion.

Separate native runtime checks cover concurrent recording and resident-memory observations. Unannotated execution stays quiet, unannotated LLVM has no profiler hooks, and source checking does not execute measurements. Platform release qualification is tracked in the 0.2 implementation profile.
