Chosen rules

A binding names its type before its name. Bindings are immutable by default; mut enables mutation. rsn performs static type inference, while const requires compile-time evaluation. persist names process-lifetime storage with chosen initialization and normal shutdown rules.

T value passes a value: Copy types copy and owning non-Copy values move without a deep clone. &T value reads through a shared borrow; &mut T value permits modification through an exclusive borrow. Calls explicitly choose x, &x, or &mut x. Already borrowed references and view values are passed directly.

The binding lines and function definition below are independent examples in suitable enclosing scopes; module-level persist initialization follows the startup rules.

i32 size = 128;
mut i32 count = 0;
rsn inferred = 128;
const i32 LIMIT = 100;
&i32 reference = &size;
i32 copied = *reference;

i32 identity(i32 value) {
    return value;
}

Every normally terminating path of a non-void function explicitly returns a value. Return-position void permits falling through or a bare return; a function returning the unit value type explicitly returns its unit value. A path that diverges does not need an impossible return.

Open decisions stay open

Type-first declarations, no visible-variable shadowing, struct/enum methods, interface contracts, and type generics with where constraints are chosen. Generic functions, overloads, default and named arguments, imports and persist initialization and shutdown now have chosen rules. Explicit typed locals may omit initializers under definite-assignment checks. Async/GPU function grammar and explicit returned-reference lifetime annotations remain open. See the grammar overview for the complete reference. Labeled negative examples demonstrate only chosen rules.
