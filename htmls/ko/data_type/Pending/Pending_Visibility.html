1입니다. 4개의 개별 질문

소비자는 생산자가 자원에 대한 접근을 중단했는지, 성공했는지, 그 기록이 소비자 도메인에서 볼 수 있는지, 그리고 소비자가 스토리지를 다룰 수 있는지 여부를 구별해야 한다. 완성된 실패는 유효한 산출 없이 quiescent 일 수 있다. 성공적인 장치 지원 스토리지는 호스트 포인터에 계속 액세스할 수 없습니다. 이러한 사실은 확인되지 않은 bool 하나로 압축할 수 없습니다.

CompletionToken은 유지된 세대별 의존성 기능입니다. DeviceReady<T>는 성공적인 출력을 장치 사용 준비성과 페어링합니다. HostReady<T>는 또한 소유권이나 매핑 대여을 유지하면서 지원되는 호스트 액세스 및 필요한 acquire/cache 작업을 증명합니다. 아무도 관련없는 할당이나 미래의 제출을위한 보편적 인 울타리가 아닙니다.

2입니다. 실행 순서 및 메모리 의존성

대기열 순서는 선택한 대기열 프로필에서 명령이 실행될 때를 결정합니다. 메모리 의존성은 또한 관련 쓰기를 사용할 수 있게 하고 특정 소비자가 볼 수 있게 합니다. 교차 큐 또는 교차 장치 사용에는 명시적 어댑터 지원 종속성 및 메모리 도메인 전환이 필요합니다. 가시성이 설정되지 않은 경우 읽기 후 쓰기 종속성에 대한 실행 전용 이벤트가 충분하지 않습니다.

종속성 이름 생성, 할당 액세스, 소비자 queue/domain 및 관련 액세스 모드. 네이티브 이벤트 객체를 재사용하려면 새로운 토큰 생성이 필요합니다. 외부 토큰을 가져오려면 문서화된 생산자 범위와 소유권 수명이 필요합니다; 원시 정수 이벤트 핸들은 이러한 사실을 증명할 수 없습니다. 종속성 주기와 호환되지 않는 장치 ID는 감지 가능한 경우 checked 오류입니다.

3입니다. 호스트 획득 및 매핑

호스트 획득은 호스트 액세스 가능한 출력에만 허용됩니다. 필요한 성공적인 완료를 기다리거나 확인하고, 필요할 때 백엔드 캐시 무효화 또는 도메인 작업을 수행하고 호스트 액세스 대여 또는 소유자를 부여합니다. 장치 전용 할당 return UnsupportedHostAccess; 호출자는 명시적 다운로드를 요청합니다. 공유 가상 주소만으로는 충분하지 않습니다.

매핑은 할당을 유지하고 매핑된 대여에 대해 충돌하는 장치 액세스를 금지합니다. 호스트 맵을 해제하려면 후속 장치가 읽기 전에 명시적인 release/flush 작업이 필요할 수 있습니다. 일관된 메모리 능력은 순서 및 대여 배타성을 그대로 유지하면서 특정 캐시 단계를 제거 할 수 있습니다. Safe API는 초기화되지 않았거나 부분적으로 실패한 출력을 일반 초기화된 Slice로 노출해서는 안 됩니다.

4입니다. 실패와 알 수없는 quiescence

정지 실행 오류는 출력 유효성과 함께 실패한 작업에서 더 이상 액세스할 수 없음을 보고합니다. 자원 정리 및 대여 대여은 선언 된 보고서를 따를 수 있습니다. 장치 또는 세션 손실은 정지를 알 수 없게 할 수 있습니다. 이 경우 정상적인 오류 return는 장치가 여전히 액세스 할 수있는 메모리에 대한 할당, 변경 또는 범위 종료를 승인해서는 안됩니다.

어댑터는 안전한 일시 중지, retain/quarantine 소유 저장소를 설정하거나 빌린 저장소를 릴리스하기 전에 명시적으로 치명적인 종료 정책을 사용해야 합니다. 댕글링 있는 장치 참조를 사용하여 안전 코드로 돌아가는 것은 금지되어 있습니다. 시간 초과 또는 취소 요청은 사용자가 더 이상 결과에 신경 쓰지 않더라도 이 증명을 대신할 수 없습니다.

5입니다. 호스트 작업 및 가시성 증거

Pending를 기다리는 호스트 Task는 장치 완성을 스케줄러와 통합할 수 있습니다. 동일한 장치 리소스 임대를 유지하며 호스트 일관성을 발명하지 않습니다. Gpu 텐서를 생성하는 Task는 Cpu 인덱싱 전에 다운로드를 요구하면서 장치 지원 값을 성공적으로 수행할 수 있습니다. 작업 scheduling/lifecycle 실패가 장치 Result를 둘러싸고 있습니다.

잠금 및 호스트 원자는 장치 메모리 가시성을 자동으로 설정하지 않습니다. Shared<T> 참조 카운팅은 메모리를 유지하지만 GPU 캐시를 플러시하거나 동시 변경를 허용하지 않습니다. 장치 범위 완료, 호스트 획득 및 명시적 릴리스는 법적 핸드오프 포인트를 정의합니다. 정확한 대상 장벽은 어댑터 책임이며 언어 수준 bool의 암묵적인 결과는 아닙니다.

6입니다. 준비는 타이핑 된 증거입니다 

// Given an accepted submission whose output is host-accessible.
mut Pending<HostBuffer<f32>> pending_host_output = prepared_host_output;
Result<Optional<HostReady<HostBuffer<f32>>>, DeviceError> readable = Pending.acquire_host(&mut pending_host_output);
// Existing producer token is moved into a dependency on the borrowed destination queue.
Result<QueueDependency, DeviceError> ordered = Pending.after(&consumer_queue, producer_token);

누락된 읽을 수 있는 값은 복용을 위해 출력을 사용할 수 없음을 의미합니다. 성공적인 주문 의존성은 선언된 생산자-소비자 관계를 스케줄링한다; 그것은 어느 하나의 할당에 즉각적인 호스트 접근을 주지 않는다.

Pending.session_status(&DeviceContext device)DeviceSessionStatushealthy/lost/quarantined 상태를 보고합니다. 모든 리스가 정지된 것으로는 증명되지 않습니다.런타임 쿼리입니다.
Pending.drain_device(&DeviceContext device)Result<DeviceDrainReport, DeviceError>허용된 추적 작업에 대한 일시 중지를 설정하거나 복구할 수 없는 세션 정책을 따릅니다. never는 오류가 발생하면 라이브 빌린 저장소를 해제합니다.기대해도 좋고, 완성도가 높지 않습니다.
