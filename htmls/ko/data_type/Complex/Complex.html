1. 기본 정보

Complex<T> 는 실수부 + 허수부 × i를 나타내는 부동소수점 성분의 쌍이며 i² = −1입니다. 성분 형식 T가 범위·반올림을 결정합니다. Complex 복소수는 실수 체계를 확장하지만 이에 맞는 수학적 전순서는 없습니다.

설계 초안. 아래 API는 의도된 Aevix 동작을 지정합니다. 그들은 컴파일러 구현, 백엔드 지원 또는 냉동 외국 ABI를 주장하지 않습니다. 일반적인 철자법은 모호하지 않은 참조 형식입니다. complex 상기 투명한 별칭은 The transparent alias Complex<f64>explicit import 를 통해서 import 할 수 있다. c64와 같은 너비가 충분한 별칭은 의도적으로 여기에 할당되지 않습니다.

참조 형식 구성 요소 형식 값 페이로드 상태
Complex<f16> f16 × 2 32 조금/4 바이트 0.2 컴포넌트 포맷 구현
Complex<bf16> bf16 × 2 32 조금/4 바이트 0.2 컴포넌트 포맷 구현
Complex<f32> f32 × 2 64 조금/8 바이트 0.2 컴포넌트 포맷 구현

import complex { Complex, complex };

f32 initial_real = 3.0;

Complex<f32> z = Complex<f32>.new(initial_real, initial_imag);
f32 magnitude = Complex<f32>.norm(z); // 5.0;

complex default_value = complex.zero();

2입니다. 선언, 소유권 및 비용

변수 선언은 유형을 먼저 배치하고 세미콜론으로 끝납니다. 컴포넌트는 정적 타이핑을 상속합니다; 문맥적 리터럴 검사는 예상 형식에서 직접 발생합니다. 스칼라 복소수를 구성하는 것은 할당되지 않으며 스칼라 할당은 두 구성 요소를 복사합니다. 바인딩은 기본적으로 불변이다; 변경는 명시적인 쓰기 가능한 바인딩이나 배타적인 대여을 필요로 한다.

스칼라를 복사해도 소유가 되지 않습니다. Array, Vector, 또는 Tensor 스토리지를 암묵적으로 복제합니다. 이러한 컨테이너는 기본적으로 이동하며 명시적 복제 및 CPU/GPU 전송은 비용을 노출시킵니다. conjugation 연산은 인수를 변경하는 대신 값을 반환합니다.

값 페이로드는 두 가지 구성 요소입니다. 정렬, 레지스터 사용, 스택 슬롯 및 포함 구조 패딩은 대상에 따라 다릅니다. 숫자 쌍은 외국 복잡한 스칼라와 자동적으로 ABI 호환이 되지 않습니다. FFI 바인딩은 구성 요소 형식, 순서, 정렬, 호출 규칙 및 소유권을 독립적으로 검증합니다.

3입니다. 수치 모델 및 오류 값

엄격한 실행은 Float 구성 요소 형식, signed zero, subnormals, explicit rounding points 및 branch 선택을 유지합니다. AOT 및 JIT는 동일한 요청된 숫자 프로파일을 사용해야 합니다. 재배치, 수축, 플러시 제로, 더 넓은 중간체 및 빠른 수학 근사치는 명시적인 프로파일을 필요로 합니다; GPU 스토리지 지원만으로는 복잡한 수학 라이브러리를 제공하지 않습니다.

기준선은 핵심 구성 요소 산술에 대해 라운드 - 투 - 가장 가까운, 넥타이 - 투 - 심지어를 사용합니다. 초월적인 구현체들은 선택된 타겟 프로파일에 그들의 정확성 및 비-유한 케이스 테이블을 게시한다. Annex-G 호환 프로파일은 특수 값에 대해 제안된 상호 운용성 기준선입니다. 해당 프로파일이 없는 타겟은 확인되지 않은 인스턴스화를 거부합니다. 유한한 checked API는 별도의 정확한 오류-값 계약으로 유지됩니다.

구현된 The ComplexError 있습니다. ZeroDivisordiv 와 reciprocal 에 의해 0 분모로 반환됩니다. 미래의 checked, 변환, 텍스트 및 대량 API는 추가 변형을 제안합니다. NonFiniteInput, NonFiniteResult, Pole, Domain, ZeroMagnitude, Inexact, OutOfRange, ImaginaryPartPresent, InvalidText, InvalidOptions, BufferTooSmall, AllocationFailed, LengthMismatch, Aliasing, 및 UnsupportedCapability. 유한한 서브노멀 또는 제로의 언더플로우는 유효한 산술값이다; 정확한 변환은 여전히 손실된 정보를 거부할 수 있다.

4입니다. 주요 지점 및 서명 0

다중 가치의 수학적 역은 선택된 브랜치를 필요로 한다. sqrt, ln정수가 아닌 힘은 로그 컷으로 음의 실제 축과 함께 주 브랜치를 사용합니다. 부호 있는 가상의 0은 절단 위 또는 아래에서 접근 방식을 구별합니다: 두 표현은 엄격한 최적화 프로그램에 의해 병합되어서는 안 됩니다.

기능 컷 또는 뛰어난 입력 선택한 동작
ln / sqrt / 비 정수 전력 부정적인 진짜 축선; ln 또한 영 극 허수 0 의 기호가 변을 선택한다. ln 위상 [, ]
asin / acos 외부 실제 광선 [−1, 1] 주요 역; 엔드포인트 poles/limits는 선택된 특수 값 프로파일을 따릅니다.
atan / asinh ±i를 초과하는 상상의 광선 주요한 역; atan에는 ±i에 극이 있습니다
아코쉬 1의 밑에 진짜 축선 nonnegative 진짜 부분을 가진 주요한 결과
아탄 외부 실제 광선 [−1, 1] 주요한 반전; ±1에 극
한국어 (ko) −1에 그리고의 밑에 진짜 축선 번역된 주요 로그 컷

미래 카탈로그 예제. 다음 분기에 민감한 sqrt 및 표현 도우미는 0.2 구현의 일부가 아닙니다.

Complex<f64> above = Complex.new(-4.0, 0.0);
Complex<f64> below = Complex.new(-4.0, -0.0);
Complex.sqrt(above); // +0 + 2i
Complex.sqrt(below); // +0 - 2i
Complex.same_bits(above, below); // false

5입니다. 완전한 기능 카탈로그

다음을 사용하는 행 C 다음과 같은 구체적인 형식에 대한 기존 형식 함수 설명 Complex<f32> 또는 복잡한 별칭. C와 Z는 동일한 선택된 복소수를 나타낸다. 남아있는 Complex. 카탈로그 표기법(Catalog notation) 더 읽기 0.2 기능 명부 C.eq와 C.magnitude를 포함하여 완전한 실행된 표면을 위해. 구성 요소 필드 사용 value.real 및 value.imag; 카탈로그의 real/imag 도우미 기능은 필드 액세스에 필요하지 않습니다.

각 함수는 아래 분류에 한 번씩 나열되며 결과와 실패 계약을 함께 설명합니다. T, Z, U, N, 정수 타입 매개변수 I, 쓰기 가능한 뷰, 콜백, 옵션은 개념적 시그니처 표기입니다. 변수 예제는 타입을 먼저 쓰는 선언을 따릅니다. 공통 스칼라 계약은 이 문서에서 다루고, 형식별 문서에서는 한계값과 반환 타입을 구체화합니다.

코어 호출은 명시적으로 return가 아닌 한 할당이 없습니다. string 또는 다른 컨테이너. 일반 연산자는 일치하는 타입의 스칼라 연산을 사용하며, 컴포넌트 형식 간에는 자동으로 변환되지 않습니다. 카탈로그는 의도적으로 일반 min/max, 비트 단위 복소수 산술, 관계보다 의미 있는 숫자를 생략합니다.

6입니다. 메타데이터와 상수 포맷 지정하기

T는 f16, bf16, f32 또는 f64입니다. Z는 Complex<T>입니다. U는 하나의 구성 요소로 동일한 너비의 부호 없는 정수입니다. 메타데이터와 생성자는 힙 저장소를 할당하지 않습니다.

개념적 시그니처 반환 계약 및 비용
Complex.component_type(Z) type 실제 구성 요소 형식 T; 컴파일 타임 메타데이터.
Complex.component_bits(Z) u32 하나의 구성 요소의 너비; 16, 32 또는 64.
Complex.storage_bits(Z) u32 가치 탑재량의 2개 구성요소 폭; ABI 패딩을 제외합니다.
Complex.byte_width(Z) u32 표준 와이어 표현을 위한 두 가지 구성 요소 byte 폭.
Complex.precision_bits(Z) u32 결합 된 정밀도가 아닌 각 일반 구성 요소의 상당한 정밀도.
Complex.epsilon(Z) T 하나의 구성 요소에서 1 이상의 간격; 일반적인 비교 허용 오차가 아닙니다.
C.zero() Z (+0, +0).
C.one() Z (1, +0).
C.imaginary_unit() Z (+0, 1).
Complex.pi(Z) Z (둥근 , +0), 선택한 T 정밀도.
Complex.e(Z) Z (반올림된 e, +0).
Complex.tau(Z) Z (둥근 2, +0).

7입니다. 건설 및 부품 액세스

입력된 피연산자는 암시적으로 승격된 never입니다. 생성자는 이미 타이핑된 컴포넌트를 취합니다; 스칼라를 변환하는 것은 별도의 명시적인 작업입니다.

개념적 시그니처 반환 계약 및 비용
C.new(T real, T imag) Z Cartesian construction; 두 가지 구성 요소 표현을 보존합니다.
Complex.from_real(T real) Z (실제, +0).
Complex.from_imag(T imag) Z (+0, 이미지).
Complex.real(Z value) T 실제 부품을 복사합니다.
Complex.imag(Z value) T 가상의 요소를 복사합니다.Copy the imaginary component.
Complex.components(Z value) (T, T) 그 순서로 (실제, 상상) 복사합니다.
Complex.with_real(Z value, T real) Z 실제 구성 요소만 교체하는 새 값을 반환합니다.
Complex.with_imag(Z value, T imag) Z 가상 구성 요소만 대체하는 새 값을 반환합니다.
C.conjugate(Z value) Z 부호 있는 0을 포함한 가상의 부호 비트를 토글합니다. 산술 라운딩 없음.
C.neg(Z value) Z 두 기호 비트를 토글합니다.
Complex.from_polar(T radius, T radians) Result<Z, ComplexError> 유한 반경 − 0 및 유한 각도 필요; 음의 반경은 영역입니다. Rounded trigonometric construction; 유한하지 않은 출력을 거부합니다.
Complex.cis(T radians) Result<Z, ComplexError> 필요한 유한 각도; cos (각도) + i sin (각도)를 구성합니다. 반올림 후 정확히 unit 등급에 대한 약속이 없습니다.

8입니다. 분류 및 술어

이러한 정의는 의도적으로 모든 유한 구성 요소와 값에서 무한한 구성 요소와 복잡한 값을 구별합니다. 술어는 일정한 작업을 사용하고 할당하지 않습니다.

개념적 시그니처 반환 계약 및 비용
C.is_finite(Z value) bool 두 요소가 모두 완료되었을 때만 참입니다.
C.is_nan(Z value) bool 두 성분 중 하나가 NaN일 때 참입니다.
Complex.is_infinite(Z value) bool 두 성분이 무한대일 때 참이 되고, 다른 성분이 NaN일 때도 참이 됩니다.
Complex.is_zero(Z value) bool 두 요소 모두 숫자로는 0이 되며 부호는 무시됩니다.
Complex.is_real(Z value) bool 가상의 구성 요소는 ±0이며 실제 구성 요소는 NaN이 아닙니다.
Complex.is_pure_imaginary(Z value) bool 실제 성분은 ±0이고 가상 성분은 NaN가 아닙니다; 0를 포함합니다.
Complex.is_unit(Z value) bool 계산 된 크기가 1와 정확히 일치하는 유한 값; 수치 unit 테스트에 대한 허용 오차 사용.
Complex.real_signbit(Z value) bool 실제 구성 요소 기호 비트를 읽습니다.
Complex.imag_signbit(Z value) bool 가상의 구성 요소 기호 비트를 읽습니다.
Complex.classify_components(Z value) (FloatClass, FloatClass) 각 구성 요소를 독립적으로 0, subnormal, normal, infinite 또는 NaN으로 분류합니다.

9입니다. 산술 & 스케일링

코어 산술은 소스 복소수를 반환합니다. 성분 +, , ×, T에서 둥근 . 일반적인 복잡한 분할과 규모는 불필요한 중간 오버플로우를 피하기 위해 확장 알고리즘을 사용합니다; 정확한 재현성은 명시 적으로 선택된 수치 프로파일에 따라 달라집니다.

개념적 시그니처 반환 계약 및 비용
C.add(Z a, Z b) Z Component-wise 합계입니다.
C.sub(Z a, Z b) Z 컴포넌트-와이즈 차이입니다.
C.mul(Z a, Z b) Z Complex 곱셈입니다. FMA 융합은 프로파일에서 명시적으로 선택해야 합니다.
C.div(Z a, Z b) Result<Z, ComplexError> 실패 가능한 complex quotient 오류를 일으키는 복잡한 지수 두 개의 부호 없는 구성 요소가 있는 분모는 ComplexError.ZeroDivisor를 반환합니다. 다른 NaN/infinity 입력은 구현된 숫자 프로파일을 따릅니다. finite-only check 는 포함되지 않습니다.
C.reciprocal(Z value) Result<Z, ComplexError> C.div(C.one(), value)에 해당하는 실패 가능한 1/value를 구현했습니다. zero는 ComplexError.ZeroDivisor를 반환합니다.
Complex.square(Z value) Z 값 × 값, 문서화 된 프로필 라운딩.
Complex.scale(Z value, T factor) Z 두 요소를 모두 실제 요소로 곱합니다.
Complex.unscale(Z value, T divisor) Z 두 성분을 실제 제수로 나눕니다.
Complex.add_real(Z value, T scalar) Z 실제 구성 요소에만 추가합니다.
Complex.sub_real(Z value, T scalar) Z 실제 성분에서만 뺄셈합니다.
Complex.scale_pow2(Z value, i32 exponent) Z 구성 요소 당 하나의 라운딩으로 2^exponent로 두 구성 요소를 스케일링합니다.
Complex.mul_add(Z a, Z b, Z c) Z Complex의 a×b+c 연산입니다. 복소 연산 전체를 한 번에 정확히 반올림하거나 하드웨어 복소 FMA를 암시적으로 사용한다고 보장하지 않습니다.

10입니다. 산술 오류 검사( E)

모든 checked 작업은 평가 전에 비-유한 입력을 거부하고, 명시적으로 제로 분모를 보고하고, 비-유한 출력을 거부합니다. 유한 반올림 및 유한 언더 플로우는 유효하며, 부정확은 산술 오류가 아닙니다. 아래의 모든 기능은 힙 스토리지를 할당하지 않습니다.

개념적 시그니처 반환 계약 및 비용
Complex.checked_add(Z a, Z b) Result<Z, ComplexError> 구성 요소 추가; NonFiniteInput 또는 NonFiniteResult.
Complex.checked_sub(Z a, Z b) Result<Z, ComplexError> Component 뺄셈; 동일한 유한 결과 정책.
Complex.checked_mul(Z a, Z b) Result<Z, ComplexError> Complex 곱셈이며 최종 성분 결과를 검사합니다.
Complex.checked_div(Z a, Z b) Result<Z, ComplexError> 두 b 성분이 모두 ±0일 때 ZeroDivisor; 그렇지 않으면 분할이 확장됩니다.
Complex.checked_reciprocal(Z value) Result<Z, ComplexError> 복소수 0을 거부합니다.
Complex.checked_scale(Z value, T factor) Result<Z, ComplexError> 유한 성분 및 유한 요소; 유한 결과 검사.
Complex.checked_unscale(Z value, T divisor) Result<Z, ComplexError> 유한 0이 아닌 실수 제수; 0은 ZeroDivisor를 제공합니다.
Complex.checked_sqrt(Z value) Result<Z, ComplexError> 주 제곱근; 유한 입력은 음의 실제 값을 포함합니다.
Complex.checked_ln(Z value) Result<Z, ComplexError> Complex의 0은 Pole에 해당하며 다른 유한 값에는 주 로그를 사용합니다.
Complex.checked_exp(Z value) Result<Z, ComplexError> 유한 입력 및 유한 지수 출력이 필요합니다.
Complex.checked_pow(Z base, Z exponent) Result<Z, ComplexError> 지수 0은 0^0를 포함하여 1을 반환합니다. 다른 0-기초의 경우는 엄격하게 양수의 실수 지수를 필요로 합니다. 음의 실수 지수는 극이고 0이 아닌 허수 지수는 영역입니다.
Complex.checked_norm(Z value) Result<T, ComplexError> 유한 구성 요소 및 유한 크기 필요.

11입니다. 크기, 위상 및 극좌표

길이는 유클리드 평면을 사용합니다. 이 값은 수학적으로 순서보다 작지 않습니다. 이러한 스칼라 출력은 T로 반올림되며 숨겨진 출력 할당이 없습니다.

개념적 시그니처 반환 계약 및 비용
C.norm(Z value) T 스케일된 hypot(real, imag), nonnegative; 실제 크기가 max(T)를 초과할 경우 오버플로우할 수 있습니다.
C.norm_squared(Z value) T real2+이미지2. 규범을 표현할 수 있을 때조차도 넘칠 수 있다; 강력한 알고리즘에서 규범을 대신할 수 없다.
Complex.l1_norm(Z value) T real+imag; 오버플로우할 수 있습니다.
Complex.phase(Z value) T atan2(imag, real), in [, ] (실제 이미지). 0 은 음수-실질 컷의 측면을 선택합니다; 원점에서 atan2 를 따릅니다.
Complex.to_polar(Z value) (T, T) (norm(value), phase(value)); 공유 할당 객체가 없습니다.
Complex.distance(Z a, Z b) T 유클리드 거리; 계산 된 구성 요소 차이는 그 자체로 넘칠 수 있습니다.
Complex.normalize(Z value) Result<Z, ComplexError> 0이 아닌 값이 필요합니다. 스케일링된 정규화는 불필요한 중간 표준 오버플로우를 방지합니다; ZeroMagnitude for zero.
Complex.project(Z value) Z Riemann-sphere projection : 모든 무한대 맵을 (+π, 부호 0); 그렇지 않으면 구성 요소를 보존합니다.

12입니다. 루트, 지수 및 로그

주 함수는 아래의 분기 규칙을 사용합니다. 스칼라 지수 인수는 명시적으로 입력됩니다. 도서관 정밀도는 기능과 표적 당 선언됩니다; 이 카탈로그는 정확하게 돌린 초월 결과를 약속하지 않습니다.

개념적 시그니처 반환 계약 및 비용
Complex.sqrt(Z value) Z 주제곱근, 음수가 아닌 실수 부분; 부호 있는 0 은 음수 실수 입력에서 변을 선택합니다.
Complex.cbrt(Z value) Z 주요 복잡한 큐브 루트입니다. 실제 cbrt와 달리, 음수의 실제 입력은 return에 음수의 실제 루트를 필요로 하지 않습니다.
Complex.powi(Z base, i32 exponent) Z Integer 지수; 지수 0은 1을 반환합니다. 음수 지수는 역수를 필요로 합니다.
Complex.powu(Z base, u32 exponent) Z 부호 없는 정수 지수; 0 지수는 1을 반환합니다.
Complex.pow_real(Z base, T exponent) Z 선택된 로그 브랜치를 통해 주된 실제 전력; 0 지수는 1을 반환합니다.
Complex.pow(Z base, Z exponent) Z 주된 복소수입니다. 지수 0은 1을 반환합니다. 다른 제로베이스 동작은 숫자 프로파일 또는 checked_pow를 따릅니다.
Complex.exp(Z value) Z Complex 지수 함수.
Complex.exp2(Z value) Z 2^value입니다.
Complex.exp10(Z value) Z 10^value입니다.
Complex.expm1(Z value) Z exp(value)−1는 0에 가까운 취소 인식 구현을 사용합니다.
Complex.ln(Z value) Z 기본 자연 로그; 상상의 부분은 [, ]에 있습니다. 0 은 극점입니다.
Complex.log2(Z value) Z 주 로그를 ln(2)로 나눕니다.
Complex.log10(Z value) Z 주 로그를 ln(10)로 나눕니다.
Complex.log_base(Z value, Z base) Result<Z, ComplexError> 교장 ln (값) /ln (기초). 비유한 입력, 값 0, 기본 0 또는 1을 거부합니다.
Complex.ln1p(Z value) Z 취소 인식 평가가 0에 가까운 Principal ln(1+value); 절단은 −1에서 시작됩니다.

13입니다. 삼각함수 & 쌍곡선 함수

모든 앵글은 라디안입니다. 순방향 함수는 극에서 멀리 떨어져 분석적입니다. 역함수 return 주값. 가용성 및 최대 오류는 호출자가 명시적으로 선택한 CPU 폴백을 포함한 대상 기능입니다.

개념적 시그니처 반환 계약 및 비용
Complex.sin(Z value) Z Complex 사인.
Complex.cos(Z value) Z Complex 코사인.
Complex.tan(Z value) Z Complex 탄젠트입니다. 실수축의 극점에서는 비유한 결과가 나올 수 있습니다.
Complex.sin_cos(Z value) (Z, Z) 반환값 (sin(value)), cos(value)); 공유 연산은 선택된 에러 프로파일을 변경하지 않습니다.
Complex.asin(Z value) Z 주요 역 사인, 실제 부분 [/2, /2].
Complex.acos(Z value) Z 주요 역 코사인, [0, ]의 실제 부분.

Complex.sinh(Z value) Z Complex 쌍곡선 사인.
Complex.cosh(Z value) Z Complex 쌍곡선 코사인.
Complex.tanh(Z value) Z Complex 쌍곡선 탄젠트.
Complex.asinh(Z value) Z 주요 역 쌍곡선 사인.
Complex.acosh(Z value) Z 주요 역 쌍곡선 코사인; 음이 아닌 실제 부분.
Complex.atanh(Z value) Z 주요 역 쌍곡선 탄젠트; ±1의 특이점.

14입니다. 평등 & 명시적 순서

Complex 값은 동등성 비교를 지원하지만 내재적인 수치 순서 관계는 없습니다. 비교 보조 함수는 용도에 맞게 이름을 붙입니다. 수치 동등성은 NaN 성분을 자기 자신과도 같다고 보지 않습니다. 원시 표현의 동등성 비교와 전순서는 별도 연산입니다.

개념적 시그니처 반환 계약 및 비용
Complex.equal(Z a, Z b) bool 두 성분 모두 수치적으로 동일하며, ±0 비교가 동일하고 NaN 비교가 거짓입니다.
Complex.not_equal(Z a, Z b) bool 논리적 부정은 평등하다.
Complex.same_bits(Z a, Z b) bool 두 원시 구성 요소 표현이 일치, 제로 기호와 NaN 페이로드를 포함.
Complex.total_compare(Z a, Z b) Ordering Lexicographic Float.total_compare on (real, imag); 수학적 크기 순서가 아닌 결정적 표현 순서.
Complex.is_close(Z a, Z b, T rel_tol, T abs_tol) Result<bool, ComplexError> 적지 않은 부정 허용 오차가 요구됩니다. 같은 무한대가 근접을 비교하지만 다른 무한대가 아닌 쌍은 그렇지 않습니다. 유한값은 스케일링된 평가와 함께 ab ≤ max(abs_tol, rel_tol×max(a,b))를 사용합니다.

15입니다. 명시적 변환

D는 대상 부동 소수점 형식이며, 반올림은 명시적인 정책입니다. 정확한 변환은 두 성분을 검사합니다. Failure never는 부분적으로 초기화된 출력을 생성합니다.

개념적 시그니처 반환 계약 및 비용
Complex.convert_exact(D, Z value) Result<Complex<D>, ComplexError> 두 구성 요소 모두 Float 정확한 변환 규칙에 따라 정확하게 나타낼 수 있어야 합니다. float-to-float 변환을 위해 보존된 부호 있는 0.
Complex.convert(D, Z value, Rounding mode) Result<Complex<D>, ComplexError> 각 구성 요소를 한 번 반올림합니다. overflow/non-finite 변환 동작은 명시적인 Float 변환 정책을 따릅니다.
Complex.from_integer_exact(T, I value) Result<Z, ComplexError> Integer는 가상 부분 +0인 T로 정확히 나타낼 수 있어야 합니다.
Complex.from_integer(T, I value, Rounding mode) Result<Z, ComplexError> 명백한 둥근 정수 - 실제 변환; 가상 +0.
Complex.to_real_exact(Z value) Result<T, ComplexError> 가상 구성 요소는 ±0이어야하며 그렇지 않으면 ImaginaryPartPresent이어야합니다. 실제 비트를 복사합니다.
Complex.to_integer_exact(I, Z value) Result<I, ComplexError> 가상의 0, 유한 적분 실수 부분 및 대상 범위가 필요합니다. 두 개의 0 부호는 모두 정수 0이 됩니다.
Complex.to_integer(I, Z value, Rounding mode) Result<I, ComplexError> 가상의 제로가 필요; 변환하기 전에 범위 검증으로 반올림 유한 실제 부분.

16입니다. 비트, 바이트 및 명시적 레이아웃

캐노니컬 바이트는 항상 실제 첫 번째, 가상의 두 번째를 저장합니다. Endianness는 각 성분 안에 적용한다; 그것은 never 성분 순서를 교환한다. 와이어 함수가 C/C++ ABI 호환성을 설정하지 않습니다.

개념적 시그니처 반환 계약 및 비용
Complex.to_bits(Z value) (U, U) 원시 실제 및 가상 비트 패턴; 할당 없음.
Complex.from_bits(T, (U, U) bits) Z 두 구성 요소 표현을 재구성합니다. 모두 지원되는 IEEE와 같은 비트 패턴이 허용됩니다.
Complex.to_le_bytes(Z value) Array<byte, 2*N> N은 byte 너비의 한 구성 요소입니다. 두 컴포넌트를 리틀 엔디언으로 인코딩합니다.
Complex.to_be_bytes(Z value) Array<byte, 2*N> 가상 전에 각 구성 요소 big-endian을 인코딩합니다.
Complex.from_le_bytes(T, Array<byte, 2*N> bytes) Z 작은 엔디안 디코딩 Little-endian Decode
Complex.from_be_bytes(T, Array<byte, 2*N> bytes) Z 빅 엔디안 디코드 Big Endian Decode
Complex.read_le(T, Slice<byte> bytes, usize offset) Result<Z, ComplexError> 읽기 전에 오프셋과 전체 너비를 검사합니다. 정렬되지 않은 버퍼는 안전한 byte 디코딩을 통해 허용됩니다.
Complex.read_be(T, Slice<byte> bytes, usize offset) Result<Z, ComplexError> Big-Endian 버퍼 디코드 확인
Complex.write_le(Z value, MutSlice<byte> buffer, usize offset) Result<unit, ComplexError> 독점적 인 대상 대여이 필요합니다. 쓰기 전에 전체 범위를 검증하고 경계 오류는 변경되지 않습니다.
Complex.write_be(Z value, MutSlice<byte> buffer, usize offset) Result<unit, ComplexError> Big-endian checked 쓰기, 동일한 실패 보증.

17입니다. 파싱 및 포맷

데카르트 문법은 로케일 독립형입니다: a+bi 주위에 선택적인 괄호, 명시적인 부호 있는 허수 구성 요소 및 각 구성 요소에 대한 Float 소수 문법. 화이트스페이스는 전체 값 주변에서만 허용됩니다. Polar 텍스트는 Cartesian 텍스트로 자동 해석되지 않습니다.

개념적 시그니처 반환 계약 및 비용
Complex.parse(T, string_view text) Result<Z, ComplexError> 전체 입력을 구문 분석합니다. 후행 데이터 및 형식이 맞지 않은 구분자를 거부합니다. 구성 요소가 아닌 토큰은 ParseOptions 기본값을 따릅니다.
Complex.parse_with(T, string_view text, ComplexParseOptions options) Result<Z, ComplexError> 명시적 비공개 토큰, 공백 및 구성 요소 문법 정책; 숨겨진 로케일 검색이 없습니다.
Complex.to_string(Z value) Result<string, ComplexError> 왕복 Cartesian 텍스트; AllocationFailed보고했다. NaN 텍스트는 임의의 페이로드를 보유하지 않습니다.
Complex.format(Z value, ComplexFormatOptions options) Result<string, ComplexError> 명시적인 Cartesian 또는 Polar 표기법, 구성 요소 정밀도 및 기호 정책; 할당 및 유효하지 않은 옵션이 실패할 수 있습니다.
Complex.format_into(Z value, MutSlice<byte> output, ComplexFormatOptions options) Result<usize, ComplexError> 유효한 UTF-8를 쓰고 기록 된 바이트를 반환합니다. BufferTooSmall에서 변경되지 않은 커밋하기 전에 용량을 확인합니다.
Complex.parse_polar(T, string_view radius, string_view radians) Result<Z, ComplexError> 두 개의 실제 필드와 대의원을 from_polar로 파싱합니다; 음의 반경을 거부합니다.

18입니다. Optional 벌크 작업

이러한 선택적 라이브러리 기능에는 명시적인 대상 실행 및 출력 저장소가 필요합니다. 그것들은 원시적인 스칼라 명령들이 아니다. MutSlice는 이미 독점적 인 쓰기 가능한보기이며 직접 전달됩니다. 소유자 매개 변수 양식 &T 및 &mut T가 선택되었습니다. 명시적 반환 참조 수명 주석은 설명적인 상태로 유지됩니다. 쓰기 전에 길이, 별칭 및 기능 검사가 완료되었습니다.

개념적 시그니처 반환 계약 및 비용
Complex.map_into(Slice<Z> input, MutSlice<Z> output, PureFn operation) Result<unit, ComplexError> 동일한 길이; 독립적인 순수 스칼라 콜백. 명시적인 O(n), 출력 할당 없음.
Complex.conjugate_into(Slice<Z> input, MutSlice<Z> output) Result<unit, ComplexError> Elementwise conjugation; 입력 및 출력 대여은 분리되어야합니다. 하나의 쓰기 가능한 버퍼에 대해 conjugate_in_place 를 사용합니다.
Complex.multiply_into(Slice<Z> a, Slice<Z> b, MutSlice<Z> output) Result<unit, ComplexError> 동일한 길이; 중복 대여이 필요합니다. O(n) 계산합니다.
Complex.dotu(Slice<Z> a, Slice<Z> b, AccumulationPolicy policy) Result<Z, ComplexError> A[k]×b[k]와 결합하지 않음. 명백한 누산기 형식 및 평가 순서; length/capability 오류가 보고되었습니다.
Complex.dotc(Slice<Z> a, Slice<Z> b, AccumulationPolicy policy) Result<Z, ComplexError> 켤레(a[k])×b[k]. 같은 명백한 감소 정책.
Complex.from_split_into(Slice<T> real, Slice<T> imag, MutSlice<Z> output) Result<unit, ComplexError> 별도의 구성 요소 배열을 압축합니다. 동등한 길이와 쓰기 가능한 저장소가 필요합니다. O(n) 기록합니다.
Complex.to_split_into(Slice<Z> input, MutSlice<T> real, MutSlice<T> imag) Result<unit, ComplexError> 별도의 real/imaginary 배열을 구체화합니다. 목적지를 분리합니다. O(n). 제로 카피 스칼라 뷰는 약속되지 않습니다.
Complex.conjugate_in_place(MutSlice<Z> values) unit 하나의 배타적 대여을 통해 각 가상의 부호 비트를 토글합니다; O(n), 할당 없음.
Complex.scale_in_place(MutSlice<Z> values, T factor) unit 선택한 숫자 프로필에 있는 모든 구성 요소를 확장합니다. O(n), 할당 없음, 전용 borrow.

19입니다. CPU, GPU 및 데이터 레이아웃

또 다른 명시적 스토리지 레이아웃이 선택되지 않는 한, 복잡한 값의 배열은 인터리브된 컴포넌트 쌍을 사용합니다. 실제 및 가상의 배열을 분리하면 특정 SIMD 또는 GPU 액세스 패턴이 개선될 수 있지만 인터리브 및 분할 레이아웃 간 변환은 O(n) 구체화입니다. 컴파일러는 관찰할 수 없는 임시를 제거할 수 있으며, 관측할 수 있는 장치 전송을 숨기거나 요청된 누산기 형식을 대체할 수 없습니다.

병렬 쓰기에는 서로 겹치지 않는 배타적 출력 대여가 필요합니다. 장치에 작업을 제출하면 실제 완료까지 입력·출력 소유권이 유지됩니다. Pending 값만으로 CPU에서 결과를 관측할 수 있다고 보장하지는 않습니다. 전송 방향·동기화·수학 라이브러리 가용성·지원 형식·원자 연산은 각각 검사합니다. Complex 덧셈이 자동으로 두 성분의 원자적 트랜잭션이 되지는 않습니다.

FFT 계획·변환·행렬 분해·합성곱·과학 특수 함수·자동 미분은 스칼라 Complex 메서드가 아니라 명시적으로 선택한 라이브러리의 기능입니다. 계획·작업 공간·실행 순서·할당에는 각각 별도 계약이 필요합니다. 스칼라 연산을 나열한 것만으로 장치의 네이티브 지원을 주장하지 않습니다.
