1입니다. 원자 와 이전 의 일 들 은 다르다

원자 세포는 위치 변경 순서가 있습니다. 값 중 하나를 관찰해도 다른 모든 메모리 위치에 대한 가시성이 자동으로 설정되지는 않습니다. release/acquire 프로토콜은 적절한 read-from 또는 release-sequence 동기화 관계가 필요하다. 일반적인 공유 원자가 아닌 변경는 유효한 발생 전과 소유권 능력없이 금지됩니다. 프로세서의 강한 행동은 언어 계약을 대체 할 수있는 것이 아닙니다.

2입니다. 편안한 Atomic 작업

이완된 접근은 원자성과 세포 변형-순서 규칙을 유지한다. 필요한 결과 만 대략적인 진단 count와 같은 독립적 인 세포와 관련이있을 때 유용합니다. 새로 초기화된 객체를 게시하거나 관련 없는 플래그 및 데이터 프로토콜을 스스로 수정하지 않습니다. 변경된 이완된 플래그를 관찰하는 루프는 이전의 모든 비원자적 기록이 보인다고 추론할 수 없다.

3입니다. 릴리스, 획득 및 그들의 RMW 반쪽

릴리스 쓰기는 이전 작업을 올바르게 구성된 프로토콜에서 해당 획득 관측값에 게시할 수 있습니다. 인수 RMW는 부하 반에 의미론을 획득하고 매장 반에 편안한 행동을 가지고; 릴리스는 반대 분할을 가지고있다. AcqRel은 두 가지 역할을 모두 제공합니다. 이러한 관계는 모든 애플리케이션 경쟁을 막거나 임의의 다중 객체 불변 트랜잭션을 만들지는 않습니다.

4입니다. 연속 일관성은 글로벌 잠금이 아닙니다.

SeqCst는 각 작업에 적합한 일반 acquire/release 관계를 유지하면서 순차적으로 일관된 작업에 대해 지정된 총계차 제약 조건을 추가합니다. 동기화되지 않은 비원자 필드를 안전하게 만들거나, 객체 수명을 예약하거나, OS 뮤텍스를 획득하는 메커니즘이 아닙니다. 알고리즘의 모든 작업을 SeqCst로 교체하면 유효하지 않은 참조, 누락된 복구 또는 깨진 비교 및 교환 루프를 복구할 수 없습니다.

5입니다. 잘못된 주문 및 유효성 검사

로드는 릴리스 저장소를 수행할 수 없으며, 저장소는 읽지 않는 값을 취득할 수 없습니다. 실패한 CAS는 로드이며 Release 또는 AcqRel을 사용할 수 없습니다. 일반적인 작업 시그니처은 스토리지를 터치하기 전에 동적 잘못된 선택 및 알려진 잘못된 상수에 대한 진단을 위한 오류를 정의합니다. 아래의 도우미는 구성 빌더에 대한 유효성 검사를 노출하며, 원자 액세스를 실행하거나 더 큰 프로토콜이 올바르다는 것을 증명하지 않습니다.

개념적 시그니처반환도메인, 오류 및 비용
Atomic.valid_load_order(MemoryOrder order)boolRelaxed, Acquire, SeqCst를 수락하십시오. 순수한 유효성 검사, 메모리 작동 없음.
Atomic.valid_store_order(MemoryOrder order)boolRelaxed, Release, SeqCst; 순수 검증을 수락합니다.
Atomic.valid_failure_order(MemoryOrder order)boolAccept Relaxed, Acquire, SeqCst; 릴리스 및 AcqRel이 유효하지 않습니다.
Atomic.valid_fence_order(MemoryOrder order)boolRelaxed를 제외한 모든 명명된 명령을 수락합니다; 펜스는 실행되지 않습니다.

6입니다. 울타리 및 메모리 스코프

울타리는 지정된 주변의 원자 액세스를 통해서만 동기화에 참여합니다. 이는 담요 플러시 명령이 아닙니다. 컴파일러 펜스는 선택한 compiler/same-thread 중단 프로파일을 처리하고 하드웨어 스레드 간 펜스를 대체하지 않습니다. 호스트, 장치, 작업 그룹 및 시스템 범위는 서로 다른 기능입니다. 순서 이름만으로는 GPU 전송 또는 외부 메모리 매핑에 대한 가시성을 확보할 수 없습니다.

7입니다. 루프, ABA 및 매립 재시도

CAS는 값이 변한 후에 동일한 비트 패턴을 관찰 할 수 있으며, ID를 사용하는 프로토콜에 대한 ABA 문제입니다. 메모리 순서는 복구된 노드를 유지하지 않습니다. 형식이 지정되지 않은 원자 주소가 아닌 명시적으로 설계된 개간 메커니즘과 유효한 소유권을 사용합니다. Atomic 호출 가능한 작업을 정의합니다. 기능 타겟 지원을 분리합니다. 이 초안에는 잠금 해제 포인터 컨테이너가 자동으로 포함되지 않습니다.

유효성 검사는 원자 액세스를 수행하거나 관계로부터의 읽기를 설정하지 않습니다. 

bool load_ok = Atomic.valid_load_order(MemoryOrder.Acquire);
bool store_ok = Atomic.valid_store_order(MemoryOrder.Release);
bool failure_ok = Atomic.valid_failure_order(MemoryOrder.Relaxed);
