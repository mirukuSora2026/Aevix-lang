1입니다. 모양은 제약이 아니라 저장소입니다.

도형은 논리적 축의 수와 범위를 나타냅니다. Shape<2, 3>는 순위 2, 6 요소 레이아웃 독립적 인 사실을 증명합니다. 행 주요 순서, 정렬, 소유권 또는 장치 배치를 선택하지 않습니다. 동적 셰이프 값은 검증된 런타임 범위를 저장합니다. DynamicShape<R>는 런타임 크기를 가진 알려진 랭크 R에 대해 제안된 라이브러리 디스크립터이다; 새로운 숫자 기본을 생성하거나 런타임 값을 임의의 컴파일-시간 파라미터로 허용하지 않는다.

N과 같은 기호적 정적 차원은 컴파일 시간 일반 매개 변수입니다. 호출자는 동일한 철자로 관련 없는 런타임 정수를 전달하여 Shape<N, 3>를 만족시킬 수 없습니다. 입력 제약 조건을 증명할 수 없는 경우, checked 생성자 return ShapeError. 성공적인 개선은 전 세계적으로 신뢰할 수 있는 주장이 아닌 실제 검증된 가치에 연결된 서술자를 생성합니다.

2입니다. 제품 및 representability

각 범위는 음이 아닌 usize 값입니다. Axis count, 요소 count, 출력 범위 합계, 변형 추론 및 byte 크기 계산은 checked 산술을 사용해야 합니다. Rank-Zero는 하나의 요소를 가지고 있습니다. 제로 범위는 논리적 액세스를 생성하지 않지만 메타 데이터를 유효성 검사에서 제외하지는 않습니다. 생성자는 명시적인 순위 및 할당 제한을 부과할 수 있으며, 이를 초과하는 것은 정수 래핑이 아닌 일반 리소스 또는 모양 오류입니다.

추론된 재형성 범위는 명시적으로 명명된 추론 함수를 통해서만 허용됩니다. 알려진 범위의 생성물은 count 요소를 분할해야 합니다. 알려진 제품이 0이면 총 count도 0일 때 추론이 모호하므로 차원을 추측하는 대신 추론 오류가 반환됩니다. 0이 아닌 count는 제로 제품 형태로 다시 형성될 수 없습니다.

3입니다. 방송 증거

추적 차원 정렬. 동일한 범위가 일치하고 하나의 범위가 다른 범위로 확장됩니다. 대표적인 축은 싱글톤 축이다. 1를 사용한 0의 결과는 0입니다. 0를 사용한 0의 결과는 0입니다. 0를 사용한 2는 유효하지 않습니다. 이 규칙은 숫자의 최대 구현이 빈 차원을 잘못 처리하기 때문에 직접 언급됩니다.

정적 브로드캐스트는 알려진 곳에서 컴파일 시간 출력 치수를 생성합니다. 런타임 호환성은 작업이 할당 또는 쓰기 전에 checked입니다. 브로드캐스트 증명은 차원만 인증합니다: 반복 주소 읽기 뷰는 그 증명을 변경할 수 있도록 사용할 수 없습니다. 장치 작업은 CPU 작업과 동일한 검증 된 모양 제약을 소비합니다.

4입니다. 축과 순열

코어 축 인수는 부호 없는 제로 기반 인덱스입니다. 삽입은 계급과 동등한 축선을 허용합니다; 접근과 감소는. Optional 어댑터는 음수 축을 허용할 수 있지만 명시적으로 정규화하고 산술 오버플로를 거부해야 합니다. 순열은 모든 축을 정확히 한 번 포함합니다. 반복 감소 축은 자동으로 중복 제거되는 대신 거부되므로 요청된 작업에는 단일 의미가 있습니다.

스퀴즈는 도끼만 허용하며, 빈 축은 싱글톤이 아닙니다. 요소를 복사하지 않고 하나를 삽입합니다. 연결되지 않은 모든 범위와 연결된 범위의 checked 합계를 확인합니다. 일괄 행렬 곱셈은 이러한 규칙을 내부 수축 제약 조건과 분리합니다.

5입니다. 모양 세련 및 소유권

반환된 설명자가 소유자 메타데이터를 참조하지 않는 한 성공적인 셰이프 검사는 요소를 빌려오지 않습니다. 메타데이터 뷰는 소유자 또는 해당 메타데이터를 대체하는 변경보다 오래 살 수 없습니다. 소유된 DynamicShape 값은 자신의 작은 설명자 저장소만 복사하며, 무제한 순위에 필요한 할당은 오류일 수 있습니다. 고정 순위 설명자는 힙 할당 없이 인라인으로 살 수 있습니다.

동적 차원에서 정적 대상으로 텐서를 수정하면 텐서를 사용하거나 API에서 명명한 대로 빌린 세련된 뷰를 반환합니다. 소유권을 사용하는 정제의 실패는 제안된 ShapeConversionError<T> 안의 원래 소유자를 반환합니다. 이렇게하면 실수로 값 비싼 저장 장치를 잃어 버리는 복구 가능한 오류가 유지됩니다.

6입니다. 명시적인 동적 검사 

Result<DynamicShape<2>, ShapeError> dimensions = Tensor.make_shape<2>([2, 3]);
// Given Slice<usize> dimensions_view and borrowed ShapeLike descriptors left_shape/right_shape.
Result<usize, ShapeError> count = Tensor.checked_element_count(dimensions_view);
Result<DynamicShape<2>, ShapeError> compatible = Tensor.broadcast_shape(left_shape, right_shape);

make_shape 에 전달된 고정 배열은 값 입력입니다. dimensions_view 와 ShapeLike 설명자는 빌린 뷰를 직접 전달합니다. 암시적 Array-to-Slice 강압은 가정되지 않는다. 모든 Result는 명시적으로 유지되며, 실패한 셰이프 검사는 무시될 수 없으며 확인되지 않은 액세스에 대한 증거로 사용됩니다.

8입니다. 디자인 경계 및 관련 페이지

모든 시그니처은 도서관 계약으로 제안됩니다. AOT 및 JIT는 동일한 유효성 검사, 수명 및 숫자 의미를 유지합니다. 최적화는 입증된 중복 작업을 제거할 수 있지만 관찰 가능한 오류 및 동기화 경계를 보존해야 합니다. 지원 설명자 유형 및 일반적인 모양 맞춤법은 디자인 후보자로 남아 있습니다; 매개 변수 전달은 승인 된 값, &T 및 &mut T 양식을 사용합니다. 반환 참조 수명 표기법은 개념적으로 남아 있습니다.
