1입니다. 넓이와 순서

0.3에서 import하는 bytes 모듈은 128비트까지의 부호 있는·없는 정수와 f16/bf16/f32/f64의 정확한 표현에 대해 명시적 LE/BE 코덱을 구현합니다. 실수 코덱은 수치 변환 없이 부호 있는 0과 모든 NaN 데이터 비트를 보존합니다. 쓰기 전에 전체 바이트 범위를 검사하고 정렬되지 않은 위치도 받습니다. 네이티브 엔디언 코덱과 Byte Order 카탈로그 전체는 별개입니다.

0.2 구현 범위. byte 그녀의 명백한 Byte.from_u8/to_u8 scalar conversion이 실행되고 있습니다. 이 페이지의 엔디안 read/write 함수와 그들이 참조하는 Integer/Float byte-codec 카탈로그는 제안으로 남아 있습니다. 그들의 사용을 Array<byte, N> 표현 계약이며, 구현 된 직렬화의 증거가 아닙니다. 자세히 보기 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

엔디언은 여러 바이트로 된 값 안에서 바이트의 순서를 정합니다. 각 바이트 안의 비트를 뒤집거나, 부호 유무를 정하거나, 완전한 파일 형식을 지정하지는 않습니다. 한 바이트짜리 필드에는 바이트 순서 구분이 필요하지 않습니다. 이 페이지는 검사 없는 네이티브 포인터 캐스트 대신 원시 슬라이스에 대한 Byte 네임스페이스 연산을 정의합니다. 모든 오프셋과 반환되는 쓰기 길이는 바이트 단위입니다. 애플리케이션 수준의 필드 스키마는 호출자가 별도로 선택합니다.

설계 초안. 이름, 지원 레코드 및 개념 구문은 제안된 Aevix 계약을 설명합니다. 그들은 실행을 주장하거나 성과를 측정하지 않습니다. 선언은 형식을 먼저 놓고 바인딩은 기본적으로 변경할 수 없습니다. MutSlice<T>는 독점적인 쓰기 가능 뷰를 나타냅니다. mut, &T, 및 &mut T 선택한 선언을 따르고 규칙을 대여하십시오. 카탈로그 관련 지원 기록 및 시그니처은 제안으로 남아 있습니다.

2입니다. 휴대용 레이아웃 및 네이티브 인터럽

리틀 엔디안은 가장 중요하지 않은 byte를 먼저 배치하고 빅 엔디안은 마지막으로 배치합니다. 따라서 u16 값 0x1234는 little-endian에서는 [0x34, 0x12], big-endian에서는 [0x12, 0x34]로 인코딩됩니다. 네이티브 오더는 실행 대상의 문서화된 표현을 의미하며, 범용 호스트 컨벤션을 의미하지 않습니다. 네이티브 순서 필드는 지정되지 않은 휴대용 파일 형식으로는 적합하지 않습니다. 스키마는 필드 순서, 너비, 패딩, 태그, 길이 및 버전 지정을 별도로 선언합니다.

일반 Integer 표현 API 및 Float 표현 API 동일한 Raw 사용 byte 이 문서의 형식입니다. 고정된 코덱이 생성 또는 소비 Array<byte, N>; 동적 코덱 borrow Slice<byte> 또는 MutSlice<byte>. 숫자 u8 배열은 암시적 재해석이 아닌 명시적 요소 변환이 필요합니다. 모델 번호:Float to_bits/from_bits 대신 부호 없는 정수 단어를 사용하고 byte 직렬화와는 구별됩니다.

3입니다. 경계, 서명 및 비용

판독값은 오프셋 ≤ 길이 및 폭 ≤ 길이 오프셋이 필요합니다. 이것은 오버 플로우 오프셋 플러스 폭을 방지 합니다. 읽기는 네이티브 정렬 요구 사항없이 초기화 된 바이트를 사용하고 힙 메모리를 할당하지 않습니다. 부호 있는 디코딩은 선택한 고정폭 2's-보완 해석을 사용합니다: ff ff는 −1를 i16로, 65535를 u16로 제공합니다. 이것은 선언 된 표현을 디코딩하는 것이지 변환 오류를 자동으로 무시하는 숫자가 아닙니다. 고정 너비는 usize로 변경되지 않습니다.

5입니다. 32 비트 필드

6입니다. 64비트 필드

8-byte 코덱은 높은 부호 없는 비트를 포함하여 모든 정수 비트를 보존합니다. f64가 모든 64-bit 정수를 정확히 나타낼 수 없기 때문에 부동 중간체는 허용되지 않습니다. 구현은 정렬된 로드 없이 결과를 조합할 수 있습니다; 네이티브 가속은 동일한 범위와 표현 계약을 보존해야 합니다. 8-byte 스토리지 지원은 네이티브 GPU 산술, 원자 또는 특정 속도를 약속하지 않습니다. Tensor 배치 및 기내 액세스 권한은 그대로 유지됩니다.

7입니다. 단일 바이트 및 부동 표현

단일 byte 함수는 중복 엔디안 접미사 없이 u8 및 i8 숫자 해석을 구분합니다. 부동 코덱은 정수에서 float로의 숫자 변환이 아닌 f32/f64 표현을 전송합니다. 전송은 부호 있는 0 및 NaN 페이로드 비트를 보존합니다; 나중에 산술은 Float 규칙을 따르고 NaN을 변환할 수 있습니다. 를 사용 Float byte API에서 여기서 코덱을 재정의하는 대신 f16 및 bf16 용. raw floating 디코드는 finiteness나 유효한 application-domain 값을 설정하지 않는다.

8입니다. 쓰기, 소유권 및 예제

그런 다음 write는 bounds failure leaves 출력을 변경하지 않음을 의미하며 하드웨어 원자 트랜잭션, 동기화 또는 내구성있는 스토리지를 약속하지 않습니다. 대여 규칙은 상충되는 소스 및 출력 별칭을 금지합니다. 숫자 스칼라 입력은 대상 바이트에 별칭을 지정하지 않습니다. never가 숨겨진 저장소를 할당합니다. 사용 Byte 버퍼 주인을 키우기 위해 그리고 Integer 산술에 대한. 

Array<byte, 2> data = [Byte.from_u8(0x34), Byte.from_u8(0x12)];
Slice<byte> view = Slice.from_array(&data);
Byte.read_u16_le(view, 0); // Result containing 4660
Byte.read_u16_be(view, 0); // Result containing 13330
Byte.read_u16_le(view, 1); // bounds error

텍스트 스트림은 자신의 UTF-16/UTF-32 코덱과 BOM 정책이 필요합니다; UTF-8는 엔디안 대안이 없습니다. 더 보기 string 및 Unicode 스칼라. API 이름 및 지원 레코드는 제안으로 남아 있으며 기본 참조는 Aevix 구현을 인증하지 않습니다.
