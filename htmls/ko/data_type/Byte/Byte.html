1입니다. 불투명 한 8 비트 값

0.2 구현 범위. 현재 byte 프리미티브는 자동으로 사용할 수 있으며 u8. Byte.from_u8(value) 및 Byte.to_u8(value) Allocation-Free Scalar Conversion(배분 없는 스칼라 변환) 암시적 숫자 또는 전체 버퍼 재 해석이 추가되지 않습니다. 아래의 명명 된 비트, 파싱, 포맷 및 코덱 도우미는 제안으로 남아 있습니다. 자세히 보기 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

현재 byte 타입은 불투명한 8비트 패턴을 저장하며 u8. 원시 파일, 메모리 버퍼, 네트워크 프레임 또는 해석이 아직 설정되지 않은 인코딩된 텍스트를 나타냅니다. byte 자체만으로는 Unicode 문자, 부호 있는 정수 또는 프로토콜 필드를 식별할 수 없습니다. 모든 256 패턴은 zero 및 0xff를 포함하여 유효합니다. 스칼라 할당은 힙 할당 없이 패턴을 복사합니다.

설계 초안. 이름, 지원 레코드 및 개념 구문은 제안된 Aevix 계약을 설명합니다. 그들은 실행을 주장하거나 성과를 측정하지 않습니다. 선언은 형식을 먼저 놓고 바인딩은 기본적으로 변경할 수 없습니다. MutSlice<T>는 독점적인 쓰기 가능 뷰를 나타냅니다. mut, &T, 및 &mut T 선택한 선언을 따르고 규칙을 대여하십시오. 카탈로그 관련 지원 기록 및 시그니처은 제안으로 남아 있습니다.

2입니다. 명시적인 숫자 경계

숫자 덧셈, 뺄셈, 곱셈, 나셈은 byte에서 직접 정의되지 않는다. 명시적으로 변환하기 Byte.to_u8 사용하기 전에 Integer 산술; 변환은 체크되지 않은 오버플로 또는 체크되지 않은 인덱싱을 승인하지 않습니다. 숫자 u8 결과를 다시 변환하는 것도 명시적입니다. 비트 단위 연산은 raw-pattern 해석을 보존합니다. 물리적 패킹, 레지스터 사용 및 외래 정렬은 값의 one-byte 표현과는 별개로 유지됩니다. 묵시적 문자 또는 텍스트 변환이 없습니다.

숫자 직렬화 경계입니다. 원시 표현 API in Integer 및 Float 사용 Array<byte, N>, Slice<byte>, 및 MutSlice<byte>. 숫자 Array<u8, N> 값은 일반적인 unsigned-integer 컬렉션으로 남습니다. 동일한 요소 너비로 인해 이러한 컬렉션 유형이 서로 교환되지 않습니다. Byte.from_u8 및 Byte.to_u8 Element Conversion에 대한 설명입니다. 이 규칙은 암시적인 전체 버퍼 캐스트나 숨겨진 복사본을 도입하지 않습니다.

3입니다. 비트와이즈 및 시프트 운영

비트 위치는 최소 유효 위치에서 0부터 시작합니다. 엄격한 교대는 자동으로 하드웨어 count 마스킹을 상속하는 대신 0...7를 허용합니다. 왼쪽 시프트는 checked 숫자 곱셈이 아닌 높은 비트를 버리는 비트 연산입니다. Rotation은 부호 없는 count를 허용하고 모듈로 8을 줄입니다. 비트 반전은 바이트 교환과 다릅니다: 1-byte 값은 byte 순서를 대체하지 않습니다. 여기서 모든 연산은 독립 스칼라 값을 반환합니다.

4입니다. 카운트와 패턴 쿼리

return 숫자 u32 값을 불투명한 byte 값이 아닌 0에서 8까지 계산합니다. 0 byte count의 모든 위치는 0을 선도하고 후행합니다. 쿼리는 힙 스토리지가 필요하지 않습니다. 경계가 있는 값 너비의 지속적인 복잡성은 암호화 상수 시간 기계 코드 또는 측면 채널 저항을 인증하지 않습니다. 명시적 패턴 비교기는 일반적인 숫자 연산자를 형식에 부여하지 않고 결정론적 순서를 제공합니다.

5입니다. 체크된 필드와 Nibbles

필드는 checked 산술을 사용하여 시작 ≤ 8 및 너비 ≤ 8 − start를 만족해야 합니다. 0폭 추출은 0을 반환합니다; 0폭의 디파짓은 0 필드를 필요로 하고 값을 변경하지 않습니다. 다른 필드 인수는 선택된 너비에 맞아야 합니다. 수정된 복사본을 반환하면 별칭을 통해 숨겨진 변경가 발생하지 않습니다. Nibble 헬퍼는 정확히 4개의 위치에서 작업하고 높은 비트를 자르는 대신 대형 구성 요소를 거부합니다.

6입니다. 16 진수 및 이진 텍스트

16진수 텍스트는 byte를 나타내지만 표시된 byte가 텍스트임을 증명하지는 않습니다. 스칼라 파서는 고정된 ASCII 문법 전체를 사용합니다. 포매터는 명시적으로 반환된 것을 할당합니다 string 또는 독점 출력 뷰에 ASCII 바이트를 기록합니다. 용량 실패는 고정 크기 쓰기 전에 발생합니다. 어떤 연산도 소수를 추론하지 않습니다. Unicode 원시에서 스칼라, 로케일 또는 소스 언어 탈출 byte. 이진법과 16진법 맞춤법은 인코딩된 프로토콜 필드와 구별됩니다.

시그니처반환계약 및 비용

Byte.parse_binary(string_view text)Result<byte, ByteError>정확히 8개의 ASCII zero/one 숫자가 필요합니다.

Byte.format_binary_into(byte value, MutSlice<byte> output)Result<usize, ByteError>8개의 ASCII 바이트를 기록하기 전에 용량을 검사합니다.

7입니다. 스칼라 사본, 버퍼 및 텍스트

소유하기 Vector<byte> 창고는 정상적으로 움직입니다. Slice<byte> 빌린 초기화 된 저장; MutSlice<byte> 단독으로 쓰기 권한이 필요합니다. 바이트를 복사하거나 범위를 확인하지 않으면 UTF-8 유효성이 설정됩니다. 다중 byte 번호는 너비, 서명 및 byte 순서이 필요합니다. 더 보기 Byte 버퍼 수집작업 및 Byte 순서 필드 코덱. 이러한 페이지는이 핵심 카탈로그를 반복하는 대신 추가 기능을 개별적으로 정의합니다.

8입니다. 예제 및 보증 

byte raw = Byte.from_u8(0xff);
u8 number = Byte.to_u8(raw);
Byte.count_ones(raw); // 8
Byte.shift_left(raw, 8); // count error
Byte.rotate_left(raw, 8); // unchanged
Byte.parse_hex("ff"); // Result containing the all-one byte

ByteError는 유효하지 않은 인덱스, 필드, 텍스트, 용량 및 할당 실패를 구분합니다. 오류 이름과 예제 문법은 초안 제안서로 남아 있습니다. 어떤 도우미도 실행 장소 간에 버퍼를 전송하지 않고, 유효하지 않은 byte를 생성하거나, 충돌하는 가변 뷰를 승인합니다. 더 보기 string 텍스트 의미론(Text semantics) 외부 참조는 기존 개념을 설명하지만 Aevix 성능은 구현하지 않습니다.
