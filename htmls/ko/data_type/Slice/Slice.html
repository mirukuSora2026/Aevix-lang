1입니다. 득표 의견

0.2 구현 범위. Slice<T>/MutSlice<T> import 할 필요가 없습니다. 상기 호출들은 The calls are Slice.from_array, from_array_mut, from_vector, from_vector_mut, len, slice 및 slice_mut인덱스를 더합니다. 슬라이싱 이름은 slice/slice_mut제안된 것이 아니라 subslice 별칭. 가변 슬라이싱 본질은 성공 또는 오류에 대한 입력 디스크립터를 소비합니다; 결과가 해당 저장소를 사용한 후 다른 뷰가 필요할 때 새로운 소유자 대여을 만듭니다. 자세히 보기 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

언어 설계 초안. Slice<T> 읽을 수 있는 view; MutSlice<T> 빌려온 글만 볼 수 있는 특별한 공간입니다. 이러한 설명자는 백업 요소를 소유하거나 할당하지 않습니다.

슬라이스는 다른 곳에서 소유하는 초기화된 인접 요소 범위의 이름을 지정합니다. 범위와 길이를 식별할 수 있는 충분한 메타데이터를 저장하지만 이러한 요소를 소유하거나 해제하지 않습니다. 짧은 슬라이스는 보이는 것을 변경합니다; never는 Array 또는 Vector 길이를 변경합니다.

읽기 뷰는 수명 규칙이 허용하는 경우 대여 메타데이터로 복제될 수 있습니다. 쓰기 가능한 기능을 중복된 작성자로 복제할 수 없습니다. MutSlice를 재차 대여하면 파생된 대여자의 수명 동안 원래 뷰의 상충되는 사용이 일시 중지됩니다.

2입니다. 소유자 수명 & 무효화

모든 견해는 원래 소유자 또는 명시 적 외국 수명과 관련이 있습니다. 로컬 소유자를 탈출하거나, 소유자 파괴에서 살아남거나, 무효한 재배치에서 Vector 버퍼를 유효하게 유지할 수 없습니다. 안전 코드는 충돌하는 소유자의 움직임과 구조 변경를 거부합니다.

길이와 일관성은 소유권이 아닙니다. 임의의 주소에서 Slice를 구성하려면 출처, 정렬, 초기화된 요소, 범위 및 권한 증명이 필요합니다. 이 카탈로그는 원시 포인터 채택 대신 안전한 소유자 기반 건설을 의도적으로 노출합니다.

고정된 배열에 대한 뷰는 Vector에 대한 것과 동일한 수명 규칙을 따릅니다. 고정 용량은 독점 액세스를 위반하는 별칭을 허용하지 않습니다. 대여 단축은 추론될 수 있지만, 그 길이 메타데이터가 여전히 존재하기 때문에 어떤 알고리즘도 댕글링 있는 뷰에 의존할 수 없습니다.

3입니다. 독점 액세스 및 연결 해제 지역

쓰기 알고리즘은 독점적으로 쓸 수 있는 기능과 호출 사이트에서 명시적으로 허용되는 변경 가능한 액세스가 모두 필요합니다. 기본 불변 선언은 변경할 수 없습니다. 읽기 Slice never를 유지하면 쓰기 권한이 부여됩니다.

확인된 분할 함수는 분할 지점을 확인한 다음 중복되지 않는 빌린 영역을 만듭니다. 두 개의 쓰기 반은 분리된 슬롯을 덮기 때문에 공존할 수 있으며, 원래의 겹치는 쓰기 기능은 일시 중단됩니다. 가변 반복자와 청크 반복자는 항복된 요소에 대해 동일한 분리를 적용합니다.

겹치는 창은 이 카탈로그에서 읽기 전용입니다. 일반적으로 쓸 수 있는 겹치는 창은 무제한의 독립적인 MutSlice 결과가 아닌 lending/short-lived 액세스 프로토콜이 필요합니다. 내부 가변성 유형과 콜백 캡처는 여전히 자체 동시성 제약이 필요합니다.

4입니다. 경계, 빈 뷰 & 덩어리

범위가 반쯤 열려 있고 usize 끝점인 0 <= start <= end <= length를 사용합니다. 빈 접미사 길이를 포함하여 빈 범위가 유효합니다. 아웃 오브 바운드 액세스는 선택한 API에 따라 Optional 또는 Result를 반환합니다.

청크와 창 너비는 양수여야 합니다. 길이보다 큰 너비는 지정된 작업에 따라 하나의 짧은 청크 또는 전체 창을 생성하지 않습니다. 정확한 청크 함수는 남은 꼬리에서 전체 청크를 분리합니다. Mutation never는 백킹 컬렉션의 요소 count를 변경합니다.

0 크기의 T는 많은 논리 요소를 가질 수 있지만 byte_len은 0입니다. 경계, 대여 배타성, 콜백 카운트 및 요소 드롭 의무는 여전히 논리적 길이를 따릅니다. 0 길이의 뷰는 첫 번째 요소가 없으며 원시 FFI 주소가 있는 경우에도 역참조되어서는 안 됩니다.

5입니다. Copy, 복제 및 오류 원자성

읽기 뷰를 복사하면 메타데이터만 복제되고 대여이 유지됩니다. 명시적 to_vector/to_array 함수는 소유된 값을 생성하고 이름에 따라 Copy 또는 Clone이 필요합니다. 소유된 리소스는 바이트를 재해석하여 딥 클로닝되지 않습니다.

copy_from 과 clone_from 은 같은 길이를 필요로 하고, 호환되는 disjoint 는 빌려온다. copy_within 은 명시적 오버랩 허용 Copy 동작이다. 경계 검사는 변경 전에 발생합니다. 복제 기반 덮어쓰기는 오류에 대한 대체 접두사를 남길 수 있으며, 모든 슬롯은 초기화 상태로 유지됩니다.

산출 건축에서 돌려보내진 배부 과실은 부분적인 산출을 청소하고 빌린 근원을 보존한다. In-place 콜백 부작용은 롤백되지 않습니다. 미래의 풀림 경로는 유효한 초기화를 유지해야 합니다; 프로세스 종료가 정리를 보장하지는 않습니다. 모든 에러와 반복자 프로토콜 이름은 여전히 제안된다.

6입니다. 알고리즘 요구 사항 및 비용

검색 위치는 소유자의 전체 버퍼가 아니라 뷰의 시작에 상대적입니다. 제공된 총 비교기에서 이진 검색에 정렬된 입력이 필요합니다. partition_point 는 true 접두사가 필요하고 false 접미사가 필요합니다. 이러한 시맨틱 전제 조건은 위반 시 메모리 안전하지 않음을 허용하지 않습니다.

부동 값을 정렬하려면 NaN 순서가 선택된 명시적 총 비교기가 필요합니다. 안정적인 정렬은 스크래치를 할당 할 수 있습니다. 불안정한 정렬은 힙 스크래치를 피합니다. 중단된 비교는 소유권을 유지하면서 순서를 변경할 수 있습니다. Eq 비교는 요소 의미론, never 초기화되지 않은 패딩을 사용합니다.

뷰를 만들거나 분할하는 작업은 O(1) 메타데이터 작업입니다. 횡단, 복사, 복제, 역방향 및 회전은 영향을 받는 요소에 비례하여 유지됩니다. 요소 크기, 비교 작업, Clone 및 Drop은 자체 비용을 추가하며, 입력값이 뷰이므로 복사 또는 장치 전송은 무료가 아닙니다.

7입니다. 전체 제안 Slice API

캐논 Slice 카탈로그입니다. 시그니처, 재대여 보장, 반환 오류, 비용은 이 문서에서 관리합니다. Array- 패밀리 Slice 가이드 중복 계약을 유지하는 대신 이러한 행에 대한 링크.

모든 rows 사용 Slice. MutSlice에서의 작업을 포함한 네임스페이스. 소유자 매개 변수는 & T 또는 & mut T 대여을 사용합니다. Slice<T> 및 MutSlice<T>보기 매개 변수는 직접 전달됩니다. 콜백 별칭, 빌린 반복자 유형 및 반환 참조 수명 설명은 제안된 라이브러리 계약으로 유지됩니다. 코어 액세스 및 오류 처리는 각 행에서 명시적입니다.

선언된 뷰 매개 변수 reborrow

현재 선택한 매개 변수 규칙 알려진 빌린 매개 변수를 일반 값 매개 변수와 구별합니다. 형식적인 MutSlice<U> 또는 &mut U 매개변수는 타입을 정규화한 뒤 호환되는 기존 배타적 접근 권한을 재대여합니다. U는 제네릭이어도 됩니다. 공유 참조와 읽기 Slice 디스크립터는 원본의 수명과 호환되는 읽기 권한을 유지합니다. 배타적 접근 권한이 Copy로 바뀌는 일은 없습니다.

아래 제안된 MutSlice 알고리즘, split, chunk 및 iterator API는 대여 입력을 사용합니다. 구현된 The Slice.slice_mut intrinsic은 문서화 된 예외입니다 : Result가 Err 인 경우에도 입력 설명자를 소비합니다. 일반 알고리즘은 액세스가 완료되면 파생 대여을 종료합니다. 반환된 참조, 읽기 뷰, 쓰기 가능 뷰 또는 반복자는 Optional, Result 또는 튜플로 래핑된 경우를 포함하여 부모 관계를 유지합니다. 충돌하는 부모 액세스는 정리 중 참조 액세스를 포함하여 모든 파생 대여이 종료 될 때까지 일시 중지됩니다.

일반 값 할당, 초기화 또는 return에 의해 설명자를 이동하는 것은 여전히 기능을 전송합니다. 일반 T value 파라미터는 또한 비-Copy 디스크립터를 이동하는데, 이는 T가 MutSlice 또는 배타적 참조로 인스턴스화되었더라도 마찬가지입니다. Optional.some 및 Result.ok과 같은 일반 컨테이너는 값 계약을 사용합니다. 구현된 The Slice.slice_mut call은 호출자의 원래 설명자를 전송하며, 그 설명자의 다른 사용으로 이어질 수 없다. 이것은 내재적 소유권 계약이지, 새로운 힘-움직임 인수 문법이 아니다. 다른 제안 된 Slice 행은 위에 언급 된 재 대여 계약을 유지합니다. 기존 쓰기 가능 뷰를 다시 빌리는 것은 mut 디스크립터 바인딩을 필요로 하지 않는 반면 디스크립터를 다시 바인딩하는 것은 필요하지 않습니다.

Slice.subslice_mut(MutSlice<T> view, usize start, usize end)Result<MutSlice<T>, BoundsError>제안된 대여 작업은 0.2 별칭이 아닙니다. 구현된 가변 슬라이싱에 Slice.slice_mut을 사용합니다.O(1)
Slice.split_at(Slice<T> view, usize index)Result<(Slice<T>, Slice<T>), BoundsError>index<=length; 2개의 반이 입력을 덮습니다.O(1)
Slice.split_at_mut(MutSlice<T> view, usize index)Result<(MutSlice<T>, MutSlice<T>), BoundsError>2개의 명백한 disjoint는 반을 씁니다; 입력 기능은 중단됩니다.O(1)
Slice.split_first(Slice<T> view)Optional<(&T, Slice<T>)>첫 번째 요소와 나머지 읽기 뷰; 비어있는 경우 없음.O(1)
Slice.split_first_mut(MutSlice<T> view)Optional<(&mut T, MutSlice<T>)>첫번째 원소와 tail write borrow를 분리합니다.O(1)
Slice.split_last(Slice<T> view)Optional<(&T, Slice<T>)>마지막 요소, 그 다음 읽기 범위 앞; 비어 있음 없음.O(1)
Slice.split_last_mut(MutSlice<T> view)Optional<(&mut T, MutSlice<T>)>마지막 요소와 이전 쓰기 대여을 분리합니다.O(1)

8입니다. 첫 번째 예

카탈로그 예제. 이 프래그먼트는 또한 스코프 노트에서 식별된 제안된 함수를 사용한다; 완전한 0.2 프로그램이 아니다.

값이 존재한다고 가정합니다. Array<i32, 4> 소유자. 각 선언은 첫 번째 유형이며 모든 실행 가능한 문은 세미콜론으로 끝납니다. 이러한 읽기 뷰는 충돌하는 소유자 변경 또는 이동하기 전에 끝나야 합니다. 

Array<i32, 4> values = [1, 2, 3, 4];
Slice<i32> view = Slice.from_array(&values);
usize count = Slice.len(view);
Optional<&i32> first = Slice.first(view);
Result<Slice<i32>, BoundsError> middle = Slice.slice(view, 1, 3);
Result<Vector<i32>, CollectionError> owned_copy = Slice.to_vector_copy(view);

Owned_copy의 Ok 값은 별도의 저장소를 가지고 있습니다. 보기와 중간은 여전히 빌린다; 그들의 서술자를 복사하는 것은 소유자의 수명을 연장하거나 소유된 요소를 생성하지 않는다.

9입니다. 병렬 처리, GPU 작업 및 FFI

읽기 공유에는 안전한 공유 액세스를 지원하는 T가 필요합니다. Disjoint write range는 호환 가능한 요소 특성 및 콜백 캡처를 통해서만 병렬 처리를 지원할 수 있습니다. 분할은 임의의 내부 참조에 대한 보편적 인 인종 안전이 아닌 별칭 증거입니다.

슬라이스는 장치 포인터가 아닙니다. CPU 스토리지를 빌리는 것은 업로드를 수행하거나 GPU 작업을 동기화하거나 해당 스토리지 커널에 액세스 할 수 없도록합니다. 명시적 전송 및 비동기 수명 규칙은 실행 및 Tensor 디자인에 속합니다.

외국에서 빌린 버퍼는 지속 시간, 초기화 된 요소 count, 정렬, 액세스 권한 및 외부 변경 계약이 필요합니다. 소유자는 대여 기간 동안 자유롭게 또는 재배치해서는 안됩니다. 릴리스 콜백은 일반 Slice 소멸자가 아닌 소유 어댑터에 속합니다.

10입니다. 텍스트, 바이트 및 관련 컬렉션

Slice<char> Unicode 스칼라 값을 색인합니다. 그것은 UTF-8가 아닙니다. string_view숫자 또는 raw-byte 슬라이스는 유효한 텍스트가 아닙니다. 소문자 보기 string 참조 인코딩 경계입니다.

byte u8와는 구별된다; 슬라이스 캐스트는 한 요소를 다른 요소로 조용히 대체해서는 안 된다. Endianness, serialization 및 FFI 레이아웃도 명시적인 변환이 필요합니다.

사용법: Array 일반적인 가족 규칙, 정적 배열 고정 소유권, 그리고 Vector 역동적인 소유권을 위해 주 소스는 이 제안을 알립니다; 컴파일러, 할당자, ABI 또는 장치 구현은 주장되지 않습니다.
