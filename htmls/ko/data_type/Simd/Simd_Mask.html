0.2 CPU 프로파일 구현

구현된 SIMD 프로파일 읽기 0.2에서 사용할 수 있는 정확한 가져오기, 지원되는 레인 카운트, checked 작업, 마스크 및 고정 어레이 액세스. 아래의 광범위한 API 카탈로그는 설계 초안으로 남아 있으며 컴파일러 지원 함수 목록이 아닙니다.

1입니다. 차선당 하나의 논리 술어

Mask<N>는 N 논리 진리 값을 포함하고 Simd 값의 count 레인과 일치합니다. bool, Array<bool, N>, 정수 벡터 또는 하드웨어 술어 레지스터에 대한 별칭이 아닌 제안된 라이브러리 유형입니다. 논리적 연산은 레인당 결과를 지정하는 동시에 네이티브 표현을 대상에 남겨 둡니다. 백엔드는 비트 패킹(bit packing), 전폭 레인 비트(full-width lane bits) 또는 다른 유효한 내부 포맷을 사용할 수 있다.

포지티브 레인 count는 컴파일 타임 제약이다. 마스크는 힙 할당없이 값으로 복사 할 수 있지만 단일 레지스터 또는 안정적인 메모리 레이아웃을 보장하지는 않습니다. 숫자 비교는 마스크를 만듭니다. 비트캐스트를 통해 마스크를 C bool 배열 포인터로 전달할 수 없습니다. 명시적인 논리 배열 변환이 필요합니다.

2입니다. 논리적 작업 및 감소

접속, 분리, 독점 및 부정은 각 레인에 독립적으로 적용됩니다. 모든 레인이 true일 때만 true입니다. 적어도 하나의 레인이 true일 때만 true입니다. count는 진정한 레인의 수를 반환합니다. first_set 및 last_set return Optional<usize>, 모든 false 마스크에 대한 유효하지 않은 센티널 인덱스를 피합니다.

N이 양수이기 때문에, 올 트루 마스크는 적어도 하나의 활성 레인을 포함한다. 미래의 제로 레인 확장은 명시적인 감소 ID가 필요하며 일반 빈 배열 동작에서 자동으로 수행되지 않습니다. 마스크 평등은 동일한 패딩 또는 레지스터 비트가 아닌 동일한 논리적 진리 값을 의미합니다.

3입니다. 값 선택 및 효과 보호

select는 이미 평가 된 두 개의 벡터 값을받습니다. 차선을 선택하지만 이러한 입력의 계산을 억제할 수는 없습니다. 제로 디바이저를 보호하려면 비활성 산수를 제외하는 마스킹된 산술 함수 또는 정규 나셈 전에 입증된 안전한 대체 약수가 필요합니다. 부하를 보호하려면 유효하지 않은 부하 이후의 선택이 아닌 마스크된 load/gather 기능이 필요합니다.

마스크된 메모리 함수는 활성 인덱스만 검증하고 액세스합니다. 비활성 유효하지 않은 인덱스에 대한 주소를 만들지 않습니다. 마스킹된 분산형은 쓰기 전에 활성 대상 사이에서 중복을 거부합니다; 비활성 레인 사이에서만 중복은 관련이 없습니다. 대여 검사기는 모든 차선이 비활성 상태 일지라도 법적 출처와 목적지 대여이 필요합니다.

4입니다. 명시적인 비트셋 변환

휴대용 비트셋 변환은 레인 i를 비트 i에 할당하며, 비트 0은 단어 0 중 가장 덜 중요한 논리적 비트입니다. Bitset<N>는 충분한 u64 단어를 포함하는 라이브러리 레코드입니다; 마스크를 구성할 때 마지막 단어에서 사용되지 않는 높은 비트는 0이어야 합니다. 소형 u64 변환은 N <= 64인 경우에만 사용할 수 있습니다. 이들은 값 변환이며 네이티브 마스크 객체 메모리를 노출시키지 않습니다.

Endianness는 명시 적으로 명명 된 little-endian 또는 big-endian 인코딩을 통해 비트 세트가 바이트로 직렬화 될 때만 중요합니다. N=64는 64의 유효하지 않은 시프트로 구현되어서는 안 된다. 안전 어댑터는 CPU 시프트 마스킹에 의존하지 않고 너비 인식 산술을 사용하여 사용되지 않는 비트의 유효성을 검사합니다.

5입니다. 마스크가 메모리 권한을 부여하지 않음

마스크는 값 술어이지 버퍼가 고유하게 대여되었거나 GPU 프로듀서가 완료되었다는 증거가 아닙니다. 마스크 된 저장소는 여전히 MutSlice 소유권을 필요로하며 활성 레인에 대한 증거를 제한합니다. 복사된 마스크는 소스 버퍼를 유지하거나 빌린 작업 수명을 연장하지 않습니다. 큐에 저장된 작업은 마스크를 값으로 캡처하거나 소유 메모리가 버퍼에 저장되어 있는 경우 명시적으로 이를 유지합니다.

마스크 작업이 네이티브인지 여부는 컴파일 기능입니다. 컴파일러는 마스크를 결합하거나 중복 검사를 제거하여 동일한 활성 액세스 세트 및 오류 동작을 증명할 수 있지만 checked 작업을 비활성 레인에서 독으로 전환할 수는 없습니다. AOT와 JIT는 이러한 의미론적 요구사항을 공유한다.

6입니다. 논리적 배열은 명시적 변환이다. 

Mask<4> active = Simd.mask_from_array<4>([true, false, true, false]);
Array<bool, 4> flags = Simd.mask_to_array(active);
usize enabled = Simd.mask_count(active);
Optional<usize> first = Simd.mask_first_set(active);

값 플래그와 활성에는 서로 다른 추상 유형이 있으며 공유 네이티브 레이아웃 보장이 없습니다. 이 예제에서는 동적 Vector를 할당하지 않으며 숫자 레인 유형으로 암묵적으로 변환하지 않습니다.

8입니다. 참조 범위

모든 인터페이스는 제안서입니다. Rust 휴대용 SIMD 문서는 명시적으로 실험적이며 공식 비교 소스로만 사용됩니다. LLVM 벡터 IR은 어휘를 낮추는 것입니다; 그것의 독과 정의되지 않은 행동 전제 조건은 안전한 Aevix 계약이 아닙니다. 언어는 자체 관찰 가능한 의미론에 의해 요구되는 모든 조건을 검증해야 한다.
