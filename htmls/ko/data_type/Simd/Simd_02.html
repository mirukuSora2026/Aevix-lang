가져오기 및 첫 사용

이 페이지에서는 구현된 0.2 컴파일러 프로파일에 대해 설명합니다. 디자인 참조에서 더 큰 카탈로그는 미래의 API를 포함; 거기에 나열된 기능은이 프로필에서 자동으로 사용할 수 없습니다.

SIMD 형식은 명시적인 가져오기가 필요합니다. 선택 항목 가져오기는 선택한 이름을 직접 노출합니다. 다음으로 import simd;, 쓰기 simd.Simd 및 simd.SimdMask.

import simd { Simd, SimdMask };

i32 main() {
    i32 values[4] = [1, 2, 3, 4];
    Simd<i32, 4> a = Simd.from_array(&values);
    Simd<i32, 4> b = Simd.splat<i32, 4>(8);
    return Simd.sum(Simd.add(a, b));
}

이 예제는 42를 반환합니다. SIMD 값과 마스크는 복사 시맨틱을 구현하고 힙 버퍼를 할당하지 않습니다. 배열 간 전송은 레인 값을 명시적으로 복사합니다.

지원되는 레인 유형

count 레인은 컴파일 타임 상수이다. 허용되는 개수는 2, 4, 8 및 16이며 숫자형 벡터에 최대 128 비트가 있습니다.

요소 종류허용된 레인 수
i8, u82, 4, 8, 16
i16, u162, 4, 8
i32, u32, f322, 4
i64, u64, isize, usize, f642

SimdMask<N> 레인당 하나의 논리적 불린을 갖는다. 그것의 포장 된 대표는 Array<bool, N> 레이아웃. 비교는 마스크를 생산; 선택은 마스크와 두 가지 대안에 동일한 레인 count가 필요합니다.

f16, bf16, char, byte, 및 bool 이 프로필의 숫자형 SIMD 요소가 아닙니다. 더 넓은 벡터는 조용히 스토리지 또는 할당 요구 사항을 변경하기보다는 거부됩니다.

구현된 작업

모든 연산은 positional arguments를 사용한다. V 아래는 1 Simd<T, N> 유형 및 M 있습니다. SimdMask<N>. 산술 함수와 마스크 함수에 제공된 값에는 일치하는 유형이 있습니다.

빌린 배열 액세스

로드 및 저장은 고정된 배열과 요소에서 측정된 오프셋을 수용합니다. 둘 다 메모리에 액세스하기 전에 전체 레인 범위가 맞는지 확인합니다. 대형 대여은 독점 변동 대여이 필요합니다. 배열은 이미 초기화되어야하며 일반 소유권 및 차입 규칙이 여전히 적용됩니다.

import simd { Simd };

i32 main() {
    mut i32 buffer[5] = [0, 0, 0, 0, 0];
    Simd<i32, 4> value = Simd.splat<i32, 4>(7);
    Simd.store(&mut buffer, 1, value);
    Simd<i32, 4> loaded = Simd.load<i32, 4>(&buffer, 1);
    return Simd.sum(loaded);
}

정렬되지 않은 요소 오프셋이 지원됩니다. 실패한 경계 검사는 안전하게 실행을 중지합니다. Slice 기반, gather/scatter, 마스킹된 메모리 및 오류가 있는 Result 반환 전송은 이 초기 프로필 외부에 남아 있습니다.

숫자 행동

Integer 추가, 뺄셈 및 곱셈 오버플로 모든 차선을 확인합니다. Integer 나누기는 모든 약수를 0으로 확인하고 부호 있는 최소값을 -1로 나누는 것을 거부합니다. 실패한 레인은 유효하지 않은 값이 노출되기 전에 실행을 멈춥니다. Integer sum은 중간 오버플로우를 포함하여 주문한 폴드의 각 덧셈을 검사합니다.

플로팅 작업은 재연동이나 fast-math 플래그 없이 f32/f64 동작을 따릅니다. 나셈은 무한대 또는 NaN을 생성할 수 있다; 음의 레인의 제곱근은 NaN을 생산한다. 평등과 질서 비교는 NaN에 대해 거짓이며 불평등은 사실입니다. Sum은 문서화된 차선 순서를 사용하며 재연관된 감소와 다를 수 있습니다.

Select는 일반적인 열망하는 기능입니다: 두 가지 대안은 차선 선택 전에 평가됩니다. 거짓 마스크는 대안을 계산하는 동안 발생하는 오버플로우, 분할 또는 기타 효과를 억제하지 않습니다.

휴대성 및 범위

컴파일러는 CPU 실행을 위해 LLVM 고정 벡터 연산을 방출한다. 백엔드는 네이티브 벡터를 선택하거나 여러 명령으로 작업을 낮출 수 있습니다. 소스 타입은 특정 명령어 count가 아닌 lane semantics를 약속하거나, ABI 또는 speedup을 등록한다.

128-bit 천장은 프로파일을 현재 휴대용 할당 정렬 계약 내에 유지합니다. AOT는 프로젝트의 ARM64 및 x86-64 백엔드 대상을 지원하며, JIT는 실행 중인 호스트에서만 실행됩니다. Cross-target 객체 생성은 네이티브 실행 테스트의 대용품이 아닙니다.

GPU 실행, 256/512-bit 값, 명시적 타겟 기능 디스패치, 포화 또는 래핑 벡터 산술, 그리고 더 큰 디자인 카탈로그의 나머지 부분은 이 프로파일에 의해 구현되지 않는다.
