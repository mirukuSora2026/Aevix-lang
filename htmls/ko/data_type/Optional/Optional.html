1입니다. 개요

0.2 구현 범위. prelude가 제공하는 타입: Optional<T>, Optional.some(value), 문맥이 정하는 Optional.none(), Optional.is_some(&value) 및 is_none. variant 생성·완전한 switch와 소유 값의 후위 ? 를 통한 Optional 반환 함수로의 전파가 구현되어 있습니다. 아래 map·unwrap·반복자 등 카탈로그 보조 함수가 자동으로 제공되는 것은 아닙니다. 자세한 내용: 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

카탈로그 상태. 지원 범위 알림은 구현된 부분집합을 밝히며 다른 API는 제안된 Aevix 계약입니다. 선택된 매개변수 형식: T value, &T value, 및 &mut T value. 타입 팩·호출 가능 타입·반환 참조의 명시적 수명 표기·오류 enum은 표시된 곳에서 설명용으로 남습니다. 모든 연산은 네임스페이스 함수를 사용하며 값 메서드 별칭은 없습니다.

Optional은 값이 없을 수도 있음을 나타냅니다. 값 없음은 예상 가능한 데이터이며 오류 payload가 아닙니다. 진단이 있는 파싱 실패에는 Result를 쓰고 선택적 검색은 None을 반환할 수 있습니다. 초기화되지 않은 저장소는 None도 Some도 아니며 유효한 Optional로 드러내지 않습니다.

2입니다. 선언 및 변형

네임스페이스 생성자를 타입 우선 선언과 함께 사용합니다. None 생성자에는 기대되는 T 또는 명시적인 타입 인수가 필요합니다. Some은 소유 payload를 소비하며 암시적으로 clone하지 않습니다. 

Optional<i32> present = Optional.some(12);
Optional<i32> absent = Optional.none<i32>();
bool found = Optional.is_some(&present);

3입니다. 안전한 검사 및 추출

variant 태그를 읽어도 payload는 이동하지 않습니다. 공유·배타적 대여 투영은 소유자 수명을 유지하며 투영한 참조가 살아 있는 동안 소유자 교체를 막습니다. 선택된 enum 분기 형식: case 패턴을 사용하는 switch. 이 카탈로그는 아직 Optional의 완전한 공개 variant 패턴 표현을 정의하지 않습니다. 이름 있는 검사·추출 API에는 각각 명시한 계약을 적용합니다.

카탈로그 제안에는 None일 때 panic하는 unwrap·검사 없는 접근·암시적 참거짓 변환이 없습니다. 대체 값·Result 변환·완전한 분기를 사용하세요. 진단 편의 기능이 복구 가능한 값 없음을 모델에 없는 중단으로 조용히 바꿔서는 안 됩니다.

4입니다. 소유권 및 현장 업데이트

소유 T의 Optional은 기본적으로 이동합니다. 명시적 복사에는 T: Copy가 필요합니다. 명시적 clone은 T의 Clone 의미를 따르며 실패할 수 있습니다. 값을 꺼낸 뒤에는 유효한 None 상태가 남으므로 소유자를 잠시라도 미초기화 상태로 두지 않습니다.

insert·교체에는 배타적 접근이 필요합니다. insert는 이전 payload를 정리한 뒤 새 payload의 대여를 반환하고 replace는 이전 payload를 호출자에게 반환합니다. 공유 대여와 동시에 변경할 수 없습니다.

5입니다. 게으른 및 열망하는 대안

이름이 다음으로 끝나는 함수는 _else 또는 _with 콜백을 받고 실행 시점을 정확히 밝힙니다. 일반 대체 값·and/or 인수·zip 입력은 호출 전에 이미 평가되며, 선택하지 않은 소유 payload도 정확히 한 번 정리합니다.

map·and_then은 존재하는 payload를 소비합니다. map_ref는 대여합니다. inspect는 관측을 위해 대여한 뒤 소유권을 그대로 반환합니다. 콜백 반환 타입은 관측용 unit 를 포함해 명시적으로 유지합니다.

6입니다. 함수 참조

T value 는 값을 전달합니다. Copy 타입은 복사하며 소유 non-Copy 값은 깊은 clone 없이 이동합니다. &T value 는 공유 읽기 대여이고 &mut T value 는 배타적 변경 대여입니다. 호출 시 각각 x, &x, 또는 &mut x 를 사용합니다. 이미 대여한 참조·뷰 값은 직접 전달하며 &를 하나 더 붙이면 타입이 바뀝니다. *ref 는 참조 대상을 읽고 씁니다. 일반적인 &mut x 에는 mut 소유자가 필요합니다. mut T value 만으로는 값 매개변수가 함수 안에서 변경 가능해질 뿐 호출자의 값을 변경하지 않습니다. 겹치는 활성 대여는 마지막 사용까지 검사합니다. 서로 겹치지 않는 영역은 안전하게 나눌 수 있으며 대여는 원본보다 오래 살 수 없습니다. 동기화된 내부 변경은 해당 타입의 계약을 따릅니다. Fn(A) -> B 는 호출 가능한 값을 설명하며 반환 참조의 수명 관계는 본문으로 문서화합니다.

7입니다. 중첩 옵션 및 Result

Optional<Optional<T>> 에는 바깥 값 없음과 존재하는 안쪽 값 없음이라는 서로 다른 상태가 있습니다. flatten이 의도적으로 합치기 전에는 구분됩니다. Optional.transpose는 존재하는 Result 안의 오류를 보존하며 바깥 값 없음은 성공적인 값 없음으로 취급합니다.

Optional<unit> 는 의미상 두 상태를 갖는 존재 표시입니다. Optional<never> 는 None만 가능합니다. 이는 타입 수준의 의미이며 어느 쪽도 특정 바이트 배치를 요구하지 않습니다.

8입니다. 실패, 레이아웃 및 드롭 규칙

Optional 래퍼 생성에는 할당이 필요하지 않습니다. payload 생성·clone·소멸 비용은 T에서 물려받을 수 있습니다. clone 실패는 대여한 원본을 유효하게 유지하고 부분 생성된 clone을 정리합니다.

컴파일러는 모든 비트 패턴·ABI 규칙이 허용할 때만 payload의 미사용 표현에 값 없음을 인코딩할 수 있습니다. 보편적인 null 포인터 최적화·태그 크기·C 호환 배치를 보장하지 않습니다. 원시 바이트에는 활성 payload를 검증하는 디코더가 필요합니다.

9입니다. 병렬, 장치 및 외부 경계

다른 Task나 장치로 Optional을 이전하려면 payload·표현 계약이 그 경계를 지원해야 합니다. 공유 Optional이 payload의 동시 변경을 허용하지는 않습니다. payload가 원자 타입이라고 Optional 저장소도 원자적으로 되는 것은 아닙니다.

C nullable 포인터·C++ optional·Python None에는 명시적 어댑터가 필요합니다. Optional의 대여 참조는 외부 객체나 고정 보호자보다 오래 살 수 없습니다. 불투명 Python 소유권은 바인딩 계층에서 유지합니다.

10입니다. 예시 및 명시적 비용 

i32 chosen = Optional.unwrap_or(Optional.some(7), 99);
Result<i32, i32> required = Optional.ok_or(Optional.none<i32>(), 404);
