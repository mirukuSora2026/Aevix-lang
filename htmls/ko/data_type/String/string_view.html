1입니다. 대여된 UTF-8 보기

0.2 구현 범위. 문자열 리터럴은 할당이 없습니다. string_view 유형. 뷰 작업View operations string.view, byte_len, scalar_count, is_empty, as_bytes, equals 그리고 checked slice_bytes. 뷰는 소스 대여을 유지합니다. validation을 통한 대여 string.view_utf8 여전히 제안; string.from_utf8 대신 바이트의 유효성을 검사하고 소유한 string를 할당합니다. 자세히 보기 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

언어 설계 초안. 아래 계약·보조 타입·함수 표기는 제안입니다. 컴파일러 구현, 확정된 문법이나 검증된 런타임을 주장하지 않습니다. 예제는 타입 우선 선언, 기본 불변성과 세미콜론으로 끝나는 문장을 사용합니다.

string_view 는 유효한 UTF-8 저장소에 대한 수명 검사를 받는 읽기 뷰의 제안된 표기입니다. 스칼라 타입을 대체하지 않으며, 원본을 소유하거나 할당·정규화하지 않고 참조 횟수도 유지하지 않습니다. 논리적 표현은 주소와 바이트 길이지만, ABI와 구체적인 크기는 아직 미정입니다. 소유 값, 불변 리터럴 저장소, 검증된 대여 바이트 슬라이스를 가리킬 수 있습니다.

이것은 체크되지 않은 포인터 쌍보다는 텍스트 특정 대여 계약입니다. UTF-8 유효성 및 소스 수명은 값을 구성하기 전에 설정됩니다. 뷰를 복사하면 디스크립터만 복사되고 동일한 차입 제한이 유지됩니다. 자세히 보기 string 참고 소유 전체 네임스페이스 및 배열 보기 관련 스토리지 모델.

2입니다. 수명 및 소유자 변경

소유자는보기의 모든 사용 중에 살아 있어야합니다. 기능은 파괴되고 있는 국부적으로 소유자로 return 뷰을 할 수 없다. 다른 객체 안에 저장된 뷰는 소유권을 연장하지 않는 동일한 수명 의무를 지닙니다. 런타임 및 형식 시스템이 소유자가 유효한 상태임을 증명하지 않는 한 백그라운드 작업에서는 범위를 넘어 작업을 유지할 수 없습니다.

뛰어난 읽기 뷰는 재배치 및 현장 편집을 포함하여 충돌하는 쓰기를 방지합니다. 주소를 변경하지 않는 편집조차도 텍스트 경계 또는 의미 론적 위치를 변경할 수 있습니다. 컴파일러는 유효하지 않은 규칙을 기억하기 위하여 프로그래머를 신뢰 대신에 이 관계를 추적한다. 소유 사본은 작은 부분 문자열을 독립적으로 유지하는 명시적인 방법이며, 바이트를 복사하는 비용입니다.

3입니다. Byte 범위와 스칼라 경계

보기 길이 바이트 수. 엔드포인트가 멀티바이트 스칼라를 가리키기 때문에 반쯤 열린 범위는 텍스트로서는 유효하지 않을 수 있습니다. 안전한 생성자는 그 범위를 거부합니다. Scalar-index 슬라이싱은 요청된 스칼라 경계로 스캔하고 대여 상태로 유지됩니다; 자소 클러스터-index 슬라이싱은 옵션인 Unicode 모듈에 속합니다.

가장 가까운 스칼라 경계로 이동하는 것은 사용자가 인식한 문자를 보존하는 것과 동등하지 않습니다. 마크와 이모티콘 시퀀스를 결합하면 여러 스칼라에 걸쳐있을 수 있습니다. Integer 오프셋은 또한 본질적인 소스 ID를 가지고 있지 않습니다: 다른 뷰에서 얻은 오프셋을 적용하려면 새로운 범위 및 경계 검사가 필요합니다. 끝 오프셋은 유효한 경계이지만 제거하거나 읽을 스칼라를 지정하지 않습니다.

4입니다. 건설 및 검증

string.view 이미 유효한 텍스트를 일정한 시간에 빌려줍니다. string.view_utf8 대신 임의의 바이트를 빌리고 텍스트를 반환하기 전에 전체 범위를 확인합니다. 기본 byte 스토리지는 결과 뷰의 수명 동안 읽기 대여되어 break UTF-8의 변경를 방지합니다. 빈 입력이 성공합니다.

확인되지 않은 변환 및 임의 원시 포인터 생성기는 안전 카탈로그에서 제외됩니다. FFI 래퍼는 뷰를 빌드하기 전에 길이, 가독성, 수명 및 인코딩을 설정해야 합니다. 뷰가 NUL로 끝날 필요는 없으며, 내장된 NUL은 byte count의 일부로 남아 있습니다. 종료자를 자동으로 추가하지 않고 호출자 버퍼로 복사합니다.

5입니다. 대여된 뷰 기능 서페이스

이들은 공유 string. 인스턴스 메서드나 두 번째 기본 네임스페이스가 아닌 뷰에 특화된 함수입니다. 반복자는 소스와 패턴을 빌려온다; 출력을 소유하는 것은 항상 명백하다.

6입니다. 평등, 순서 및 Optional 데이터

뷰와 소유자는 동일한 UTF-8 평등 계약을 사용합니다. 동등한 콘텐츠는 동일한 주소 또는 공유 소유권을 의미하지 않습니다. 비교도 뷰 생성도 Unicode 정규화를 수행하지 않습니다. 비어 있는 텍스트는 없는 선택적 값과 구별됩니다. 검색 매치의 부재는 다음과 같이 표현된다. Optional잘못된 입력 또는 잘못된 슬라이싱은 다음과 같이 표현됩니다. Result.

제안된 설명자는 복사하지 않고 일반 읽기 전용 string 함수로 전달될 수 있습니다. 예비 용량, 쓰기 가능한 바이트 또는 크기 조정 가능한 컨테이너 인터페이스를 노출하지 않습니다. 별도의 가변 텍스트 뷰 디자인은 추가 불변성이 필요하며 여기에 도입되지 않습니다.

7입니다. 예제 

string_view text = "café";
Result<string_view, TextError> suffix = string.slice_bytes(text, 2, 5);
Optional<usize> location = string.find(text, "fé");
Result<string, TextError> independent = string.from_view(text);

모든 예제는 세미콜론으로 끝납니다. 빌린 리터럴은 저장 수명 동안 유효합니다. 소유 생성자는 복사가 할당할 수 있기 때문에 결과를 반환합니다; 이것은 자유 캐스트가 아닙니다.

8입니다. 타겟 및 비교 소스

AOT 및 JIT는 수명과 유효성 검사를 보존해야 합니다. 컴파일러 제거 복사본은 소스 작업이 의미상 소유자를 생성하는지 여부를 변경하지 않습니다. GPU 표현에는 명시적인 스토리지 접근성과 지원되는 작업이 필요하며, CPU 주소를 단순히 장치 보기에 내장할 수는 없습니다. Unicode 라이브러리 지원은 별도로 선언되어 있습니다.

C++ string보기 상기 소유하지 않는 표면은, The not owning surface, Rust UTF-8보기 유효성 및 checked 경계를 알립니다. Swift의 분리된 코드-unit 뷰는 또 다른 비교 포인트를 제공합니다. 이러한 참조는 자신의 동작을 지정합니다; 이 제안 된 수명 보증은 독립적 인 Aevix 구현 및 검증이 필요합니다.
