1입니다. Optional Unicode 텍스트 서비스

0.2 구현 범위. UTF-8 유효성, 스칼라 카운팅 및 byte/scalar/grapheme 카운트 간의 차이는 구현된 string 유형에 적용됩니다. 정규화, 자소 클러스터 세그멘테이션, 케이스 폴딩 및 Unicode아래 -property API는 라이브러리 제안서로 남아 있습니다. scalar_count는 grapheme가 아닙니다. count. 자세히 보기 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

언어 설계 초안. 아래 계약·보조 타입·함수 표기는 제안입니다. 컴파일러 구현, 확정된 문법이나 검증된 런타임을 주장하지 않습니다. 예제는 타입 우선 선언, 기본 불변성과 세미콜론으로 끝나는 문장을 사용합니다.

unicode. 유효한 UTF-8 텍스트에서 작동하는 선택적 라이브러리 네임스페이스입니다. 그것은 정규화, 자소 클러스터 세분화, 전체 케이싱, 로케일 대조 및 보안 분석의 표현을 변경 하지 않고 추가 string. 스칼라 속성 도우미는 다음과 같이 유지됩니다. char 참조이 페이지는 텍스트 시퀀스에 대한 알고리즘을 설명합니다.

UnicodeProfile 고정 알고리즘 및 데이터 버전을 식별합니다. 그것은 원시적이거나 운영 체제의 현재 테이블을 사용하겠다는 약속이 아닌 제안 된 라이브러리 설명자입니다. 요청된 프로파일은 명시적으로 사용 가능해야 하며, 다른 버전을 자동으로 대체하면 관찰 가능한 결과가 변경됩니다.

2입니다. 정상화와 평등

NFC 및 NFD는 정규 정규 정규화를 수행하고 NFKC 및 NFKD는 호환성 매핑을 추가로 적용합니다. 호환성 정규화는 의미 있는 차이를 제거할 수 있으며 never는 암시적 생성자 또는 비교 단계입니다. 두 정규화된 문자열을 연결한다고 해서 그 경계가 정규화된 상태로 유지되는 것을 보장하지는 않습니다.

기본 string 같음은 byte 같음으로 유지됩니다. 응용 프로그램은 표준 비교를 선택하거나 문서화 된 경계에서 키를 정규화합니다. 케이스 폴딩은 별도의 변형이며 임의의 정규화 단계를 상호 교환 할 수 없습니다. UAX에서 #15 정규화 알고리즘과 적합성 기대치를 정의합니다; Aevix는 여전히 테스트된 구현이 필요합니다.

3입니다. 스칼라, 그래프 및 단어

확장된 자소 클러스터 클러스터는 사용자가 인식한 텍스트 단위에 근접하며, 글리프 카운트, 터미널 셀 너비 또는 애플리케이션 커서 위치를 보장하지 않습니다. 세그멘테이션은 유효한 UTF-8로 유지되는 소스 상대적인 byte 범위를 반환합니다. 단어와 문장 경계는 영어만 있는 공백이 아닌 명명된 프로필과 선택적인 맞춤 설정을 사용합니다.

시퀀스와 이모티콘을 결합하려면 단일 스칼라를 넘어서는 것이 필요할 수 있습니다. 따라서 무작위 그래프에 접근하려면 횡단 또는 명시적 인덱스 구조가 필요합니다. 스트리밍 세그먼트러는 지연된 컨텍스트가 필요할 수 있으며, 임의의 Unicode 입력에 대해 고정된 작은 룩-비하인드가 보장되지 않습니다. 비교 알고리즘은 다음과 같이 지정됩니다. UAX에서 #29.

6입니다. 로케일, Collation 및 보안

전체 케이스 매핑은 스칼라와 바이트 수를 변경할 수 있습니다. 로케일 관련 dotted-I 동작은 ASCII 폴딩, 기본 Unicode 폴딩 및 로케일 케이싱이 다른 API인 이유를 보여줍니다. 모델 번호:Unicode White_Space 또한 ASCII 공백과 다르며, 제로 폭 포맷 문자는 자동으로 제거되지 않습니다. ICU 사례 매핑 이러한 차이를 문서화합니다.

Collation은 명시적 로케일, 옵션 및 데이터 프로파일을 사용합니다. 정렬 키는 동일한 collator 구성 및 버전에서만 비교할 수 있습니다. 이를 저장하려면 메타데이터가 필요합니다. Confusable detection은 두 식별자가 동일한 사람에 속하거나 텍스트가 안전하다는 증거가 아닌 선택적 검토 신호입니다. 정상화만으로는 스푸핑을 막을 수 없습니다.

8입니다. 예제, 버전 및 실행 대상 

string_view decomposed = "e\u{0301}";
Result<string, UnicodeError> composed = unicode.nfc(decomposed, profile);
usize groups = unicode.grapheme_count(decomposed, profile); // One extended grapheme cluster;
Result<bool, UnicodeError> same = unicode.canonical_equal("é", decomposed, profile);

프로파일 변수는 이미 선택한 불변 라이브러리 리소스를 나타냅니다. Unicode 이스케이프 표기법은 최종 리터럴 문법에 대한 예시입니다. 할당 실패, 사용할 수 없는 데이터 버전, 잘못된 옵션 및 리소스 제한은 복구 가능한 오류입니다. 오류가 없는 반복기는 프로파일 설정 후 오류가 없는 작업 공간 할당 없이 지원되는 기본 규칙만 포함합니다. 사전 기반 또는 맞춤 세그멘테이션은 별도의 실패 가능한 setup API를 필요로 하며, 자동으로 대체되지는 않습니다.

CPU Unicode 지원은 기본 GPU 지원이 아닙니다. 장치 알고리즘은 명시적으로 전송된 테이블, 지원되는 작업 및 이와 동등한 버전화된 의미론을 필요로 합니다. 회귀 검사에는 고정된 버전, 수명 사례, 확장 제한 및 로케일별 예제에 대한 정규화 및 분할 적합성 데이터가 포함되어야 합니다. 게시된 소스 참조가 Aevix 적합성을 설정하지 않습니다.
