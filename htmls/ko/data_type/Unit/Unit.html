1입니다. 개요

0.2 구현 범위. unit 및 Unit.value() import 없이 사용할 수 있습니다. unit-returning 함수는 해당 값을 명시적으로 반환합니다. return-position void 분리되어 있습니다. unit 값의 비교가 지원됩니다. 아래의 서식, 변환 및 기타 편의 기능은 제안 된 API로 남아 있습니다. 자세히 보기 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

카탈로그 상태. 지원 범위 알림은 구현된 부분집합을 밝히며 다른 API는 제안된 Aevix 계약입니다. 선택된 매개변수 형식: T value, &T value, 및 &mut T value. 타입 팩·호출 가능 타입·반환 참조의 명시적 수명 표기·오류 enum은 표시된 곳에서 설명용으로 남습니다. 모든 연산은 네임스페이스 함수를 사용하며 값 메서드 별칭은 없습니다.

unit 하나의 값이 있습니다. 부재 또는 불가능한 결과보다는 추가 데이터없이 성공적인 완료를 모델링합니다. Optional<unit> 여전히 어떤 것과도 구별되지 않음(unit); Result<unit, E> 여전히 성공과 실수를 구별합니다.

2입니다. unit 값 선언

다음 문서를 참고하세요: Unit. 미완성 리터럴 문법에 의존하지 않고 값을 구성하는 네임스페이스입니다. 형식은 소문자이며 네임스페이스는 대문자를 유지합니다. Unit 스칼라는 Copy입니다. 

unit completed = Unit.value();
Result<unit, i32> success = Result.ok(Unit.value());
Optional<unit> present = Optional.some(Unit.value());

3. unit 가치와 return 위치 void

unit 제네릭 컨테이너 내에서 사용할 수 있는 일반적인 값 유형입니다. void is a return-position marker under the current function design; unit의 컨테이너 요소 유형이나 별칭이 아닙니다.

return unit에 선언된 함수는 void가 아니며 명시적이어야 합니다. return Unit.value(); 정상적으로 종료되는 모든 경로에 void 기능은 처음부터 끝까지 또는 사용할지도 모릅니다 return;. 함수의 끝에 있는 값 표현식은 암시적으로 return가 되지 않습니다.

4입니다. 제품 및 변형 의미

unit 필드는 데이터를 전달하지 않지만 일반적인 인터페이스 모양을 유지할 수 있습니다. unit의 Result는 실패할 수 있는 유효성 검사, 리소스 닫기 또는 변경에 유용합니다. unit 값을 삭제해도 작업이 다시 수행되지 않습니다.

이 초안은 모든 빈 사용자 정의 구조체 또는 빈 튜플을 unit와 자동으로 동일시하지 않습니다. 빈 튜플 철자나 별칭은 문법으로 문서화해야 합니다. 동일한 스토리지 크기만으로는 유형 ID가 설정되지 않습니다.

5입니다. 함수 참조

T value 는 값을 전달합니다. Copy 타입은 복사하며 소유 non-Copy 값은 깊은 clone 없이 이동합니다. &T value 는 공유 읽기 대여이고 &mut T value 는 배타적 변경 대여입니다. 호출 시 각각 x, &x, 또는 &mut x 를 사용합니다. 이미 대여한 참조·뷰 값은 직접 전달하며 &를 하나 더 붙이면 타입이 바뀝니다. *ref 는 참조 대상을 읽고 씁니다. 일반적인 &mut x 에는 mut 소유자가 필요합니다. mut T value 만으로는 값 매개변수가 함수 안에서 변경 가능해질 뿐 호출자의 값을 변경하지 않습니다. 겹치는 활성 대여는 마지막 사용까지 검사합니다. 서로 겹치지 않는 영역은 안전하게 나눌 수 있으며 대여는 원본보다 오래 살 수 없습니다. 동기화된 내부 변경은 해당 타입의 계약을 따릅니다. Fn(A) -> B 는 호출 가능한 값을 설명하며 반환 참조의 수명 관계는 본문으로 문서화합니다.

6입니다. 스토리지 및 레이아웃

unit 페이로드는 제로 데이터 바이트가 필요합니다. 컨테이너는 여전히 차별자, 길이, 패딩 또는 정렬이 필요할 수 있습니다. N unit 값의 Array에는 요소 데이터 바이트가 할당되지 않은 경우에도 N개의 논리 요소가 있습니다.

고유한 unit 값은 고유한 주소를 가질 필요가 없습니다. 포인터 산술, 고유 주소 가정 또는 직렬화된 패딩은 제로 크기 저장소에서 추론할 수 없습니다. 외국 ABI는 급여없는 결과를 다르게 나타낼 수 있습니다.

7입니다. 오류 및 정리

Unit.value 및 Unit.equal은 실패하지 않습니다. string 할당 또는 호출기 버퍼를 소유해야 하기 때문에 서식 지정이 실패할 수 있습니다. unit의 Result는 성공 페이로드가 0 크기 임에도 불구하고 오류를 유지합니다. Result 표현식을 버리면 다음과 같이 경고합니다. 공유 Result 정책; 그 페이로드는 암시 적으로 포장되지 않습니다.

자원 정리는 자원 계약을 소유하는 데 있습니다. 소유자를 unit로 교체하는 것은 누출에 대한 권한이 아니며 소유자를 이동하거나 파괴하는 것은 추적 상태를 유지합니다. 복구 가능한 닫기 오류는 명시적 닫기 작업에 속합니다.

8입니다. FFI 및 콜백 적응

C void 및 C++ void return는 일반 Aevix 코드에서 사용하는 경우 unit를 오가는 바인딩 어댑터가 필요합니다. 어댑터는 C가 void 유형의 값을 가지고 있다고 주장하지 않습니다. Python 아무도 unit의 바이너리 레이아웃이 아닌 관리 object/sentinel입니다.

unit를 반환하는 콜백은 Aevix 명시적-return 규칙을 따라야 합니다. void 콜백은 자체 return 위치 계약을 사용합니다. 바인딩은 데이터 페이로드가 경계를 넘지 않는 경우에도 외국 호출 규칙을 보존해야 합니다.

9입니다. 병렬 및 장치 동작

unit를 복사하면 데이터 전송 페이로드가 없지만 unit를 반환하는 작업을 실행하면 동기화가 필요하고 오류가 발생할 수 있습니다. unit의 Pending는 빌린 버퍼를 재사용하기 전에 완료해야 하는 미완성 GPU 작업을 나타낼 수 있습니다.

페이로드의 부족은 작업이 무료, 완전 또는 재주문이 안전하다는 증거가 아닙니다. 효과, 리소스 대여 및 작업 수명은 운영 계약의 일부로 유지됩니다.

10입니다. 예제 및 경계 

unit marker = Unit.value();
bool same = Unit.equal(marker, Unit.value());
Result<string, AllocError> text = Unit.format(marker);
Optional<unit> absent = Optional.none<unit>();

일부(unit)와 None은 다른 값으로 남아 있습니다. Result를 무시하면 오류를 unit로 변환하거나 전파하지 않습니다. 독립형 폐기된 Result 표현식은 경고; 명시적 처리 및 전파는 일반 Result 계약을 유지합니다.
