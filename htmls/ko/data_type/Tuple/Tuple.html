1입니다. 개요

0.2 구현 범위. Tuple<...> 그것은 prelude에 있습니다. 상기 호출들은 The calls are Tuple.make, len, is_empty, get<I>, get_mut<I> 및 copy. Access는 명시적 튜플 대여과 컴파일 시간 유효한 인덱스를 사용합니다. 복사하려면 모든 필드가 Copy여야 합니다. 아래의 복제, 역방향,지도, 적용 및 Array 변환 기능은 제안으로 남아 있습니다. 자세히 보기 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

카탈로그 상태. 지원 범위 알림은 구현된 부분집합을 밝히며 다른 API는 제안된 Aevix 계약입니다. 선택된 매개변수 형식: T value, &T value, 및 &mut T value. 타입 팩·호출 가능 타입·반환 참조의 명시적 수명 표기·오류 enum은 표시된 곳에서 설명용으로 남습니다. 모든 연산은 네임스페이스 함수를 사용하며 값 메서드 별칭은 없습니다.

튜플은 알려진 수의 다른 유형을 그룹화합니다. Tuple<i32, bool> 하나의 i32와 하나의 bool를 포함하며, 유형 또는 필드 수를 변경하면 다른 튜플 유형이 생성됩니다. 명명된 도메인 레코드는 필드 이름이 의미를 전달할 때 Struct에 속합니다.

2입니다. 선언 및 건설

Type-first 선언은 전체 제품 유형을 표시합니다. Tuple.make 비 Copy 입력을 이동합니다. 필드가 할당을 소유할 수는 있지만 제품 자체에 대한 숨겨진 힙 할당은 없습니다. 

Tuple<i32, bool> status = Tuple.make(7, true);
usize fields = Tuple.len(&status);
bool empty = Tuple.is_empty(&status);

3입니다. 정적 액세스 및 이종 유형

필드 인덱스는 컴파일 타임 인수입니다. 런타임 정수는 임의의 이종 필드와 return를 단일 제한되지 않은 유형으로 선택할 수 없습니다. 동적 대안에는 명시적 열거형, 동질적인 Array 또는 애플리케이션 정의 방문자가 필요합니다.

Field, Prefix, Suffix, Reverse, Repeat, 및 count 이 카탈로그에는 추가적인 기본 형식 또는 최종화된 구문이 아닌 설명적인 형식-팩 표기법이 있습니다.

4입니다. 소유권, 대여 및 변경

이 초안은 튜플 소유자가 기본적으로 이동하도록 합니다. Tuple.copy 각 분야에 Copy 요구 Tuple.clone Clone이 필요합니다. 클론은 각 필드 계약을 따른다; Shared를 복제하는 것은 참조된 객체를 재귀적으로 복제하지 않는다.

필드 대여은 포함 된 튜플보다 오래 살 수 없습니다. 전용 필드는 해당 필드를 별칭하는 액세스와 충돌합니다. 펀딩금액이 중복될 수 있습니다. 전체 튜플의 이동은 모든 필드 대여이 살아있는 동안 금지되어 있습니다.

5입니다. 형식 변경 변환

Concatenation, reversal, push, pop 및 split은 새로운 정적 제품 유형을 구성합니다. 동적 용량 컨테이너 작업이 아니며 튜플의 크기를 조정하지 않습니다. 컴파일러 전문화는 인라인 필드 이동을 할 수 있습니다; 의미론적 작업은 여전히 필드 내용으로 확장됩니다.

매핑은 적절하게 타이핑된 콜백의 튜플을 사용한다. 단일 콜백이 모든 관련 없는 필드 유형을 수락한다고 가정할 수는 없습니다. Tuple.try_map 하나의 공유 오류 유형을 사용하므로 출력 유형은 정적으로 알려져 있습니다.

6입니다. 함수 참조

T value 는 값을 전달합니다. Copy 타입은 복사하며 소유 non-Copy 값은 깊은 clone 없이 이동합니다. &T value 는 공유 읽기 대여이고 &mut T value 는 배타적 변경 대여입니다. 호출 시 각각 x, &x, 또는 &mut x 를 사용합니다. 이미 대여한 참조·뷰 값은 직접 전달하며 &를 하나 더 붙이면 타입이 바뀝니다. *ref 는 참조 대상을 읽고 씁니다. 일반적인 &mut x 에는 mut 소유자가 필요합니다. mut T value 만으로는 값 매개변수가 함수 안에서 변경 가능해질 뿐 호출자의 값을 변경하지 않습니다. 겹치는 활성 대여는 마지막 사용까지 검사합니다. 서로 겹치지 않는 영역은 안전하게 나눌 수 있으며 대여는 원본보다 오래 살 수 없습니다. 동기화된 내부 변경은 해당 타입의 계약을 따릅니다. Fn(A) -> B 는 호출 가능한 값을 설명하며 반환 참조의 수명 관계는 본문으로 문서화합니다.

7입니다. 부분 건설 및 실패

튜플은 모든 필드가 초기화된 후에만 관찰할 수 있습니다. 클론 또는 오류 가능성이 있는 매핑에 실패하면, 완성된 출력은 한 번 파괴되고, 나머지 소유된 입력은 한 번 파괴되며, 초기화되지 않은 필드 이스케이프에 대한 참조는 없습니다. 빌린 출처는 여전히 유효합니다.

CloneError는 설명 오류 복제 오류 계약이며 할당 실패 정보를 보존해야 합니다. 파괴자는 청소 중에 모델링되지 않은 복구 가능한 실패를 소개해서는 안됩니다. 명시적 리소스 닫기 작업은 Result 값과 같은 오류를 전달합니다.

8입니다. 레이아웃, 비용 및 제로 크기 필드

컴파일러는 정렬 패딩을 삽입할 수 있다. 필드 오프셋, 메모리 내 정렬, 호출 규칙 및 테일 패딩은 타겟 레이아웃 사양을 필요로 합니다. 기본 제품 레이아웃은 휴대용 C 구조체 ABI가 아닙니다. 안전 코드는 패딩을 초기화된 바이트로 검사할 수 없습니다.

Arity는 대상 usize로 표시할 수 있어야 하며 전체 레이아웃은 대상 크기 및 정렬 제한을 충족해야 합니다. 유효하지 않은 정적 레이아웃이 컴파일 시간에 거부됩니다. 힙 객체로 자동 전환되지 않습니다. Type-pack 쿼리는 컴파일러 지원을 필요로 한다; 네임스페이스 표기만으로는 모든 도우미를 기본 명령어로 만들 수 없다.

0 크기의 필드는 여전히 유형, 수명 및 소멸자 의미론을 가지고 있습니다. 0 크기의 리소스를 포함하는 튜플은 0이 아닌 정리 작업을 수행할 수 있습니다. 튜플은 단순히 count 필드가 작기 때문에 복사하는 것이 항상 싼 것은 아닙니다.

9입니다. 장치 및 외부 인터페이스

튜플은 선택한 대상에서 모든 필드와 필요한 작업을 지원하는 경우에만 장치 호환이 가능합니다. 호스트 string 또는 잠금을 포함하는 튜플을 GPU 커널로 자동으로 낮출 수 없습니다. 명시적인 전송은 지원되는 콘텐츠에서 작동하고 수명을 보존합니다.

C++ std::tuple 및 Python 튜플은 Aevix 튜플 ABI를 공유하지 않습니다. 바인딩은 필드에 따라 필드를 조정하거나 명시적으로 지정된 레코드 레이아웃을 사용합니다. Python 튜플 요소는 해당 경계에 있는 관리 Python 개체로 유지됩니다.
