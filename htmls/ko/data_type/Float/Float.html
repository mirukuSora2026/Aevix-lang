1. 기본 정보

0.3 컴파일러는 f16/bf16과 u16, f32와 u32, f64와 u64 사이의 정확한 Float.from_bits<T>·Float.to_bits 내장 기능을 제공합니다. 산술·할당·수치 변환 없이 부호 있는 0과 NaN 데이터 비트를 포함한 모든 표현 비트를 유지합니다. 모든 너비나 Float 카탈로그 전체의 구현을 뜻하지 않습니다. 명시적 LE/BE 저장 코덱은 import하는 bytes 모듈에 속합니다.

0.2 구현 범위. 자동으로 사용할 수 있는 형식은 f16, bf16, f32 및 f64; float 는 다음 타입의 별칭입니다: f64. 수치 접미사, 스칼라 산술과 비교가 구현되어 있습니다. 구현된 네임스페이스 호출은 Float.convert<D>(value), Float.convert_exact<D>(value) 및 Float.to_integer_exact<I>(value)입니다. 앞의 두 함수는 정수 또는 부동소수점을 입력받고 부동소수점 목적지를 요구합니다. 마지막 함수는 부동소수점을 입력받고 정수 목적지를 요구합니다. 반환 타입은 Result 이며 오류 타입은 FloatError 입니다. 반올림 모드 인수는 받지 않습니다. 분류·비트/바이트 인코딩과 아래 수학 함수 카탈로그는 0.2에 구현된 API가 아닙니다. 자세한 내용: 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

Aevix는 다음 형식의 이진 부동소수점 값을 제공합니다: f16, bf16, f32, 및 f64. 편의 별칭 float 는 정확히 f64입니다. 스칼라는 힙 할당 없이 값을 복사합니다. 소유 배열과 텐서에는 각각의 소유권 계약이 적용됩니다.

설계 초안. 이 참조 문서는 제안된 계약과 포괄적인 함수 카탈로그를 기록합니다. 컴파일러 구현, 최종 문법이나 검증된 하드웨어 지원을 주장하지 않습니다. 모든 함수는 Float. 네임스페이스를 사용하며 인스턴스 메서드는 제외합니다.

2입니다. 수치 모델 및 리터럴

제안된 기본 규칙: 일반 핵심 산술은 가장 가까운 값으로 반올림하고, 정확히 중간이면 짝수를 선택해 목적지 형식에 맞춥니다. 부호 있는 0과 점진적 언더플로를 유지합니다. AOT와 JIT는 이 계약을 보존해야 합니다. 결합 순서 변경, 역수 대체, 융합 연산과 비정규수의 0 처리는 명시적으로 선택한 별도 수치 프로파일이 필요합니다. 더 넓은 내부 명령어는 관측 가능한 결과가 명세된 연산과 일치할 때만 허용합니다.

IEEE 형식은 유한 값, +0, -0, 무한대와 NaN을 인코딩합니다. 오버플로 결과는 무한대가 될 수 있고 아주 작은 결과는 비정규수나 0이 될 수 있습니다. 이는 수치 결과이며 메모리 안전성 실패가 아닙니다. 지원하는 IEEE 형식에서 Float.sqrt(-1.0) 의 결과는 NaN이지만 Float.checked_sqrt(-1.0) 는 아래 제안에 따라 복구 가능한 오류를 반환합니다. 유한 값 전용 형식에는 별도의 범위 초과 계약이 필요합니다.

NaN은 자기 자신을 포함한 모든 값과 같지 않으며, 일반 순서는 부분 순서입니다. 산술은 NaN payload를 보존할 필요가 없습니다. 명시적인 비트·바이트 연산은 표현을 보존합니다. 엄격한 핵심 산술만으로 장치 간 초월함수 라이브러리 결과가 같아지는 것은 아닙니다. 각 수학 프로파일은 정확도·재현성 보장을 공개해야 합니다. 관련 구분: LLVM 부동소수점 모델 및 Rust f32 보장. 

float ordinary = 3.25;       // float aliases f64
f32 small = 3.25;     // contextual literal rounding
f64 value = 0.1;      // nearest representable approximation
Float.is_nan(Float.sqrt(-1.0)); // true under the draft IEEE contract

십진 리터럴은 수학적 값을 나타내며 문맥이 정한 타입으로 직접 반올림합니다. 타입이 정해진 값에는 암시적 수치 캐스트를 적용하지 않습니다. 명시적 NaN·무한대 생성자를 사용해 오버플로한 유한 리터럴을 조용히 허용하지 않습니다. 십육진 부동소수점 리터럴은 아직 문법 제안입니다.

3입니다. 함수 표기 및 오류 계약

API 이름과 형식 매개변수는 아직 설명용 표기입니다. T value, &T value, &mut T value는 선택된 매개변수 형식입니다. T 는 지원하는 부동소수점 형식을 나타냅니다. 다음 표시가 있는 인수는 x, y, 또는 a 별도 설명이 없으면 같은 T 타입입니다. D 는 목적지 부동소수점 타입, I 는 정수 타입, U 는 같은 폭의 부호 없는 비트 타입, B 는 저장 바이트 수입니다. 구현된 수치 변환은 다음과 같은 제네릭 타입 인수를 사용합니다: Float.convert<f32>(value). 다음과 같은 미구현 카탈로그 표기는 Float.epsilon(f32) 아직 설명용입니다.

FloatClass, RoundingMode, Ordering, FloatError, ParseError, FormatError, ByteError, FloatParts와 기능 설명자는 보조 타입입니다. 구현된 FloatError variant는 OutOfRange, NonFinite 및 NonExact이며 나머지 보조 타입은 아직 제안입니다. 승인된 스칼라 목록에 추가되는 타입이 아닙니다. 반올림 모드는 TiesEven, TiesAway, TowardZero, TowardPositive, 및 TowardNegative.

checked 산술 제안은 비유한 피연산자, 잘못된 정의역, 0인 제수와 유한 결과의 오버플로를 거절합니다. 반올림된 유한 값, 비정규수와 점진적 언더플로는 성공 결과로 유지합니다. 정확한 산술이나 모든 언더플로의 검출을 보장하지는 않습니다. 검사는 일반적인 Result 값이며 호스트의 다음 상태를 조용히 물려받아서는 안 됩니다: errno, 예외, 전역 반올림 상태. 형식이나 선택된 백엔드가 지원하지 않는 함수에는 컴파일 타임 기능 진단을 냅니다.

제안됨 FloatError.OutOfRange 유한 인코딩이 없는 요청된 인접 값을 보고합니다. 제안됨 FormatError variant 포함하다 InvalidSpecification, BufferTooSmall, 및 AllocationFailed. string 생성 서식 지정 기능 return 할당 실패를 통해 Result; caller-buffer 포맷팅은 용량을 개별적으로 검증하고 힙 할당을 수행하지 않습니다.

7입니다. 산술 & 크기

일반 산술은 숫자 기준선을 사용합니다. fma 하나의 최종 라운딩을 요청한다; 그것은 분리된 곱셈과 덧셈으로부터 의도적으로 구별된다. 체크되지 않은 IEEE 디비전은 부호 있는 무한대 또는 NaN을 생성할 수 있습니다. 무한대 또는 NaN을 요구하는 함수는 명시적 대체 정책이 선택될 때까지 이러한 결과가 없는 형식에서 사용할 수 없습니다.

17입니다. 명시적 수치 변환

구현됨으로 명시한 세 행은 제네릭 목적지 인수를 사용합니다. 제안된 from_integer/from_integer_exact 이름은 0.2 별칭이 아닙니다. 대신 다음을 사용하세요: Float.convert<D>/Float.convert_exact<D>. 다른 반올림 모드와 포화 변환은 아직 제안입니다. exact 변환을 요청하지 않았다면 비정규수나 0으로 반올림되는 유한 변환도 성공합니다.

숫자 변환과 비트 재해석은 서로 다릅니다. exact 부동소수점 간 변환은 수학적 값과 부호 있는 0을 보존합니다. NaN payload 변환에는 별도의 인코딩 정책이 필요합니다. 정수에는 별도의 음의 0 표현이 없으므로 어느 부호의 0이든 정수 0으로 변환합니다. 반올림 변환은 반올림 모드를 드러냅니다. 정수 변환은 반올림한 정수를 정확한 정수 범위와 비교해야 하며, 다음 값을 반올림한 부동소수점 표현과 비교하는 것만으로는 I.MAX 충분하지 않습니다.

18입니다. Byte 표현 및 버퍼 액세스

원시 직렬화 사용 byte상기 불투명한 옥 타입은 The opaque octet type Byte숫자형 정수 대신, u8. 그들 사이에 암묵적인 변환은 없습니다: use Byte.from_u8 또는 Byte.to_u8 각 옥에 대해 숫자 값이 필요할 때 명시 적으로. 숫자형 비트 워드 API는 문서화되지 않은 정수형을 유지합니다.

고정폭 인코딩 return 스택 친화적 Array 값; 그들은 할당하지 않는다 Vector. Byte 순서은 명시적입니다. 기본 순서는 로컬 interop에 유용하며, 휴대용 저장소는 거의 또는 큰 엔디안을 사용하지 않습니다. NaN 비트를 읽는 것은 후속 산술이 신호 상태를 보존한다는 것을 약속해서는 안됩니다.

19입니다. 파싱 및 포맷

21입니다. CPU, GPU, AOT 및 JIT 지원

백엔드 기능은 저장, 핵심 산술, 변환, 비정규수, 수학 함수와 원자 연산을 각각 다룹니다. 어떤 형식은 저장할 수 있어도 네이티브 산술은 지원하지 않을 수 있습니다. 미지원 연산에는 명시적으로 선택한 대체 동작이나 컴파일 진단이 필요합니다. 정밀도를 조용히 낮추거나 비정규수를 0으로 처리하거나 CPU/GPU 사이에서 텐서를 옮겨서는 안 됩니다.

저정밀도 텐서 저장이 저정밀도 누적을 뜻하지는 않습니다. 누적 타입은 명시적으로 선택합니다. JIT 특수화도 AOT와 같은 수치 프로파일을 유지합니다. 병렬 축약은 문서화된 순서 또는 명시적인 비결정적 프로파일을 사용합니다. 선택적 fast-math 프로파일로 처리량을 높일 수는 있지만 NaN·무한대·부호 있는 0·융합·결합 순서에 허용하는 변화를 각각 명시해야 합니다.

전역 부동소수점 환경 변경, 호스트별 예외 플래그, 무제한 정밀도 부동소수점, 십진 연산, 임의 난수 생성, 복소수 연산과 텐서 할당은 이 스칼라 네임스페이스의 범위 밖입니다. 안전한 비트 변환은 포함하지만 검사 없는 부동소수점→정수 변환을 안전한 기본값으로 제안하지는 않습니다. 각각 별도의 설계 결정입니다.

근사 비교는 뺄셈 전에 비유한 값을 처리해야 합니다. 같은 무한대는 근사적으로 같고 NaN은 절대 같지 않으며 서로 다른 무한대는 거짓입니다. 허용 오차는 명시적으로 유지합니다. 해시와 맵 키의 동등성에는 별도로 선택한 표현 정책이 필요하며 일반적인 NaN 민감 수치 동등성만으로는 부족합니다.

외부 참조는 각자의 언어·라이브러리를 설명합니다. 이 독립적인 Aevix 초안의 참고 자료이며 Aevix의 동작·성능을 인증하지 않습니다. 카탈로그는 핵심 함수와 선택적 라이브러리 후보를 함께 다루며 모든 함수가 어디서나 구현되었다고 주장하지 않습니다.
