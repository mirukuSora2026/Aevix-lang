1. 기본 정보

0.2 구현 범위. 자동으로 사용할 수 있는 형식은 f16, bf16, f32 및 f64; float 는 다음 타입의 별칭입니다: f64. 수치 접미사, 스칼라 산술과 비교가 구현되어 있습니다. 구현된 네임스페이스 호출은 Float.convert<D>(value), Float.convert_exact<D>(value) 및 Float.to_integer_exact<I>(value)입니다. 앞의 두 함수는 정수 또는 부동소수점을 입력받고 부동소수점 목적지를 요구합니다. 마지막 함수는 부동소수점을 입력받고 정수 목적지를 요구합니다. 반환 타입은 Result 이며 오류 타입은 FloatError 입니다. 반올림 모드 인수는 받지 않습니다. 분류·비트/바이트 인코딩과 아래 수학 함수 카탈로그는 0.2에 구현된 API가 아닙니다. 자세한 내용: 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

bf16 8 비트가 일반 significand 정밀도인 16-bit 바이너리 부동소수점 값입니다. 이 형식은 형식화된 컨텍스트에서 명시적으로 선택되거나 유추됩니다.The default type is selected explicitly or inferred from a typed context. float 별칭이 남음 f64.

2입니다. 비트 표현

높은 비트는 기호를 저장하고 8 지수 비트와 7 분수 비트를 저장합니다. 정규값은 (−1)서명 (1 + fraction / 2)를 참조하십시오.7) × 2지수 127. Zero/subnormal 인코딩은 0개의 지수를 사용합니다. 올원 지수는 무한대 또는 NaN을 나타냅니다.

3입니다. 문자 및 형식 추론

문자 그대로의 A bf16 컨텍스트는 해당 대상 형식으로 직접 반올림됩니다. 입력되지 않은 소수 실제 리터럴 기본값: f64. 이전에 입력한 값은 암시적으로 변환되지 않습니다. 상수 구문 분석은 의도하지 않은 중간 라운딩이 다른 형식을 거치지 않도록 해야 합니다. 

bf16 value = 1.5;
// Declaration syntax is illustrative.
Float.to_bits(value);
Float.is_finite(value);

0.1와 같은 소수에는 일반적으로 정확한 유한 이진 표현이 없습니다. 리터럴은 정확하게 반올림된 값이지 정확한 소수 유리수가 아닙니다. 유한 범위를 벗어나는 값은 명시적으로 문서화된 변환 또는 리터럴 진단 정책이 필요합니다.

4입니다. 정밀 & 반올림 경계

일반 값에는 8 유효 이진수가 있습니다. 간격은 크기에 따라 변한다; 엡실론은 1 바로 위의 간격이며 보편적인 비교 공차가 아니다. 

// Round-to-nearest, ties-to-even at a precision boundary.
bf16 a = 256;
a + 1;   // rounds back to 256

Float.next_up(a); // adjacent representable value

크기가 대부분의 256인 모든 정수는 정확합니다. 그 경계를 넘어서, 일부 정수는 정확하게 남아 있고 다른 정수는 그렇지 않습니다. 정수 값을 유지할 때 정확한 변환을 선택합니다. 기본 스칼라 라운딩은 가장 둥글고 짝수이며, 다른 정책에는 명시적인 API 선택이 필요합니다.

5입니다. 제로, 인피니티, NaN 및 서브 노멀

양수와 음수 0은 숫자적으로 동일하지만 부호 비트가 다릅니다. NaN은 자신과의 평등을 포함하여 일반적인 비교에서 순서가 정해지지 않습니다. 무한대는 고유한 숫자 값이며 가장 큰 유한 값이 아닙니다.

비정상 값은 0과 가장 작은 정상 크기 사이의 간격을 채웁니다. 엄격한 실행 프로파일은 이러한 값을 유지합니다. 이를 0으로 만드는 대상은 해당 동작을 별도의 옵트인 기능으로 노출해야 하며 문서 계약을 자동으로 변경해서는 안 됩니다.

애플리케이션 특정 유한값 제약 조건을 적용하기 전에 분류 함수를 사용합니다. 계산된 산술은 0으로 나셈, 유효하지 않은 도메인 또는 비-유한 결과가 될 때 명시적인 대안입니다. Result 오류.

6입니다. 유형 변환

Float.convert_exact 수학적 값이 대상 형식으로 나타낼 수 있는지 여부를 보고합니다. Float.convert 명확한 반올림 정책을 사용하고 정확성을 잃을 수 있습니다. 좁혀지는 것은 조용히 비트 캐스트가되지 않습니다.

Float.to_integer_exact<I>(value) 대상 정수 범위에서 유한 적분 입력이 필요합니다. 분수 값 반환 FloatError.NonExactNaN/infinity return - 비디오 NonFinite범위 실패 반환Range failure returns OutOfRange. 반올림된 정수 변환은 별도의 제안된 API입니다.

기타 float → 이 형식정확함 또는 반올림은 명시 적으로 선택해야합니다.

NaN 페이로드와 부호 있는 0은 형식 간에 변환할 때 별도의 표현 보존 정책이 필요합니다.

7입니다. 산술 및 공통 함수 바인딩

산술 반환 bf16 일반적인 Float 계약에 따라. 더 작은 스토리지 타입은 초월적 동작들이 네이티브 하드웨어 명령어들을 갖는다는 것을 의미하지 않는다. 백엔드 promotion/emulation는 요청된 라운딩 포인트를 보존하고 비용을 노출해야 합니다.

8입니다. 비교 및 인접 값

일반적인 비교는 NaN이 순서가 없는 숫자 순서를 따릅니다. Float.total_compare 부호 있는 0 및 NaN 인코딩을 포함하여 원시 부동 소수점 값을 정렬하기 위한 명시적 토탈 오더 경로를 제공합니다.

대략적인 비교는 absolute/relative 허용오차 또는 명시적인 ULP 정책을 지정해야 합니다. Never는 보편적인 포용력으로 이 체재의 epsilon를 사용합니다. next_up, next_down, 및 next_after 포맷의 표현 가능한 그리드를 탐색하고 Float의 특수 값 규칙을 따르십시오.

9. string 및 Byte 표현

원시 직렬화 사용 byte상기 불투명한 옥 타입은 The opaque octet type Byte숫자형 정수 대신, u8. 그들 사이에 암묵적인 변환은 없습니다: use Byte.from_u8 또는 Byte.to_u8 각 옥에 대해 숫자 값이 필요할 때 명시 적으로. 숫자형 비트 워드 API는 문서화되지 않은 정수형을 유지합니다.

상기 원시 저장소는 The raw storage is 2 바이트. 명백한 리틀 엔디언 및 빅 엔디언 변환이 생성됩니다. Array<byte, 2>byte 순서는 부동 소수점 형식을 변경하지 않습니다. 동적 버퍼 읽기 및 쓰기는 전체 범위를 확인합니다.

가장 짧은 왕복 포맷터는 문서화된 파서 아래에서 동일한 유한 값으로 다시 파싱하는 10진수 텍스트를 방출합니다. NaN 텍스트는 임의의 페이로드를 보존하지 않습니다. 정확한 페이로드 전송은 비트 또는 byte API를 사용합니다. 

bf16 value = 1.5;
Array<byte, 2> bytes = Float.to_be_bytes(value);
bf16 decoded = Float.from_be_bytes(bf16, bytes);
Float.parse(bf16, "1.5");
Float.format_into(value, buffer, options);

기존 버퍼로 포맷하면 새 출력 할당이 방지됩니다. string 생성 포맷터에는 명시적인 할당 실패 경로가 있습니다.

10입니다. 배열, 텐서 및 실행 대상

Array<bf16, N>, Vector<bf16>, 및 Tensor<bf16, Shape, Place> 이 형식의 값을 저장합니다. 값 복사는 스칼라 힙 할당을 필요로 하지 않습니다; 컬렉션은 자신의 move/copy 규칙을 따릅니다.

저장, 산술, 변환, 특수 함수 및 원자 지원은 각 대상에 대해 별도로 checked입니다. 엄격한 AOT 및 JIT 실행은 동일한 형식 의미를 사용합니다. FMA 수축, 빠른 수학 reassociation 및 subnormal 플러싱은 명시적인 정책이 필요합니다.

감소의 누산기 형식 및 평가 순서가 표시되어야 합니다. 더 넓은 축적은 별개의 선택이며 스토리지 형식으로 반복 반올림하여 다른 결과를 얻을 수 있습니다. FFI는 형식 이름만 일치시키는 것이 아니라 외부 형식과 ABI를 확인해야 합니다.
