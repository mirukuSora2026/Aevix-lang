1입니다. ASCII는 char의 서브셋입니다.

ASCII는 U+007F를 통해 U+0000를 다룹니다. ASCII 스칼라가 남아 있습니다 char; 이 페이지는 char8 프리미티브나 허가된 8비트 텍스트 인코딩을 생성하지 않습니다. 128 코드 포인트에는 컨트롤과 DEL이 포함됩니다. 그들의 UTF-8 철자는 하나의 byte이지만, 높은 비트 byte는 ASCII가 아니며 UTF-8 문자를 독립적으로 설정하지 않습니다. 부분 집합은 모든 컨트롤이 메시지에 적합하다는 것을 의미하지는 않습니다.

설계 초안. 이름, 지원 레코드 및 개념 구문은 제안된 Aevix 계약을 설명합니다. 그들은 실행을 주장하거나 성과를 측정하지 않습니다. 선언은 형식을 먼저 놓고 바인딩은 기본적으로 변경할 수 없습니다. MutSlice<T>는 독점적인 쓰기 가능 뷰를 나타냅니다. mut, &T, 및 &mut T 선택한 선언을 따르고 규칙을 대여하십시오. 카탈로그 관련 지원 기록 및 시그니처은 제안으로 남아 있습니다.

2입니다. 고정 분류 규칙

Char.ascii_* 술어는 명시적인 숫자 규칙을 사용하고 never는 프로세스 로케일을 참조합니다. 비 ASCII 입력은 Unicode 분류로 되돌아가기보다는 거짓입니다. 이 초안은 탭, 라인 피드, 양식 피드, 캐리지 return 및 공간의 다섯 가지 공백 문자를 선택합니다. 여기서 Unicode White_Space가 포함되더라도 세로 탭은 거짓입니다. 인쇄 가능은 공간을 포함하지만 그래픽은 제외하며, 어떤 속성도 프로토콜 유효성 검사기나 터미널 안전 보증서가 아닙니다.

시그니처 반환 계약 및 비용
Char.ascii_is_alphabetic(char c) bool A–Z 또는 a–z; 비-ASCII는 할당 없이 false를 반환합니다.
Char.ascii_is_alphanumeric(char c) bool ASCII 문자 또는 십진수; non-ASCII는 할당 없이 false를 반환합니다.
Char.ascii_is_uppercase(char c) bool A–Z; non-ASCII는 할당 없이 false를 반환합니다.
Char.ascii_is_lowercase(char c) bool a–z; non-ASCII는 할당 없이 false를 반환합니다.
Char.ascii_is_digit(char c) bool 0–9; non-ASCII는 할당 없이 false를 반환합니다.
Char.ascii_is_hex_digit(char c) bool 0–9, A–F 또는 a–f; 비-ASCII는 할당 없이 false를 반환합니다.
Char.ascii_is_octal_digit(char c) bool 0–7; non-ASCII는 할당 없이 false를 반환합니다.
Char.ascii_is_binary_digit(char c) bool 0 또는 1; 비-ASCII는 할당 없이 false를 반환합니다.
Char.ascii_is_whitespace(char c) bool HT, LF, FF, CR 또는 SPACE; VT 제외; 비-ASCII는 할당 없이 false를 반환합니다.

Char.ascii_is_graphic(char c) bool U+0021...U+007E; 비-ASCII는 할당 없이 false를 반환합니다.
Char.ascii_is_printable(char c) bool U+0020...U+007E; 비-ASCII는 할당 없이 false를 반환합니다.
Char.ascii_is_punctuation(char c) bool 문자와 숫자를 제외한 그래픽 ASCII; 비-ASCII는 할당 없이 false를 반환합니다.
Char.ascii_is_blank(char c) bool SPACE 또는 Horizontal 탭; ASCII가 아닌 것은 할당 없이 false를 반환합니다.
Char.ascii_is_sign(char c) bool + 또는 -; non-ASCII는 할당 없이 false를 반환합니다.

3입니다. ASCII 케이스 매핑

케이스는 26 기본 라틴 문자만 변경합니다. 그들의 스칼라 결과 never 확장 및 할당이 필요하지 않습니다. 비 ASCII 입력은 변경되지 않으므로 é와 를 비교하면 구별이 무시됩니다. 도우미는 국제 접기, 정규화 또는 로케일 민감 정렬을 수행하지 않습니다. 비교기는 변경되지 않은 비 ASCII 스칼라를 숫자로 순서할 수 있습니다: ASCII 접힘은 두 입력이 모두 ASCII라는 전제 조건이 아닌 변환의 이름을 지정합니다. 전체 텍스트 일치는 string 계약에 속합니다.

시그니처 반환 계약 및 비용
Char.ascii_to_lowercase(char c) char A–Z를 a–z로 변환하며 다른 스칼라는 그대로 유지합니다.
Char.ascii_to_uppercase(char c) char a–z를 A–Z로 변환하며 다른 스칼라는 그대로 유지합니다.
Char.ascii_equal_ignore_case(char left, char right) bool ASCII 접힘 후 비교; never Unicode 접힘 비ASCII 스칼라.
Char.ascii_compare_ignore_case(char left, char right) Ordering ASCII 접기 후 스칼라 값을 비교합니다. 로케일이나 할당이 없습니다.

4입니다. 디지트 파싱 및 Radix

ASCII 십진수는 9를 통해서 0입니다. 기수 도우미는 또한 대문자와 소문자가 동일한 값을 나타내는 기본 라틴어 문자를 인식합니다. 2...36 외부의 기수는 오류이며, 숫자가 아닌 허용 기수는 없음을 생성합니다. 아랍어-인도어 및 fullwidth 십진수는 유효한 Unicode 스칼라 그러나 실패 ASCII 손가락 시험에 남아 있다. 전체 숫자 문자열은 명시적 기호, 구분자, 범위 및 소비 규칙을 필요로 합니다.

시그니처 반환 계약 및 비용
Char.ascii_digit_value(char c, u32 radix) Result<Optional<u32>, CharError> 기수 2...36 필요; ASCII 숫자와 문자 만 수락.

5입니다. 인코딩 및 디코딩 확인

인코딩은 범위 유효성 검사 후에만 스칼라와 불투명한 byte를 연결합니다. 0xff와 같은 유효한 byte는 ASCII 디코딩할 수 없습니다. U+00FF는 숫자 값이 u8에 적합하기 때문에 ASCII가 되지 않습니다. NUL은 자동 종료 마커가 아닌 유효한 ASCII입니다. 전체 입력 구문 분석은 유효한 접두사 뒤에 오는 텍스트를 거부합니다. 스칼라와 byte 결과는 독립적인 값 복사이며, 생성자는 주변 버퍼의 소유권을 설정하지 않습니다.

시그니처 반환 계약 및 비용
Char.ascii_from_u8(u8 value) Result<char, CharError> NUL 및 컨트롤을 포함한 0 ... 127를 수락하십시오. 하이 비트 입력을 거부하십시오.
Char.ascii_encode(char c) Result<byte, CharError> 하나의 ASCII 스칼라를 하나의 byte로 인코딩합니다.
Char.ascii_decode(byte value) Result<char, CharError> 하나의 7비트 byte를 디코딩합니다. 값 128...255를 거부합니다.
Char.ascii_parse(string_view text) Result<char, CharError> 정확히 하나의 ASCII 스칼라를 필요로하고 전체 입력을 소비합니다.
Char.ascii_escape(char c) Result<string, CharError> ASCII 진단 이스케이프를 할당합니다. 비 ASCII 입력을 거부합니다.

6입니다. 다른 Unicode 답변

사용법: Char Unicode 속성 및 전체 매핑 제안. Unicode 문자는 ASCII 외부에 있을 수 있으며, 숫자 속성은 분수를 나타낼 수 있으며, 소수점 자리는 ASCII byte 철자를 가질 필요가 없습니다. ASCII 전용 규칙은 프로토콜 문법에 유용하지만 해당 문법은 구분 기호, 이스케이프, 길이 및 유효성 검사를 정의해야 합니다. 함수가 스칼라를 유효한 식별자로 자동 전환하거나 완전한 요청을 검증하지 않습니다.

7입니다. 소유권 및 비용

분류 및 단일 스케일 ASCII 변환은 힙 스토리지를 할당하지 않습니다. 이 제한된 복잡성은 하나의 기본 명령 또는 암호화 타이밍을 증명하지 않습니다. 진단 string 출력은 명시적인 Result 경로를 통해 할당됩니다. 입력 뷰는 소유자의 수명을 유지하지만 반환된 스칼라 값은 독립적입니다. Vector<char> 같은 representation을 가질 필요는 없다. Vector<byte>. 의도적으로 텍스트와 원시 저장소를 선택; 스칼라 복사는 소유 컨테이너를 복사하지 않습니다.
