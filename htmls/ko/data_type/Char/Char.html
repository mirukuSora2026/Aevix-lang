1입니다. 스칼라 ID

0.2 구현 범위. char 리터럴과 스칼라 비교를 통해 자동으로 사용 가능한 Unicode 스칼라 유형입니다. Char 카탈로그에 나열된 Unicode 속성, 케이스 매핑, 파싱 및 인코딩 도우미는 0.2 API를 구현하지 않습니다. 구현된 텍스트 구성 포함 string.push_charTextError Result를 명시 적으로 사용합니다. 자세히 보기 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

현재 char type은 하나의 Unicode 스칼라 값을 나타냅니다. 스칼라는 서로게이트 범위를 제외한 코드 포인트입니다; UTF-8 byte, UTF-16 unit, 글리프 또는 반드시 사용자가 인식한 문자가 아닙니다. 이 페이지는 소개하지 않습니다. char8, char16, 또는 char32 기본. Scalars는 값 힙 할당 없이 복사합니다. 그들의 물리적 인 ABI는 별도의 목표 계약으로 남아 있습니다.

설계 초안. 이름, 지원 레코드 및 개념 구문은 제안된 Aevix 계약을 설명합니다. 그들은 실행을 주장하거나 성과를 측정하지 않습니다. 선언은 형식을 먼저 놓고 바인딩은 기본적으로 변경할 수 없습니다. MutSlice<T>는 독점적인 쓰기 가능 뷰를 나타냅니다. mut, &T, 및 &mut T 선택한 선언을 따르고 규칙을 대여하십시오. 카탈로그 관련 지원 기록 및 시그니처은 제안으로 남아 있습니다.

Destination-buffer 알려진 인코더 MutSlice<byte> 또는 MutSlice<u16> 매개 변수는 자신의 액세스에 대한 기존 쓰기 가능한 뷰를 reborrow. 그들은 그 서술자를 소비하거나 그것의 배타적 능력을 복사하지 않는다; 그것은 파생된 대여이 끝난 후에 재사용될 수 있다. 설명자는 단순히 기존의 권한을 빌려주기 위해 mut 바인딩일 필요는 없다. 일반 값 이동 및 일반 T 값 매개 변수는 여전히 비 Copy 기능을 전송합니다. 제공된 반환 된 빌린 데이터는 마지막 사용 또는 정리를 통해 소스 대여을 유지합니다. 자세히 보기 Slice 매개 변수 계약.

2입니다. 주변 지역이 아닌 버전 데이터

속성 응답은 컴파일러가 제공하는 Unicode 데이터 아티팩트에 따라 다릅니다. 빌드는 정확한 버전, 데이터 파일 및 지문을 기록합니다. AOT 및 JIT는 동일한 아티팩트를 사용합니다. 이 초안은 단지 참조 웹 사이트가 하나 있기 때문에 릴리스 번호를 선택하지 않습니다. 테이블을 업데이트하는 것은 눈에 보이는 툴체인 변경입니다. 운영 체제 로캘이나 다운로드한 런타임 테이블은 자동으로 분류를 변경할 수 없습니다. ASCII 전용 헬퍼는 전용 페이지에서 고정 된 숫자 규칙을 사용합니다.

3입니다. 건설 및 메타 데이터

설정하기 전에 숫자 입력 확인 char. 부적합한 스칼라를 생성하지 않고 대리자와 범위 밖의 정수가 실패합니다. 할당 상태, 개인 용도, NUL 및 비문자 상태는 스칼라 유효성을 변경하지 않습니다. 애플리케이션은 더 엄격한 교환 정책을 별도로 부과할 수 있으며, 생성자는 데이터를 자동으로 대체하거나 삭제하지 않습니다. CharError is a proposed tagged error record, 및 할당 호출이 할당 실패를 노출 할당.

4입니다. 분류 방식

Predicates는 경계 속성 테이블 검색을 통해 하나의 스칼라를 검사합니다. 할당이 모든 대상에 대해 하나의 기계 명령 또는 동일한 대기 시간을 보장하지는 않습니다. 알파벳, 숫자 및 공백 속성은 ASCII 분류와 다릅니다. 식별자 속성은 유용한 렉서 입력이지만 키워드, 정규화, 스크립트 제한 및 보안 프로파일은 언어 식별자 사양에 속합니다. 성공적인 속성 테스트는 never가 안전한 디스플레이 또는 유효한 완전한 토큰을 증명하는 것입니다.

5입니다. 속성 및 이름 쿼리

속성 결과 레코드는 추가 스칼라 프리미티브가 아닌 드래프트 지원 설명자입니다. 스칼라에 표시 가능한 이름이 없는 경우에도 속성에 기본값이 있을 수 있습니다. 스크립트, 블록, 방향성, 너비 및 분할은 서로 다른 질문에 대답합니다. 벡터와 문자열을 할당하는 것은 명시적인 Result 계약을 가지고 있습니다. 빠른 검사 값은 시퀀스를 검사하는 대신 완전한 정규화 알고리즘에 대한 힌트입니다. 정확한 유리수 특성은 분수를 십진수로 조용히 취급하는 것을 피합니다.

6입니다. 간단한 매핑 및 전체 확장

간단한 매핑 return 하나의 스칼라, 간단한 매핑이 존재하지 않을 때 ID를 적용. 전체 매핑이 확장 될 수 있으므로 return string 할당된 작업을 통해 스칼라에는 이웃한 문맥이 없다: 이 기능은 마지막 시그마 선택, 임의적인 낱말 제목 casing, 또는 locale 과민한 전체 원본 변환을 실행할 수 없다. 기본 non-Turkic 케이스 폴딩은 로케일 독립적이며 정규화되지 않습니다. context-sensitive 및 locale-aware 전체 텍스트 작업 unicode., 포함 unicode.lower 및 unicode.lower_locale.

시그니처 반환 계약 및 비용
Char.simple_lowercase(char c) char 간단한 매핑 또는 ID를 적용; 할당 또는 이웃 컨텍스트 없음.
Char.simple_uppercase(char c) char 간단한 매핑 또는 ID를 적용; never 확장을 잘라.
Char.simple_titlecase(char c) char 간단한 제목 매핑 또는 ID를 적용; 아니 단어 경계 추론.
Char.simple_case_fold(char c) char 기본 non-Turkic 단순 접기 또는 ID를 적용하십시오. 할당 없음.
Char.to_lowercase(char c) Result<string, CharError> 기본 isolated-scalar 소문자 매핑을 할당합니다. 확장될 수 있습니다.
Char.to_uppercase(char c) Result<string, CharError> 전체 대문자 매핑을 할당; 여러 스칼라가 가능합니다.
Char.to_titlecase(char c) Result<string, CharError> isolated-scalar full title mapping (단어 제목이 아닌)을 할당합니다.
Char.case_fold(char c) Result<string, CharError> 풀 디폴트의 non-Turkic 접기를 할당합니다; 정규화는 분리됩니다.

7입니다. 인코딩 및 탈출

UTF 인코더는 유효한 스칼라를 소비하고 코드 단위를 생성하며 never는 또 다른 원시 문자를 생성합니다. 고정 배열은 초기화된 임시 저장소를 포함합니다; 후행 패딩이 추가 텍스트가 아니기 때문에 사용된 길이가 중요합니다. 소스 이스케이프와 진단 출력은 바이너리 전송과 다르며 디버그 표기은 안정적인 외부 프로토콜이 아닙니다. 명시적 디코더 및 대상 버퍼 인코더는 Unicode 스칼라 페이지에 있습니다. 인코더가 string 정규화 또는 로케일을 둘러싼 BOM 정책을 유추하지 않습니다.

시그니처 반환 계약 및 비용

Char.utf16_length(char c) u32 하나 또는 두 개의 UTF-16 코드 단위를 반환합니다.
Char.to_utf8(char c) (Array<byte, 4>, u32) 0- 덧대진 저장소와 사용된 길이를 반환합니다. 접두사만 인코딩된 텍스트입니다.
Char.to_utf16(char c) (Array<u16, 2>, u32) zero-added code-unit 저장소와 사용된 길이를 반환합니다.
Char.to_string(char c) Result<string, CharError> 정확히 이 스칼라를 포함하는 유효한 UTF-8 텍스트를 할당합니다.
Char.escape_unicode(char c) Result<string, CharError> 명시적인 16진수 값을 포함하는 스칼라 이스케이프를 할당합니다.
Char.escape_default(char c) Result<string, CharError> 번역된 소스-문자적 탈출을 할당합니다.
Char.escape_debug(char c) Result<string, CharError> 휴대용 직렬화 형식이 아닌 진단 표기을 할당합니다.

8입니다. 스칼라, Graphemes 및 소유권

e 다음에 결합 된 급성 악센트는 두 개의 스칼라를 포함하고 하나의 자소 클러스터 클러스터를 형성 할 수 있습니다. 이모티콘 시퀀스에는 여러 스칼라가 포함될 수 있습니다. 따라서 하나의 스칼라를 계산, 인덱싱 또는 삭제하는 것이 반드시 표시된 문자를 편집하는 것은 아닙니다. 대여 string_view 및 Slice<char> 그들의 소유자의 수명을 유지. Array<T, N> 및 Vector<T> 그들의 정상적인 사본을 따르거나 계약을 이동하십시오; 스칼라 베끼는 주위 소유 저장을 중복하지 않습니다.

9입니다. 예제 및 관련 참조 

char letter = 'A';
u32 value = Char.to_u32(letter);
Char.is_valid_scalar(0xd800); // false
Char.to_uppercase('ß'); // Result containing SS
Char.utf8_length('한'); // 3
Char.to_string(letter); // explicitly allocating Result

참고: Unicode 스칼라 엄격한 해독을 위해, 아스키 보조배터리 사용시, 그리고 string Sequence 연산을 위한 Array 및 Integer 저장 및 숫자 변환을 설명합니다. 외부 소스는 독립적인 설계 선택을 알립니다; 구현된 Aevix 런타임을 설정하지 않습니다.
