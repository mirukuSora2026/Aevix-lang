1입니다. 동적 길이 및 별도의 소유권

0.2 구현 범위. Vector<T> 및 T values[] import 할 필요가 없습니다. 컨텍스트 동적 리터럴을 통해 다음과 같이 소유자를 구성합니다. Result<Vector<i32>, CollectionError> values = [1, 2];. 상기 호출들은 The calls are Vector.len(&owner), Vector.capacity(&owner), Vector.reserve(&mut owner, additional) 및 Vector.push(&mut owner, value). 지금 예약 Result<unit, CollectionError>푸시 리턴 Push Returns Result<unit, InputError<T>>실패에 대한 거부된 입력을 보존합니다. Vector.newcopy/clone 및 기타 카탈로그 constructors/algorithms는 0.2 API가 아닙니다. 자세히 보기 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

0.3 개발 중 insert 계약. Vector.insert(&mut owner, index, value) 는 다음을 받는다: index <= length. 잘못된 인덱스는 다음 오류를 반환합니다: InputError<T>.OutOfBounds { public T input; } 를 할당이나 원소 이동 전에 반환합니다. 입력 소유자와 기존 벡터는 보존됩니다. 크기 확장 실패는 사용하지 않은 입력과 함께 AllocationFailure 또는 SizeOverflow를 반환합니다. 위의 공개된 0.2 부분집합은 그대로이며, 이 소스 확장이 나머지 카탈로그 API까지 구현한다는 뜻은 아닙니다.

언어 설계 초안. Vector는 런타임 길이의 growable 소유자입니다. 그것은 고정된 것과 다르다. Array<T, N>이 카탈로그에서는 API가 아닌 제안된 계약을 설명합니다.

Vector<T> 별도의 인접 버퍼에 초기화된 접두사를 소유합니다. 길이는 런타임에 변경 될 수 있습니다. 용량은 사용 가능한 요소 슬롯을 계산합니다. 두 번째 길이가 아니며 여분의 슬롯에 유효한 T 값이 포함되어 있음을 의미하지는 않습니다.

할당 및 함수 전송은 Copy 요소에서도 기본적으로 소유자를 이동합니다. 별도의 버퍼는 명시적인 copy/clone API에 의해서만 복제됩니다. 암시적 Copy-on-Write 공유 또는 숨겨진 요소별 참조 카운팅은 이 제안의 일부가 아닙니다.

2입니다. 길이, 수용량 & 검사된 성장

invariant는 0 <= length <= capacity <= the 대상의 지원되는 요소 바인딩입니다. Push는 하나의 초기화된 요소를 추가합니다. 어떤 요소도 생성하지 않고 변경 용량을 예약합니다. 변경 길이의 크기를 조정하고 추가 또는 삭제를 초기화해야 합니다.

모든 길이 합계, byte 크기 제품 및 할당 레이아웃은 사용 전에 checked입니다. 제안된 논리 바운드는 isize.MAX입니다. 0이 아닌 요소 바이트도 대상 개체 바운드에 맞아야 합니다. 할당자 실패는 수학적 크기 오버플로우와는 별개입니다.

성장은 요청된 것보다 더 많이 예약할 수 있습니다. reserve_exact는 의도적인 초과를 피하지만 할당자 반올림을 제어하지 않습니다. 자동 축소는 제외됩니다. 명확하고 잘린 용량 유지. 명시적 축소 요청은 실패하거나 요청된 최소 용량보다 더 많은 용량을 남길 수 있습니다.

3입니다. 이동, 복제 및 소모 오류

Vector를 이동하는 것은 별도의 버퍼 소유권 핸들을 전송하며, 요소를 가로채거나 복제하지 않습니다. 이것은 제안된 모델의 O(1) 메타데이터이며, 필드 오더나 외국 ABI 레이아웃에 대한 공개 약속이 아닙니다. 라이브 대여은 여전히 소유자의 움직임을 제한합니다.

Clone은 T: Clone이 필요하며 별도의 Vector 버퍼를 생성합니다. 엘리먼트 클론은 자원을 재귀적으로 분리하기보다는 공유 핸들을 복사할 수 있다. Copy에는 T: Copy가 필요하지만 여전히 새로운 동적 버퍼를 할당합니다.

오류가 있는 작업이 입력을 소비하면 오류 계약이 소유권을 설명합니다. InputError<T> 사용하지 않는 요소를 포함하고 있습니다. OwnerError<C> 완전히 실패한 변환 소스를 전달합니다. 소모하는 try_map은 이전 요소가 소비된 후 return 콜백 오류를 일으킬 수 있으며, 원래 입력을 재구성하는 대신 이들을 청소합니다.

4입니다. 대여 및 재분배

읽기 요소 참조, 슬라이스 및 반복자는 벡터 소유자 및 현재 버퍼에 따라 다릅니다. 재할당은 물리적 주소를 무효화할 수 있다; 삽입 및 제거는 또한 재할당 없이 인덱스가 나타내는 요소를 변경할 수 있다.

안전한 구조적 또는 용량 변화 변경는 소유자에 대한 독점적 인 액세스가 필요하며 충돌하는 대여이 살아있는 동안 금지되어 있습니다. 충분한 용량을 보유한다고 해서 라이브 공유 대여을 통해 변경할 수 있는 권한이 부여되지는 않습니다. iter_mut 및 split 뷰는 무제한 별칭 대신 연결 해제 권한을 부여합니다.

매개 변수 사용 T value 가치에 의하여, &T value 공유 대여, 그리고 &mut T value 단독 대여. 패스 소유자를 호출합니다 x, &x, 또는 &mut x; 복용 &mut owner 에는 mut 바인딩. 기존 참조 및 빌린된 보기는 직접 전달 됩니다. 콜백 별칭, 오류 레코드 및 반환 참조 수명 표기는 설계 설명으로 남아 있습니다. MutSlice<T> 이는 독점적인 쓰기 가능한 연속 뷰이며 추가 주소 연산자 없이 직접 전달됩니다.

5입니다. 실패 보증 및 부분 작업

기존 요소를 이동하기 전에 예약 및 기본 삽입 사전 비행 크기와 할당. 그들의 반환된 실패는 벡터를 보존한다; 거절된 이동된 입력은 그들의 오류로 반환된다. 새 출력 생성자는 구성에 실패할 경우 초기화된 접두사만 삭제합니다.

대량 복제 및 오류 발생 가능한 콜백은 문서화 된 기본 보증을받습니다. 완성 된 추가 값 또는 처리 된 제거가 남아있을 수 있습니다. 모든 소유된 요소는 초기화되고 정확히 한 번 삭제됩니다; 담요 롤백 약속이 적용되지 않습니다.

정렬은 일관된 총 비교기를 필요로 합니다; 플로팅 값은 명시적인 NaN 순서를 필요로 합니다. 안정적인 정렬은 스크래치를 할당 할 수 있습니다; 불안정한 정렬은 힙 스크래치를 피합니다. 중단된 비교는 원래 순서가 아닌 초기화된 요소의 순열을 남길 수 있습니다. Unwind 구문은 아직 결정되지 않았으며 프로세스 종료는 최종화를 약속할 수 없습니다.

6입니다. 빈, 제로 크기 및 리소스 요소

빈 벡터는 할당된 용량을 보유할 수 있다. 제로 사이즈 T는 페이로드 할당 없이 양의 논리 길이를 가질 수 있습니다; 용량은 논리적이며 Rust의 usize.MAX 컨벤션을 사용할 필요가 없습니다. 대상 count 제한은 여전히 적용됩니다.

페이로드 제로 크기는 구성, 반복, 콜백, ID 또는 드롭 효과를 지우지 않습니다. 자원과 같은 0 크기의 값을 갖는 벡터를 지우는 것은 여전히 O(length) 요소 완결을 요구할 수 있다. 복잡성 행 count 요소 작동, Clone, Drop, 큰 인라인 이동 및 비교기 비용이 추가되었습니다.

Safe APIs never는 초기화되지 않은 용량을 T 값으로 표시하거나 임의의 set_len/raw-pointer 채택을 허용합니다. 이들은 할당자, 정렬, 초기화 된 길이 및 파괴 계약으로 별도로 지정된 안전하지 않은 시설 또는 FFI 시설이 필요합니다.

7입니다. 전체 제안 Vector API

캐논 Vector 카탈로그입니다. 시그니처, 소유권 보장, 반환 오류, 비용은 이 문서에서 관리합니다. Array- 패밀리 Vector 가이드 중복 계약을 유지하는 대신 이러한 행에 대한 링크.

Transform<T, U>, TryTransform<T, U, E>, 및 RefTransform<T, U> 콜백 계약(Callback Contracts)이 아닌 Map<K, V> 모음집 종류. 그들의 마지막 콜러블 타입 표기은 라이브러리 디자인 디테일로 남아 있습니다.

모든 호출 가능한 이름은 개별적으로 나열됩니다. By-value 소유 매개 변수는 입력을 이동시킵니다. 공유 및 독점 참조 매개 변수는 &T 및 &mut T를 사용합니다. CollectionError, BoundsError, BuildError<E>, InputError<T>그리고 transformation-error carrier는 구현이 아닌 error-value 타입을 제안한다.

고정 배열 const 매개 변수가 표시되지 않는 한 길이, 오프셋 및 개수는 usize입니다. SearchResult 및 반복자 콜백 이름은 정확한 문법이 열려있는 라이브러리 프로토콜을 설명합니다.

8입니다. 첫 번째 예

각 소유자는 기본적으로 변경할 수 없습니다. 메타데이터 및 명시적인 복사 작업은 통화 사이트에서 소유자를 대여합니다. 실패 가능한 할당은 Result에서 볼 수 있습니다.

이 예제에서는 구현된 0.2 하위 집합만 사용합니다. 의도적으로 푸시 실패를 둘러싸는 CollectionError 유형으로 매핑합니다. postfix ?가 InputError를 자동으로 변환하지 않습니다.

Result<i32, CollectionError> example() {
    mut i32 items[] = [1, 2]?;
    Vector.reserve(&mut items, 8)?;
    Result<unit, InputError<i32>> pushed = Vector.push(&mut items, 3);
    if (Result.is_err(&pushed)) return Result.err(CollectionError.AllocationFailure);
    return Result.ok(Vector.len(&items) == 3 ? 0 : 1);
}

예비, 푸시 또는 제거를 위해 &mut 소유자를 복용 하기 전에 mut 바인딩을 사용 합니다. 이러한 대여은 마지막 사용까지 중복 된 액세스를 제외합니다; 추가 용량은이 규칙을 면제하지 않습니다. 선택받은 자 ? 연산자는 Result 반환 함수에서 호환되는 오류를 전파합니다. 오류 처리 규칙.

9입니다. 알고리즘 비용 & 관찰

엔드 삽입은 일반적인 기하학적 성장에 걸쳐 상각된 O(1) 요소 작업으로, 특정 성장 작업에서 O(length) 재배치됩니다. 그것은 지속적인 지연을 보장하지 않습니다. 앞면 또는 가운데 insertion/removal는 접미사를 이동한다; swap_remove는 그 이동을 피하기 위해 순서를 변경한다.

예약 전략, 정렬 구현, 반복자 융합 및 JIT 전문화는 콜백 순서, 반환된 오류 및 소유권을 보존해야 합니다. CPU/GPU 처리량 요구 전에 벤치마크가 필요합니다. 고정 배열 변환은 모든 인라인 요소를 이동할 수 있습니다; 그것은 무료 메타데이터 캐스트가 아닙니다.

10입니다. 병렬 처리, 텍스트 및 상호 운용성

이 조인트 쓰기 뷰는 호환 가능한 요소 특성과 안전한 캡처된 상태로만 병렬 작업을 지원할 수 있습니다. Shared 소유자, 내부 가변성 및 외국 별칭은 자체 동기화가 필요하며 Vector 유형만으로는 T 레이스가 필요하지 않습니다.

CPU/GPU 전송은 명시적이며 Vector 이동 또는 복제와는 별개입니다. 커널과 비동기 작업은 버퍼를 살아있게 유지하고, 레이아웃과 모양을 검증하고, 장치 기능을 존중해야 합니다. 여기서는 GPU 할당이나 커널 지원이 약속되지 않습니다.
