1입니다. 개요

0.2 구현 범위. never 내장되지 않은 형식입니다.A built-in unhabited type. Never.unreachable() return 유형 never를 가진 실행한 안전한 함정입니다; 그것은 가치를 제조하지 않거나 정상적인 청소를 실행하지 않습니다. Never.absurd 그리고 이 카탈로그에 있는 Result 적출 헬퍼는 계획안 남아 있습니다. 자세히 보기 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

카탈로그 상태. 지원 범위 알림은 구현된 부분집합을 밝히며 다른 API는 제안된 Aevix 계약입니다. 선택된 매개변수 형식: T value, &T value, 및 &mut T value. 타입 팩·호출 가능 타입·반환 참조의 명시적 수명 표기·오류 enum은 표시된 곳에서 설명용으로 남습니다. 모든 연산은 네임스페이스 함수를 사용하며 값 메서드 별칭은 없습니다.

never 유효한 값이 없습니다. 그것은 불가능한 변형 또는 never가 정상적으로 반환하는 계산을 표현합니다. 하나의 값을 갖는 unit와 일반 완성을 허용하는 return 위치 void와는 다릅니다.

2입니다. 구성 또는 기본값 없음

없습니다. Never.new, 0 초기화, 기본값, 구문 분석 함수, 또는 유효한 비트 패턴 생성자. never를 반환하는 것으로 광고된 함수는 정상적인 실행에서 컨트롤을 분리하거나 전송해야 합니다.

안전하지 않거나 never를 생산한다고 거짓으로 주장하는 외국 코드는 계약을 위반합니다. 컴파일러는 진짜 불가능성에 근거를 둔 부호를 제거할지도 모른다, 그래서 그런 틀린 선언은 정확함 경계이다.

3입니다. 흐름 및 명시적 반환 제어

비-void 함수의 경우, 모든 일반적으로 종료되는 경로는 명시적으로 값을 반환합니다. 분산이 입증된 경로는 불가능한 return 문을 필요로 하지 않습니다. 이 예외는 i32, unit 또는 다른 일반 값 유형을 반환하는 함수에서 도달 가능한 fallthrough를 허용하지 않습니다.

무한 루프, 프로세스 종료 또는 반환되지 않는 외국 통화는 실제 계약 하에서만 분산 된 제어 흐름 효과를 가질 수 있습니다. never라는 단어 자체는 정리, 종료 또는 특정 런타임 오류 정책을 보장하지 않습니다.

4입니다. 불가능한 일반 변형

Result<T, never> Ok(T)만 포함할 수 있습니다. Result<never, E> Err (E)만 포함할 수 있습니다. Optional<never> 오직 하나가 될 수 있을 뿐이다. 이러한 속성을 통해 일반 API는 더미 오류를 발명하지 않고 무류성을 나타낼 수 있습니다. 

Result<i32, never> success = Result.ok(7);
i32 value = Result.into_ok(success);
Optional<never> no_value = Optional.none<never>();

5입니다. 함수 참조

T value 는 값을 전달합니다. Copy 타입은 복사하며 소유 non-Copy 값은 깊은 clone 없이 이동합니다. &T value 는 공유 읽기 대여이고 &mut T value 는 배타적 변경 대여입니다. 호출 시 각각 x, &x, 또는 &mut x 를 사용합니다. 이미 대여한 참조·뷰 값은 직접 전달하며 &를 하나 더 붙이면 타입이 바뀝니다. *ref 는 참조 대상을 읽고 씁니다. 일반적인 &mut x 에는 mut 소유자가 필요합니다. mut T value 만으로는 값 매개변수가 함수 안에서 변경 가능해질 뿐 호출자의 값을 변경하지 않습니다. 겹치는 활성 대여는 마지막 사용까지 검사합니다. 서로 겹치지 않는 영역은 안전하게 나눌 수 있으며 대여는 원본보다 오래 살 수 없습니다. 동기화된 내부 변경은 해당 타입의 계약을 따릅니다. Fn(A) -> B 는 호출 가능한 값을 설명하며 반환 참조의 수명 관계는 본문으로 문서화합니다.

6입니다. 컨테이너 및 거주성

never의 zero-length Array는 구성 할 요소가 없을 수 있습니다. 양의 길이를 갖는 never의 Array는 안전하게 완전히 초기화될 수 없다. never의 zero-length Slice는 소스 및 정렬 계약이 유효한 경우에만 빈 대여을 설명 할 수 있습니다.

never의 Vector는 비었을 수 있습니다. Safe append에서 유효한 never 요소를 수신할 수 없습니다. 변형이나 길이가 불가능할 것으로 예상되었기 때문에 일반 작업이 초기화되지 않은 메모리에 액세스해서는 안 됩니다.

7입니다. 레이아웃과 표현 경계

이 문서에서는 never에 대한 휴대용 byte 크기, 정렬 또는 호출 규칙을 약속하지 않습니다. 컴파일러는 사람이 살지 않는 열거형 변형을 제거하거나 사용 가능한 틈새를 사용할 수 있지만 이러한 최적화는 안정적인 직렬화 또는 FFI 계약이 아닙니다.

포인터 또는 참조 표현은 유효한 never 참조자의 증명 그 자체가 아닙니다. 안전한 대여은 항상 참조 유형의 초기화 된 유효한 값을 필요로합니다.

8입니다. 청소 및 자원 수명

분산은 하나의 범용 소멸자 정책을 정의하지 않습니다. 끝없는 계산은 그것의 살아있는 자원을 유지한다; 중단 과정은 소멸자를 달리지 않을지도 모른다; 풀리는 것은, 지원되면, 그것의 분리되는 지정된 정리 규칙을 따른다.

비동기 장치 오류는 정상적인 결과를 제공할 수 없는 경우에도 대기 상태가 될 때까지 기내 리소스를 유지해야 합니다. 불가능한 유형은 기본 액세스가 끝나기 전에 대여이 종료되는 것을 허용하지 않습니다.

9입니다. 외국으로 돌아오지 않는 전화

외국 반환 주석은 실제 구현 및 호출 규칙에 대해 검증되어야 합니다. 가져온 비복귀 계약에도 불구하고 반환되는 함수는 경계 위반을 만듭니다. 일반적인 Result 오류가 아닙니다.

사용법: Result<T, E> 회복할 수 있는 실패. 정상적인 값이 존재하지 않는 경우에만 never를 사용하십시오; 컴파일러는 숨겨진 기본값을 삽입하는 대신 조작된 생성자를 거부해야 합니다.
