2입니다. 컴파일 시간 범위와 타입 아이덴티티

3입니다. 완전한 초기화 & 빈 배열

모든 안전한 값에는 정확히 N개의 초기화된 요소가 있습니다. 고정 길이가 자동 0 초기화를 뜻하지는 않습니다. 기본 생성은 T의 Default 연산을 호출합니다. 반복에는 명시적 Copy·Clone 의미가 필요하며 인덱스 생성자는 각 요소를 독립적으로 만듭니다.

길이 0은 유효하며 첫 요소·마지막 요소가 없습니다. N=0인 인덱스 생성자는 요소 콜백을 호출하지 않습니다. 일반 인수 식은 함수 호출 전에 평가되므로 출력 길이 0이 외부 부작용을 지우지는 않습니다.

실패 가능한 생성자·clone 생성자는 Err 이전에 생성에 성공한 요소만 정리합니다. 부분 초기화된 출력이 외부로 나가지 않습니다. 콜백이 자원을 쓰거나 여러 요소 생성에 성공한 뒤 오류를 반환해도 이 정리 의무가 적용됩니다.

4입니다. Contiguity, 정렬 및 제로 크기 요소

원소 슬롯은 네이티브 스트라이드 size_of(T)를 간격으로 연속 배치됩니다. 원소 데이터의 크기는 그 크기의 N배이며, T 내부의 패딩은 그대로 남습니다. 중첩 배열의 선형 원소 순서는 행 우선입니다. 패딩이나 네이티브 메모리 배치 자체가 전송 형식의 계약은 아닙니다.

N=0이거나 T의 크기가 0이면 payload 바이트 길이가 0일 수 있지만 정렬·동일성·길이·요소 생명주기 의미는 유지됩니다. 빈 객체의 실제 ABI 표현이 모든 외부 컴파일러의 빈 배열 표현과 같다고 보장하지 않습니다.

제안된 경계는 대상 개체 경계 내에서 isize.MAX 및 0이 아닌 페이로드 크기보다 큰 논리 길이를 필요로 합니다. 이러한 한계에 맞는 유형은 특정 스택 프레임이 구체화 될 수 있음을 보장하지 않습니다. 명시적 Box 또는 Vector 배치는 별도의 오류 가능성 할당 경로를 제공합니다.

5입니다. 이동, Copy, 클론 및 배치

소유 고정 배열은 T가 스칼라 Copy 타입이어도 기본적으로 이동합니다. 소유권 이전 후 이전 바인딩은 사용할 수 없습니다. 최적화로 저장소 이동을 생략할 수는 있지만 큰 인라인 배열과 배열 전체 교환을 항상 상수 시간이라고 설명해서는 안 됩니다.

Array.copy 는 Copy 요소를 요구하며 N개 값 전체를 명시적으로 복제합니다. Array.clone 는 Clone을 요구하고 요소의 동작을 따르므로 공유 핸들이나 중첩 할당을 포함할 수 있습니다. 자원 소유자의 memcpy나 항상 깊은 clone을 뜻하지는 않습니다.

인라인 소유권은 저장소 포함 관계를 설명하며 반드시 스택에 둔다는 뜻은 아닙니다. 배열은 필드이거나 Box 안에 있을 수도 있습니다. 배열을 다른 함수로 이동해도 내용이 GPU로 전송되거나 공유 참조로 바뀌지는 않습니다.

6입니다. 경계, 지속적인 평가 및 대여

인덱스는 usize 값입니다. 읽기는 요소를 대여하고 쓰기에는 배타적 권한이 필요합니다. 길이가 고정되어도 범위 밖 읽기나 동시에 겹치는 쓰기 뷰를 허용하지 않습니다.

얻기 위한 상수 호출은 None으로 접을 수 있으며, 상수 checked 액세스는 Err로 접을 수 있습니다. 형식이 잘못되었거나 불가능한 유형 수준 재형성은 컴파일 시간 진단입니다. 컴파일러는 모든 알려진 실패를 런타임 트랩으로 처리하는 대신 서로 다른 공개 계약을 보존해야 합니다.

경계 검사 제거는 증명에 기반한 최적화입니다. AOT와 JIT는 유효한 인덱스·실패 값에서 일치해야 합니다. 요소·반복자·파생 뷰가 원본 소유자를 대여하는 동안 소유자는 살아 있어야 하며 이동할 수 없습니다.

7입니다. 중첩된 모양 및 소유권 변환

정적 concat은 두 명의 소유자를 소비하고 N+M 요소를 형성합니다. Owned split은 길이가 N 인 분리 된 소유자를 반환합니다. Zip과 unzip은 일치하는 범위가 필요하며 각 요소를 한 번 전송합니다.

row-major order를 보존하고 변형한다. Reshape는 유효한 영차원을 포함하여 N과 동일한 대상 제품을 필요로 합니다. 조옮김은 위치의 매핑을 변경하며 O(R*C) 이동이 필요할 수 있습니다. 스트라이드이 큰 조옮김은 인접한 Array 뷰가 아닌 TensorView에 속합니다.

컴파일 타임 차원은 무제한 언롤링 또는 코드 확장을 정당화하지 않습니다. 최적화는 루프를 선택하거나 모양을 전문화 할 수 있습니다. 콜백 순서, 드롭 안전, 정확한 정수 크기 산술 및 관찰 가능한 오류는 언어 계약으로 유지됩니다.

8입니다. 고정 확장 기능 전문 분야

이들은에 문서화된 기능의 전문화이다 일반적인 Array 카탈로그두 번째 네임스페이스가 아닙니다. Read/write/consume와 콜백 별칭은 기술 표기법이며, 정확한 수명 표기은 열려 있습니다.

9입니다. 첫 번째 예

다음의 구성 및 소유권 이전은 선택된 타입-퍼스트 선언 순서를 나타낸다. 생성자 표기과 명시적인 반환 참조 수명 주석은 초안으로 남아 있습니다; 매개 변수 대여 양식이 선택됩니다. 

i32 fill = 0;
Array<i32, 4> zeroes = Array.from_copy(i32, 4, &fill);
Array<i32, 4> duplicate = Array.copy(&zeroes);
Array<i32, 4> moved = zeroes;
usize count = Array.len(&moved);

이동 후 0은 더 이상 소유 바인딩이 아닙니다. Duplicate는 독립된 고정된 배열입니다; 이동된 값은 여전히 4입니다. Vector 성장 작업을 자동으로 호출하거나 추가 공유 소유자를 만드는 예는 없습니다.

10입니다. 병렬 처리, FFI 및 관련 유형

서로 겹치지 않는 대여 범위를 병렬 처리하려면 요소·콜백에 적절한 스레드 안전 제약이 필요합니다. 고정 크기는 증명을 단순화하지만 임의의 캡처 상태를 데이터 경쟁에서 안전하게 만들지는 않습니다. checked 산술이 실패할 수 있으면 축약 순서를 명세해야 합니다.

FFI에는 크기·정렬·요소 배치·대여 수명·할당자 소유권 계약이 명시되어야 합니다. string 핸들·참조·패딩된 레코드가 든 네이티브 배열이 자동으로 C 호환 요소 버퍼가 되지는 않습니다.

의 배열 char 인코딩된 텍스트 바이트가 아닌 Unicode 스칼라 값을 보유합니다. 더 보기 string 및 bytebyte는 u8와 구별됩니다. 장치 전송, 안전하지 않은 원시 포인터 채택 및 외국 할당 릴리스는 이러한 시그니처에 의해 암시되지 않는 별도의 명시적 기능입니다.
