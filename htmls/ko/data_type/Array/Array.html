2입니다. 요소 유형, 길이 및 레이아웃

3입니다. 소유권, 초기화 및 파기

Safe 생성자는 완전히 초기화된 배열만 게시합니다. 원시 저장소와 별도로 초기화된 출력 요소를 추적합니다. 초기 반환된 오류는 초기화된 접두사를 정확히 한 번 파괴합니다. 어떤 안전한 API도 초기화되지 않은 여분의 슬롯을 노출시키거나 조작된 길이 메타데이터를 허용하지 않습니다.

Clone T의 의미에 따라 복제: 공유 핸들을 복제하면 공유 리소스를 유지할 수 있습니다. 그것은 보편적 인 deep-copy 보증이 아닙니다. Copy 자원 소유자는 byte 복사본을 통해 안전하게 될 수 없습니다.

Array 파괴는 모든 소유 요소를 한 번 해제합니다. 정확한 요소 파괴 순서와 풀기 구문은 여전히 언어 사양이 필요합니다. 반환된 오류는 초기화 안전성을 유지해야 하며, 프로세스 종료는 정리를 약속할 수 없습니다. 콜백의 외부 부작용은 never가 자동으로 롤백됩니다.

4입니다. 대여, 액세스 및 변경 가능성

Read borrows는 공존 할 수 있습니다. write borrow는 읽기 또는 쓰기 액세스 중복을 배제하는 반면, disjoint 서브레인지는 checked 분할을 통해 별도로 빌릴 수 있습니다. 빌린 모든 결과는 소유자와 함께 만료되며 수명 벗어날 수 없습니다.

Array.get 일반적인 부재에 대해 Optional를 반환합니다. Array.at 경계 진단에 대한 Result를 반환합니다. 검사되지 않은 위치도 읽습니다. 반환된 요소는 대여됩니다; 그것을 아직 초기화되지 않은 배열에서 이동시키는 것은 교체 또는 소모 변환을 필요로 합니다.

매개 변수는 선택한 양식을 사용합니다. T value, &T value, 및 &mut T value. 촬영 중 &mut owner 에는 mut 소유자 바인딩입니다. 기존 참조 및 대여된 보기는 직접 전달됩니다. 알려진 전용 참조 또는 MutSlice 매개 변수는 다음에서 해당 참조를 다시 불러옵니다. 함수 reborrow 규칙.

Slice<T> 읽기 뷰를 나타냅니다. MutSlice<T> 이 문서에서 사용되는 설명 전용 쓰기 가능 뷰 유형입니다. 쓰기 재지갑은 원본 기능의 충돌하는 사용을 중지합니다.

5입니다. 오류, 콜백 및 비용

콜백 라벨 Transform, TryTransform, RefTransform, 및 TryRefTransform 기능적인 계약이 아닌, Map<K, V> 모음집 종류. 그들의 마지막 콜러블 타입 표기은 라이브러리 디자인 디테일로 남아 있습니다. Vector 및 Slice API 시그니처은 다음과 같은 경우에만 유지됩니다. Vector 카탈로그 및 Slice 카탈로그.

CollectionError, BoundsError명명된 소유권 보존 오류는 라이브러리 오류 유형이 제안됩니다. InputError<T> 거절당한 후 사용되지 않은 이동된 입력을 반환합니다. OwnerError<C> 실패한 사용 전환의 원래 소유자를 반환합니다. 콜백 반환 E는 try 함수에 의해 보존됩니다.

Bounds-only failures는 mutation이 발생하기 전에 미리 체크한다. 깨끗한 부분 출력을 생성합니다. In-place cloning/replacement 및 콜백 변경는 행이 말하는 곳에서 유효한 부분 변경을 남길 수 있습니다. 비교기 요구 사항은 과도성 및 전체 순서를 포함합니다. 정렬되지 않은 이진 검색 입력은 메모리 안전하지 않음을 부여하지 않고 알고리즘 계약을 위반합니다.

복잡성 count 요소 작업. 큰 인라인 T, 클론, 드롭, 비교 또는 콜백의 이동은 상당한 작업을 추가 할 수 있습니다. 고정 배열 이동 및 전체 배열 스왑은 O(N) 요소를 터치할 수 있으며, 최적화 도구는 움직임을 생략할 수 있지만 언어는 이를 약속하지 않습니다. AOT 및 JIT는 눈에 보이는 콜백 순서와 오류를 보존해야 합니다.

6입니다. 전체 제안 Array API

이러한 개별적으로 명명된 함수는 고정 크기 배열을 포함합니다. 알고리즘은 명시적인 콜백을 수용한다; 시그니처의 콜백 타입 이름은 설명적인 별칭이다. 일반적인 이름은 보편적인 특성을 약속하지 않습니다: 평등은 Eq가 필요하고, 정렬은 총 비교기가 필요하며, clone/copy에는 별도의 요구 사항이 있습니다.

핵심 리터럴은 위에서 설명한 대로 확정되고 구현됐습니다. 명시적 캡처 클로저와 Fn/FnMut/FnOnce 기반 기능은 0.2에 구현됐으며, 설명용 알고리즘 콜백 별칭과 나머지 라이브러리 API는 여전히 설계 단계입니다. 각 API 행은 기존 구현을 주장하는 대신 관찰 가능한 소유권, 실패, 비용의 계약을 설명합니다.

Array.binary_search(&Array<T, N> values, &T needle, Compare<T> compare) SearchResult 정렬된 입력과 동일한 일관된 총 비교기가 필요합니다. O(log N) 비교
Array.lower_bound(&Array<T, N> values, &T needle, Compare<T> compare) usize 첫째, 일정한 순서로 정렬되지 않은 위치입니다. O(log N) 비교
Array.upper_bound(&Array<T, N> values, &T needle, Compare<T> compare) usize 첫째, 일정한 순서에 따라 더 큰 위치. O(log N) 비교
Array.equal(&Array<T, N> left, &Array<T, N> right) bool T: Eq; 원소 대등함. O(N) 등호 호출
Array.compare(&Array<T, N> left, &Array<T, N> right, Compare<T> compare) Ordering 전체 비교를 렉시코그래피; NaN 명시적인 총 float 비교기가 필요합니다. O(N) 비교
Array.sort(&mut Array<T, N> values, Compare<T> compare) Result<unit, CollectionError> 안정적인 정렬; 재주문하기 전에 스크래치를 예약합니다. 비교기 failure/termination는 재정렬되었지만 유효한 요소를 남길 수 있습니다. O(N log N) 비교; 스크래치는 할당할 수 있음
Array.sort_unstable(&mut Array<T, N> values, Compare<T> compare) unit 불안정한 in-place 종류; 요구되는 틀림없는 일관된 총 비교 측정기; 중지에 불변 순서 보증 없음. O(N log N) 비교; 힙 스크래치 없음
Array.is_sorted(&Array<T, N> values, Compare<T> compare) bool 인접한 순서를 검사합니다. empty/single-element 배열이 정렬됩니다. O(N) 비교

반복 및 변환

매개 변수 형식 T 값, &T 값 및 &mut T 값은 선택한 문법을 따릅니다. API 이름, 유형 팩, 콜백 및 명시적 반환 참조 수명 주석은 표시된 곳에서 초안으로 유지됩니다.

함수 시그니처 반환 요구 사항 및 실패 계약 비용
Array.iter(&Array<T, N> values) ReadIterator<T> 읽기 대여 수율; 소유자는 대여 보유. O(1) 생성; O(N) 횡단
Array.iter_mut(&mut Array<T, N> values) WriteIterator<T> 배타적이고 부조화 된 요소가 대여됩니다. 소유자 변경는 일시 중지됩니다. O(1) 생성; O(N) 횡단
Array.into_iter(Array<T, N> values) OwnedIterator<T> 요소를 제거합니다; 이터레이터를 삭제하면 남아있는 모든 요소를 청소합니다. O(N) 가능한 소유자 이동; O(N) 횡단
Array.fold(&Array<T, N> values, A initial, Fold<A, T> step) A 순차 왼쪽 접기; 콜백은 checked 숫자 의미를 선택합니다. O(N) 호출
Array.try_fold(&Array<T, N> values, A initial, TryFold<A, T, E> step) Result<A, E> Err에 정지; 입력 배열은 빌린 남아 있다, 외부 콜백 효력은 남아 있다. O(N) 호출
Array.all(&Array<T, N> values, Predicate<T> test) bool short-circuits; 비어 있는 반환값이 true입니다. O(N) 최악의 경우
Array.any(&Array<T, N> values, Predicate<T> test) bool short-circuits; 빈 반환은 false이다. O(N) 최악의 경우
Array.into_vector(Array<T, N> values) Result<Vector<T>, OwnerError<Array<T, N>>> 요소를 사용하기 전에 대상을 할당합니다. allocation/size 실패는 Err에서 원래 소유자를 그대로 반환합니다. O(N) 이동 및 할당
Array.to_vector_clone(&Array<T, N> values) Result<Vector<T>, CollectionError> T: Clone; 명시적으로 할당된 복제본, 원본 보존됨. O(N) 클론과 할당
Array.into_box(Array<T, N> values) Result<Box<Array<T, N>>, OwnerError<Array<T, N>>> 소유자를 명시적 할당으로 옮기고, 할당 실패는 원래 소유자를 반환합니다. O(N) 이동 및 할당 가능

7입니다. 첫 번째 예

카탈로그 예제. 이 프래그먼트는 또한 스코프 노트에서 식별된 제안된 함수를 사용한다; 완전한 0.2 프로그램이 아니다.

가정 values 기존 읽기 액세스 가능Name Array<i32, 3>. 아래의 선언은 네임스페이스 접근과 명시적인 중복을 보여준다; 모든 실행 가능한 문은 세미콜론으로 끝난다. 

Array<i32, 3> values = [1, 2, 3];
usize count = Array.len(&values);
Optional<&i32> first = Array.first(&values);
Array<i32, 3> duplicate = Array.copy(&values);
Result<Vector<i32>, CollectionError> dynamic_copy = Array.to_vector_clone(&values);

마지막 작업은 별도의 Vector를 할당합니다. 원래의 고정 길이를 변경하지 않습니다. 매개 변수 대여 양식이 선택됩니다. 오류 유형 표기 및 명시적인 반환 참조 수명 주석이 제안됩니다. 괄호 구성 문법은 위에 정의되어 있습니다; 제안된 Array 헬퍼 호출은 그 문법과는 별개입니다.

8입니다. 병렬 처리, 장치 및 FFI

공유 읽기 뷰는 T가 안전한 공유 액세스를 지원하는 경우에만 병렬로 안전합니다. 쓰기 뷰를 결합하지 않으면 중복되는 변경를 방지할 수 있지만 캡처된 공유 상태 및 내부 가변성은 여전히 자체 동기화가 필요합니다. 소유권을 나누는 것이 자동으로 임의의 T 스레드를 안전하게 만들지는 않습니다.

Array/Vector는 전송 소유권을 동일한 스토리지 모델로 이동하며, GPU로 바이트를 전송하지 않습니다. Tensor 변환 및 명시적 장치 전송은 요소 레이아웃, 모양, 대상 기능 및 비동기 버퍼 수명에 대한 유효성을 검증해야 합니다. 이 문서에는 백엔드 지원이 포함되어 있지 않습니다.

FFI borrow는 length, alignment, initialization, permission, 그리고 누가 할당을 해제하는지를 기술해야 한다. 빈 버퍼와 0 크기의 버퍼는 포인터가 존재하기 때문에 간단히 역참조할 수 없습니다. 일반 배열은 모든 C++ 템플릿 인스턴스화와 ABI 호환되도록 약속되지 않습니다.

9입니다. 텍스트, 문자, 바이트

다음 Array<char, N> Unicode 스칼라 값을 포함하며, N UTF-8 바이트 또는 N 사용자가 인식한 graphemes가 아닙니다. 소문자 사용 string 참조 텍스트 인코딩 및 string 작업.

byte 구별하여 u8배열 캐스트나 뷰가 자동으로 요소 ID를 변경하지 않습니다. 오시는 길 Byte 참조 명시적 byte/numeric 변환. 연속 스토리지만으로는 UTF-8, 포인터 출처, endianness 또는 외부 레코드 레이아웃의 유효성을 검사하지 않습니다.

10입니다. 디자인 상태 및 참조 범위

이 카탈로그는 Aevix 디자인 제안서입니다. 기본적으로 Move-by-default 소유자, 명시적 복제, checked 크기 및 오류 값을 사용하며 다른 언어의 할당, 예외 또는 Copy-On-Write 정책을 상속하지 않습니다.

나열된 기본 참조는 고정 범위, 연속성, 차입, 초기화, 재배치, 알고리즘 전제 조건 및 복사 비용에 대한 checked였습니다. 이들은 Aevix 구현, ABI 호환성, 측정 된 성능 또는 GPU 자격의 증거가 아닌 연구 자료입니다.
