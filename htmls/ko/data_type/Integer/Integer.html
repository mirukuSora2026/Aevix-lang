1입니다. 개요

0.2 구현 범위. 정수 기본 타입인 i128/u128, 및 int = i32 에는 import가 필요하지 않습니다. 리터럴, 같은 타입끼리의 산술, 비교, 비트 연산과 Integer.convert<D>(value) 가 구현되어 있습니다. 이 변환은 정수 입력과 정수 목적지만 허용하며 반환 타입은 Result<D, IntegerError>입니다. 실패 시에는 OutOfRange 를 반환합니다. 정수에서 부동소수점으로 변환할 때는 구현된 Float.convert/convert_exact 를 사용하세요. 더 넓은 카탈로그의 이름 있는 산술·파싱·포매팅·바이트 인코딩 함수는 여전히 제안입니다. 자세한 내용: 0.2 구현 프로필; 나머지 카탈로그 항목은 설계 계약입니다.

언어 설계 초안. 이 참조는 제안된 Aevix 정수 모델을 설명합니다. API 카탈로그는 구현 또는 호환성 주장이 아닙니다. 선언 구문과 일반적인 산술 실패 경계는 이제 규칙을 선택했습니다. 언어 문법; 0.2 구현은 다음을 포함한 명시적인 숫자 접미사를 추가합니다. i128 및 u128. 자세히 보기 구현 범위 실행 가능한 기능들

정수는 고정된 유한 범위의 정숫값을 나타냅니다. Aevix의 정수 설계에는 부호 있는 i8, i16, i32, i64, i128, 부호 없는 u8, u16, u32, u64, u128, 대상 환경의 크기를 따르는 isize 및 usize가 포함됩니다. 부호 있는 값은 2의 보수를 사용합니다. 별칭 int 는 다음 표기와 같습니다: i32; float 는 다음 표기와 같습니다: f64.

폭이 N이면 부호 있는 타입의 범위는 −2^(N−1) 부터 2^(N−1)−1까지이며, 부호 없는 타입의 범위는 0 부터 2^N−1입니다. 대상 크기 정수는 대상 환경의 주소 모델을 따릅니다. 직렬화 데이터나 CPU/GPU 공유 인터페이스에서 그 폭을 고정값으로 가정해서는 안 됩니다.

이 페이지는 공통 동작을 정의합니다. Int8 참조 문서 에는 i8 의 경계와 특수한 결과를 설명합니다.

2입니다. 선언 및 초기화

타입 추론은 리터럴의 값이 요구되는 정수 타입에 들어갈 때 허용합니다. 문맥이 타입을 제한하지 않으면 정수 리터럴의 기본 타입은 int, 또는 i32입니다. 값이 이 기본 타입에 들어가지 않으면 컴파일러가 오류를 보고하며, 더 넓은 타입을 조용히 선택하지 않습니다.

값은 기본적으로 변경할 수 없습니다. 변경하려면 명시적으로 mut 를 선언해야 합니다. 예: mut i32 value = 0;. 공통 연산에는 다음과 같은 네임스페이스 함수를 사용합니다: Integer.checked_add(a, b). 이 설계에는 정수 인스턴스 메서드가 없습니다.

3입니다. Integer 리터럴

0.2는 십진 리터럴과 명시적인 0b 이진, 0o 팔진, 0x 십육진 표기를 지원합니다. 다음과 같은 접미사는 42i64 또는 42u128 리터럴의 타입을 고정합니다. 리터럴은 숫자 값을 나타내며 비트 패턴을 재해석하라는 지시가 아닙니다.

음의 최솟값도 표현할 수 있어야 합니다. 컴파일러는 부호와 리터럴의 크기를 함께 평가한 뒤 목적지 범위를 검사합니다. 먼저 양의 크기가 해당 부호 있는 타입에 들어갈 것을 요구해서는 안 됩니다.

컴파일 타임 수학 계산에는 더 넓은 내부 표현을 사용할 수 있습니다. 그렇다고 런타임 임의 정밀도 정수를 추가하거나, 타입이 정해진 식의 폭을 바꾸거나, 범위를 벗어난 초기화를 허용하는 것은 아닙니다.

4입니다. 산술 작업

이미 타입이 정해진 피연산자에는 암시적 수치 승격을 적용하지 않습니다. 일반 산술은 같은 정수 타입끼리 수행합니다. 목적지 폭이 부족하면 연산 전에 명시적으로 폭을 넓히세요. 결과의 폭을 나중에 넓혀도 이미 발생한 오버플로를 되돌릴 수는 없습니다.

선택된 일반 정수 산술 정책은 실패를 검사하며 런타임 연산이 실패하면 안전 중단을 수행합니다. 일반 연산자는 해당 정수 타입을 결과로 내고 자동으로 Result를 반환하지 않습니다. 이름 있는 checked API의 반환 타입은 Result<T, IntegerError>이며, 선택된 어휘적 checked(expression) 형식은 직접 작성한 정수 산술을 Result로 반환합니다. 실패 경계는 명시적이며 기대 타입, AOT/JIT 모드나 최적화 프로파일에 따라 바뀌지 않습니다. 자세한 내용: 검사 산술. 안전 중단의 정확한 종료·정리 정책은 아직 열린 설계 과제입니다.

절단 나눗셈은 0 방향으로 반올림하며 나머지는 피제수의 부호를 따릅니다. 유클리드 나눗셈은 제수의 수학적 절댓값보다 작은 음이 아닌 나머지를 만듭니다. 제수가 음수이면 바닥 나눗셈과 유클리드 나눗셈의 결과가 다릅니다.

5입니다. 비교 및 비트와이즈 운영

동등성·순서 비교는 같은 타입의 숫자 값을 비교하며 결과 타입은 bool입니다. 이미 타입이 정해진 피연산자는 암시적으로 수치 변환되지 않습니다. 값을 보존하는 명시적 변환으로 타입 간 변환 의도를 밝힙니다. 타입 미지정 리터럴은 문맥에서 타입을 받을 수 있습니다. 비트 연산은 고정 폭 표현을 대상으로 합니다.

시프트 횟수 검증과 정보 보존은 별개입니다. 유효한 횟수는 0부터 폭보다 1 작은 값까지입니다. 횟수만 검사하는 왼쪽 시프트는 상위 비트를 버릴 수 있습니다. exact 시프트는 역연산으로 원래 값이 복원되는지도 검사합니다. 부호 있는 오른쪽 시프트는 부호 비트를 확장하며 논리 오른쪽 시프트는 0을 채웁니다. 회전은 모든 비트를 보존하고 횟수를 폭으로 나눈 나머지를 사용합니다.

부호 있는 최솟값을 −1 로 나누면 오버플로가 발생합니다. 이 입력의 독립적인 나머지 연산은 0을 반환하도록 제안되어 있지만 몫·나머지 결합 연산은 계속 실패합니다. wrapping이나 saturation도 0으로 나누기의 결과를 정의하지 않습니다.

상수 접기는 공개 계약을 보존합니다. 상수 checked 호출은 Err로 접힐 수 있습니다. 잘못된 타입 지정 리터럴이나 필수 상수 값에는 컴파일 타임 진단을 냅니다. 최적화가 문서화된 오류 값을 정의되지 않은 동작으로 바꿔서는 안 됩니다.

8입니다. 성능 및 메모리

정수는 복사 가능한 단순 값입니다. 스칼라 저장에 독립적인 힙 할당이나 참조 카운트는 필요하지 않습니다. 표현 크기가 레지스터 사용, 구조체 패딩, 호출 규약이나 스택 배치를 결정하지는 않습니다. 배열 전체 복사는 별도의 집합 값 정책이며 비용이 클 수 있습니다.

스칼라 checked 결과는 힙 할당 없이 표현할 수 있습니다. 검사와 오류 처리에도 실제 비용이 있으며, 컴파일러는 명세된 동작을 보존할 때만 검사를 제거할 수 있습니다. 바이트 변환은 고정 배열을 반환하므로 힙 버퍼를 할당하지 않습니다. 텍스트 포매팅은 출력용 할당과 호출자가 제공한 저장소에 쓰기를 구분합니다.

Integer.is_multiple_of(T x, T multiple) bool 정확한 divisibility; 제안된 zero convention: 0만이 0의 배수입니다.
Integer.next_multiple_of(T x, T multiple) Result<T, IntegerError> 최소 배수 >= x; 는 양수의 배수를 필요로 합니다; 유효하지 않은 입력 또는 대형 결과가 오류를 반환합니다.
Integer.previous_multiple_of(T x, T multiple) Result<T, IntegerError> 가장 큰 배수 <= x; 필요한 양의 배수; 부호 있는 MIN보다 넘칠 수 있습니다.
Integer.align_up(U x, U alignment) Result<U, IntegerError> 필요한 2의 긍정 힘 정렬; InvalidAlignment 또는 Overflow.
Integer.align_down(U x, U alignment) Result<U, IntegerError> 밑으로 반올림; 정렬이 2의 양수가 아닌 한 InvalidAlignment

9.17입니다. 수론 및 모듈식 산술 고급

U는 부호 있는 크기를 나타냅니다. 중간 오버플로가 수학적으로 표현 가능한 결과를 손상시키지 않아야합니다.

개념적 시그니처 반환 타입 계약 및 오류
Integer.gcd(T a, T b) U 정확한 음이 아닌 최대 공약수의 크기; gcd(0,0)는 0입니다.
Integer.lcm(T a, T b) Result<U, IntegerError> Nonnegative 최소공배수; 입력이 0이면 0; 결과가 U에 맞지 않으면 오버플로우.
Integer.pow_mod(T base, u64 exponent, U modulus) Result<U, IntegerError> 캐노니컬 nonnegative 잔기; 0 계수는 InvalidModulus, 1 계수는 0을 반환합니다.
Integer.mod_inverse(T x, U modulus) Result<U, IntegerError> 계수 >= 2 및 동위 원소 입력이 필요합니다. InvalidModulus 또는 NoInverse. Result는 계수 아래에 있습니다.

9.18입니다. 부호 없는 넓은 단어 산술 고급

모든 단어가 부호 없는 형식과 일치합니다. Tuple 필드 레이블은 개념적입니다. 64-bit 쌍에는 공용 128-bit 유형이 필요하지 않습니다.

개념적 시그니처 반환 타입 계약 및 오류
Integer.add_carry(U a, U b, bool carry) (U word, bool carry) a + b + carry; 낮은 단어와 발신이 전달됩니다.
Integer.sub_borrow(U a, U b, bool borrow) (U word, bool borrow) 정확한 a-b-borrow; 모듈 형 저 단어 및 발신 대여.
Integer.mul_wide(U a, U b) (U low, U high) 정확한 이중 폭 제품, 낮은 단어 먼저.
Integer.div_wide(U low, U high, U divisor) Result<(U quotient, U remainder), IntegerError> 지수가 한 단어에 맞지 않을 경우 high*2^width+low; DivisionByZero 또는 Overflow를 나눕니다.

적용 가능성 및 구현 경계

인수는 명시적으로 이질적인 변환 및 비교를 제외하고 일치하는 유형을 사용합니다. 서명 전용 함수는 부호 없는 형식 인수를 거부합니다. Integer.wrapping_neg unsigned modular negation 부호 없는 모듈 부정 Integer.unsigned_abs 및 Integer.abs_diff return unsigned values; 넓은 carry 함수는 boolean carry 또는 borrow 비트를 사용한다.

비트 범위와 버퍼 오프셋 검증 계산 자체가 오버플로해서는 안 됩니다. 잘못된 타입 지정 리터럴에는 컴파일 타임 진단을 내며, 유효한 상수 checked 호출은 Err로 접힐 수 있습니다. 0인 제수에 wrapping·saturation 값을 만들어 주지 않습니다. 실패 전파가 앞서 발생한 부작용을 되돌리지는 않습니다.

파싱 오류는 빈 입력, 유효하지 않은 radix 또는 digit 및 범위 밖의 값을 구분해야 합니다. 수학-값 포맷은 선택적인 고정폭 비트-패턴 포맷과 다르다: 음수 16진수 출력은 자동으로 원시 비트 덤프가 아니다. Atomic 작업에 속함 Atomic<T> 문서. 백엔드, GPU, FFI 및 할당자 범위는 릴리스 전에 구현 및 검증이 필요합니다.

10입니다. 예제

다음 호출은 제안된 표기법을 설명합니다. 가정 a 및 b 있습니다. i32 값 40 및 2; Err 예외가 아닌 오류 값의 이름을 지정합니다. 

Integer.checked_add(a, b);    // Ok(42)
Integer.convert<i64>(a);      // Ok(40)
Integer.bit_width(i32);       // 32
Integer.div_rem_trunc(a, b);  // Ok((20, 0))

크기 계산에서는 할당 전에 곱셈을 검증해야 합니다. 아래 식은 검사되는 계산을 나타내며 확정된 선언·오류 전파 문법이 아닙니다. 

Integer.checked_mul(element_count, element_size);
// Handle Overflow before allocating the resulting byte count.

11입니다. 컴파일 및 병렬 실행

AOT와 JIT는 산술 정책, 오류 결과와 평가 순서를 보존해야 합니다. 검증된 가드 아래에서는 특수화로 검사를 제거할 수 있습니다. 백엔드는 나눗셈·시프트 등에서 정의되지 않은 동작이나 poison이 발생하지 않도록 보호해야 합니다.

checked 산술의 결합 순서를 임의로 바꿀 수는 없습니다. 수학적으로 같은 식도 중간 오버플로에 따라 구별되기 때문입니다. 병렬 축약에는 누적 폭·순서 정책·실패 계약이 명시되어야 합니다. 정수 저장·산술·원자 연산의 지원은 서로 다른 GPU 기능입니다. FFI 어댑터는 외부 ABI와 일치해야 하며 Aevix 별칭이 외부 언어의 다음 타입을 재정의하지는 않습니다: int.
