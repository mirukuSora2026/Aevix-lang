범위와 현황

이 문서는 0.2V 미리보기의 구현 범위입니다. 더 큰 타입·API 설계 카탈로그와는 구분됩니다. 컴파일러 패키지의 파일명은 0.2.0-dev를 유지하며, 컴파일러와 VS Code 확장은 버전을 0.2.0으로 표시합니다. 기존 0.1 계열은 release/0.1에 보존되어 있습니다. 현재 macOS ARM64, Linux ARM64와 에뮬레이션한 Linux x86-64 빌드는 각각 CTest 검사 43개를 모두 통과했습니다. 해당 호스트에서는 사용자별 설치 경로 이전, PATH, AOT/JIT와 제거 검사도 통과했습니다. Windows 배포물은 AOT 전용이며 COFF·정적 링크 프로브 9개와 패키지 검사를 거쳤습니다. 네이티브 실행은 아직 검증되지 않았습니다. 성능을 바꾸는 최적화는 최종 외부 검토가 끝날 때까지 보류합니다.

메모리는 네이티브 값과 명시적 소유자를 사용합니다. 추적형 가비지 컬렉터나 JVM 방식의 예약 힙은 없습니다. 지원하는 언어 범위에는 소유권·대여 검사가 적용됩니다. 임의의 외부 코드와 비정상적인 프로세스 종료에는 정상 정리 보장이 적용되지 않습니다.

수치 값

부호 있는 정수와 부호 없는 정수는 i128 및 u128까지 지원합니다. 부동소수점 형식은 f16, bf16, f32, f64입니다. int는 i32의 별칭이고 float는 f64의 별칭입니다. 타입 지정 리터럴 접미사는 정확한 수치 타입을 선택합니다. 최적화 빌드에서도 정수 연산의 런타임 안전 검사를 유지합니다. 카탈로그의 checked(expression)이나 일반적인 이름 기반 checked 연산 API까지 구현한 것은 아닙니다. 지원하지 않는 캐스트와 암시적 축소 변환은 거절합니다.

Integer.convert<T> 의 반환 타입은 Result<T, IntegerError>입니다. Float.convert<T> 는 반올림을 허용하고, Float.convert_exact<T> 및 Float.to_integer_exact<T> 는 정확히 표현할 수 없는 값을 거절합니다. 반정밀도 형식은 16비트 저장소와 이식 가능한 반올림 보조 함수를 사용합니다. 이 구현 범위의 외부 C ABI는 128비트 스칼라 값을 허용하지 않습니다.

Result<i8, IntegerError> narrow(i64 input) {
    return Integer.convert<i8>(input);
}

i32 main() {
    u128 bit = 1u128 << 100;
    return bit > 0u128 ? 0 : 1;
}

텍스트, 튜플과 배열

문자열 리터럴은 할당이 없는 UTF-8 string_view 값입니다. 소유 문자열의 생성과 변경은 명시적인 TextError 결과를 반환합니다. 바이트 길이, 유니코드 스칼라 수, 자소 군집 수는 서로 다른 개념입니다. 구현된 텍스트 호출은 byte_len, scalar_count, is_empty, view, as_bytes, equals, from_view, from_utf8, slice_bytes, append, push_char, clear입니다. 뷰는 원본 저장소에 대한 대여를 유지합니다.

Tuple.make는 입력의 소유권을 가집니다. get<I>와 get_mut<I>는 상수 인덱스의 필드를 대여합니다. 튜플은 기본적으로 이동하며, Tuple.copy를 사용하려면 모든 필드가 Copy를 지원해야 합니다. 반복 고정 배열은 길이가 0일 때도 원본 식을 한 번 평가하며 Copy 요소가 필요합니다. Slice.slice와 Slice.slice_mut는 검사된 뷰 또는 BoundsError를 반환합니다.

Result<usize, TextError> count_text() {
    string owner = string.from_view("Aé한🙂")?;
    return Result.ok(string.scalar_count(&owner));
}

void arrays() {
    i32 zeros[128] = [0; 128];
    Tuple<i32, bool> status = Tuple.make(200, true);
    &i32 code = Tuple.get<0>(&status);
    return;
}

제네릭과 호출 가능 객체의 기반

투명 타입 별칭은 타입 동일성을 유지합니다. 뒤쪽 타입 기본값과 const usize 매개변수로 크기가 정적으로 정해지는 사용자 정의 컨테이너를 지원합니다. 상수 인수는 표기가 아니라 값으로 정규화합니다. 기본값이 있는 매개변수 뒤에는 필수 매개변수를 둘 수 없습니다. 일반 const 함수와 임의의 상수 매개변수 타입은 이 범위에 포함되지 않습니다.

명시적 캡처 클로저 는 스택 환경과 정적 호출을 사용하며 Fn, FnMut, FnOnce 제약을 지원합니다. 캡처와 대여 제한을 검사하며, 박싱된 콜백을 암시적으로 할당하지 않습니다. 클로저 반환 타입 추론과 소유형 동적 호출 래퍼는 초기 구현 범위에 포함되지 않습니다.

struct Buffer<T = i32, const usize N = 4> {
    public Array<T, N> values;
};

i32 main() {
    i32 factor = 3;
    rsn multiply = [factor](i32 value) -> i32 { return value * factor; };
    return multiply(14) == 42 ? 0 : 1;
}

Complex<T = f64> 및 complex = Complex<f64> 를 사용하려면 complex를 명시적으로 import해야 합니다. 공개 타입 함수 17개가 생성, 성분 연산, 크기, 켤레, 비교와 Result를 반환하는 나눗셈을 제공합니다. ComplexError.ZeroDivisor 는 0인 제수를 보고합니다. numeric.Floating 기능 계약 은 내장 부동소수점 형식으로 봉인되어 있습니다. 사용자 구조체가 이를 구현하더라도 기본 수치 연산을 사용할 자격을 얻지는 않습니다.

CPU SIMD와 병렬 실행

구현된 SIMD 범위 는 simd의 명시적 import를 요구하며 수치 벡터를 128비트로 제한합니다. 레인별 정수 검사와 순서가 정해진 합산을 유지합니다. 특정 명령어 수나 속도 향상 대신 레인의 의미를 보장합니다.

parallel.for_each 는 스칼라 MutSlice와 검증된 이름 있는 worker를 사용합니다. 각 worker는 겹치지 않는 요소를 받으며 호출은 모든 worker가 끝날 때까지 기다립니다. 캡처 클로저, 일반 Task API, 분리 실행 작업과 GPU 실행은 이 범위에서 지원하지 않습니다.

실행과 도구

LLVM ORC JIT는 검증된 모듈, 정적 호스트 심볼, 최적화 수준, 캐시된 진입점 조회와 추적되는 모듈 제거를 지원합니다. 참조 중인 모듈과 종료 콜백을 소유한 모듈은 언로드할 수 없습니다. 호출은 호스트 프로세스 안에서 실행됩니다. JIT는 샌드박스가 아니며 자동 계층화, OSR, 추측적 역최적화를 보장하지 않습니다.

@bench 는 함수별 경과 시간과 표본으로 측정한 프로세스 RSS를 보고합니다. RSS에는 한 함수가 소유한 할당뿐 아니라 프로세스 전체가 포함됩니다. 계측은 짧은 호출의 측정값에 영향을 줍니다. 계측 표기가 없는 코드는 프로파일러 훅을 참조하지 않습니다.

실행: aevixc --check-deps 명령은 프로브를 실행하지 않고 네이티브 빌드 요구 사항을 확인합니다. 설치 프로그램은 PATH를 등록하고 일치하는 런타임을 포함하지만 플랫폼 SDK를 설치하지는 않습니다. 플랫폼 설정과 제거는 설치 안내 를 참고하세요.

릴리스의 한계

대상은 macOS ARM64, Linux ARM64/x86-64와 Windows x86-64입니다. 현재 Linux 배포물은 Ubuntu 24.04.5 LTS와 glibc 2.39 환경에서 검증했습니다. 다른 배포판과의 호환성은 별도 확인이 필요합니다. 현재 macOS 개발 설치 프로그램은 macOS 26.0 이상이 필요하며 설치 내용을 변경하기 전에 이 조건을 검사합니다. 코드 서명은 ad hoc 방식이고 PKG는 서명·공증되지 않았습니다. PKG는 시스템에 설치하지 않고 payload를 검사했으며, 실제 설치 검사는 사용자별 .run으로 진행했습니다. 소스 루트 아래의 모듈 파일명 stem과 폴더명에는 현재 다음 규칙을 사용합니다: [A-Za-z_][A-Za-z0-9_]*. 유니코드 모듈 이름과 하이픈이 들어간 stem은 이 범위에 포함되지 않습니다. JIT는 호스트 CPU에서 실행됩니다. Windows 네이티브 실행과 MSVC는 아직 검증되지 않았습니다. 오브젝트 파일이나 교차 링크된 실행 파일만으로 네이티브 동작을 입증할 수는 없습니다.

GPU/Tensor 실행, 전체 라이브러리 카탈로그, 사용자 정의 소멸자, 포매터와 디버거는 0.2에 포함되지 않습니다. 셀프 호스팅은 0.5로 예정되어 있습니다. 광범위한 설계 페이지의 API 목록보다 소스와 런타임 근거가 우선합니다.
