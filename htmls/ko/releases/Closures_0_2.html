클로저는 값입니다

클로저는 함수 본문과 명시적으로 캡처한 값을 결합합니다. 매개변수는 일반적인 타입 우선 문법을 사용하고, 화살표 뒤에는 반환 타입을 명시합니다. 클로저마다 고유한 구체 타입을 추론하려면 rsn 를 사용하세요.

i32 main() {
    i32 factor = 3;
    rsn multiply = [factor](i32 value) -> i32 {
        return value * factor;
    };
    return multiply(14) == 42 ? 0 : 1;
}

빈 캡처 목록의 표기는 []입니다. 바깥 지역 변수는 캡처 목록에 적어야 본문에서 사용할 수 있습니다. 클로저 식으로 변수를 초기화하므로 클로저 선언은 세미콜론으로 끝납니다.

구현된 범위. 이 예제는 0.2 컴파일러가 지원하는 동작을 설명합니다. 더 큰 컬렉션 API 카탈로그에는 추가로 제안된 콜백과 알고리즘이 포함됩니다.

각 값을 캡처하는 방식 선택하기

캡처의미원본에 미치는 영향
[value]값으로 캡처합니다. Copy 값은 복사하고 다른 값은 이동합니다.이동한 소유자는 이전 바인딩으로 사용할 수 없습니다.
[&read]공유 대여를 캡처합니다.대여가 살아 있는 동안 충돌하는 변경은 거절합니다.
[&mut write]배타적 대여를 캡처합니다.변경 가능한 원본 저장소가 필요하며 충돌하는 접근을 배제합니다.
[value, &read, &mut write]명시적 캡처 방식을 조합합니다.캡처한 각 값의 이동·대여 규칙은 그대로 유지됩니다.

본문에서는 대여한 캡처도 원래 이름으로 사용합니다. 저장된 참조를 통한 접근은 컴파일러가 처리하므로 캡처했다는 이유만으로 추가 역참조가 필요하지 않습니다.

i32 main() {
    i32 base = 10;
    rsn add_base = [&base](i32 value) -> i32 {
        return value + base;
    };
    return add_base(2) == 12 ? 0 : 1;
}

캡처한 참조는 원본 저장소보다 오래 살 수 없습니다. 호출로 소비되는 환경 내부의 참조를 반환하는 것도 거절합니다. 환경을 이동해도 캡처 필드가 지닌 수명 제한은 유지됩니다.

Fn, FnMut과 FnOnce

계약호출 수신자0.2 분류
Fn<Tuple<Args...>, Output>공유 대여: &F.Copy 값 캡처나 공유 대여 캡처만 사용하는 읽기 전용 클로저입니다.
FnMut<Tuple<Args...>, Output>배타적 대여: &mut F.명시적 배타적 캡처를 포함하여 캡처 값을 변경할 접근 권한이 필요한 클로저입니다.
FnOnce<Tuple<Args...>, Output>값: F.non-Copy 값을 캡처하여 소유하는 클로저입니다. 호출하면 환경을 소비합니다.

다음 Fn 클로저는 FnMut과 FnOnce 요구를 충족합니다. FnMut은 FnOnce 요구를 충족합니다. 반대 방향은 거절합니다. 인수와 결과 타입은 계약과 일치해야 합니다.

0.2의 분류는 보수적입니다. 본문에서 읽기만 하더라도 non-Copy 값을 하나라도 값으로 캡처하면 FnOnce가 됩니다. 캡처한 객체의 메서드 호출에도 환경을 변경할 접근 권한이 필요할 수 있습니다. 다른 언어에서 재사용할 수 있는 모든 클로저를 이 구현이 추론하지는 않습니다.

i32 main() {
    mut i32 total = 1;
    mut rsn change = [&mut total](i32 delta) -> i32 {
        total += delta;
        return total;
    };
    i32 first = change(2);
    i32 second = change(4);
    return first == 3 && second == 7 ? 0 : 1;
}

변경 가능한 클로저를 직접 호출하려면 mut 바인딩이 필요합니다. 원본 값이 변경 가능하다는 사실만으로 클로저 바인딩도 변경 가능해지지는 않습니다.

제네릭 함수에 클로저 전달하기

이 계약들은 기본 타입 환경에서 사용할 수 있습니다. 인수 튜플은 콜백 시그니처를 나타내며, 호출자는 런타임 튜플을 만들지 않고 일반 인수를 전달합니다.

T map<T, F>(T value, &F callback)
    where F implements Fn<Tuple<T>, T> {
    return callback(value);
}

i32 update<F>(&mut F callback, i32 value)
    where F implements FnMut<Tuple<i32>, i32> {
    return callback(value);
}

i32 main() {
    i32 factor = 3;
    rsn multiply = [factor](i32 value) -> i32 {
        return value * factor;
    };
    return map(4, &multiply) == 12 ? 0 : 1;
}

제네릭 본문은 선언된 계약에 따라 검사합니다. FnOnce 제약 아래에서 F callback 를 받는 함수는 한 번만 호출할 수 있으며 두 번째 호출은 이동 오류입니다. 재사용 가능한 콜백을 소비하지 않고 호출하려면 &F 또는 &mut F 를 해당 계약과 함께 사용하세요.

usize consume<F>(F callback, usize extra)
    where F implements FnOnce<Tuple<usize>, usize> {
    return callback(extra);
}

Result<usize, TextError> owned_example() {
    string text = string.from_view("abc")?;
    rsn once = [text](usize extra) -> usize {
        return string.byte_len(&text) + extra;
    };
    return Result.ok(consume(once, 2));
}

저장소, 호출과 현재 한계

컴파일러는 캡처 목록으로 구체적인 환경 레코드를 만들고 정적으로 선택되는 호출 함수를 생성합니다. 환경은 일반적인 값 저장소를 사용하므로 클로저를 만드는 것만으로 숨은 힙 객체를 할당하지는 않습니다. 캡처한 string이나 vector는 별도 버퍼를 소유할 수 있으며, 큰 Copy 값을 캡처하여 복사할 때는 일반적인 값 복사 비용이 듭니다.

특수화와 일반 LLVM 최적화가 환경 필드를 제거하거나 호출을 인라인화할 수 있습니다. 이러한 변환은 프로그램과 최적화 수준에 따라 달라집니다. 모든 클로저가 기계어에서 사라진다고 언어가 보장하지는 않습니다.

  • 캡처 목록과 매개변수 타입은 명시해야 합니다. -> 뒤에는 반환 타입을 반드시 적어야 합니다.
  • 현재 호출 계약은 구체적인 제네릭 콜백을 설명합니다. 소유형 동적 호출 래퍼와 dyn Fn 디스패치는 이 범위에 포함되지 않습니다.
  • 클로저 매개변수 목록은 인수 개수가 고정되어 있습니다. self 는 생성되는 수신자를 위한 예약 이름입니다.
  • CPU 병렬 worker 에는 검증된 이름 있는 함수가 필요합니다. 0.2의 parallel.for_each는 클로저를 받지 않습니다.

검사한 동작

클로저 통합 검사는 AOT·ORC JIT 호출, 실제 제네릭 Fn/FnMut/FnOnce 특수화, 공유·배타적 캡처와 소유 string 캡처를 검사합니다. 거절 검사는 암시적 지역 변수 캡처, 공유 캡처를 통한 쓰기, 변경 불가능한 FnMut 바인딩 호출, 충돌하는 원본 변경, FnOnce 재사용, 환경 참조의 수명 이탈과 병렬 worker로 전달한 클로저를 거절하는지 확인합니다.

이 컴파일러 검사와 각 릴리스 플랫폼의 최종 네이티브 검증은 별개입니다. 구현 범위 에 플랫폼별 현황을 기록합니다.
