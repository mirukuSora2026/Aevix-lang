확정 범위

사용자는 0.3의 전체 CPU 라이브러리 목표를 위해 작은 C++ 네이티브 연결층을 선택했다. GPU 전용 작업은 계속 보류한다. CPU 라이브러리 구현과 실행 검사는 승인되었으며, GPU 전용 작업은 승인 범위 밖에 있다.

개발 트리에는 파일과 프로세스의 별도 세대 레지스트리를 기반으로 하는 이동 전용 io.File·process.Child 소스 소유자가 있습니다. 등록된 비공개 연산은 파일 IO, UTF-8 path/fs/env 호출, 시계, sleep, argv 기반 프로세스 시작·대기를 검사된 컴파일러 연결과 AIR 내리기를 통해 연결합니다. 컴파일러가 관리하는 system 내장 기능은 표준 스트림의 범위가 있는 IO를 별도로 제공합니다. 이는 닫힌 라이브러리 부분 구현이며, 범용 네이티브 핸들 문법·임의의 FFI 권한·전체 CPU 카탈로그 지원을 뜻하지 않습니다. 공개된 0.2 프로필은 그대로입니다.

타입이 있는 네이티브 소유자

네이티브 소유자는 이동만 가능하며 C++ 타입에 자원 종류를 포함합니다. 이동하면 정리 책임도 이전합니다. 비어 있거나 이동된 소유자는 자원을 해제하지 않습니다. 정리는 noexcept이며 현재 소유자에 대해 한 번 실행합니다. 공개 원시 주소 접근자, 정수 변환, clone, 소유권을 떼어 내는 원시 release는 제공하지 않습니다.

C++ 타입 식별자는 서로 다른 자원 태그를 혼용하지 못하게 합니다. 그렇다고 핸들을 다른 스레드로 넘길 수 있다는 뜻은 아닙니다. 현재 소스 소유자는 스레드 간 이동이나 공유 권한을 제공하지 않으며, 이를 허용하려면 별도의 컴파일러 계약이 필요합니다.

범위가 있는 바이트 대여

소스 파일 API는 Slice<byte>와 MutSlice<byte>를 받으며, 수정 버퍼는 비공개 네이티브 호출 동안 수정 재대여합니다. 내부 C++ 어댑터는 범위가 있는 바이트 뷰를 사용합니다. 동기 호출 동안 입력은 읽기 전용이고 출력은 배타적으로 수정할 수 있습니다. 빈 버퍼는 유효합니다. 비어 있지 않은 버퍼는 null 데이터를 가질 수 없으며, 길이와 주소 범위 산술의 오버플로를 검사합니다.

포인터와 길이만 검사해서는 임의의 C++ 포인터가 가리키는 실제 할당 크기를 증명할 수 없습니다. 실제 배열이나 span에서 만든 뷰를 우선 사용합니다. 등록된 컴파일러 경로는 타입이 있는 슬라이스를 전달하고 동기 호출 동안 대여를 유지합니다. 원시 ABI는 신뢰된 네이티브 어댑터로 제한됩니다.

닫힌 연산 계약

앞서 만든 범용 C++ 서술자 기반은 Release·ReadBytes·WriteBytes를 정의하며, 현재 OS 라이브러리는 타입이 있는 별도의 닫힌 연산 레지스트리를 사용합니다. Release는 소유자를 소비하며 바이트 대여를 받지 않습니다. ReadBytes는 수정 가능한 네이티브 상태와 출력 버퍼를 모두 수정 대여합니다. WriteBytes는 수정 가능한 네이티브 상태를 수정 대여하고 입력 버퍼를 읽습니다. 바이트를 읽을 때도 파일 위치는 바뀔 수 있습니다.

모든 연산은 동기식입니다. 대여 보관·반환, Aevix 콜백, 대여한 버퍼를 사용하는 비동기 작업, Aevix 전역·persist 저장소 접근을 금지합니다. 알 수 없는 ID나 변경된 효과는 거부합니다. 정리 권한은 Release에만 있으며 일반 입출력에는 부여하지 않습니다.

일반 소스 호출자는 컴파일러 연결 심벌과 비공개 소스 헬퍼를 사용할 수 없습니다. 소스의 extern 선언, import 경로, 모듈 이름, 타입 이름, 사용자 어노테이션으로 네이티브 권한을 얻을 수 없습니다. 로더는 신뢰된 표준 모듈의 알려진 비공개 선언만 표시하며, 의미 검사는 닫힌 서명과 실제 모듈 식별자를 확인합니다. 임의의 공개 C extern 서명에는 기존 스칼라 전용 제한이 유지됩니다.

별도로 컴파일러가 관리하는 콘솔 intrinsic은 이 네이티브 핸들 연산 ID를 재사용하지 않는다. 동기 실행 효과가 알려진 연산이며 Aevix 대여를 보관하거나 Aevix 콜백을 호출하거나 Aevix persist 저장소를 살펴볼 수 없다. 일반 네이티브 핸들의 정리 권한은 바뀌지 않는다.

오류와 부분 처리량

내부 결과에는 상태, 네이티브 오류 코드, 완료한 바이트 수가 들어갑니다. 런타임은 진행량이 전달된 버퍼를 넘지 않는지 확인합니다. 일부 처리를 완료한 뒤 오류가 날 수 있으며, 오류가 롤백을 뜻하지는 않습니다. error 모듈은 OS 코드와 바이트 진행량을 담는 공개 IO 오류를 정의합니다. 현재 File과 OS 소스 래퍼는 등록된 런타임 결과를 명시적인 Result 값으로 변환하며, 범용 암시적 오류 변환은 없습니다.

자동 자원 해제는 flush나 close의 성공을 보고하지 못합니다. 실패 가능한 저장과 명시적 close에는 별도 Result API가 필요합니다. 실제 컴파일러 관리 바인딩이 필요한 효과를 증명하기 전까지 persist 정리에서 불명확한 외부 효과를 거부하는 기존 제한을 유지합니다.

신뢰하는 C++ 경계

네이티브 어댑터는 검토하는 C++ 런타임 코드입니다. 기술자 검사는 선언된 계약을 확인하며, 임의의 C++ 구현 자체를 증명하지는 않습니다. 악의적인 네이티브 코드의 포인터 보관이나 할당 범위 밖 쓰기를 막을 수는 없습니다. 어댑터를 작게 유지하고 범위가 있는 연산을 사용하며 부분 실패·자원 해제를 검사합니다.

이 기반은 AOT·JIT 실행 방식과 독립적입니다. 소스·네이티브 예제 검사는 등록된 파일, path/fs, 환경 변수, 시간, 프로세스 연산을 다룹니다. 지원하는 각 OS/CPU 조합은 여전히 자체 실행 검사가 필요하며, 교차 대상 오브젝트 생성만으로 실행이 검증되지는 않습니다.

소스 통합의 완료 조건

현재 등록된 소스 호출은 신뢰된 선언·모듈 식별자로 연결하고, 정확한 서명과 자원 역할을 검사하며, 연산을 AIR로 전달하고, 비공개 헬퍼의 일반 호출을 거부합니다. 새 네이티브 자원 종류에는 소유권, 정리, 생성, 대여, 효과, AOT/JIT 검사가 모두 필요합니다. 사용자 이름이나 경로가 일치하는 것만으로는 권한을 얻을 수 없습니다. 파일시스템 순회, 손실 없는 네이티브 경로, 프로세스 출력 수집·리디렉션·시간 제한, 일반 동기화와 나머지 CPU 카탈로그는 이 부분 구현에 포함되지 않습니다.
