선택한 범위와 현황

선택된 0.3 범위: 명시적으로 import하는 system 모듈이 제공할 함수는 print, println, printf, input, flush, 및 log입니다. print와 println에는 텍스트나 내장 스칼라를 직접 전달할 수 있고, 텍스트와 타입이 정해진 값을 다음 연산자로 조합할 수도 있습니다: +. 기존 자원·FFI·라이브러리 기반 목표에 콘솔 IO를 추가합니다. 출력 전용 포매팅·조합 규칙은 아래에 명시합니다.

0.2에는 미구현입니다. 아래 예제는 개발 중인 컴파일러를 대상으로 하며, 배포된 0.2 컴파일러가 받아들이는 프로그램은 아니다. 현재 작업 트리에는 컴파일러와 런타임 구현이 있고 0.3 출시 전에 AOT/JIT 회귀 검사를 마무리하고 있다. 아래 계약은 이 구현과 더 넓은 라이브러리 카탈로그를 구분한다.

선택된 함수 계획한 용도 권장 결과
system.print(value_or_composition) 줄바꿈 없이 대여한 텍스트, 내장 스칼라 또는 조합한 조각을 출력합니다. Result<unit, system.IoError>
system.println(value_or_composition) 대여한 텍스트, 내장 스칼라 또는 조합한 조각을 출력하고 줄바꿈을 붙입니다. Result<unit, system.IoError>
system.printf(format, values...) 포맷에 맞춰 출력하며 줄바꿈을 자동으로 붙이지 않습니다. Result<unit, system.IoError>
system.input<T = string>() string은 완전한 UTF-8 한 줄을, 지원되는 스칼라는 공백으로 구분한 토큰 하나를 읽는다. Result<Optional<T>, system.ReadError>
system.flush() 표준 출력을 명시적으로 flush한다. Result<unit, system.IoError>
system.log(level, message, code = "") info, warning, error 레코드를 표준 오류에 쓴다. 텍스트 코드는 생략할 수 있다. Result<unit, system.IoError>

이 표는 호출 형태이며 가변 인수 함수 선언이나 범용 조합 타입을 정의하지 않는다. print와 println에는 값 하나가 필요하다. printf와 log는 아래에서 설명하는 별도의 검사된 호출 형태를 사용한다. 사용자 정의 타입의 출력은 아직 구현하지 않았다.

import와 호출 형태

모듈 전체를 가져오는 import system; 는 다음과 같은 한정된 호출을 사용합니다: system.print(...) . 내보낸 오류 이름은 system.IoError입니다. IO 타입을 자동 prelude에 추가하지 않습니다.

import system;

Result<unit, system.IoError> write_summary(string_view label, i32 count) {
    system.print("Summary: ")?;
    system.println(label)?;
    system.printf("%s: %d\n", label, count)?;
    return Result.ok(Unit.value());
}

Result를 반환하도록 제안한 보조 함수입니다. 기존에 선택한 i32 main() 규약을 바꾸거나 ? 를 호환되지 않는 정수 반환 main에서 허용하지는 않습니다.

선택적 import에는 기존 규칙을 적용합니다. 별도 파일의 다음 형태는 선택한 이름만 노출하며 무관한 system 내보내기는 따로 import해야 합니다. 이름 충돌에는 import한 모듈 한정 경로를 사용하며 새 별칭·오버로드 병합 규칙은 추가하지 않습니다.

import system { println, IoError };

Result<unit, IoError> announce() {
    println("ready")?;
    return Result.ok(Unit.value());
}

출력과 오류

인식된 print·println 호출은 string_view, 대여한 소유 string, 내장 스칼라 또는 아래 출력 조합을 받습니다. 이 출력 문맥에서는 소유 string 인수를 자동으로 대여하여 읽습니다. 다음 명시적 호출도 유효합니다: string.view(owner) . 소유 string 조각에도 같은 비소비 대여 규칙을 적용합니다. 소유자를 이동하거나 clone하지 않으며 반환 뒤에 호출자의 대여를 보관할 수도 없습니다. 포매팅·내부 버퍼링의 복사·할당에는 비용과 실패 동작을 명시해야 합니다.

출력의 반환 타입은 Result<unit, system.IoError> 입니다. 쓰기와 자원 연산이 실패할 수 있기 때문입니다. 앞부분을 성공적으로 쓴 뒤에도 Err가 발생할 수 있으며 터미널 출력을 되돌릴 수는 없습니다. 하위 계층의 짧은 쓰기는 명세된 write-all 정책으로 처리해야 합니다. 오류 뒤에 호출자가 메시지 전체를 무조건 다시 보내도 된다고 약속해서는 안 됩니다.

error 모듈은 ReadFailed, WriteFailed, FlushFailed, Interrupted, WouldBlock, Closed, InvalidUtf8, InputTooLong, AllocationFailure, SizeOverflow, Unsupported를 정의한다. 읽기·쓰기 실패에는 제공 가능한 OS 코드와 payload 바이트 진행량을 보존한다. EOF는 Optional의 부재이며 OS 오류가 아니다. 런타임은 프로세스 전체의 시그널 처리기를 설치하지 않는다. broken pipe 시그널은 호스트 프로세스의 정책을 따르므로 Result를 반환하기 전에 프로세스가 종료될 수 있다.

+로 출력 조합하기

권장하는 0.3 의미: 인식된 system.print 또는 system.println 호출의 출력 인수 안에서는 + 노드에 텍스트 피연산자가 있으면 출력 조각을 결합합니다. 이미 만들어진 조합도 텍스트 피연산자로 취급하므로 다른 타입의 값을 계속 연결할 수 있습니다. 컴파일러는 선택적 import를 포함해 실제 import된 선언을 해석합니다. 이름만 print나 println인 무관한 함수에는 특별 동작을 적용하지 않습니다. 출력 호출 전용 구문이며 전역 string 연산자나 암시적 스칼라→string 변환이 아닙니다.

초기에 직접 인수와 조합 조각으로 지원할 값은 string, string_view, 내장 부호 있는 정수와 부호 없는 정수, f32/f64, bool, char, 및 byte입니다. 직접 전달한 값도 조각과 같은 내장 포매터를 사용합니다. 텍스트는 UTF-8 바이트를 유지하고 정수는 십진 숫자를 사용합니다. bool의 표기는 true 또는 false이며 char는 유니코드 스칼라를 UTF-8로 씁니다. byte는 0x 뒤에 소문자 16진수 두 자리를 정확히 붙여 수치 u8과 구별합니다.

지원되는 f32/f64 값은 원래 부동소수 형식의 값으로 다시 변환할 수 있는 가장 짧은 10진수 텍스트를 사용하며 로캘에 의존하지 않는다. 현재 콘솔 특수화는 f16과 bf16을 거부한다. 음의 0의 부호를 보존하며, 비유한 값은 다음 표기를 사용한다: nan, inf, 또는 -inf. NaN payload를 텍스트로 보존한다고 보장하지 않는다. 유한 값은 연결된 C++ 런타임의 std::to_chars로 원래 값으로 다시 변환할 수 있는 최단 문자열로 만든다. 고정 표기와 지수 표기의 선택을 버전 간 직렬화 형식으로 보장하지는 않는다. 안정적인 저장 형식에는 별도의 명세를 갖춘 코덱을 사용한다. 임의의 구조체·인터페이스 변환, 암시적 unwrap, Result·Optional payload 변환은 추가하지 않는다.

일반적인 우선순위, 괄호 묶음과 왼쪽 결합을 유지합니다. 숫자 피연산자 둘은 기존 타입·산술 실패 규칙에 따라 숫자 결과를 계산합니다. 식의 다른 위치에 string이 있다고 앞선 숫자 부분 트리를 개별 출력 값으로 평탄화해서는 안 됩니다.

import system;

Result<unit, system.IoError> write_count(i32 count) {
    system.println("count: " + count)?;
    system.println(count)?;
    system.println(count + 1)?;
    system.println("sum: " + 1 + 2)?;
    system.println("sum: " + (1 + 2))?;
    system.println(1 + 2 + " apples")?;
    return Result.ok(Unit.value());
}

count가 5이면 각 줄은 count: 5, 5, 6, sum: 12, sum: 3, 및 3 apples순서로 출력됩니다. 넷째 줄은 정수 조각 둘을 표시하며 셋째·다섯째·여섯째 줄은 먼저 숫자 합을 계산합니다. 별도의 반환 전용 bool→정수 편의 기능이 있어도 bool 값의 출력은 계속 논리 텍스트입니다. 자세한 내용: 0.3 편의 기능 계획.

평가·소유권·비용

이 출력 호출이 첫 바이트를 쓰기 전에 피연산자를 왼쪽부터 오른쪽으로 각각 한 번 평가합니다. 숫자 부분식과 피연산자 내부의 일반 단락·조건부 평가를 유지합니다. 말단 식은 다른 출력 호출을 포함해 자체 부작용을 가질 수 있고 그 효과는 되돌리지 않습니다. 평가가 ? 를 통해 탈출하거나 끝나지 않으면 바깥 출력 호출은 아직 쓰기를 시작하지 않은 상태입니다.

소유 string은 대여하여 읽고 각 텍스트 대여와 임시 소유자는 호출이 반환할 때까지 유지합니다. 스칼라 조각 값은 일반 Copy 규칙으로 복사합니다. 암시적 소유자 이동이나 깊은 clone은 없습니다. 이미 대여한 string을 나중 피연산자에서 변경하려 하면 대여 검사기가 거절합니다. 예를 들어 name을 읽는 조합에서 나중에 &mut name 을 요구하는 함수를 호출하면 두 접근을 동시에 유지할 수 없습니다.

import system;

Result<unit, system.IoError> show_label(&string label, i32 count) {
    system.println(*label)?;
    system.println("label: " + *label + ", count: " + count)?;
    return Result.ok(Unit.value());
}

두 호출 모두 label을 통해 기존 소유자를 읽으며 소비하지 않습니다. 각 텍스트 대여는 내부 버퍼링을 포함한 해당 호출의 쓰기가 끝날 때까지 유효합니다.

이 구문에 중간 소유 string은 필요하지 않습니다. 스칼라 포매팅과 바이트를 출력 스트림으로 복사하는 작업은 여전히 있습니다. 포매팅·버퍼링에서 할당한다면 할당·용량 실패를 호출의 Result<unit, system.IoError> 계약에 명시적으로 포함해야 합니다. 항상 할당이 없다고 홍보해서는 안 됩니다. 일부를 출력한 뒤 쓰기가 실패할 수 있으며 println의 줄바꿈 추가도 같은 실패 가능 호출의 일부입니다.

출력 호출 단위 잠금은 피연산자 평가 후에 얻습니다. 이후 같은 스트림 API의 다른 호출에 대해 조합한 조각과 줄바꿈을 한 호출로 직렬화합니다. 여러 호출이 한 트랜잭션이 되지는 않으며 독립적인 OS writer는 이 보장 밖에 있습니다. 출력이 암시적으로 flush를 수행하지는 않습니다.

출력 밖에서의 경계

조합은 인식된 출력 호출이 소비합니다. 변수에 대입하거나 반환·캡처하거나 숨은 string 값처럼 임의의 보조 함수에 전달할 수는 없습니다. 조합 전체에 괄호를 붙여도 소유자가 되지는 않습니다. 다른 위치의 숫자 + 와 기존 타입 호환 규칙은 바뀌지 않습니다. 일반 소유 텍스트 생성은 별도의 실패 가능한 연산으로 유지하며, 제안된 string.concat 및 string.format API의 반환 타입은 Result<string, TextError>입니다. 이 카탈로그 항목들이 0.2에 구현된 대안이라는 뜻은 아닙니다.

이 구문은 printf의 컴파일 타임 포맷 요구를 완화하거나 기존의 동종 values[] 가변 인수를 바꾸거나 일반 사용자 정의 연산자 오버로딩을 추가하지 않는다. AOT/JIT의 승인·거부 검사는 인식된 선언, 조합의 경계, 평가 순서와 대여 수명을 확인한다.

C varargs 없는 검사형 printf

초기에 권장하는 printf 는 익숙한 백분율 스타일 변환을 사용하되 포맷·인수 수·인수 타입을 컴파일 시점에 검사합니다. 포맷은 우선 리터럴 또는 지원하는 컴파일 타임 string으로 제한합니다. 예제의 표기는 %s 가 string_view, %d 가 i32, %% 를 쓰면 문자 그대로의 퍼센트를 출력한다. 구현된 변환은 %s 는 텍스트에, %d 는 부호 있는 정수에, %u 는 부호 없는 정수에 사용한다. %f 및 %g 는 f32/f64에, %c 는 char에, %b 는 bool에 사용하고, %% 를 쓰면 문자 그대로의 퍼센트를 출력한다. 두 부동소수 변환 모두 원래 값으로 다시 변환할 수 있는 가장 짧은 텍스트를 사용한다. C printf처럼 소수점 이하 여섯 자리를 기본으로 출력한다고 보장하지 않는다. 폭, 정밀도, 길이 수정자, 그 밖의 변환은 컴파일 타임에 거부한다. 다음과 같은 안전하지 않은 변환은 금지한다: %n.

혼합 타입 인수는 컴파일러가 검사하는 intrinsic을 사용한다. 예제의 string_view와 i32 인수는 의도적으로 서로 다른 타입입니다. 기존의 동종 i32 values[] 가변 인수 매개변수 문법을 확장한 것은 아니다. 컴파일러는 기존 문법이나 소유권 규칙을 바꾸지 않고 모든 자리 표시자와 값을 검사한다.

이 인터페이스를 검사되지 않은 C varargs로 lowering하거나 C의 기본 인수 승격에 의존해서는 안 됩니다. 포맷 문자열이 암시적 소유권 이동, 깊은 clone이나 임의의 출력 가능 타입 변환을 추가하지는 않습니다. 잘못된 정적 포맷은 컴파일 오류로 처리하고 실제 출력·자원 실패는 Result 값으로 유지합니다.

타입이 있는 입력·EOF·UTF-8

input() 및 input<string>() return Result<Optional<string>, system.ReadError>. 문자열은 한 줄 안의 모든 공백을 보존한다. 입력이 he ll o 이면 그 텍스트를 그대로 얻는다. LF와 CRLF 줄 끝은 제거하지만 단독 CR은 텍스트에 남는다. 안쪽 Optional로 빈 줄과 EOF를 구분한다. 소유 문자열에는 할당과 소유권 이전이 명시적으로 드러난다.

input<i32>() 등 지원되는 스칼라 특수화는 앞쪽 ASCII 공백을 건너뛰고 토큰 하나를 읽는다. 다음 입력에서 정수 세 개를 읽으면 10 20 30 이면 10, 20, 30을 얻는다. 토큰 뒤의 구분자는 스트림에 남으므로, 바로 뒤에서 문자열을 입력받으면 그 줄의 나머지가 빈 문자열일 수 있다. 자동으로 줄을 건너뛰지 않는다. char 입력은 유니코드 스칼라 하나로 이루어진 토큰을 읽는다. 이는 공백으로 구분한 토큰 추출이며, C++ iostream의 모든 숫자 접두사 해석이나 로캘 동작을 보장하지 않는다.

스칼라 토큰에는 다음과 동일하게 입력 전체를 엄격하게 변환하는 규칙을 적용한다: T.parse(value): 8~128비트 정수와 별칭, f32/f64, bool, char, byte를 지원한다. 비유한 부동소수 값, 잘못된 형식, 표현 범위를 벗어난 값은 오류다. ReadError.Io 는 다음 값을 담는다: IoError; ReadError.Parse 는 다음 값을 담는다: ParseError. 입력이 실패해도 일부 바이트는 이미 소비되었을 수 있다. 잘못된 토큰도 소비하므로 다음 토큰을 읽을 때 앞으로 진행할 수 있다.

관측한 입력 권장 결과
텍스트 뒤에 줄 종결자가 있는 줄 Ok(Some(text))이며 종결자는 제거합니다.
빈 줄 Ok(Some(""))이며 EOF가 아닙니다.
다음 줄의 바이트를 하나도 읽기 전에 EOF Ok(None).
종결자 없이 끝나는 마지막 줄 뒤의 EOF Ok(Some(text))를 반환하고, 다음 성공한 읽기에서 None을 반환합니다.
잘못된 UTF-8, IO 실패, 크기 제한 실패 또는 할당 실패 Err(...) 를 검토된 오류 정책에 따라 반환합니다.

표에는 생성자 문법이 아닌 결과 표기를 사용한다. 빈 줄의 payload는 소유권을 가진 빈 문자열이다. 네이티브 스트림 경계는 UTF-8 바이트를 읽고 쓴다. macOS ARM64에서는 로컬 실행으로 확인했지만, Linux와 Windows의 네이티브 콘솔 동작은 Windows 콘솔 코드 페이지 처리를 포함해 각 대상 환경에서 통과해야 할 조건으로 남는다.

구현은 LF와 CRLF 줄 끝을 인식해 제거하고, 단독 CR은 보존하며, 잘못된 UTF-8은 대체 문자로 바꾸지 않고 거부한다. 버퍼 크기는 대상 환경의 ptrdiff 한도를 넘을 수 없다. 읽기가 실패하면 제공 가능한 OS 오류와 payload 바이트 진행량을 보존한다. 할당이나 디코딩이 실패해도 이미 소비한 입력은 되돌리지 않는다.

import system;

Result<Optional<string>, system.ReadError> read_next_line() {
    return system.input();
}

구조화된 로깅

system.log(level, message, code) 는 다음을 받는다: system.info, system.warn, 또는 system.error는 해당하는 다음 항목을 식별한다: system.LogLevel 변형에 해당한다. 마지막 텍스트 코드가 필요하지 않으면 생략한다. 로그는 stderr에 기록하며 다음을 반환한다: Result<unit, system.IoError>이므로 호출자가 쓰기 실패를 전파할 수 있다. 제어 흐름이 예외 방식으로 바뀌지는 않는다.

import system;

Result<unit, system.IoError> announce() {
    system.log(system.info, "Compiler ready")?;
    system.log(system.warn, "Cache entry ignored", "W1001")?;
    system.log(system.error, "Cannot open source", "E1001")?;
    return Result.ok(Unit.value());
}

레코드 형식은 [INFO] Compiler ready, [WARN W1001] Cache entry ignored, 및 [ERROR E1001] Cannot open source이며, 각 레코드 끝에 줄바꿈 하나를 붙인다. 인수를 평가하고 형식을 변환한 다음, 레코드 전체를 출력하는 동안 출력 잠금을 유지한다. 로그에 타임스탬프, 색상, 파일 출력, 자동 flush 또는 영구적인 오류 코드 레지스트리를 추가하지 않는다. 코드는 애플리케이션이 제공하는 텍스트다. 계획된 0.5 컴파일러 진단 는 버전이 있는 자체 컴파일러 코드와 소스 위치 모델을 사용한다.

버퍼링·flush·자원 경계

쓰기, 라이브러리 버퍼의 flush와 자원 해제를 구분합니다. 버퍼에 성공적으로 썼다고 터미널에 이미 표시됐다는 뜻은 아닙니다. 줄바꿈 추가가 명세되지 않은 flush를 암시해서도 안 됩니다.

추가로 선택한 연산: 명시적인 system.flush() 호출이며 반환 타입은 Result<unit, system.IoError>를 사용해야 한다. 특히 프롬프트를 출력한 뒤 입력을 기다리기 전에 필요하다. 이 기능은 0.3 콘솔 구현에 포함된다.

지원하는 OS마다 표준 스트림 소유권, 리디렉션과 닫기 동작을 정의합니다. 자동 정리가 실패 가능한 flush의 성공을 보장하지는 않습니다. 피연산자 평가 뒤 스레드 안전한 호출 단위 스트림 직렬화를 권장하되 경쟁하는 호출 사이의 상대 순서는 정하지 않습니다. 여러 호출이 자동으로 하나의 출력 트랜잭션을 이루지는 않습니다.

공개 system API는 검토된 text/format 및 io/resource 기능 위의 편의 계층이어야 한다. 길이가 있는 바이트 대여, 소유권, OS 오류 변환, 안전한 FFI 규칙을 우회하면 안 된다. 이 콘솔 구현은 동기식이며 GPU 연산이나 셸 실행을 구현하지 않는다. 승인된 더 넓은 CPU 라이브러리 작업은 별개로 진행한다.

현재 AOT 경로는 대상에 맞는 Aevix C++ 런타임 아카이브와 C++ 표준 라이브러리를 연결한다. macOS에서는 libc++, Linux와 GNU Windows에서는 libstdc++를 사용하며 Linux에는 pthread 지원도 필요하다. 교차 대상 객체에는 아직 연결되지 않은 런타임 호출이 남을 수 있다. 실행 파일을 만들려면 대상에 맞는 런타임·링커·sysroot가 필요하다.

검토·구현 완료 조건

  1. 텍스트·스칼라 직접 전달과 조합의 호출 형태, 정확한 결과 타입, 오류 범주, 줄바꿈 정책과 명시적 flush 단계를 확정합니다.
  2. 최단 부동소수점 표현의 동률 처리와 고정·지수 표기 선택을 명세하고, 부호 있는 0·비유한 값·소문자 두 자리 byte 출력을 검사합니다. 일반 숫자 +를 바꾸지 않고 인식할 import 선언, 조합 문맥, 평가 순서, 대여·임시값 수명과 실패 가능한 할당을 정합니다.
  3. 동종 가변 인수를 바꾸지 않고 혼합 타입 printf intrinsic과 검사할 포맷 문법을 승인합니다.
  4. 동기 표준 스트림에 필요한 자원·FFI·바이트·UTF-8·할당·오류 기반을 완성합니다.
  5. 직접 전달한 스칼라·대여한 소유자, 텍스트·스칼라 연쇄, 괄호로 묶은 숫자 합, 정수 오버플로, 한 번의 평가, 충돌하는 변경, 임시값 정리와 출력 전 탈출을 검사합니다. 저장된 조합, 이름만 같은 무관한 함수와 지원하지 않는 출력 타입은 거절합니다.
  6. 빈 입력·빈 줄·CRLF·종결자 없는 마지막 줄·잘못된 UTF-8·크기 제한·할당 실패·짧거나 중단된 쓰기·부분 출력·broken pipe·리디렉션 스트림·flush 오류·동시 호출을 구현하고 검사합니다.
  7. 지원 대상의 AOT·JIT에서 같은 언어·소유권 동작을 검증합니다. 그 후에만 구현된 함수라고 설명합니다.

라이브러리 기반 에 더 넓은 구현 순서를 기록합니다. 0.2 실행 가능 범위 는 이 계획 문서로 바뀌지 않습니다.
