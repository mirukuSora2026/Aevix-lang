제안과 현재 범위

0.3의 목표는 동기식 CPU 라이브러리 카탈로그 전체입니다. 실행을 중단했다가 이어가는 Task 계약 10개와 async 기반은 0.4에 포함합니다. GPU 전용 Pending, 장치 큐, 커널, 전송은 계속 보류합니다. 구현과 기능별 실행 검사는 승인되었지만 CPU 카탈로그 전체는 아직 미완성입니다. 공개된 0.2 프로필은 기존 릴리스의 지원 범위를 나타냅니다.

현재 소스 모듈은 명시적 오류, Optional/Result 변환, Array/Slice 도우미, 해시 및 AVL 순서 컬렉션, 텍스트·코덱, CPU shape/tensor/quantization 기반, 스칼라 도우미, 등록된 File/Process/path/fs/env/time 연산을 제공합니다. 컴파일러에 연결된 Shared/Weak, Atomic, Mutex/RwLock, 소유 Task 연산에는 해당 범위의 소유권·실행 검사가 있습니다. 제공 함수마다 명시적인 소스 호출 형식과 오류 타입을 사용하므로, 공개 선언 개수만으로 모든 원본 서명·콜백·비용·수명 계약의 완성을 판단하지 않습니다.

기록된 39088693 체크포인트는 macOS ARM64에서 CTest 138개 전체를 703.69초 만에 통과했습니다. 동결한 컴파일러·런타임·라이브러리·테스트·도구·데이터 입력 526개와 수명 주기가 기록된 공개 선언 3,797개가 검사한 스냅샷을 식별합니다. 이후 변경에는 별도 근거가 필요하며, 이 결과가 Linux·Windows 실행이나 CPU 전체 지원을 입증하지는 않습니다. 성능을 바꾸는 최적화는 Claude의 최종 검토까지 계속 보류합니다.

네이티브 자원은 선택된 타입이 있는 네이티브 경계 기반을 사용합니다. 개발 트리에는 컴파일러가 관리하는 Drop, 콘솔 호출과 별도의 타입별 레지스트리 식별자를 기반으로 하는 이동 전용 io.File·process.Child 소유자가 있습니다. 신뢰된 표준 모듈의 알려진 비공개 헬퍼는 검사된 서명과 닫힌 연산 연결을 사용합니다. 이것이 임의의 소스 extern에 네이티브 권한을 주거나 자원 카탈로그 전체를 완성하지는 않습니다.

현재 바이트·소유 Task 프로필

import하는 bytes 모듈은 일반 소스 함수 128개를 제공하며 bytes.ByteError에는 변형 16개가 있습니다. i128/u128까지의 명시적 LE/BE 정수 코덱, f16/bf16/f32/f64의 정확한 표현 코덱, 스칼라 비트 연산, 엄격한 이진·hex 텍스트, 겹침에 안전한 복사, 실패 가능한 소유 버퍼 확장·슬라이싱, 엄격한 UTF8 검사·소유 변환을 포함합니다. 수정 전에 전체 범위와 용량을 검사합니다. UTF8 디코딩은 먼저 검사한 뒤 string.from_utf8에서 다시 검사하고 복사할 수 있으므로, 한 번의 순회나 할당 없는 처리를 약속하지 않습니다. 네이티브 엔디언 코덱, 지연 반복자, 원본 Byte 서명과의 정확한 대응은 별도 계약입니다.

copy_within은 오름차순의 단위 간격 범위를 받습니다. 버퍼 길이에서 시작·끝이 같은 열린 빈 범위와 목적지가 버퍼 길이인 빈 복사는 유효합니다. 끝점이 뒤집히면 ReversedRange를 반환하고, 내림차순이나 단위 간격이 아닌 설명자는 비어 있어도 NonContiguousRange로 거부합니다. 닫힌 끝점은 1을 더하기 전에 기존 원소를 가리키는지 검사합니다. 원본·목적지 검사를 모두 마친 뒤에만 쓰고, 겹침에 맞춰 안전한 방향으로 복사하며 할당하지 않습니다.

spawn으로 실행하는 Task 작업은 허용된 작업자마다 네이티브 스레드 하나를 사용합니다. 인수 없는 구체적인 컴파일러 클로저 중 캡처·결과를 온전히 소유하고, 전달·간접 호출·전역 접근·Drop 효과 검사를 통과한 경우만 허용합니다. 정적 수명의 대여 뷰도 거부합니다. 각 관찰 핸들은 지역 Scope의 대여를 유지합니다. 이 프로필에서는 Task/Scope의 전역·persist 저장, 중첩 스코프, 작업 스레드 안의 spawn, 대여 작업, 풀, detach를 지원하지 않습니다. Shared/Weak·잠금·Atomic의 조건부 스레드 전달 판정이 이 허용·정리 검사를 생략하게 하지는 않습니다.

Task를 discard해도 관찰 권한만 소비하며 작업과 정리 의무는 Scope에 남습니다. join은 작업이 반환한 Result를 자동으로 합치지 않습니다. 회수를 재시도해야 하면 ScopeError.Retry가 닫힌 Scope를 보존합니다. close_admission은 여러 번 호출해도 안전하지만 완료를 기다리지는 않습니다. active_count는 준비·대기·실행 중인 자식을 포함하는 관찰 순회이며, 하나의 일관된 시점이나 완료를 보장하지 않습니다. scope_status는 Open/Closing만 제공합니다. executor는 선택한 네이티브 스레드 백엔드를 나타내며 고유한 스케줄러·스레드 식별자가 아닙니다.

원본 Task 59개 항목 중 현재 소스 후보가 있는 항목은 27개이며, 대응하는 호출 제공자가 없는 항목은 32개입니다. 동기식 계약 22개는 계속 0.3의 목표이고 Awaitable·중단형 계약 10개는 0.4에 포함합니다. Task.wait는 원본 59개에 없는 추가 블로킹 편의 함수입니다. Task.id와 Task.ready는 기록된 138개 테스트 체크포인트 이후 추가했으며, 해당 기능의 별도 검증 근거를 구분합니다. 이름이 일치해도 정확한 서명·소유권·결과 타입·비용 계약은 별도로 맞춰야 합니다.

Task.ready는 이미 계산된 소유 값을 Scope에 옮기며 작업자 스레드를 시작하지 않습니다. 관리 정보와 결과 저장소를 할당할 수 있고 SpawnError를 담는 실패 가능한 결과를 반환합니다. 생성에 실패하면 값으로 전달받은 입력을 소비하고 정리합니다. 초기 지원 범위에서는 대여한 데이터와 숨은 Task 대여를 거부합니다. Task.id는 불투명한 Copy 진단용 식별자를 반환하며 네이티브 핸들이나 주소를 노출하지 않고 Scope의 수명을 연장하지 않습니다.

Task.cancel_token과 cancel_clone은 CancellationError를 사용하는 실패 가능한 결과를 반환합니다. Task.cancellation은 Result<CancellationToken, TaskError>를 반환하며 알림 상태만 보존합니다. Task·Scope·캡처·결과·JIT 코드의 수명은 연장하지 않습니다. request_cancel은 별개 타입인 TaskCancelRequest를 사용합니다. 취소는 계속 협력 방식입니다. deadline_after는 검사한 단조 시간을 조합하며 async 타이머를 등록하거나 호출자를 중단하지 않습니다.

0.3 system 편의 계층

선택된 0.3 콘솔 범위에는 import system; 와 콘솔 함수 system.print, system.println, system.printf, 및 system.input, system.flush, 및 system.log. 이 기능은 0.2에 구현되어 있지 않습니다. 콘솔 IO 계획 에는 텍스트·스칼라의 직접 출력과 출력 전용 + 조합을 지원하며, 명시적 Result 오류, 한 줄 전체의 문자열 입력, 토큰 단위 스칼라 입력, 선택적인 로그 코드, flush를 제공한다. 연결된 페이지에 현재 계약과 대상 환경별 실행 한계를 기록한다. 이 편의 기능 계획 은 반환 전용 bool→정수 변환, 명시적 Boolean 변환, 필드 축약과 원시 리터럴을 유지합니다.

system은 아래의 text/bytes/convert 및 io 기반 위에 공개 편의 계층으로 둔다. 검사하지 않은 C 가변 인수를 추가하는 대신 기존의 형식 변환, 길이가 있는 버퍼, 스트림, 자원, 오류 계약을 재사용한다. 서로 다른 타입을 받는 printf 인수는 검사된 0.3 내장 기능을 사용한다. 기존의 같은 타입만 받는 values[] 가변 인수 문법은 바뀌지 않습니다. 기존 자원·FFI 목표와 구현 순서를 유지합니다.

표현 비트·범위 조회

Float.from_bits<T>와 Float.to_bits는 f16/bf16과 u16, f32와 u32, f64와 u64 사이의 정확한 표현 비트를 재해석합니다. 이 컴파일러 내장 기능은 산술·수치 변환·할당·NaN 정규화를 수행하지 않습니다. 부호 있는 0과 NaN 데이터 비트도 유지합니다. 스칼라 수학과 별개이며 지원하지 않는 f8 오버로드를 추가하지 않습니다. bytes 코덱은 명시적으로 선택한 바이트 순서로 이 표현을 읽고 씁니다.

Range.start/end/step_magnitude/step/is_inclusive/is_descending/is_empty는 정수 Range를 읽기 대여해 소비하거나 진행시키지 않고 조회합니다. 간격은 방향과 짝을 이루는 부호 없는 크기입니다. import하는 ordering 모듈은 공통 Copy 열거형 Ordering.Less/Equal/Greater와 순수 도우미 10개를 제공하며 bytes도 같은 타입을 재공개합니다. 정수 변환은 열거형 배치 대신 -1/0/1을 사용하며 then의 인수는 호출 전에 이미 평가됩니다. ordering과 bytes는 새 원시 타입이나 자동 제공 모듈이 아닙니다.

import하는 스칼라·유니코드 프로필

명시적으로 import하는 floating 모듈은 f16/bf16/f32/f64의 분류·부호·크기·인접 값·전체 순서·형식 상수를 위한 소스 함수 108개를 추가합니다. 정확한 표현 도우미가 낮은 정밀도 산술을 자동으로 넓히거나 f8을 추가하지는 않습니다. 기존 math 모듈은 네이티브 f32/f64 C 수학 함수를 감쌉니다. 호스트의 수치 동작이 모든 플랫폼에서 올바른 반올림을 보장하지는 않으며, lgamma에는 스레드에 안전한 재진입 연결층이 더 필요합니다.

명시적으로 import하는 integer 모듈은 128비트와 네이티브 너비까지의 부호 있는·없는 정수 12종에 대해 함수 이름 48개, 오버로드 528개, 상수 24개를 제공합니다. 검사·순환·포화·넘침 보고 산술, 비트 연산, 크기 도우미는 소스 타입 IntegerArithmeticError를 사용합니다. 원본 Integer 이름 공간을 자동으로 연결하는 기능은 아닙니다. 더 넓은 시프트·비트 필드, 나눗셈 반올림, 파싱·서식화, 변환 계약은 항목별로 남아 있습니다.

명시적으로 import하는 unicode 모듈에는 스칼라·ASCII·코드 단위·속성·대소문자·이름 함수 107개가 있습니다. Char 카탈로그는 Core 직접 연결 2개, 같은 결과 타입을 사용하는 소스 대안 76개, UnicodeError로 오류 타입을 바꾼 소스 대안 29개로 대응됩니다. 소스 대안이 Char 이름 공간의 메서드를 추가하지는 않습니다. 함수 50개는 재현 가능한 테이블과 완전한 원본 라이선스를 갖춘 고정 Unicode 17 데이터를 사용합니다. 전체 대소문자 매핑은 독립 스칼라의 기본 규칙을 적용합니다. 속성 조회는 문자열 전체 정규화, 자소·단어·문장 분할, 문맥·로케일 대소문자 변환, 정렬, 양방향 배치, 터미널 너비 기능을 제공하지 않습니다.

명시적으로 import하는 boolean 모듈은 정수 0/1·0이 아닌 값 정책, 즉시·지연 소유 값 선택, 엄격한 파싱, 실패 가능한 텍스트, 트랜잭션 방식의 제한된 버퍼 출력을 위한 소스 함수 20개를 제공합니다. BooleanError는 설계상의 AllocError/BufferError 서명과 다른 오류 타입입니다. 검사를 통과한 이 스칼라 제공자는 사용할 수 있는 CPU 부분집합을 넓히지만 Boolean·Float·Integer·Char·SIMD·Tensor 카탈로그의 모든 계약을 완성하지는 않습니다.

기존 카탈로그에 추가할 기능

  • 확장되는 소스·AST·타입 테이블을 위한 소스 범위와 타입이 지정된 ID.
  • 구조화된 IO 오류와 컴파일러 진단으로의 명시적 오류 매핑. 개발 중인 Error 인터페이스는 읽기 대여를 통한 검사를 지원하고, 실제 소유형 AnyError는 Result<T, AnyError>를 지원합니다. 둘 다 0.2에는 포함되지 않습니다. 변환은 명시적이며, 실패 가능한 포장은 실패할 때 원래 오류를 보존합니다. 현재 AnyError는 Box<dyn Error>를 소유하고 포장은 명시적이며 실패할 수 있습니다. 작은 오류를 인라인으로 저장하는 기능은 구현되지 않았습니다. 구체적인 타입의 오류는 자신의 데이터를 유지합니다.
  • 크기가 제한된 reader, write-all과 실패 후 부분 진행 상태의 명세.
  • 손실 없는 OS 경로와 환경 값.
  • 덮어쓰기 없이 게시하는 임시 출력 트랜잭션.
  • 무작위 컬렉션 해시와 구분되는 안정적인 내용 해시.
  • 할당 실패 주입, 테스트·퍼징 보조 도구와 결정적인 fixture.
  • 버전이 지정된 AIR·캐시 직렬화와 스트리밍 포매팅 writer.

API 초안

확정된 콘솔 함수 이름과 제안된 시그니처는 0.3 system 콘솔 IO. 아래 코드는 과거의 계약 예시이며 현재 API를 그대로 복사해 쓰는 참고 자료는 아닙니다. 현재 서명과 수명 주기 버전은 다음 목록에 기록합니다: 소스 API 목록; 더 넓은 자원·컬렉션 계약은 각각 별도의 구현이 필요합니다.

Result<usize, IoError> read(&mut File self, MutSlice<byte> output);
Result<usize, IoError> write(&mut File self, Slice<byte> input);
Result<unit, IoError> flush(&mut File self);
Result<ExitStatus, ProcessError> wait(&mut Child self);
Optional<&V> get(&Map<K, V> self, &K key);
Result<T, ParseError> parse_integer<T>(string_view input, u32 radix);

대여한 키의 조회에서 키를 몰래 clone해서는 안 됩니다. iterator·콜백 API에는 요소 소유권과 참조 수명이 명시되어야 합니다. 필수 API를 기존 제네릭 계약으로 표현할 수 없을 때만 연관 타입 기능을 추가합니다.

부트스트랩의 필수 조건에서 제외할 항목

부트스트랩 부분집합은 의존 순서를 정하며, 선택한 0.3 동기 CPU 라이브러리 목표를 줄이지 않습니다. CPU Tensor·Quantized·동기화·동기 Task API는 검토 가능한 CPU 계획에 유지하고, 실행을 중단하는 Task API와 async 기반은 0.4로 옮깁니다. 구현은 승인되었지만 아직 미완성이며, 선택한 동기 카탈로그를 실제로 검사해야 0.3을 완성했다고 할 수 있습니다. GPU와 GPU 전용 Pending API는 이 작업에 포함하지 않으며, 패키지 레지스트리 호스팅은 별도 기반입니다.
