제안과 현재 범위

아래 의존성 순서는 최종 외부 검토를 기다리는 제안입니다. 연결된 페이지에는 사용자가 선택한 0.3 목표를 기록합니다. 0.2에는 내장 컬렉션·텍스트·오류의 일부 기능과 numeric.Floating·Complex 소스 라이브러리가 이미 구현되어 있습니다. Map, 일반 IO, Process와 나머지 광범위한 카탈로그 API는 향후 작업입니다. 자세한 내용: 현재 구현 범위.

첫 선행 과제는 스칼라 전용 FFI와 아직 없는 사용자 정의 네이티브 자원 정리입니다. 함수 목록을 길게 나열해도 이러한 소유권 계약을 대신할 수는 없습니다.

0.3 system 편의 계층

선택된 0.3 콘솔 범위에는 import system; 와 다음 네 함수가 포함됩니다: system.print, system.println, system.printf, 및 system.input. 이 기능은 0.2에 구현되어 있지 않습니다. 콘솔 IO 계획 에는 텍스트·스칼라의 직접 출력과 출력 전용 + 조합도 포함됩니다. 이 목표와 아직 API 검토가 필요한 정확한 시그니처·오류 처리·UTF-8/EOF 규칙·명시적 flush 단계를 구분합니다. 편의 기능 계획 은 반환 전용 bool→정수 변환, 명시적 Boolean 변환, 필드 축약과 원시 리터럴을 유지합니다.

system은 아래 text/bytes/convert와 io 기반 위에 공개 편의 계층으로 둡니다. 검사되지 않은 C varargs를 추가하는 대신 기존 포매팅·범위 제한 버퍼·스트림·자원·오류 계약을 재사용합니다. printf의 혼합 타입 인수에는 검토된 0.3 intrinsic이 필요하며, 기존의 동종 values[] 가변 인수 문법은 바뀌지 않습니다. 기존 자원·FFI 목표와 구현 순서를 유지합니다.

0.3 추가system 콘솔 편의 기능줄바꿈 없는 print, 줄바꿈을 붙이는 println, 검사되는 printf와 UTF-8 줄 입력을 제공합니다. 자세한 내용: 세부 계획.text/format과 io 기능을 바탕으로 구축합니다. 제안된 출력은 Result<unit, system.IoError>이고 입력은 Result<Optional<string>, system.IoError>입니다. EOF, 빈 줄·마지막 줄, 잘못된 UTF-8, 부분 출력과 명시적 flush 실패를 구분합니다. 세부 API와 혼합 타입 intrinsic은 검토가 필요합니다.
4ioRead.read, Write.write, 크기가 제한된 read_to_end, write_all, 버퍼링, stdin/stdout/stderr.부분 읽기·쓰기는 정상적인 동작입니다. EOF와 오류는 다릅니다. 실패 후 유지되는 진행 상태와 flush 실패를 명세하고, 짧은 IO·중단된 IO와 크기 제한을 검사합니다.
5path / fs손실 없는 네이티브 경로, 어휘적 components/join/parent/extension, metadata/symlink_metadata, canonicalize, 디렉터리 항목, 파일과 임시 디렉터리.경로 문자열 연산과 OS 조회는 다릅니다. Unix 바이트 경로와 Windows UTF-16은 항상 UTF-8 문자열로 표현되는 것이 아닙니다. 링크, 권한, 덮어쓰기 정책과 정리를 검사합니다.
6process / env / time인수·환경 변수, 실행 파일 경로, argv 기반 프로세스 생성, 출력 파일 리디렉션, wait, timeout과 단조 시계.암시적으로 셸을 해석하지 않습니다. 시작 실패, 시간 초과, 시그널과 종료 코드를 구분하고 자식 프로세스의 종료 상태를 각각 한 번만 회수합니다. 따옴표·메타문자, UTF-16과 디스크립터 수명을 검사합니다.
7컴파일러 지원 / build타입이 지정된 ID·범위, 선택적 인터닝, 진단, 안정적인 내용 해시, 대상·도구 체인 설정과 임시 산출물 게시.확장 가능한 저장소에 오래 유지되는 대여 대신 안정적인 ID를 사용합니다. 성공한 출력만 게시합니다. 오래된 ID, 결정적인 오류, 손상된 캐시 거절과 깨끗한 부트스트랩을 검사합니다.

기존 카탈로그에 추가할 기능

  • 확장되는 소스·AST·타입 테이블을 위한 소스 범위와 타입이 지정된 ID.
  • 구조화된 IO 오류와 컴파일러 진단으로의 명시적 오류 매핑입니다. 계획된 Error 인터페이스는 대여 기반 검사를 지원하고 구체적인 소유형 AnyError는 Result<T, AnyError>를 지원합니다. 둘 다 0.2에는 포함되지 않습니다. 변환은 명시적이며 실패 가능한 패킹은 실패 시 원래 오류를 보존합니다. 인라인 부분집합은 선택한 고정 크기 오류로 제한하고, 구체 타입 오류는 자신의 payload를 유지합니다.
  • 크기가 제한된 reader, write-all과 실패 후 부분 진행 상태의 명세.
  • 손실 없는 OS 경로와 환경 값.
  • 덮어쓰기 없이 게시하는 임시 출력 트랜잭션.
  • 무작위 컬렉션 해시와 구분되는 안정적인 내용 해시.
  • 할당 실패 주입, 테스트·퍼징 보조 도구와 결정적인 fixture.
  • 버전이 지정된 AIR·캐시 직렬화와 스트리밍 포매팅 writer.

API 초안

확정된 콘솔 함수 이름과 제안된 시그니처는 0.3 system 콘솔 IO에 정리되어 있습니다. 이 자원·컬렉션 초안은 제안된 시그니처이며 현재 실행 가능한 프로그램이 아닙니다. 자원 정리와 정확한 오류·타입 이름은 0.3 계약 검토에서 정합니다.

Result<usize, IoError> read(&mut File self, MutSlice<byte> output);
Result<usize, IoError> write(&mut File self, Slice<byte> input);
Result<unit, IoError> flush(&mut File self);
Result<ExitStatus, ProcessError> wait(&mut Child self);
Optional<&V> get(&Map<K, V> self, &K key);
Result<T, ParseError> parse_integer<T>(string_view input, u32 radix);

대여한 키의 조회에서 키를 몰래 clone해서는 안 됩니다. iterator·콜백 API에는 요소 소유권과 참조 수명이 명시되어야 합니다. 필수 API를 기존 제네릭 계약으로 표현할 수 없을 때만 연관 타입 기능을 추가합니다.

부트스트랩의 필수 조건에서 제외할 항목

정규식, 네트워크/TLS, 로캘 정렬, 전체 자소 군집·정규화 테이블, 광범위한 직렬화 형식, 비동기 실행기, 일반 스레드 풀, 패키지 레지스트리와 GPU는 컴파일러 부분집합 이후에 구현할 수 있습니다. 기존의 작은 CPU SIMD·병렬 범위는 독립적으로 유지할 수 있습니다.
