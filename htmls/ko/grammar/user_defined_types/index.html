1입니다. 설정된 값 규칙에서 형식 빌드Build Types from the Seted Value Rules

Aevix 사용자 정의 형식은 기본 제공 값으로 동일한 형식 우선 선언, 정적 유형, 소유권, 대여, 가시성 및 명시적 반환을 사용합니다. 구조체는 구체적인 값 유형입니다; 그 이름은 힙 할당을 요청하거나 공유 ID를 제공하지 않습니다.

확인된 디자인. 이 페이지의 규칙은 언어 디자인 중에 선택되었습니다. 예제는 소스 수준 사양입니다. parser, runtime, benchmark 또는 backend 실행은 청구되지 않습니다.

3입니다. 완전한 작은 값 유형

struct Point {
    public f64 x;
    public f64 y;

    public Point new(f64 initial_x, f64 initial_y) {
        return Point { x = initial_x, y = initial_y };
    }

    public f64 get_x(&Point self) {
        return (*self).x;
    }
};

Point point = Point.new(1.0, 2.0);
f64 coordinate = point.get_x();

일반 형식 함수는 초기화된 포인트를 반환합니다. 읽기 메서드는 수신기를 빌리고 Copy 스칼라를 반환합니다. 포인트는 Copy 구현을 선언하지 않기 때문에 이동 유형으로 남아 있습니다. 공공 분야는 가변성과 대여에 따라 직접 접근 할 수 있습니다.

4입니다. 한 눈에 확인된 규칙

주제 선택된 규칙 의미
초기화 Type { field = expression } 이름 선택 필드; 필수 필드는 정확히 한 번 초기화됩니다.
필드 액세스 private by default; 공개 옵트인. 이니셜라이저 액세스 및 이후 필드 액세스는 모두 checked입니다.
가변성 기본적으로 불변의 소유자; 일반 쓰기에 대한 명시적 mut. Visibility가 쓰기 권한을 제공하지 않습니다.
팩토리 Type.new(...) 일반적인 receiverless 타입의 기능입니다. 선언 된 return 유형은 유형 자체 또는 Result 일 수 있습니다.
수신자 &Type self, &mut Type self, Type self 읽기 대여, 독점 쓰기 대여, 또는 일반 값 전송.
Copy implements Copy 이는 명백한 내장 기능입니다. 모든 필드는 Copy여야 하며 암시적 딥 중복이 없어야 합니다.
제네릭 타입 struct Pair<T> 및 where T implements Copy T에 대한 경계는 페어 자체를 Copy로 만들지 않습니다.

5입니다. 열거형, 인터페이스 및 일반 유형Enums, Interfaces, and General Types

열거형은 type-function 및 receiver 모델을 재사용하면서 명시적으로 선택한 변형 및 페이로드 패턴을 추가합니다. 일반적인 구조체, 열거형 및 인터페이스 선언은 angle-bracket 유형 매개 변수를 사용합니다. 확인된 구문에 대한 전용 페이지를 읽으십시오. 이 섹션에서는 새로운 인터페이스, 패턴 또는 제약 조건을 선택하지 않습니다.

6입니다. 아직 열려 있는 결정

  • 필드 기본값과 생략된 필드 초기화는 필수 필드 규칙을 초과합니다.
  • 사용자 정의 정리 선언, 사용자 정의 정리가 있는 형식에서 부분 이동 및 전체 필드 프로젝션 이동 규칙.
  • 물리적 레이아웃, 정렬 제어, 안정적인 외국 표현, 자동 평등 또는 기타 연산자 파생.
  • 일반 필드 자동 역참조 및 래퍼 포워딩은이 프로필 외부에 남아 있습니다. 메서드 오버로드, field/method 이름 충돌 거부, 0.2에서 이미 작동하는 나중에 정의된 함수나 메서드 호출.
  • 일반적인 수정자 조합은 자체 규칙의 적용을 받습니다. 유형 헤더 순서가 설정됩니다 : 일반 매개 변수, 다음 구현, 다음 위치. 더 보기 제네릭.
