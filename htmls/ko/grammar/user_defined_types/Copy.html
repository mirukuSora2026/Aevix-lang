개요 구조체 방법 및 팩토리 Copy 및 이동

언어 레퍼런스

문법 개요기반사용자 정의 타입열거형제네릭 타입선언자료형

1입니다. 기본적으로 사용자 정의 값 이동

struct Point {
    public i32 x;
    public i32 y;
};

Point original = Point { x = 1, y = 2 };
Point destination = original;

포인트에는 Copy 선언이 없으므로 대상은 소유자를 수신하고 원본을 다시 사용할 수 없습니다. 이 기본값은 모든 필드가 Copy 스칼라일 경우에도 적용됩니다. 컴파일러 최적화는 이전 바인딩의 소스 수준 유효성을 변경할 수 없습니다.

동일한 기본값이 열거형에도 적용됩니다. 원시적인 Copy values 는 설정된 스칼라 동작을 유지합니다. 집계는 자동으로 상속되지 않습니다. Copy 왜냐하면 그것은 단지 그것들을 포함하고 있기 때문입니다.

2입니다. 구현 Copy로 선택

struct Coordinates implements Copy {
    public i32 x;
    public i32 y;
};

Coordinates first = Coordinates { x = 1, y = 2 };
Coordinates second = first;
i32 first_x = first.x;
i32 second_x = second.x;

Copy가 선택된 집계 옵트인입니다. 두 바인딩 모두 값 복사 후에도 사용할 수 있습니다. 선언은 임의의 사용자 정의 복제 함수가 아닌 컴파일러-checked 내장 기능을 요청합니다.

Copy는 선언된 모드에 따라 일반 값 초기화, 값 인수, 값 수신기 호출 및 값 반환에 적용됩니다. 읽기 및 쓰기 대여 매개 변수는 여전히 대여; Copy는 값 인수로 변환하지 않습니다.

3입니다. 개인 필드를 포함한 모든 필드 확인

요구 사항 이유
모든 struct 필드는 Copy입니다. 전체 값은 독점적 인 자원 소유자를 복제하지 않고 복제 할 수 있습니다.
모든 열거형 변형의 모든 필드는 Copy입니다. Copy는 활성 태그를 기반으로 한 런타임 결정이 아닌 정적 유형 기능입니다.
개인 필드와 변형이 포함되어 있습니다. 가시성은 컴파일러에서 안전하지 않은 중복 의무를 숨길 수 없습니다.
중첩 집계는 자체 Copy 계약을 충족합니다. 포함된 형식은 다른 형식의 이동 기본값을 우회할 수 없습니다.
Shared-참조 사본은 소스 대여 수명을 보존합니다. 참조를 복사해도 새 백업 소유자가 생성되지 않습니다.

거절된 선언들 개인 소유의 string 또는 독점 참조는 전체 유형을 비 Copy로 만듭니다.

struct BadOwnerCopy implements Copy {
    public i32 id;
    string name; // Invalid Copy requirement: string owns its data.
};

struct BadLoanCopy implements Copy {
    &mut i32 target; // Invalid Copy requirement: exclusive loans are not Copy.
};

동일한 철자를 가진 빈 일반 인터페이스는 컴파일러 기능을 대체할 수 없습니다. 수동으로 작성된 딥 카피 기능도 Copy를 인증할 수 없습니다. 추가 Non-Copy field to an 명시적인 Copy 형식 계약이 변경 될 때까지 형식이 거부 되어야 합니다.

4입니다. 값 복사를 소유자 복제와 구분합니다.

가치 카테고리 Copy 처리 경계
원시 Copy 스칼라 설립 일반적인 값 복사. 관련 기본 유형 계약을 참조하십시오.
&T Shared 기준은 Copy일 수 있습니다. 사본은 동일한 참조를 가리키고 대여 제약을 유지합니다.
&mut T Copy가 아닙니다. 제한 없는 별칭으로 독점 액세스를 복제할 수 없습니다.
struct / enum 없이 구현 Copy 기본값으로 이동합니다. 모든 스케일 콘텐츠가 자동으로 집계를 선택하지 않습니다.
유효한 구현을 가진 struct / enum Copy 일반적인 값 복사가 허용됩니다. 컴파일러는 모든 필드와 열거형의 모든 변형을 검사합니다.
string Copy가 아닙니다. 문자를 소유하는 것은 조용히 깊이 클로닝되지 않습니다.
Vector<T> Copy가 아닙니다. growable 버퍼 소유자는 암시적으로 중복되지 않습니다.
Box<T> Copy가 아닙니다. 고유한 힙 소유자는 T가 Copy이더라도 암시적으로 중복되지 않습니다.

명시적 중복 API에는 자체 작업 및 실패 계약이 있습니다. 예를 들어 명시적 Box 복제는 일반 값 Copy와 동일한 작업을 할당할 수 없습니다. 이 페이지는 범용 클론 인터페이스나 마지막 클론 메서드 문법을 소개하지 않습니다.

5입니다. Shared 참고 사본은 본래 수명을 유지합니다

struct CounterView implements Copy {
    public &i32 target;
};

i32 source = 7;
CounterView first_view = CounterView { target = &source };
CounterView second_view = first_view;
i32 observed = *(second_view.target);

두 의견은 출처에 관한 것입니다. 둘 다 소스를 소유하거나, 소스를 독립 저장소로 복사하거나, 수명을 연장하지 않습니다. 두 복사본 모두 동일한 소스 유효성 및 충돌 액세스 검사의 적용을 받습니다.

거절당한 탈출구 Copy 뷰는 죽은 로컬에 대한 참조를 return 할 수 없습니다.

CounterView invalid_view() {
    i32 local = 7;
    return CounterView { target = &local }; // Invalid: local cannot outlive this call.
}

참조 필드는 나중에 형식 삭제 또는 소유권 래퍼가 콘크리트 유형을 숨기는 경우에도 숨겨진 소스-대여 제약을 전달할 수 있습니다. 전체 작성된 수명 파라미터 및 반환 참조 주석 구문은 열려 있습니다.

6입니다. 수신자 표기이 호출 모드를 결정합니다.

receiver 가치 능력 효과
&Coordinates self 호출은 좌표가 Copy인지에 관계없이 대여을 통해 읽습니다.
&mut Coordinates self 이 호출은 전용 쓰기 권한이 필요합니다; Copy는 별칭을 승인하지 않습니다.
Coordinates self 일반 값 호출은 Coordinates가 Copy를 명시적으로 구현하기 때문에 복사할 수 있습니다.
User self 비 Copy 사용자 일반 값 호출은 사용자 소유자를 이동시킵니다.

자동 메서드 대차 편의는 선언된 참조 수신기를 따릅니다. 값을 복사할 수 있는지에 따라 다른 수신기 모드를 선택하지 않습니다. 대여된 dyn 뷰는 단순히 하나의 가능한 구현이 Copy이기 때문에 값 수신자 지원을 얻지 못합니다.

7입니다. 열거형은 모든 변형을 검사합니다.

enum Direction implements Copy {
    North;
    East;
    South;
    West;
};

Direction first_direction = Direction.North;
Direction second_direction = first_direction;

Copy 선언은 전체적으로 방향에 적용됩니다. 페이로드 열거형은 개인 변형을 포함한 모든 변형 필드를 확인해야 합니다. 비-Copy 페이로드는 현재 값이 빈 변형인 경우에도 Copy를 방지합니다.

별도로 선택된 소모 enum 스위치는 비 Copy 소유의 enum을 이동시킵니다: switch (move value)는 원래 바인딩을 사용할 수 없게 만듭니다. Copy 열거형 피연산자의 정확한 명시적 소비 처리는 열려 있습니다. 이 페이지는 강제 무효화 또는 일반 복사를 선택하지 않습니다. 소스 수준 이동 시맨틱은 특정 물리적 byte 복사 명령을 약속하지 않습니다. 읽기 열거형 모든 스위치 모드 및 페이로드 바인딩.

8입니다. T에 바인딩된 Copy가 컨테이너에서 선택되지 않음

struct Pair<T> where T implements Copy {
    public T first;
    public T second;
};

Pair<i32> numbers = Pair<i32> { first = 10, second = 20 };
Pair<i32> destination = numbers;

여기서 절은 Copy 형식 인수를 필요로 합니다. 그것은 선언하지 않습니다 Pair<T> Copy 자체, 그래서이 Pair<i32> 주인이 움직인다. 별도로 선언 된 구현 Copy 옵트 인은 유효한 전체 필드 검사에서 복사 할 일반 집계가 필요합니다.

Pair<string> string를 소유하는 것이 Copy가 아니기 때문에 경계를 위반합니다. 일반적인 기능 요구 사항은 선택한 기능을 사용합니다. name-follow 타입 파라미터와 파라미터-list-following where; 여러 함수 요구 사항이 주제를 반복하고 쉼표로 구분됩니다. 상기 헤더 순서는 The header order struct CopyPair<T> implements Copy where T implements Copy: type의 자체 implements 리스트는 제약 조건이 있는 곳에 선행한다. 읽기 일반 유형 선택된 type-parameter 문법에 대해.

9입니다. Copy는 기계 명령 약속이 아닌 시맨틱 기능입니다.

Copy는 숨겨진 딥 복제, 할당 또는 CPU/GPU 전송 없이 값 복제를 허용합니다. 컴파일러는 입증된 중복 복사본을 제거하거나 관찰 가능한 값과 소유권 유효성을 유지하면서 효율적인 표현을 선택할 수 있습니다. 큰 Copy 값은 여전히 실제 데이터 이동을 요구할 수 있습니다.

이동은 또한 시맨틱 소유권 이전입니다; 물리적 바이트는 이동하거나 최적화 될 수 있습니다. 단어 Copy에서 성능을 추론하고 혼자 이동하지 마십시오. Scope cleanup은 현재 해당 범위에 소유한 값만 해제하고 이전 후에는 소유자를 다시 해제하지 않습니다.

사용자 지정 정리 선언과 Copy와의 호환성은 해결되지 않았습니다. 사용자 정의 소멸자 본문, 중복 완성 프로토콜 또는 대여 수표 면제는이 내장 기능에 의해 암시되지 않습니다.

10입니다. 필요한 거부 및 개방형 기능 정책

조건 선택한 결과
Copy 선언에는 Copy가 아닌 필드가 포함됩니다. 필드가 비공개일 때를 포함하여 선언을 거부합니다.
Copy 열거형은 모든 변형에서 비 Copy 페이로드를 포함합니다. 선언을 거부하십시오; 활성 태그 테스트는 그것을 구출 할 수 없습니다.
이동되지 않은 Copy 소유자가 다시 사용됩니다. 다음 사용을 거부합니다.
복사된 공유 참조는 유효한 소스 수명을 이스케이프합니다. [중고] 거절을 버려라
Copy 일반 인수 바인딩이 충족되지 않습니다. 타입 인스턴스화를 거부합니다.
  • 사용자 정의 정리 및 부분 이동 호환성이 열려 있습니다.
  • 일반 Clone 인터페이스, 사용자 연산자 파생, 비교 파생 및 딥 카피 표기법은 열려 있습니다.
  • 안정적인 공공 layout/FFI 보장 및 복사 비용 진단은 열려 있습니다. 0.2 컴파일러는 일반 계약을 확인하고 구체적인 전문화를 만듭니다.
  • 이들은 소스 레벨의 거부 카테고리이며, 컴파일러 진단 코드로 구현되지는 않는다.
