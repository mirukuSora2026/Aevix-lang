언어 레퍼런스

문법 개요기반사용자 정의 타입열거형제네릭 타입선언자료형

1입니다. 건설 및 거동을 위한 하나의 기능 모델

struct User {
    string name;
    i32 level;

    public User new(string initial_name, i32 initial_level) {
        return User { name = initial_name, level = initial_level };
    }

    public i32 get_level(&User self) {
        return (*self).level;
    }

    public void set_level(&mut User self, i32 new_level) {
        (*self).level = new_level;
        return;
    }

    public User into_user(User self) {
        return self;
    }
};

new는 수신자가 없으며 User.new(...)를 통해 호출됩니다. get_level은 공유 수신기를 통해 읽습니다. set_level은 독점 수신기를 통해 씁니다. into_user는 일반적인 값 전송을 사용합니다. 모든 일반 비-void 성공적인 경로 return 명시 적으로; void 정상적으로 종료 하거나 return; 철자 수 있습니다.

2입니다. 팩토리은 receiverless 유형 기능입니다

User make_user(string owned_name) {
    return User.new(owned_name, 1);
}

new라는 단어는 특별한 생성자 키워드가 아닌 선택된 전통적인 함수 이름입니다. 타입은 동일한 선언과 Type.function(...) 호출 모델을 사용하여 다르게 명명된 팩토리를 정의할 수 있습니다. 그들의 선언 된 인수와 return 유형은 소유권과 실패를 결정합니다.

이 예제에서는 이미 소유한 string 인수를 팩토리으로 이동합니다. #현재 아래 텍스트 리터럴 초안, 리터럴은 string_view입니다; string 소유를 만드는 것은 명시적 오류 생성자를 사용합니다. 이러한 예제는 암시적 리터럴 대 소유자 변환을 추가하지 않습니다.

선언 유형 안의 팩토리은 private 필드를 초기화할 수 있습니다. 호출자는 반환된 전체 값과 함수의 액세스 권한을 봅니다; 호출자는 해당 개인 필드에 직접 액세스하지 않습니다. 호출 표기은 힙 객체를 자동으로 할당하지 않습니다.

이 모델에서는 return 형식이 없는 생성자 선언과 별도의 할당 키워드가 도입되지 않습니다. 기능 하중 초과 선택은 안으로 선택됩니다 과부하0.2는 동일한 직접 멤버 이름을 가진 필드와 메서드를 거부하며, 별개의 함수 시그니처은 과부하 세트를 형성할 수 있습니다. 더 일반적인 래퍼 포워딩 및 클래스 상속은이 프로필 외부에 남아 있습니다.

3입니다. 공사가 실패 할 수있는 Result를 반환합니다.

enum ProfileError {
    NegativeLevel;
};

struct Profile {
    string name;
    i32 level;

    public Result<Profile, ProfileError> new(string initial_name, i32 initial_level) {
        if (initial_level < 0) {
            return Result.err(ProfileError.NegativeLevel);
        }
        return Result.ok(Profile { name = initial_name, level = initial_level });
    }
};

Result<Profile, ProfileError> build_profile(string owned_name) {
    return Profile.new(owned_name, 1);
}

실패는 숨겨진 생성자 예외가 아닌 Result 선언의 일반적인 값입니다. 거부된 경로에서 initial_name은 함수의 소유로 남아 있으며 정상적인 정리를 따릅니다. 성공하면 이미 소유한 string 인수가 초기화된 프로필로 이동한 다음 Result로 이동합니다.

이것은 사용자 정의 예제이며, 추가된 표준 생성자 API가 아닙니다. 기존 postfix ? 규칙은 적합한 Result 반환 함수에서 일치하는 Result 오류를 전파 할 수 있습니다. 성공적인 return는 명시적입니다.

4입니다. 수신기 모드를 명시적으로 선언합니다.

선언 의미 통화 효과
&User self Shared는 사용자의 대여을 읽었습니다. 소유자 이동 없음; 충돌 쓰기 대여은 제외됩니다.
&mut User self 사용자의 단독 대여입니다. 기존 쓰기 권한과 호환 가능한 독점 대여이 필요합니다.
User self 일반 사용자 값 매개 변수입니다. 해당 유형이 Copy인 경우 Copy; 그렇지 않으면 전체 소유자를 이동합니다.
자체 수신기 없음 Receiverless 유형 기능. User.new(...) 선언된 일반적인 인수만 전달합니다.

self 는 receiver 변수이다; 그 타입은 명시적으로 기록된다. 호출이 멤버 구문을 사용하기 때문에 값 수신기는 자동으로 대여으로 변경되지 않습니다. 또한, 일반적인 불변의 값 파라미터는 단지 수신기에 의한 임의의 변경를 부여하지 않는다.

5입니다. 읽기 전화는 자동 및 명시적인 차입을 허용합니다.

i32 read_user_level(string owned_name) {
    User user = User.new(owned_name, 1);
    i32 automatic_read = user.get_level();
    i32 explicit_read = (&user).get_level();

    &User existing_read = &user;
    i32 reference_read = existing_read.get_level();
    return reference_read;
}

첫 번째 읽기 호출은 get_level의 선언으로 표시된 공유 수신자 대여을 제공합니다. 두 번째는 대여에 대한 설명이다. 둘 다 동일한 권한, 수명 및 충돌 검사를 적용합니다. 기존 레퍼런스는 다른 레퍼런스 레이어에 자동으로 래핑되지 않고 직접 전달되거나 다시 대여됩니다.

수취인 표현식은 한 번 평가됩니다. 메서드의 편리성은 사용자를 깊이 복제하거나, 래퍼를 할당하거나, 다른 프로세서로 전송하지 않습니다.

6입니다. 쓰기 호출은 독점적 인 능력이 필요합니다.

void update_user_level(string owned_name) {
    mut User editable = User.new(owned_name, 1);
    editable.set_level(2);
    (&mut editable).set_level(3);

    &mut User existing_write = &mut editable;
    existing_write.set_level(4);
    return;
}

자동 및 명시적 쓰기 호출은 동일한 쓰기 가능한 소스 및 호환 가능한 전용 대여이 필요합니다. 공유 참조를 단독 참조로 업그레이드할 수 없습니다. 일반 소유 사용자는 쓰기 대여을 받기 전에 mut가 필요합니다. 이미 유효한 &mut 사용자는 참조자의 쓰기 능력을 수행한다.

거부된 전화 일반 불변 소유자와 공유 대여은 쓰기 권한을 제공하지 않습니다.

void invalid_writes(string owned_name) {
    User fixed = User.new(owned_name, 1);
    fixed.set_level(2); // Invalid: no owner write permission.
    &User read_only = &fixed;
    read_only.set_level(3); // Invalid: cannot upgrade shared access.
    return;
}

마지막 사용 대여 추론은 수명 또는 중복 수표를 이완시키지 않습니다. 반환 된 값을 통해 탈출하는 참조는 유효한 출처를 계속 필요로합니다; 담요 "모든 대여은 세미 콜론으로 끝납니다"규칙은 가정되지 않습니다.

7입니다. 값 수신기는 Copy를 따르거나 이동

User transfer_user(string owned_name) {
    User original = User.new(owned_name, 1);
    User destination = original.into_user();
    i32 retained_level = destination.get_level();
    return destination;
}

사용자가 string를 소유하고 있으며 Copy를 선언하지 않았기 때문에 구체적인 값 호출이 원래의 자신을 이동하고 해당 소유자를 반환합니다. 원래 바인딩은 더 이상 사용할 수 없습니다. 회원 호출 표기에 대한 어떤 것도 이 선언된 값 수신자를 자동으로 대여하지 않습니다.

사용을 거부했습니다. 원본은 값 수신자에 의해 소비되었습니다.

i32 invalid_reuse(string owned_name) {
    User original = User.new(owned_name, 1);
    User destination = original.into_user();
    return original.get_level(); // Invalid: original has moved.
}

명시적으로 Copy 유형의 경우 값 수신기는 일반 값 인수와 동일한 값 복사 규칙을 따릅니다. 이 구체적인 호출 규칙은 현재 dyn 호출 가능한 서페이스를 통해 값 수신자를 적격하게 만들지 않습니다; 그 서페이스는 별도로 문서화됩니다.

8입니다. 명시적으로 역참조된 수신기 필드 액세스

struct Counter {
    i32 count;

    public Counter new(i32 initial_count) {
        return Counter { count = initial_count };
    }

    public i32 read(&Counter self) {
        return (*self).count;
    }

    public void write(&mut Counter self, i32 replacement_count) {
        (*self).count = replacement_count;
        return;
    }
};

Counter의 메서드는 개인 count 필드를 사용할 수 있습니다. 참조 수신기는 필드를 선택하기 전에 명시적으로 역참조됩니다. 호출 사이트에서 자동 리시버 대여은 표현식 내에서 필드 자동 역참조를 승인하지 않습니다.

초기 또는 대체 매개 변수 이름은 필드 및 눈에 보이는 외부 변수와 다릅니다. 초기화 키는 필드를 식별합니다; 새로운 로컬 바인딩이 아닙니다. 정확한 네임스페이스 및 예약 이름 정책은 열려 있습니다.

9입니다. 일반 평가, 범위 및 정리 유지

수신기 표현식을 한 번 평가하고 기존 호출 규칙에 따라 한 번 왼쪽에서 오른쪽으로 일반적인 호출 인수를 평가합니다. 팩토리이나 방법체는 효과를 가질 수 있습니다; 호출하는 것은 나중에 실패할 때 롤백을 약속하지 않습니다. 필요한 대여 갈등은 평가 순서에 관계없이 여전히 진단되어야합니다.

매개 변수와 수신기 이름은 함수 본문에서 볼 수 있는 로컬 이름입니다. 중첩된 선언은 그들을 그림자로 만들 수 없습니다. Public/private는 로컬 변수가 아닌 method/type 인터페이스에 적용됩니다. 소유자를 반환하는 것은 그것을 전송한다; 스코프 정리는 여전히 그곳에 있는 초기화된 값들을 해제한다.

작동 보존된 규칙
Shared 메서드 호출 원본은 유지되는 모든 공유 참조보다 오래 유지되어야 합니다.
Exclusive 메서드 호출 활성 대여 기간 동안 중복된 액세스가 없습니다.
Value 메서드 호출 Copy 또는 이동은 구체적인 유형 기능을 따릅니다.
Result 팩토리에서의 실패 명시적 오류 값; 정상적인 정리, 암시적 복구 클론 없음.
공개 방법 외부 가시성; 소유자 수명 확장 없음.

10입니다. 열거형 및 일반 형식에 대해 동일한 모델 재사용

열거형은 동일한 수신기 없는 함수와 입력된 수신기 모드를 사용합니다. 열거형 내부의 팩토리은 자신의 개인 페이로드 필드를 초기화할 수 있으며, 메서드는 해당 유형의 액세스 경계 내에서 개인 변형을 검사할 수 있습니다. 동작이 활성 변형에 의존할 때 선택된 열거형 스위치 규칙이 필요합니다.

일반 구조체, 열거형 및 인터페이스 선언은 선택한 angle-bracket 구문과 명시적 제약 조건을 사용합니다. 일반 함수 선언 및 호출 추론 선택됩니다. 제네릭 메서드는 동일한 함수 템플릿과 정적 호출 규칙을 사용합니다. type 의 implements 리스트는 where 절에 선행합니다. 접근 가능한 메서드는 나중에 정의된 메서드를 호출할 수 있습니다; 컴파일러는 본문을 검사하기 전에 시그니처을 수집합니다. 읽기 열거형 및 일반 유형.

별도의 Box 페이로드 메서드 호출 편의는 선언 된 수신자 대여을 재사용합니다. 명시적 Box.as_ref/Box.as_mut 뷰, dyn 적격성, 충돌 정책 및 소유권 제한은 범용 래퍼 자동 참조 규칙보다는 해당 참조에 속합니다.

11입니다. 통화 정책 열기

  • Method/field 및 wrapper-method 충돌 및 오버로드, 기본 인수 및 매개 변수 이름 간의 인터페이스 관련 상호 작용. 일반 과부하 선택 및 기본 인수와 명명된 인수 선택됩니다.
  • 일반 필드 자동 역참조 및 범용 래퍼 역참조 기능.
  • 참조-return 수명 주석, 추가 일반 방법 관련 규칙 및 고급 자체 양식. 일반 일반 함수 선언 및 호출 추론 선택됩니다.
  • 모든 메서드 범주와 완전한 수정자 순서의 기본 표시.
  • 사용자 지정 소멸자 메서드와 특수 생성자 프로토콜은 일반 팩토리에서 지정되지 않습니다.
  • 명시적 캡처 클로저 및 콘크리트 일반 Fn/FnMut/FnOnce 콜백 0.2에서 구현됩니다. 동적 호출 가능한 래퍼, async/GPU 메서드 시그니처 및 독립형 forward-prototype 구문을 소유하는 것은 이 프로파일 밖에 남아 있습니다. Qualified Module에 대한 자세한 내용은 모듈과 import.
