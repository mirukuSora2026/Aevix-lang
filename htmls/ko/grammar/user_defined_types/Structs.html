언어 레퍼런스

문법 개요기반사용자 정의 타입열거형제네릭 타입선언자료형

1입니다. 구조체와 그 필드 선언

struct Point {
    public f64 x;
    public f64 y;
};

Point origin = Point { x = 0.0, y = 0.0 };
f64 horizontal = origin.x;

변수 이름 앞에 형식 이름이 있습니다.The type name before the variable name. 모든 필드 선언과 변수 초기화는 세미콜론으로 끝납니다; 완전한 구조체 선언은 };로 끝납니다. 필드는 유형과 이름으로 선언됩니다. 이러한 예제는 이름이 아닌 명시적 형식을 사용합니다: 유형 구문.

포인트는 f64 필드가 Copy임에도 불구하고 이동 유형입니다. Copy 필드를 읽는 것은 전체 소유자를 전송하지 않고 해당 필드를 복사할 수 있습니다. 자동 집계 평등, 순서, 또는 물리적 표현이 함축되지 않습니다.

2입니다. 기본적으로 필드 가시성은 비공개입니다.

struct User {
    string name;
    public i32 level;
};
필드 폼 접근 경계 변환 권한
string name; 선언 형식에 대한 개인 정보입니다. 가시성은 가변적인 소유자 또는 대여을 생성하지 않습니다.
private string name; 명시적 개인은 동일한 필드 액세스 경계를 가지고 있습니다. 정상적인 대여 및 소유권은 여전히 적용됩니다.
public i32 level; 형식 자체에 액세스할 수 있는 형식 외부에서 사용할 수 있습니다. 일반적인 쓰기에는 쓰기 가능한 장소와 호환되는 전용 대여이 필요합니다.

가시성 수정자는 로컬 바인딩이 아닌 module/type 선언에 속합니다. 공개 필드는 액세스 할 수없는 유형 경계를 통해 해당 포함 유형을 노출 할 수 없습니다. 다른 모든 선언 범주의 기본 표시는 필드 규칙으로 지정되지 않습니다.

3입니다. 필드 이름으로 초기화

Point point = Point { x = 1.0, y = 2.0 };
Point reordered = Point { y = 4.0, x = 3.0 };

각 초기화 키는 선언된 필드를 선택합니다. 필드 표기은 목적지를 결정하고, 서면 순서는 표현 평가를 결정합니다. 이니셜라이저는 필수 필드 완전성, 중복 키, 알 수 없는 이름, 유형 호환성 및 액세스 권한을 확인합니다.

조건 선택한 결과
필요한 필드가 누락되었습니다. 컴파일 시간 거부; 부분적으로 초기화 된 안전한 구조체는 노출되지 않습니다.
필드는 한 번 이상 지정됩니다. 컴파일 시간 거부.
알 수 없는 필드 이름이 지정되었습니다. 컴파일 시간 거부.
값이 호환되지 않는 필드 유형입니다. 컴파일 시간 거부; 이미 입력된 숫자는 암시적 프로모션을 받지 못합니다.
호출자가 지정한 개인 필드에 접근할 수 없습니다. 컴파일 시간 거부.

예를 거부합니다. 이러한 조각은 의도적으로 별도의 이니셜라이저 규칙을 위반합니다.

Point missing = Point { x = 1.0 }; // Invalid: y is missing.
Point duplicate = Point { x = 1.0, x = 2.0, y = 3.0 }; // Invalid: duplicate x.
Point unknown = Point { x = 1.0, y = 2.0, z = 3.0 }; // Invalid: no z field.
i32 typed_integer = 1;
Point wrong_type = Point { x = typed_integer, y = 2.0 }; // Invalid: typed i32 is not f64.

4입니다. 초기 액세스는 checked

명명된 이니셜라이저는 사설 필드 경계를 통한 이스케이프 해치가 아닙니다. 외부 코드는 단순히 이름을 표기으로 개인 필드를 설정할 수 없습니다. 필요한 개인 필드가 초기화되어야 하는 경우, 접근 가능한 타입-내부 팩토리은 초기화를 수행할 수 있고 return는 완전한 소유자가 될 수 있다.

외부 조각이 거부되었습니다. User.name는 비공개입니다. 이 함수는 사용자 선언 외부에 있으며 이미 소유한 string를 수신합니다.

User invalid_external_initialization(string owned_name) {
    return User { name = owned_name, level = 1 }; // Invalid: private name.
}

현재 팩토리 참고 에서는 확정된 타입 내부 함수 문법을 설명합니다. 필드 기본값은 0.2 프로필에 포함되지 않습니다. 암시적인 0, 빈 string, 임시 대체 값을 넣어 주지 않습니다. 계획 0.3 필드 속기 필요한 값을 생략하거나 개인 액세스를 우회하지 않고 지정된 이니셜라이저를 축약합니다.

5입니다. 초기화 표현식을 한 번, 왼쪽에서 오른쪽으로 평가

struct OrderSample {
    public i32 first;
    public i32 second;
};

i32 next(&mut i32 running_count) {
    return ++(*running_count);
}

mut i32 counter = 0;
OrderSample ordered = OrderSample {
    second = next(&mut counter),
    first = next(&mut counter)
};

작성된 두 번째 표현식이 먼저 실행되고 1가 생성되며, 작성된 첫 번째 표현식이 2를 생성한다. 선언 순서는 관찰 가능한 이니셜라이저 효과를 재정렬하지 않습니다. 여기서 완료된 각 호출은 스칼라를 반환하고 대여을 보유하지 않으므로 다음 호출은 자체 독점 대여을 만들 수 있습니다.

나중에 실패하면 이전 효과 또는 이동된 입력이 롤백되지 않습니다. 기존 소유권 정리 규칙은 여전히 평가에 의해 소유 된 값을 관리합니다. 부분적으로 구성된 집계에 대한 정확한 진단 및 구현 메커니즘은 컴파일러 설계의 일부로 남아 있습니다.

6입니다. 일반적인 필드 쓰기는 소유자 가변성을 따릅니다.

Point fixed = Point { x = 1.0, y = 2.0 };
mut Point editable = Point { x = 1.0, y = 2.0 };
editable.x = 3.0;

일반 변경할 수 없는 소유자의 허가는 읽히지만 직접 필드는 기록하지 않습니다. mut는 소유자 수준의 쓰기 권한을 제공합니다. 가시성과 대여은 여전히 액세스를 허용해야 합니다. 공개 필드는 불변의 인스턴스를 가변으로 만들지 않습니다.

글 쓰기를 거부했습니다. 고정은 일반적인 불변의 소유자입니다.

fixed.x = 3.0; // Invalid: immutable owner.

내부 동기화 유형은 자체 계약을 유지합니다. 그들의 존재는 관련없는 불변의 필드에 임의의 쓰기를 부여하지 않습니다. 필드 당 불변성 수정자와 필드 기본값은 여기에 소개되지 않습니다.

7입니다. 값을 옮기지 않고 빌려준다.

Point point = Point { x = 5.0, y = 6.0 };
&Point read_view = &point;
f64 observed = (*read_view).x;

mut Point editable = Point { x = 7.0, y = 8.0 };
&mut Point write_view = &mut editable;
(*write_view).x = 9.0;

Shared 대여은 읽기 액세스를 보존하고 충돌하는 쓰기를 제외합니다. 독점 대여은 하나의 호환 가능한 기능을 통해 액세스를 허용하고 중복되는 충돌을 제외합니다. &mut를 저장하는 불변의 바인딩 포인트는 참조자를 수정할 수 있다; 그 자체의 바인딩 가변성은 그 참조를 리바인딩하는 것에 관한 것이다.

명백한 변론은 의도적입니다. 필드 자동 역참조는 메서드 호출 편의 규칙에 의해 선택되지 않습니다. 대여은 그들의 근원 수명에 의해 경계 하 고, 입증 된 disjoint 필드 대여은 임의 중복을 허용 하지 않고 허용 될 수 있습니다.

8입니다. 기본값으로 전체 값 전송 이동

Point initial = Point { x = 1.0, y = 2.0 };
Point destination = initial;
f64 observed = destination.x;

대상은 포인트 소유자를 받습니다. 포인트가 Copy를 선택하지 않았기 때문에 이니셜은 더 이상 라이브 값으로 사용할 수 없습니다. 할당, 값 매개 변수 및 반환은 자동으로 딥 클로닝 필드가 아닌 선택한 소유권 모델을 따릅니다.

사용을 거부했습니다. 주인은 이미 움직였다.

f64 stale = initial.x; // Invalid: initial was moved.

Copy를 추가하는 것은 형식에 대한 별도의 명시적인 결정이며 컴파일러-checked입니다. 전체 값 전송은 물리적으로 memcpy, 포인터 전용 이동 또는 특정 스택 레이아웃을 약속하지 않습니다. 현장 수준의 부분 이동 및 사용자 정의 정리와의 상호 작용은 열려 있습니다.

9입니다. 로컬 및 이름이 모호하지 않게 유지

Point point = Point { x = 1.0, y = 2.0 };
{
    f64 local_coordinate = point.x;
    f64 adjusted_coordinate = local_coordinate + 1.0;
}
f64 outside_coordinate = point.y;

로컬 이름은 어휘 영역과 하위 영역에서 사용할 수 있습니다. 새로운 변수는 보이는 변수를 포함하여 이미 보이는 변수를 숨기지 않아야 합니다. Public/private는 범위를 넓히거나 수명을 연장하기 위해 로컬 변수를 장식할 수 없습니다.

섀도우를 거부한다. 내부는 눈에 띄는 소유자를 숨길 것입니다.

Point point = Point { x = 1.0, y = 2.0 };
{
    Point point = Point { x = 3.0, y = 4.0 }; // Invalid: visible-variable shadowing.
}

독립적인 열거형 스위치 브랜치는 개별적으로 선택된 스코프를 가지고 있습니다. 열거형. 이러한 필드 및 소유자 규칙은 다른 모든 선언 컨텍스트에서 형제 재사용을 독립적으로 결정하지 않습니다.

10입니다. 할당 및 정리 계약 분리

명명된 이니셜라이저는 구체적인 값을 만듭니다. Type.new는 신체가 작업을 결정하는 일반적인 기능입니다. 표기은 Box 할당, 공유 소유권, 딥 클론 또는 CPU/GPU 전송을 암시적으로 요청하지 않습니다. 필드 이니셜라이저 또는 호출된 API는 자체적인 명시적 할당 및 리소스 비용을 가질 수 있습니다.

정상적인 스코프 출구에서 현재 소유된 초기화된 값은 설정된 소유권 규칙에 따라 한 번 청소됩니다. 이전 된 소유자는 목적지에서 청소되며 다시 원래 위치에서 청소되지 않습니다. 보존된 참조는 여전히 원래의 백업 소유자가 유효한 상태로 유지되어야 합니다.

작동 선택된 의미 철자에서 유추되지 않음
Point { x = 1.0, y = 2.0 } 완전히 초기화 된 구체적인 값을 만듭니다. 힙 배치, 안정적인 외국 레이아웃 또는 자동 딥 카피.
Point.new(1.0, 2.0) 선언된 receiverless 형식 함수를 호출합니다. 특별한 생성자 할당 규칙.
Point destination = initial; 비Copy 포인트에 대한 소유권을 이전합니다. CPU/GPU 전송 또는 복제.
&point checked 읽기 대여을 만듭니다. 소유권은 원래의 삶을 넘어서 확장됩니다.

11입니다. 구조체 정책 열기

  • 필드 기본 표현식, 대체 생략된 필드 메커니즘 및 초기화 update/spread 구문.
  • 사용자 정의 파괴자 표기, 집계 내의 필드 정리 순서 및 부분 이동 제한.
  • 필드 자동 역참조는 메서드 호출 차입 편의의 외부에 남아 있습니다. 0.2에서는 field/method 이름 충돌이 거부되며, 고유한 메서드 시그니처이 오버로드되고 나중에 정의된 메서드는 프로토타입 없이 호출될 수 있습니다. 더 보기 과부하 및 메서드 호출.
  • 메모리 레이아웃, 정렬 지시어, ABI 보증, 외부 표현 주석.
  • 자동 비교, 연산자 파생, 상속 또는 공유 힙 ID는 여기에서 선택되지 않습니다.
  • Reference-return 수명 주석 구문과 완전한 수정자 문법은 열려 있습니다.
