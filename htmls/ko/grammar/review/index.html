1입니다. 범위 및 증거

역사적인 디자인 리뷰 아래의 인벤토리 및 검토 횟수는 초기 문서 스냅샷을 설명합니다. 후속 0.2 작업 구현 부분 명시적 일반 추론, 후행 기본값 및 const usize 매개 변수, 명시적 캡처 클로저, 및 CPU 병렬 처리. 현재 구현 프로필 기록은 행동 및 플랫폼 증거를 지원했습니다.

두 명의 독립적 인 검토자가 선언, 문법 및 데이터 유형 참조를 조사했습니다. 초기 스냅샷에는 134 HTML 페이지와 485 Aevix 코드 블록이 포함되어 있으며 빈 줄과 주석을 포함한 총 2,990 코드 줄이 포함되어 있습니다. 한 리뷰는 구문, 예제 및 파서 경계에 초점을 맞추고 다른 하나는 소유권, 대여, 유형 및 상호 참조 계약에 중점을 둡니다. 결과는 통합 전에 cross-checked였습니다.

검토 레코드는 실제 충돌하는 진술, 누락된 통합 규칙 및 이미 명시적으로 표시된 주제를 구분합니다. 위의 카운트는 수정 예제와 새로운 참조 페이지가 추가되기 전에 초기 스냅샷을 설명합니다. 그들은 파서가 모든 블록을 수락했다는 주장이 아닙니다.

3입니다. 선택한 통합 규칙

  • Array 접미사는 혼합 fixed/dynamic 배열을 포함하여 Array/Vector 유형을 완료하기 위해 맵을 지정합니다. 매개 변수 컨텍스트는 variadic 인수에 대한 마지막 단일 빈 괄호를 보유합니다. 전체 동적 배열 매개 변수는 완전한 형식을 사용합니다.
  • 동적 배열 리터럴 구조에는 CollectionError Result가 있습니다. 중첩된 하위 목록은 하나의 재귀 구조에 참여하는 반면 일반 Result 요소는 자동으로 포장되지 않은 never입니다. Context-free nonempty 리터럴은 기본적으로 고정된 배열입니다.
  • Variadic 팩은 Copy 값을 복사하고 다른 값을 호출 프레임 임시 소유권으로 이동합니다. 호출자는 읽기 전용 액세스를 수신합니다; 팩 대여은 탈출할 수 없습니다. 0 개의 인수가 허용되고, spread 및 named variadics는 초기 서페이스 외부에 있습니다.
  • 알려진 mutable-reference/view 형식 매개 변수가 자동으로 재대여됩니다. 변수 팩 요소와 일반 일반 T 값 입력은 치환 후 예외를 얻지 못합니다. 명시적 소비 본질은 자체 계약을 유지합니다: 구현된 Slice.slice_mut는 MutSlice 입력 디스크립터를 소비합니다.
  • 형식화된 로컬은 초기화 전에 선언될 수 있으며, 명확한 할당 검사와 불변의 경로당 정확히 하나의 초기화가 있습니다. Const, persist 및 rsn에는 이니셜라이저가 필요합니다.
  • Postfix propagation과 삼항 선택은 하나의 공백 독립 구문 정책을 사용합니다: 고유한 완전한 파싱이 사용됩니다; 여러 개의 완전한 파싱은 괄호를 필요로 합니다. 운영자 우선 순위 및 generic-angle/shift-token 처리가 중앙 집중화됩니다.
  • 가장 가까운 곳에 있는 사람(들)과 비교하면 unbraced 실행 가능한 단일 문은 계속 지원되며 선언 본문에는 중괄호가 필요합니다.
  • 모든 case/default는 여전히 최종 break를 필요로 한다. 더 이른 return는, 계속하거나 전파한 과실 일반적으로 종료할지도 모릅니다; 혼자 syntactically 필수 unreachable 후행 break는 진단되지 않습니다.
  • 타입 피연산자는 문서화된 내장 본질만을 위한 컴파일 타임 피연산자입니다. 이는 일반적인 런타임 값이 아닙니다. 이 내재적 규칙은 0.2에서 유추될 수 있는 함수 제네릭 인수와는 별개이며, 주요 명시적 부분으로 제공되거나 기본값으로 완료될 수 있습니다.
  • 가져오기 및 표시 확인 후, 고유한 module/member 선언에 대한 전체 경로는 애매모호하게 사용됩니다. 숨겨진 모듈이나 긴 접두사 우선 순위가 도입되지 않았습니다.

4입니다. 남은 디자인 작업

초기 감사는 count가 의도적으로 우발적 인 모순으로 기능을 열지 않았습니다. 이 스냅샷에서 남은 정책 선택 사항으로는 returned/stored 참조 수명 표기법, 사용자 지정 정리 후크 및 부분 이동 제한 및 최소 OS/libc/deployment 매트릭스가 있습니다. 현재 릴리스 요구 사항 및 자격 증명은 이제 구현 프로필 및 설치 정보에 의해 추적되며, 해결되지 않은 일반 수명 및 사용자 정의 정리 설계는 별도로 유지됩니다.

초기 검토는 또한 identifier/literal 문법, 숫자 주석, 가시성, 인터페이스 충돌, generic-method/dynamic 적격성, project/package 메타데이터 및 추가 작업을 위한 백엔드 스키마를 나열했습니다. 나중에 0.2 구현은 해당 목록의 구체적인 부분을 해결했습니다. 명시적 캡처 일반 콜백, const usize 매개 변수 및 후행 기본값이 지원됩니다. 더 넓은 카탈로그 콜백 API, 셰이프 파라미터, 일반 Task API 및 GPU 실행은 현재 프로필 외부에 남아 있습니다. 명시적 CPU SIMD 및 범위 지정된 작업자 parallel.for_each가 구현됩니다.

let, auto, fn, uppercase String, old static storage declaration, actual name: 형식 로컬 선언 또는 명확한 문 세미콜론 생략이 초기 긍정-예제 검사에서 발견되었습니다. 127:i8와 같은 후보 리터럴 주석은 이름 우선 변수 선언이 아니며 여전히 별도의 어휘 정책이 필요합니다.

5입니다. CPU 실행 요구 사항

처음에는 macOS·Linux의 AArch64와 x86-64를 선택했고, Windows 지원은 이후로 미뤘습니다. 현재 0.2 구현에는 Windows x86-64 대상도 포함됩니다. 객체 파일·링크 검사와 네이티브 실행의 구분은 다음 문서에서 확인할 수 있습니다: 현재 플랫폼 상태. 공유 frontend/AIR 파이프 라인, 대상 인식 LLVM AOT 생성 및 ORC JIT가 구현됩니다. 직접 네이티브 코드 생성기는 이후의 확장 포인트로 남아 있으며, 현재 내부 런타임 인터페이스는 공개된 안정적인 ABI를 구성하지 않습니다.

대상, 실행, Runtime/ABI, 런타임 platform/architecture/startup, 툴체인, aevix 실행 및 이식성 테스트 폴더가 source/header 자리 표시자 없이 추가되었습니다. 네이티브 실행, 교차 컴파일, 대상 ABI 호환성 및 외국-CPU 에뮬레이션은 별도의 기능으로 유지됩니다. 더 보기 실행 아키텍처 및 초기 i32 main() 계약.

6입니다. 검사 경계

수정은 HTML 구조, 중복 식별자, 로컬 링크 및 앵커, 코드 마크업 및 문 종료기에 대한 checked입니다. 독립적 인 검토자는 새로운 소유권 규칙을 다시 확인했습니다. Shared CSS 및 JavaScript는 변경되지 않습니다. 문서 및 폴더 구조는 컴파일러, 대여 검사기 증명, CPU 실행 결과, GPU 결과 또는 벤치마크를 구성하지 않습니다.

원래 검토에서는 모든 CPU/OS 조합에 대해 기본 AOT/JIT 및 ABI가 확인되어야 했습니다. 현재의 자격 증명은 구현 프로파일에 별도로 기록됩니다. 정적 HTML 검사, 교차 생성 개체 파일 및 에뮬레이션된 실행은 고유한 증거 경계를 유지해야 합니다.
