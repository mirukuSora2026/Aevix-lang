0.2 구현 현황. 상수 제네릭 크기, 뒤쪽 매개변수의 기본값, 투명한 타입 별칭, numeric.Floating 은 구현되어 있습니다. 아래 절에서는 구현된 기능과 남아 있는 설계 제한을 구분합니다.

1입니다. 요구 사항과 형식 매개 변수 분리

struct Pair<T> where T implements Copy {
    public T first;
    public T second;
};

선택된 표기에서는 where T implements Copy 를 struct Pair<T> 뒤, 본문 앞에 둡니다. 꺾쇠괄호는 T를 도입하고 where 절은 T가 제공해야 할 기능을 명시합니다. 인라인 T: Copy 제약 표기를 사용하지 않고 요구 사항을 선택합니다.

승인된 제네릭 타입 선언 종류에도 같은 절 형식을 적용합니다. 여러 요구 사항은 주어를 반복하고 쉼표로 구분합니다. 예: where T implements Copy, T implements Leveled. 모든 요구 사항을 충족해야 하며, 타입과 함수에 같은 형식을 적용합니다.

2입니다. 구체적인 인수에 대한 요구 사항 확인

Pair<i32> numbers = Pair<i32> {
    first = 10,
    second = 20
};

i32는 확정된 Copy 기능을 충족하므로 이 구체 사용은 제약을 만족합니다. 컴파일러는 필드 값이 작거나 현재 사용되지 않는다는 이유로 허용하는 대신 지정한 타입의 실제 기능을 검사합니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: owning string does not implement Copy;
Pair<string> invalid_words(string initial_first, string initial_second) {
    return Pair<string> {
        first = initial_first,
        second = initial_second
    };
}

소유 string은 이동 기반이며 이 요구 사항을 충족할 수 없습니다. 거부 예제의 함수는 이미 소유 중인 string을 받으므로, 의도한 오류는 암묵적 리터럴→소유 값 변환이 아니라 Copy 제약 미충족입니다. 참조는 원본 추적을 유지하면서 자신의 Copy 규칙을 충족할 수 있습니다. 기능 일치는 참조 대상의 수명을 늘리지 않습니다.

3입니다. Copy 요구 사항이 컨테이너 Copy를 표시하지 않음

선언 속성의미
where T implements Copy허용된 모든 T는 Copy여야 합니다.
유형 T의 분야구체적인 필드는 T의 checked 값 전달 동작을 갖는다.
동봉하는 구조체 또는 enum별도로 Copy를 선택하지 않는 한 여전히 기본값으로 이동합니다.
전체 유형 Copy컴파일러는 별도의 옵트인 하에서 모든 필드 또는 모든 열거형 페이로드를 검증합니다.
Pair<i32> original = Pair<i32> {
    first = 1,
    second = 2
};
Pair<i32> moved = original;

제약이 있는 이 Pair도 대입하면 이동합니다. 제약은 T에 관한 사실을 나타낼 뿐 Pair의 공개 값 의미를 선언하지 않습니다. 컨테이너에 명시적으로 적용하려면 다음 구문을 사용합니다: struct CopyPair<T> implements Copy where T implements Copy. 타입의 implements 목록은 where 절보다 앞에 옵니다.

Copy는 컴파일러가 검사하는 내장 기능이며, 개발자가 할당이나 깊은 복사를 수행하도록 재정의하는 기본 본문이 아닙니다. 소유 컬렉션·Box·독점 참조를 제약이 있는 제네릭 타입으로 감싼다고 해서 Copy로 만들 수는 없습니다.

4입니다. 요구 사항은 일반 인터페이스의 이름을 지정할 수 있습니다.

interface Leveled {
    public i32 get_level(&Self self);
};

struct LevelHolder<T> where T implements Leveled {
    T item;
};

이 요구 사항은 지정한 타입이 선택된 Leveled 계약을 구현할 때만 허용합니다. 동작은 인터페이스에 선언된 수신자 타입과 반환 계약에서 정해집니다. private인 item 필드는 일반 struct 접근 규칙을 따르며, 제약이 필드를 public으로 만들지는 않습니다.

일반 인터페이스 요구 사항은 제네릭 검사에서 사용할 수 있는 동작을 명시합니다. 임의의 필드 접근, 암묵적 깊은 복사, Copy 상태, 힙 저장, 동적 메서드 선택 권한을 부여하지 않습니다. 제네릭 함수 본문은 선언된 요구 사항을 기준으로 검사합니다. 자세한 내용은 다음 문서를 참조하세요: 제네릭 함수. 제네릭 메서드는 메서드 이름 뒤에 자체 매개변수를 선언하며 정적으로 특수화됩니다.

5입니다. 일반 열거형과 인터페이스에서 선택한 절 사용

enum Snapshot<T> where T implements Copy {
    Empty;
    Present {
        public T value;
    };
};

interface Inspector<T> where T implements Copy {
    public T sample(&Self self);
};

enum의 요구 사항은 페이로드 매개변수를 제한합니다. Snapshot 자체는 별도의 Copy 구현이 없으면 여전히 이동 기반입니다. Inspector에서 T는 제약이 있는 타입 인자이고 Self는 구현 수신자 타입이므로, 이름과 역할이 서로 다릅니다.

제약이 enum의 모든 항목 처리 검사나 동적 인터페이스 메서드 제한을 없애지는 않습니다. 여러 매개변수는 다음 형태로 선언할 수 있습니다: <T, E>; 요구 사항은 다음처럼 쉼표로 구분합니다: where T implements Copy, E implements Copy.

6입니다. 요구 사항은 액세스 또는 대여을 우회하지 않습니다.

상황Result
T 인터페이스 구현선언 된 계약 만 약속되며 구체적인 개인 필드는 비공개로 유지됩니다.
모델 번호:Copy복사본은 T의 의미 체계를 따르며, 복사된 공유 참조는 여전히 동일한 저장소를 대상으로 합니다.
T는 자원을 소유일반 이동과 정리는 그대로 유지되며 인터페이스 바인딩은 이를 복제하지 않습니다.
값을 변경할 수 없음Name여기서 절은 일반적인 변경를 승인하지 않습니다.
값 포함 대여원본 수명 및 충돌 액세스 검사는 활성 상태로 유지됩니다.

인터페이스 제약과 명시적 dyn은 서로 다른 필요를 해결합니다. 전자는 타입 인자의 정적 요구 사항을 명시하고, 후자는 타입이 지워진 뷰를 통해 실행 중 호출 가능한 구현을 선택합니다. 이 구문으로 둘 사이의 변환을 추론하지는 않습니다.

7입니다. 런타임 폴백 없이 누락된 기능 거부

선택된 요구 사항을 충족하지 않는 구체 인스턴스화는 정적 검사에서 거부합니다. Copy를 위한 자동 clone 대체 동작, 인터페이스가 없을 때의 런타임 메서드 이름 조회, 암묵적 어댑터 구현은 없습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

struct Token {
    public i32 value;
};

// Rejected: Token has not opted into Copy;
Pair<Token> tokens = Pair<Token> {
    first = Token { value = 1 },
    second = Token { value = 2 }
};

이 예제는 첫 절의 Pair를 사용합니다. 원시 타입 Copy 필드가 있다고 해서 사용자 정의 Token이 자동으로 Copy가 되지는 않습니다. 정확한 오류 문구와 진단 식별자는 컴파일러 작업이며, 이 페이지는 거부되는 의미상의 이유를 기록합니다.

8입니다. 오픈 제약 문법 및 관련 참조

  • 함수 요구 사항은 다음 표기를 사용합니다: where T implements Copy, T implements Leveled: 주어를 반복하고 쉼표로 구분하며 모든 제약을 충족해야 합니다. 별도의 인라인 제약 구문은 선택하지 않았습니다.
  • 순서는 다음과 같습니다: struct Name<T> implements Interface where T implements Requirement.
  • 조건부 구현, 부정 제약, 연관 타입의 동등성 제약, 구조적 제약은 미정입니다.
  • 제네릭 함수의 위치와 호출 추론은 다음 문서에서 정합니다: 함수 문서; 메서드도 같은 제네릭 목록 위치와 정적 특수화 규칙을 사용합니다.
  • const usize 인자와 뒤쪽 기본값은 구현되어 있습니다. 임의의 상수 타입, Shape 매개변수, 수명 매개변수 구문, 부정 제약, 연관 타입 제약은 이 프로필에 포함되지 않습니다.
