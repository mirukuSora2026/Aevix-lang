추적 기본값 및 추론

struct·enum·interface·함수의 제네릭 매개변수 목록에는 뒤쪽 타입·상수 매개변수의 기본값을 지정할 수 있습니다. 기본값은 앞선 매개변수를 사용할 수 있습니다. 기본값이 있는 매개변수 뒤에는 필수 매개변수를 둘 수 없으며, 기본값은 자기 자신이나 뒤쪽 매개변수를 참조할 수 없습니다.

struct Pair<T = i32, U = T> {
    public T first;
    public U second;
};

T identity<T = i32>(T value) {
    return value;
}

i32 main() {
    Pair value = Pair { first = 20, second = 22 };
    i32 result = identity(value.first + value.second);
    return result;
}

함수 인수는 추론에 사용됩니다. 명시적 함수 타입 인자는 제네릭 목록의 앞부분만 지정할 수 있으며, 나머지는 추론이나 뒤쪽 기본값으로 완성합니다. 인자를 생략한 제네릭 타입 이름은 기본값을 사용합니다. 컴파일러는 필드 초기식의 값으로 임의의 제네릭 struct 타입을 추론하지 않습니다.

컴파일 시간 상수 범위

값 매개변수는 다음 구문을 사용합니다: const usize N. 현재 컴파일러는 usize 상수 매개변수를 허용합니다. 인자는 usize에 들어가는 음이 아닌 컴파일 타임 값이어야 합니다. 런타임 변수, 음수, usize의 범위를 넘는 부호 없는 값은 거부합니다.

struct Buffer<T = i32, const usize N = 4> {
    public Array<T, N> values;
    public usize len(&Self self) {
        return N;
    }
};

usize width<T, const usize N>(&Array<T, N> values) {
    return N;
}

i32 main() {
    i32 items[4] = [1, 2, 3, 4];
    usize count = width(&items);
    Buffer buffer = Buffer { values = items };
    return buffer.len() == count ? 42 : 1;
}

같은 크기를 정수 리터럴이나 접근 가능한 const 이름으로 적을 수 있습니다. 컴파일러는 값을 정규화하므로 4와 2 * 2로 계산되는 상수는 같은 특수화를 가리킵니다. 길이가 0인 고정 배열도 허용합니다. 기본값에는 상수식을 사용할 수 있습니다. 보다 큼 또는 시프트 연산자를 포함한 식은 닫는 꺾쇠괄호와 구별되도록 괄호로 감싸세요.

배열 크기는 Array 타입, 고정 배열 선언자, 대여, 제네릭 컨테이너 필드를 통해 추론할 수 있습니다. 상수 매개변수는 정적 타입이나 컴파일 타임 값을 제어하며, 실행 중 차원이 변하는 타입을 만들지는 않습니다.

투명 타입 별칭

public type UserId = u64;
type Samples = Array<f32, 4>;

UserId identity(UserId value) {
    return value;
}

별칭은 같은 타입의 다른 표기입니다. 새로운 명목 타입을 만들거나 소유권·표현·오버로드 식별·인터페이스 충족·변환 규칙을 바꾸지 않습니다. 별칭 순환은 컴파일 오류입니다. 가져온 별칭에도 일반 public/private 접근 규칙이 적용됩니다. 제네릭 별칭 선언은 이 프로필에 포함되지 않습니다.

플로팅 계약 Floating Contract

import numeric { Floating };

T twice<T>(T value) where T implements Floating {
    return value + value;
}

i32 main() {
    f32 result = twice(21.0f32);
    return result == 42.0f32 ? 42 : 1;
}

실제 numeric 모듈은 다음 계약을 공개합니다: Floating. 이는 컴파일러가 인식하는 스칼라 형식 계약이며 내장 f16·bf16·f32·f64만 구현합니다. 해당 형식의 투명한 별칭도 이를 충족합니다. Floating은 Copy 동작, 산술 +·-·*·/, 비교, 단항 부호를 보장합니다. 정확한 산술, NaN이 있을 때의 전순서, 비트 연산, 새로운 사용자 정의 연산자 오버로드를 보장하지는 않습니다.

사용자는 struct나 enum에 이 봉인된 계약을 구현할 수 없습니다. Floating이라는 이름의 사용자 정의 인터페이스는 일반 인터페이스이며 내장 수치 연산 권한을 얻지 않습니다. 컴파일러는 표기뿐 아니라 가져온 계약의 원래 정체성을 검사합니다. Copy만으로 산술이 허용되지는 않으며, 제약 없는 T에는 여전히 +를 사용할 수 없습니다.

컴파일러 범위

구체 타입·상수 인자는 정적 특수화를 결정합니다. AOT와 JIT는 하나의 컴파일 안에서 정규화된 식별을 재사용합니다. 추론 오류와 지원되지 않는 기능 사용은 기계어 생성 전에 진단합니다.

Shape 매개변수, 임의 타입의 상수 매개변수, 연관 타입, 수명 매개변수 구문, 공변성·반공변성, 사용자 정의 연산자 계약은 이 구현 프로필에 포함되지 않습니다. CPU SIMD와 Complex는 명시적 import와 각 문서의 제약을 사용합니다.
