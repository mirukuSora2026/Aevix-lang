1입니다. 구체적인 형식에 대한 선언 재사용

제네릭 타입 선언은 다음 위치에 타입 매개변수를 도입합니다: <...>. 구체적으로 사용할 때도 같은 꺾쇠괄호 형식으로 타입 인자를 지정합니다. 예: Pair<i32> 또는 Outcome<string, i32>. 지정한 타입은 필드와 메서드의 계약을 고정하며, 타입을 이름으로 나타내는 런타임 문자열이 아닙니다.

확정 범위. 제네릭 struct·enum·interface가 승인되었습니다. 제네릭 함수 선언과 호출 도 확정되었습니다. 0.2 프로필에는 다음 기능도 포함됩니다: const usize 매개변수, 뒤쪽 타입·값 매개변수의 기본값, 투명한 별칭. Shape 매개변수, 수명 매개변수 구문, 임의의 필드 값에 기반한 컨테이너 추론은 이 프로필에 포함되지 않습니다.

2입니다. 3 집중된 언급

구현된 추가 사항0.2 제네릭

상수 크기, 뒤쪽 기본값, 투명한 별칭, 봉인된 Floating 기능.

3입니다. 제약된 일반 구조체

struct Pair<T> where T implements Copy {
    public T first;
    public T second;
};

Pair<i32> numbers = Pair<i32> {
    first = 10,
    second = 20
};

i32는 Copy를 충족하므로 이 조건에서 허용됩니다. 소유 string은 Copy를 충족하지 않으므로 이 선언의 Pair<string>은 거부됩니다. T의 요구 사항은 Pair에 대한 Copy 선언이 아니므로 Pair 자체는 여전히 기본적으로 이동합니다.

4입니다. 선택한 양식 한 눈에 보기

형태목적
struct Pair<T>제품 같은 사용자 정의 값을 매개 변수화합니다.
enum Outcome<T, E>열거형 변형의 페이로드 유형을 파라미터화합니다.
interface Reader<T>행동 계약의 유형을 파라메터화합니다.
Pair<i32>제네릭 선언을 구체적인 타입 인수와 함께 사용합니다.
where T implements Copy일반 선언 헤드 뒤에 선택된 기능이 필요합니다.

where 절은 타입 인자 목록과 기능 요구 사항을 분리합니다. 인라인 콜론 제약은 지원하지 않습니다. 타입 자체의 implements 목록은 해당 타입의 where 제약보다 앞에 옵니다. 함수 문서는 쉼표로 구분하는 요구 사항과 호출 추론을 정의합니다.

5입니다. 일반적인 유형은 동일한 소유권 규칙을 유지합니다.

구체 필드는 지정된 타입의 Copy·이동·읽기 대여·쓰기 대여 계약을 따릅니다. 타입 매개변수는 복제·가변성·필드 접근·수명 연장 권한을 부여하지 않습니다. public/private 필드와 타입 전체의 Copy 명시는 일반 struct·enum과 똑같이 적용됩니다.

인스턴스화된 인터페이스도 동작을 설명합니다. 제네릭 매개변수만으로 런타임 디스패치, 동적 박싱, 데이터 전송이 도입되지는 않습니다. 0.2 컴파일러는 구체 정적 특수화 전에 계약을 검사하며, AOT와 JIT는 같은 파이프라인을 사용합니다.

6입니다. 개방형 일반 설계 및 관련 참조

  • 제네릭 함수 구문, 호출 위치의 앞부분 또는 전체 명시 목록, 추론, 뒤쪽 기본값은 다음 문서에서 설명합니다: 제네릭 함수; 제네릭 메서드도 이름 뒤에 매개변수를 둡니다.
  • 함수 제약은 주어를 반복하고 쉼표로 구분합니다. 타입의 implements 목록은 where; 조건부 구현 선언은 지원하지 않습니다.
  • const usize 인자, 뒤쪽 기본값, 투명한 별칭은 구현되어 있습니다. Shape 매개변수, 수명 매개변수 구문, 공변성·반공변성 확장, 연관 타입은 이 프로필에 포함되지 않습니다.
  • 구체 특수화는 AOT와 JIT에서 선언된 계약을 유지합니다. 제네릭 메서드는 dyn 뷰에서 사용할 수 없습니다. 제네릭 ABI 보장과 향후 코드 공유 전략은 미정입니다.
