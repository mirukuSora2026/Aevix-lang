선언전체 자료형연산자와 표현식제어 흐름

1. 스코프·접근 권한·수명

스코프는 이름을 사용할 수 있는 곳을, 접근 권한은 선언 경계를 통해 무엇을 공개할 수 있는지를 정합니다. 수명은 값이나 자원이 유효한 기간을 정합니다. Aevix는 이를 구분합니다. public 접근 권한이 지역 변수나 대여한 자원을 계속 살려두지는 않습니다.

설계 문서. 확정된 언어 규칙은 직접 설명하고, 미정 정책과 권고안은 따로 표시합니다. 이 예제들이 컴파일러·런타임·진단 시스템의 구현을 뜻하지는 않습니다.

지역 바인딩은 기존의 타입 우선 구문을 사용하며 기본적으로 불변입니다. 변경하려면 다음을 명시합니다: mut. rsn 은 동적 조회가 아니라 정적 추론을 수행합니다. 선택된 struct, enum, 및 interface 형태가 타입의 접근 권한을 구체화합니다. 모듈 경로와 import 규칙은 다음 문서에서 정했습니다: 모듈과 import. 사용자 정의 정리 선언은 아직 미정입니다.

2. 지역 선언과 하위 스코프

지역 렉시컬 스코프에 선언한 변수는 바인딩이 보이는 그 스코프와 중첩 스코프에서 사용할 수 있습니다. 조건문·반복문의 본문에 선언을 쓰려면 명시적 블록이 필요합니다. 중괄호는 실행 가능한 일반 문장 하나에만 생략할 수 있으며, 중괄호 없는 선언을 위한 특별한 스코프는 없습니다. 영역 밖에서는 지역 이름을 찾을 수 없습니다. 중첩 영역은 바깥 불변 변수를 읽을 수 있지만, 변경하려면 적절한 가변 바인딩이나 참조 권한이 여전히 필요합니다.

i32 outer = 10;
{
    i32 inner = outer;
    i32 observed = inner;
}
i32 still_available = outer;

닫는 중괄호에서 안쪽 지역 바인딩이 끝나며 바깥 바인딩은 자신의 스코프에 남습니다. 다음 코드는 선언 영역을 벗어난 이름을 의도적으로 사용합니다.

허용되지 않는 예제. 지역 이름은 자신의 렉시컬 영역 밖에서 사용할 수 없습니다.

{
    i32 inside = 10;
}
i32 escaped_name = inside; // Invalid: inside is out of scope.

3. public과 private 선언 접근

public 및 private 는 모듈·타입 선언의 공개 경계에 적용되며 지역 변수 선언에 붙이지 않습니다. public은 해당 선언 경계를 통한 외부 접근을 허용하고 private은 선언 경계 내부로 제한합니다. 어느 한정자도 쓰기 참조를 주거나 저장 공간을 할당하거나 값의 수명을 늘리지 않습니다.

선언 문맥확정된 규칙경계
모듈·타입 선언 경계public과 private은 접근 권한을 제어합니다.타입 멤버는 선택된 struct·enum·interface 규칙을 따르고, 모듈 조회는 확정된 import 경로와 이름 충돌 규칙을 따릅니다.
지역 변수public이나 private을 붙이지 않습니다.이름은 선언 영역과 중첩 영역 안에서만 사용할 수 있습니다.
공개된 소유 값이나 참조일반 소유권·대여 규칙은 그대로 적용됩니다.호출자는 접근할 때마다 유효한 소유 값이나 대여 권한을 유지해야 합니다.

허용되지 않는 예제. public으로 지역 변수의 가시 범위를 넓힐 수 없습니다.

void local_visibility() {
    public i32 count = 0; // Invalid: visibility modifier on a local.
    return;
}

struct 필드와 enum 페이로드 필드는 기본 private이며, enum 항목 이름은 enum의 접근 범위 안에서 기본 public입니다. 이름을 지정한 필드 초기화와 case 바인딩도 접근 제어를 따릅니다. 타입 내부 팩토리는 private 필드를 초기화할 수 있습니다. 모듈 최상위의 타입·함수·상수는 기본 private입니다. 모듈 경로를 붙이는 규칙은 Import와 접근 권한을 따릅니다. 그 밖에 미정인 멤버 종류의 기본 접근 권한은 아직 열려 있습니다.

4. 보이는 변수 이름의 가리기 금지

새 변수 선언은 겹치는 렉시컬 영역에서 이미 보이는 변수를 가려서는 안 됩니다. 타입을 바꾸거나 mut을 붙여도 같은 이름의 재선언이 허용되지는 않습니다. 함수 매개변수는 함수 본문에서 보이는 지역 바인딩이므로 안쪽 선언이 그 의미를 조용히 대신할 수 없습니다.

허용되지 않는 예제. 안쪽 선언이 이미 보이는 바깥 바인딩을 가립니다.

i32 count = 1;
{
    i32 count = 2; // Invalid: visible-variable shadowing.
}

서로 다른 값을 나타내는 두 바인딩에는 다른 이름을 쓰세요. 기존 가변 바인딩에 대입하는 것은 대입이지 새 선언이 아닙니다.

mut i32 count = 1;
{
    i32 next_count = 2;
    count = next_count;
}

확정된 case 스코프. 모든 case와 default에는 독립적인 암묵적 지역 스코프가 있습니다. 바깥의 보이는 변수를 가리지 않는다면 서로 다른 분기에서 본문 중괄호 없이 같은 지역 이름을 사용할 수 있습니다. 헤더 바인딩과 본문 지역 변수는 해당 분기를 나갈 때 끝납니다. 0.2는 겹치지 않는 다른 형제 블록의 이름 재사용도 허용합니다. 아직 보이는 상위 스코프 이름은 가릴 수 없습니다.

case 내부 이름

i32 choose_value(i32 code) {
    mut i32 result = 0;
    switch (code) {
        case 1:
            i32 value = 10;
            result = value;
            break;
        case 2:
            i32 value = 20;
            result = value;
            break;
        default:
            break;
    }
    return result;
}

각 value 바인딩은 서로 다른 분기에 속합니다. result 바인딩은 바깥 함수 스코프에서 공유하므로 분기 안에서 다시 선언할 수 없습니다. 합법적으로 유지한 참조의 수명은 계속 원본과 사용을 따릅니다. 분기를 나간다고 대여 의무가 사라지지는 않습니다.

5. 접근 권한이 변경 권한을 주지는 않습니다

바인딩은 보이면서도 불변일 수 있습니다. 선택된 다음 형태는 T value, &T value, 및 &mut T value 값의 소유권, 공유 접근, 독점적인 대상 접근을 구분합니다. &mut T 타입의 불변 참조 바인딩도 허용된 대상을 수정할 수 있습니다. 참조 바인딩 자체의 가변성은 그 참조를 다시 대입할 수 있는지를 정합니다.

mut i32 count = 1;
&mut i32 target = &mut count;
*target = 2;
i32 observed = *target;

&mut owner를 만들려면 owner 바인딩에 mut이 필요합니다. public은 이 권한을 만들지 않습니다. Atomic·Mutex 같은 동기화 타입은 각자의 접근 계약을 유지하며 임의의 가변 별칭을 허용하지 않습니다.

6. 이름과 대여한 뷰

참조나 뷰는 원본이 유효할 때만 이름으로 사용할 수 있습니다. 참조가 보인다고 다른 별칭을 통해 원본을 이동·파괴·재할당할 수 있다는 뜻은 아닙니다. 공유 읽기는 공존할 수 있지만 활성 대여와 충돌하는 독점 접근은 금지됩니다.

Array<i32, 3> values = [1, 2, 3];
Slice<i32> view = Slice.from_array(&values);
usize count = Slice.len(view);

이미 있는 Slice·MutSlice·string_view나 호환 참조는 맞는 대여 매개변수에 그대로 전달합니다. 지역 스코프 규칙은 주소 취하기를 한 겹 더 추가하지 않습니다. 마지막 사용 분석으로 텍스트상 블록의 끝보다 대여가 일찍 끝날 수 있지만 원본 소유 값의 수명은 늘릴 수 없습니다.

7. 바인딩은 끝나도 소유권은 이동할 수 있습니다

지역 스코프가 끝나면 그 지역 바인딩을 제거하고 아직 그곳이 소유한 값의 정리를 수행합니다. 소유권이 이미 다른 곳으로 이동했다면 이전 바인딩이 다시 파괴하지 않습니다. 소유 값을 반환하면 함수의 닫는 중괄호에서 반환 자원을 파괴하는 대신 호출자에게 넘깁니다.

Vector<i32> make_values() {
    Vector<i32> values = Vector.new(i32);
    return values;
}

공유 소유도 다른 강한 소유자가 남아 있다면 핸들 하나의 지역 스코프보다 페이로드를 오래 유지할 수 있습니다. Weak 관찰자는 페이로드를 살려두지 않습니다. 별도의 자원 정리 문서 에서 이 해제 의무를 설명합니다.

8. 영역에서 나가기

블록 완료, break, continue, return, ?를 통한 오류 전파는 해당 제어 흐름이 통과하는 영역을 나갑니다. 지역 정리는 실제로 벗어나는 영역을 따릅니다. 중첩 반복문의 break가 바깥 함수를 끝내지는 않으며, return은 여러 중첩 영역을 한꺼번에 벗어날 수 있습니다.

?는 호환되는 Result 반환 함수에서 오류를 반환하는 확정된 축약 표기입니다. 일반 스코프·소유권·수명 검사를 그대로 따르므로 대여한 지역 값을 탈출시킬 수 없습니다. 각 구문은 다음 문서를 참고하세요: 제어 흐름 및 연산자 에서 세부 구문을 확인할 수 있습니다.

case의 지역 스코프는 독립적입니다. 앞선 return, 반복문의 continue, 발산 경로 또는 Result ? 는 허용되지만 마지막 case break는 여전히 작성해야 합니다. 그 break에 도달할 수 없어도 그 이유만으로 오류나 경고가 되지는 않습니다. return·continue·Err는 실제로 나가는 영역만 정리합니다. 이 예외가 일반 도달 불가능 코드 정책을 정하거나 무한 실행을 스코프 종료로 바꾸지는 않습니다. 자세한 내용은 case 종료의 파싱 규칙.

9. 지속 저장소와 public 접근

persist 는 별도 계약에 따라 선언마다 프로세스 수명의 저장소를 제공합니다. 접근할 수 없던 지역 이름을 전역에서 찾게 하거나 선언을 타입 멤버로 바꾸거나 공유 수정을 안전하게 만들지는 않습니다. public도 일반 지역 할당을 지속 저장소로 바꾸지 않습니다.

최상위 초기화는 프로그램 진입 전에, 지역 초기화는 처음 도달했을 때 스레드 하나가 수행합니다. 제네릭 함수의 저장소 식별 규칙과 정상 종료 순서는 이제 다음 문서에서 정했습니다: 지속 저장소. 스레드별 저장소 변형은 미정입니다. 이름 사용 범위와 저장 기간은 별도로 검사해야 합니다. 다음 문서에서 변수 선언 확정된 선언 형태를 확인할 수 있습니다.

10. 필수 거부 조건과 미정 정책

조건선택된 결과뜻하지 않는 것
지역 이름을 렉시컬 영역 밖에서 사용이름 조회를 거부합니다.같은 이름의 살아 있는 변수를 동적으로 찾지 않습니다.
지역 바인딩에 public 또는 private 사용지역 선언을 거부합니다.public 지역 변수의 수명 연장은 없습니다.
이미 보이는 변수를 가리는 재선언이름 가리기를 거부합니다.겹치지 않는 형제 스코프의 이름은 재사용할 수 있지만 보이는 바깥 지역 이름의 가리기는 금지됩니다.
대여한 값이 원본의 유효 수명 밖으로 탈출안전하지 않은 탈출을 거부합니다.public 접근 권한으로 이 오류를 무시할 수 없습니다.
다른 case의 지역 이름을 사용자신의 분기 밖에서 이름 조회를 거부합니다.서로 다른 case의 지역 이름은 같아도 되지만 보이는 바깥 이름은 가릴 수 없습니다.

이는 소스 규칙의 요구 사항이지 실제 컴파일러 오류 코드가 아닙니다. 진단은 선언과 관련 충돌 사용을 가리켜야 합니다.

11. 관련 문서

현재 사용자 정의 타입 문서 는 필드 접근과 메서드 receiver를 설명하고, Enum Switch 는 독립된 분기와 페이로드 바인딩을 설명합니다. 모듈 조회는 다음에서 정했습니다: 모듈과 import. 사용자 정의 정리 구문은 미정입니다. 겹치지 않는 형제 블록의 이름 재사용은 이미 0.2에서 지원합니다. 접근 권한이 지역 소유 값이나 대여 원본의 수명을 늘리지는 않습니다.
