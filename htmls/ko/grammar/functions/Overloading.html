관련 레퍼런스

기본 함수 선언제네릭 타입인터페이스모듈과 import영속 저장소전체 자료형

1입니다. 유효한 오버로드를 통해서만 함수 이름 공유

i32 select(i32 value) {
    return value;
}

i64 select(i64 value) {
    return value;
}

i32 select(i32 first, i32 second) {
    return first + second;
}

void use_selection() {
    i32 small = select(10);
    i64 wide = 20;
    i64 retained = select(wide);
    i32 sum = select(1, 2);
    return;
}

하나의 원래 모듈 내에서 파라미터 유형 또는 개수는 과부하를 구별합니다. i32 리터럴 기본값은 첫 번째 단일 인수 형식을 선택하고, 이미 입력된 i64는 두 번째를 선택하고, 두 개의 인수는 세 번째를 선택합니다. 일반 매개 변수 권한은 일치의 일부로 유지되며 과부하 해상도는 쓰기 기능을 제조할 수 없습니다.

2입니다. 유형, 함수 및 상수는 하나의 모듈 네임스페이스를 공유합니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: a constant and a function cannot share this module name;
const i32 scale = 2;

i32 scale(i32 value) {
    return value;
}

함수 오버로드는 서로 다른 매개 변수 시그니처에 대한 특정 예외입니다. 형식이나 상수가 동일한 선언 이름을 차지하는 것을 허용하지 않습니다. Public/private는 이러한 세 가지 선언 범주에 대한 고유한 네임스페이스가 아닌 액세스에 영향을 미칩니다.

매개 변수 이름은 호출에 도움이되지만 다른 매개 변수 type/count 시그니처을 만들지는 않습니다. 그렇지 않으면 동일한 함수는 단순히 인수의 이름을 변경하여 다시 선언할 수 없습니다.

3입니다. 반환 형식만으로는 선언을 구분할 수 없습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: these parameter signatures are identical;
i32 convert(i32 value) {
    return value;
}

f64 convert(i32 value) {
    return 1.0;
}

i32 또는 f64 유형으로 수신 변수를 기록한다고 해서 이 과부하가 적법하게 설정되는 것은 아닙니다. 반환 컨텍스트 일반 추론은 그렇지 않으면 일치하는 후보의 해결되지 않은 형식 매개 변수를 채웁니다. return 전용 오버로드를 승인하거나 인수 추론 유형을 대체하지 않습니다.

4입니다. 선택한 환경 설정을 순서대로 적용

단계선택된 행동
선언 출처 해결다른 원래 모듈은 별도의 과부하 가족으로 남아 있습니다. 모호한 가져온 짧은 이름은 먼저 자격이 있어야 합니다.
Map 인수인수 names/positions, 일반 카운트, 사용 가능한 기본값, 전달 모드, 일반 대체 및 선언 된 요구 사항을 확인하십시오.
입력된 입력 사용암시적 숫자 변환 없이 이미 입력된 인수 정보를 사용하는 좁은 후보.
형식이 없는 숫자 리터럴 비교하기generic/non-generic 타이 규칙 전에 i32 정수 또는 f64 실제 기본값과 일치하는 호환 가능한 후보를 선호합니다.
달리 동등한 일반 넥타이를 깨십시오.부적합이 그렇지 않으면 동등할 때 non-generic 후보자를 선호하십시오.
그렇지 않으면 동등한 팩 넥타이를 깨십시오.앞의 유형, 리터럴 및 generic/non-generic 환경 설정 후, 다양한 것보다 고정 파라미터 후보를 선호합니다.
남은 타이를 거부합니다.소스 순서, 가져오기 순서, 추측 너비 또는 기본값 count 폴백이 없으면 승자가 선택됩니다.

명시적 형식 인수는 일반 후보자를 요청합니다. 이것은 컴파일-시간 선택이다; 표현식은 어떤 오버로드가 성공할 것인지를 발견하기 위해 추측적으로 실행되지 않는다. 추가 숫자 변환 순위 또는 임의의 가중치 일치 점수가 도입되지 않습니다.

5입니다. 리터럴의 기본값 앞에 입력된 증거

i32 choose_pair(i32 first, i32 second) {
    return first;
}

i64 choose_pair(i64 first, i64 second) {
    return first;
}

void use_later_typed_argument() {
    i64 wide = 40;
    i64 result = choose_pair(10, wide);
    return;
}

형식화된 i64가 암시적으로 변환되지 않기 때문에 wide는 i32 후보를 배제합니다. 나머지 i64 매개변수 컨텍스트는 형식이 지정되지 않은 정수 리터럴을 허용합니다. 10의 이전 소스 위치는 잘못된 i32 결정을 강제할 수 없습니다.

이 선택 순서는 평가 순서를 변경하지 않습니다: 첫 번째 인수는 두 번째 인수 이전에 평가됩니다. 정적 형식 정보는 이러한 런타임 부작용과 독립적으로 컴파일러에서 사용할 수 있습니다.

6입니다. 일반성보다 기본 숫자 형식 우선

i32 numeric(i32 value) {
    return value;
}

i64 numeric(i64 value) {
    return value;
}

f32 real_numeric(f32 value) {
    return value;
}

f64 real_numeric(f64 value) {
    return value;
}

void use_literal_defaults() {
    i32 whole = numeric(10);
    f64 real = real_numeric(0.5);
    return;
}
i64 prefer_literal_default(i64 value) {
    return value;
}

T prefer_literal_default<T>(T value) {
    return value;
}

void default_before_generic_tie() {
    i32 selected = prefer_literal_default(10);
    return;
}

마지막 호출은 정수 기본값과 일치하기 때문에 일반 T = i32 후보를 선택합니다. 비제네릭 i64 후보는 단순히 비제네릭이기 때문에 이기지 않는다; 그 선호는 문자적 적합성이 달리 묶여진 후에만 적용된다.

7입니다. 동등한 적합성을 위해서만 구체적인 기능을 선호한다.

i32 identity(i32 value) {
    return value;
}

T identity<T>(T value) {
    return value;
}

void use_generic_ties() {
    i32 concrete = identity(10);
    i32 generic = identity<i32>(20);
    return;
}

일반 호출에는 똑같이 적합한 콘크리트 i32 함수와 일반 i32 전문화가 있으므로 비원형 형식이 승리합니다. 명시적인 angle-bracket 호출은 제네릭 패밀리를 직접 선택합니다. 0.2에서 명시적 함수 제네릭 인수 목록은 선행 부분을 제공할 수 있습니다. 추론 또는 후행 기본값은 나머지 매개 변수를 해결해야 합니다. 더 보기 제네릭 프로파일 Generic Profile.

8입니다. 기본 후보자가 승리하지 않을 때 추측하지 마십시오.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

i8 small_number(i8 value) {
    return value;
}

i16 small_number(i16 value) {
    return value;
}

// Rejected: both accept 10, neither matches the i32 default;
void ambiguous_numeric_literal() {
    rsn result = small_number(10);
    return;
}

최소 너비 설정은 없습니다. 이미 입력 된 인수를 제공하거나 그렇지 않으면 모호성을 제거합니다. 호환 가능한 비 기본값 후보가 하나만 남아 있는 경우 컨텍스트 리터럴 입력은 해당 후보를 사용할 수 있습니다. 규칙은 모든 비 i32 숫자 매개 변수를 금지하지 않습니다.

void resolve_with_a_type() {
    i8 value = 10;
    i8 result = small_number(value);
    return;
}

9입니다. 더 적은 기본값은 기본 설정이 아닙니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

i32 choose_default(i32 value) {
    return value;
}

i32 choose_default(i32 value, i32 offset = 0) {
    return value + offset;
}

// Rejected: both match equally; the omitted-default count is not ranked;
void ambiguous_default_count() {
    i32 result = choose_default(10);
    return;
}

두 함수 모두 별개의 선언된 매개변수 카운트를 가지고 있으며 공존할 수 있지만, 단일 인수 호출은 애매합니다. 어떤 규칙도 제로 디폴트 인수를 사용하는 후보를 선호하지 않습니다. 두 인자 호출은 두 번째 함수를 직접 선택할 수 있습니다. 더 보기 인수와 기본값.

10입니다. 오버로드 일치 전에 모듈 제품군 해결

이러한 독립적인 모듈들이 각각 choose라는 이름의 public 함수를 노출시킨다고 가정하자. 코드 블록은 별도의 모듈 픽스처이며 하나의 모듈에 연결하기위한 선언이 아닙니다.

단위 calculations.integer

public i32 choose(i32 value) {
    return value;
}

단위 calculations.real

public f64 choose(f64 value) {
    return value;
}

Consumer(소비자): 의도된 가족을 식별하는 자격

import calculations.integer { choose };
import calculations.real { choose };

void use_qualified_calls() {
    i32 first = calculations.integer.choose(10);
    f64 second = calculations.real.choose(0.5);
    return;
}

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected in that consumer: different originating modules share choose;
void invalid_pooled_set() {
    i32 result = choose(10);
    return;
}

인자는 하나의 모듈의 함수를 선택함으로써 애매모호한 짧은 이름을 적법하게 만들 수 없다. 원래의 두 오버로드 제품군은 never 풀링입니다. 로컬 패밀리와 다른 가져온 패밀리는 동일한 규칙을 따릅니다. 로컬 이름은 가져온 패밀리를 자동으로 흡수하거나 능가하지 않습니다.

재수출 경로를 통해 동일한 정식 원본 선언에 반복적으로 액세스해도 해당 선언의 경쟁 복사본이 생성되지 않습니다. 형식 및 함수 ID는 원래 선언을 따르고 자격 증명 권한은 선택한 가져오기 및 다시 내보내기 경로를 따릅니다.

11입니다. 이름이 시그니처 ID가 아닌 후보 일치에 참여

각 후보는 지정된 인수를 선언된 매개 변수에 매핑합니다. 알 수 없는 이름, 중복된 바인딩 및 지정된 형식이 유효하지 않은 후의 위치 인수입니다. 공개 매개 변수 이름은 유효한 명명 된 호출을 변경하기 때문에 호출 가능한 API의 일부입니다.

동일한 매개 변수 types/count를 가진 함수는 단순히 다른 매개 변수 이름을 통해 고유한 과부하가 될 수 없습니다. 지정된 인수 표현식의 소스 평가 순서는 선택된 매개변수 위치가 다른 경우에도 유지됩니다.

12입니다. 최종 타이 break로만 고정 대 가변 환경 설정 적용

i32 choose_pack(i32 value) {
    return 1;
}

i32 choose_pack(i32 values[]) {
    return 2;
}

void fixed_wins_equal_tie() {
    i32 selected = choose_pack(10);
    return;
}

두 후보 모두 i32 인수를 수락하고 둘 다 비정형입니다. 최종 팩 타이-break는 고정 파라미터 기능을 선호하므로 지정된 디자인에서 1가 선택됩니다. 이것은 관찰된 Aevix 실행이 아닙니다.

T generic_or_pack<T>(T value) {
    return value;
}

i32 generic_or_pack(i32 values[]) {
    return 2;
}

void generic_preference_still_runs_first() {
    i32 selected = generic_or_pack(10);
    i32 explicit_generic = generic_or_pack<i32>(10);
    return;
}

일반 호출은 최종 고정 대 가변적 타이 break에 도달하기 전에 비일반 팩 후보를 선택합니다; 선택된 것은 2입니다. 명시 적으로 입력 된 호출은 일반 함수를 선택하고 10를 반환합니다. 숫자 리터럴 환경 설정도 동점-break보다 일찍 유지됩니다.

생략된 일반 기본값의 count는 순위가 없습니다. 다른 오리진 모듈은 별도의 과부하 패밀리로 남아 있으며, 정규 복제 재수출은 추가 후보자를 만들지 않으며 나머지 동점은 여전히 컴파일 시간 모호성입니다.

  • 암시적 사용자 정의 변환, 확장 메서드 조회 및 추가 인터페이스 방법 충돌은 이러한 자유 함수 규칙에 의해 도입되지 않습니다.
  • 팩 규칙은 별칭을 활성화하거나, 개인 선언을 노출하거나, 선택되지 않은 형제 자매를 가져오거나, named/spread 팩을 허용하거나, 외국 varargs ABI를 정착하지 않습니다.
