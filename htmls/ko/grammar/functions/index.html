1입니다. 기존 Function Contract 기반으로 구축

Aevix는 함수 이름 앞에 return 형식을 쓰고 각 매개 변수 이름 앞에 매개 변수 형식을 씁니다. 값은 해당 유형이 Copy일 때 복사되고 그렇지 않으면 이동되며 공유 및 전용 대여은 명시적인 기능으로 유지됩니다. 이 페이지는 초기 선언 참조 후에 선택된 기능 기능을 사용하여 해당 계약을 확장합니다.

설계 문서. 선택된 규칙은 여기에 문서화되어 있으며, 자세한 내용은 명시 적으로 구분됩니다. 예제는 구현된 파서, 컴파일러, 대여 검사기 또는 런타임의 결과가 아니라 언어 디자인 일러스트레이션입니다.

4입니다. 유형 및 호출 인텐트를 직접 읽으십시오.

T identity<T>(T value) {
    return value;
}

i32 add_offset(i32 value, i32 offset = 1) {
    return value + offset;
}

void receive(i32 values[]) {
    return;
}

void demonstrate() {
    i32 inferred = identity(10);
    i32 explicit_type = identity<i32>(20);
    i32 adjusted = add_offset(offset = 3, value = 7);
    receive(1, 2, 3);
    return;
}

두 개의 아이덴티티 호출은 컴파일 타임에 인자라는 이름의 add_offset 맵을 T = i32를 선택한다; 그들의 소스 순서는 파라미터 순서와 일치할 필요가 없다. variadic 예제에서는 임시 팩에 대한 읽기 전용 Slice 같은 보기를 사용합니다. 요소는 일반적인 Copy-or-move passing을 따르며, 피호출자는 팩 저장소를 성장, 소비 또는 내보낼 수 없습니다.

5입니다. 소유권, 비용 및 평가를 계속 표시

기능 기능은 암시적 숫자 캐스트, 소유자 클론, 복싱 또는 장치 전송을 추가하지 않습니다. 일반적인 argument는 계속 동작한다. 기본값은 임의의 런타임 함수를 할당하거나 호출할 수 없습니다. Copy 값은 여전히 실제 복사 비용을 가질 수 있습니다; 컴파일 타임 선택은 모든 작업을 무료로 만들지 않습니다.

명시적 인수 표현식은 한 번 실행되며, 왼쪽에서 오른쪽으로 소스 순서로 실행됩니다. 명명된 인수를 재정렬하면 평가 순서가 변경되며, 각 결과의 이름을 지정하는 매개 변수는 변경되지 않습니다. 오버로드 해상도와 일반 검사는 어떤 후보가 작동하는지 결정하기 위해 인수 표현식을 실행하지 않습니다.

6입니다. 닫힌된 variadic 규칙 및 남아 있는 결정

Variadic 팩은 같은 타입의 인자를 0개 이상 허용하고, 일반적인 Copy/move 소유권을 사용하고, 팩에 대한 숨겨진 힙 할당 없이 콜 바운딩된 읽기 전용 뷰를 제공합니다. 팩이 초기에 지원되지 않기 전에 가변 바인딩, 확산 및 일반 기본값으로 명명된 가변 팩 바인딩입니다. 달리 묶인 고정 파라미터 과부하는 기존 type/literal/generic 환경 설정 이후에만 승리합니다.

  • 일반 동적 배열 매개 변수, 반환 및 일반 인수는 표준 Vector 유형을 사용합니다. 고정 값 매개 변수는 Array 소유자를 이동하고 전체 배열은 명시적 &Array/를 사용합니다.&Vector입니다. 제품정보
  • 0.2 프로파일은 후행 type/const 기본값, 부분적으로 명시적인 함수 일반 인수 및 정적 일반 메서드를 지원합니다. 임의 필드 기반 컨테이너 추론, lifetime/Shape 매개 변수 및 일반 const 기능 시설은 프로필 외부에 남아 있습니다. 일반 메서드는 dyn를 통해 호출할 수 없습니다. generics 구현하기.
  • 물리적 ABI, 프레임 제한 및 세부적인 요소 정리 순서은 별도의 사양이 필요합니다. 동적 배열 리터럴 할당 오류는 선택된 CollectionError 캐리어를 사용합니다.
