관련 레퍼런스

기본 함수 선언제네릭 타입인터페이스모듈과 import영속 저장소전체 자료형

1입니다. 일반 매개 변수에 후행 기본값이 있을 수 있음

i32 add_offset(i32 value, i32 offset = 1) {
    return value + offset;
}

void use_default() {
    i32 implicit_offset = add_offset(7);
    i32 explicit_offset = add_offset(7, 3);
    return;
}

Omitting offset은 선언된 상수 1를 사용하며, 공급은 제공된 값을 사용합니다. 첫 번째 매개 변수는 여전히 필요합니다. 기본값은 선언의 호출 계약의 일부이며 일반적인 인수를 Optional 값으로 만들지 않습니다.

2입니다. 첫 번째 기본값 후, 나중에 일반 매개 변수는 기본값이 필요합니다.

i32 encode(i32 first, i32 second = 0, i32 third = 0) {
    return first * 100 + second * 10 + third;
}

void use_trailing_defaults() {
    i32 first_only = encode(1);
    i32 first_two = encode(1, 2);
    i32 all_three = encode(1, 2, 3);
    return;
}

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: a required ordinary second parameter follows a default;
i32 invalid_trailing_default(i32 first = 0, i32 second) {
    return second;
}

이 규칙은 일반적인 매개 변수에 관한 것입니다. 초기 규칙에서 variadic 매개 변수 앞의 기본 일반 매개 변수가 지원되지 않습니다. 필수 일반 접두사는 허용됩니다. 명시적인 자체 수신기에는 기본값이 없을 수 있습니다. 기본 문법은 새로운 묵시적 수신기를 생성하지 않습니다.

3입니다. 기본값은 Copy 호환 컴파일 시간 상수여야 합니다.

const i32 DEFAULT_OFFSET = 3;

i32 configured_offset(i32 value, i32 offset = DEFAULT_OFFSET) {
    return value + offset;
}
요구 사항의미
컴파일 시간 상수이 값은 선택된 컴파일-시간 상수 요구사항을 만족해야 한다; 임의의 런타임 계산은 허용되지 않는다.
Copy 호환 값생략된 인수를 제공하는 것은 하나의 공유 소유 기본 객체를 사용할 수 없습니다.
숨겨진 복제 또는 할당 없음기본값은 string/container를 할당하거나 암시적 복제 함수를 호출하는 요청이 아닙니다.
정상적인 Copy 비용은 남아 있습니다더 큰 허용된 값을 복사하는 것은 여전히 작업이 필요할 수 있습니다; 최적화는 행동을 보존해야 합니다.
완전 한 표현 문법허용된 상수 표현식의 전체 집합은 열려 있습니다; 간단한 숫자와 명명된 const 예제는 const 함수 기능을 정의하지 않습니다.

이 규칙은 Copy를 재정의할 수 있는 딥 클론 훅으로 만들지 않습니다. string 및 기타 비-Copy 리소스 값을 소유하는 것은 기본적으로 자동으로 생성되는 것이 아니라 명시적 소유권 API 하에 제공되어야 합니다.

4입니다. 기본값을 얻기 위해 임의의 함수를 실행하지 마십시오.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

i32 compute_offset() {
    return 1;
}

// Rejected: an ordinary function call is not an allowed default here;
i32 invalid_runtime_default(i32 value, i32 offset = compute_offset()) {
    return value + offset;
}

이 단순한 일반 함수 본문조차도 결과가 일정하게 보이기 때문에 컴파일 타임 호출 상태를 얻지 못합니다. 미래의 상수 기능 시설은 별도의 결정이 필요합니다. 기본 선택은 임의의 런타임 부작용이나 숨겨진 실패 생성 할당을 도입해서는 안 됩니다.

5입니다. 호출 사이트에서 parameter_name = 표현식 사용

void use_named_arguments() {
    i32 positional = encode(1, 2, 3);
    i32 named = encode(first = 1, second = 2, third = 3);
    i32 reordered = encode(third = 3, first = 1, second = 2);
    i32 mixed = encode(1, third = 3, second = 2);
    i32 skipped_default = encode(first = 1, third = 3);
    return;
}

이것은 trailing-default 예제에서 인코딩을 사용합니다. 처음 네 개의 호출은 첫 번째 = 1, 두 번째 = 2 및 세 번째 = 3입니다. 마지막 호출은 두 번째 호출을 생략하므로 0를 사용합니다. 명명된 인수는 모든 매개 변수 순서에 나타날 수 있지만 모든 위치 인수는 첫 번째 명명된 인수 앞에 나타나야 합니다.

호출 사이트 이름은 로컬 할당이나 명명된 필드 구성이 아닌 매개변수 바인딩입니다. 로컬 변수를 선언하거나 매개 변수 가변성을 변경하거나 함수의 receiver/borrow 계약을 우회하지 않습니다.

6입니다. 작성된 원본 순서로 명시적 표현 평가

i32 record_digit(&mut i32 trace, i32 digit) {
    *trace = *trace * 10 + digit;
    return digit;
}

void demonstrate_source_order() {
    mut i32 trace = 0;
    i32 result = encode(
        third = record_digit(&mut trace, 3),
        first = record_digit(&mut trace, 1),
        second = record_digit(&mut trace, 2)
    );
    return;
}

작성된 표현식은 세 번째, 첫 번째, 두 번째 순서로 실행됩니다: trace는 312가 됩니다. 결과는 매개 변수 이름과 일치하므로 결과는 123입니다. 이 숫자는 지정된 동작을 나타내며, 관찰된 Aevix 실행 결과가 아닙니다.

각 표현식은 한 번 실행됩니다. 매핑은 컴파일 시간에 발생하며 부작용을 선언 순서로 재정렬하지 않습니다. 각 record_digit 호출은 다음 시작 전에 임시 배타적 대여을 완료합니다. 명명된 인수는 일반적인 중복-대여 검사를 약화시키지 않습니다.

7입니다. 인수 레이블이 값 전달을 변경하지 않음

string relay(string value) {
    return value;
}

string move_named_string(string original) {
    string result = relay(value = original);
    return result;
}

string 소유는 위치 또는 이름으로 전달 여부를 이동합니다. literal-to-owner 변환 또는 자동 복제는 발생하지 않습니다. 호환 가능한 대여 인수는 기존 reference/view 계약과 마찬가지로 전달됩니다.

이전 인수를 평가하면 효과가 있고 나중에 작업이 실패하면 인수 이름을 지정해도 롤백이 생성되지 않습니다. 확립 된 실패와 Result 전파 경계는 여전히 둘러싸는 표현을 지배합니다.

8입니다. 알 수 없는, 중복된, 잘못된 인자 거부

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: fourth is not a parameter of encode;
void unknown_name() {
    i32 result = encode(first = 1, fourth = 4);
    return;
}

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: first is already supplied positionally;
void positional_and_named_duplicate() {
    i32 result = encode(1, first = 2);
    return;
}

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: a named argument is followed by a positional one;
void positional_after_named() {
    i32 result = encode(first = 1, 2);
    return;
}

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: the same named parameter is supplied twice;
void repeated_named_argument() {
    i32 result = encode(first = 1, second = 2, second = 3);
    return;
}

모든 필요한 일반 매개 변수도 제공되어야 합니다. 모든 맵핑과 타입 검사는 유효한 호출을 실행하기 전에 일어난다; 컴파일러는 형식이 잘못된 호출을 실행하지 않고 빠진 이름을 발견한다.

9입니다. 공개 매개 변수 이름은 API의 일부입니다.

호출자는 public 함수의 매개 변수 이름에 의존할 수 있습니다. 공개 파라미터의 이름을 변경하면 break가 호출자의 종류와 위치 순서가 변경되지 않더라도 호출자의 이름을 지정할 수 있습니다. 따라서 문서화 및 호환성 결정은 이러한 이름을 호출 가능한 API의 일부로 취급해야 합니다.

함수를 가져오는 것은 매개 변수 이름을 변경하지 않습니다. 이 언어는 현재 임포트 별칭을 제공하지 않습니다. 동일한 원래 함수를 다시 내보내면 기본 선언과 호출 계약이 유지됩니다. 일반 공개 매개변수 이름은 명명된 호출의 일부로 남아 있으며, variadic 팩 자체는 지원되는 명명된 인수가 아닙니다.

10입니다. 기본값과 이름은 숨겨진 순위 점수를 추가하지 않습니다.

기본값은 후보를 호출 가능하게 만들 수 있으며, 명명된 인수는 호환되지 않는 매개 변수 이름을 가진 후보를 배제할 수 있습니다. 그러나 생략 된 기본값의 수는 순위 기준이 아닙니다. 두 명의 똑같이 적합한 후보자는 더 적은 기본값을 사용하더라도 모호한 상태로 남아 있습니다.

반환 형식은 중복된 매개 변수 시그니처을 구분하지 않습니다. 다른 원래 모듈의 함수 세트는 인수가 일치하기 전에 별도의 상태로 유지됩니다. 더 보기 기본값-count 모호함 및 모듈-출처 경계 완전한 Examples

11입니다. 기본 및 다양한 경계

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: defaults before a variadic pack are unsupported;
void invalid_default_then_pack(i32 prefix = 0, i32 values[]) {
    return;
}

필요한 일반 접두사가 최종 팩 앞에 있을 수 있습니다. 반복된 인수는 위치 표현식을 사용합니다; 이름별로 팩을 공급하고 배열을 전파하는 것은 초기에 지원되지 않습니다. 일반 명명된 인수는 여전히 위치 우선 규칙을 따릅니다. 가변 가변 바인딩도 지원되지 않습니다. 수정을 위해 명시적 가변 배열 또는 MutSlice 매개 변수를 사용하십시오.

  • 완전한 상수 표현 문법과 가능한 컴파일 타임 함수 기능은 열려 있습니다.
  • 일반적인 타입-파라미터 디폴트와 추가적인 필드-디폴트 정책은 일반 함수 파라미터 디폴트에 의해 도입되지 않는다.
  • Variadic storage/ownership와 fixed-versus-variadic ties가 이제 선택됩니다; 그들의 전용 참조를 공개로 취급하기보다는 참조하십시오.
