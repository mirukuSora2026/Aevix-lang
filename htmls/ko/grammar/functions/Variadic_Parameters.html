1입니다. 마지막, 아마도 빈 인수 팩을 사용 하 여 []

void receive(i32 values[]) {
    return;
}

usize pack_len<T>(T values[]) {
    return Slice.len(values);
}

void send_values() {
    receive();
    receive(1, 2, 3);
    usize empty_count = pack_len<i32>();
    usize count = pack_len(1, 2, 3);
    return;
}

상기 선택된 표기은 The selected spelling T values[] 마지막 매개 변수 위치입니다. 0개 이상의 같은 타입의 인자를 받습니다; 일반적인 Vector 파라미터가 아닙니다. 호출자는 임시 소유 팩을 준비하고 호출자는 읽기 전용을 통해 액세스합니다. Slice<T>-보기처럼. T에는 Copy 전용 제한이 적용되지 않습니다.

일반 빈 팩은 여전히 충분한 유형 정보가 필요합니다. 여기 pack_len<i32>() 형식화되지 않은 빈 호출은 요소 유형을 발명할 수 없습니다.A untyped empty call cannot invent an element type. 일반적인 argument/destination 추론 규칙이 계속 적용됩니다.

3입니다. Copy 간단한 값, 소유자 이동 또는 참조 전달

usize count_owned(string values[]) {
    return Slice.len(values);
}

void send_owned_strings(string first, string second) {
    usize count = count_owned(first, second);
    return;
}

각 string 소유는 해당 소스에서 팩으로 이동합니다. 피뢰침은 사용 또는 교체하지 않고 끈을 관찰 할 수 있습니다. 팩은 소유자로 남아 있으며 통화가 정상적으로 완료되면 여전히 소유된 요소가 정리됩니다. 읽기 전용 호출자 뷰는 들어오는 인수를 대여하거나 호출자의 이동된 소유자를 보존하지 않습니다.

usize count_borrowed(&string values[]) {
    return Slice.len(values);
}

string keep_original(string original) {
    usize count = count_borrowed(&original);
    return original;
}

상기 팩 요소는 The pack element is &string. Shared-참조 값은 원래 참조 권한과 수명이 보존되는 동안 복사되며 텍스트 소유자는 이동되거나 복제되지 않습니다. pack 요소는 value 인수입니다: 기존의 non-Copy 전달 &mut U 또는 MutSlice<U> handle as a bare argument 핸들을 팩으로 옮긴다. 전용 외부에 대한 자동 리보로우 예외 &mut U 또는 MutSlice<U> 매개 변수는 팩 요소 T가 그 유형을 가지고 있기 때문에 단순히 적용되지 않습니다. 다음과 같은 명시적 인수 표현 &mut owner 대신, 그 표현에 새로운 대여을 만듭니다. 읽기 전용 팩은 여전히 독점 요소 기능을 복사하거나 추출할 수 없습니다. 소유 string는 문자 그대로 조용히 생성되지 않습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: the owning string was moved into the pack;
string invalid_reuse(string original) {

}

// Rejected: a string_view literal cannot supply an i32 element;

형식이 지정되지 않은 숫자 리터럴은 해결된 매개 변수 컨텍스트와 일치할 수 있습니다. 이미 입력된 값은 암시적 숫자 변환을 받지 않습니다. 균질 포장은 이질적인 목록이나 외국의 varargs-promotion 규칙이 아닙니다.

4입니다. 팩보기는 탈출하거나 저장을 소비 할 수 없습니다

Result<i32, BoundsError> first_value(i32 values[]) {
    &i32 first = Slice.at(values, 0)?;
    return Result.ok(*first);
}

읽기 전용 Slice 작업으로 팩을 검사할 수 있습니다. 이 예제에서는 i32 pointee를 복사하여 해당 값을 반환하지만 return는 임시 저장소를 참조하지 않습니다. 빈 팩은 유효하지만 일반 경계-checked 액세스는 여전히 return 오류일 수 있습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: the temporary pack view would outlive its call;
Slice<i32> invalid_return(i32 values[]) {
    return values;
}

뷰는 호출에서 살아남은 방식으로 반환, 저장 또는 캡처되지 않을 수 있습니다. 팩에서 소유 한 요소에 대한 대여도 마찬가지로 팩의 수명에 의해 제한됩니다. 요소 자체가 공유 참조인 경우 해당 참조를 복사하면 원래 외부 참조 수명이 유지될 수 있으며 팩 슬롯이나 팩 소유 값이 더 오래 유지되지 않습니다.

읽기 전용 액세스는 슬롯을 대체하거나 스토리지를 늘리거나 비 Copy 소유자를 추출하거나 독점 요소 대여을 제조 할 수 없습니다. 기존의 모든 동기화된 내부-접근 계약은 그 요소 타입의 속성으로 남아 있다; 팩 자체는 추가적인 변경 능력을 부여하지 않는다. 수정 또는 소유권 소비가 필요한 경우 일반 Vector, Array, MutSlice 또는 명시적 가변 배열 대여 매개 변수를 사용합니다.

기존 배열은 반복된 인수로 자동으로 확산되지 않으며, 명시적 확산 형식은 초기 규칙에서 지원되지 않습니다. Slice 매개변수는 호출자가 이미 런타임 길이 뷰를 가지고 있을 때 일반적인 대안입니다.

Array 소유자는 기본적으로 이동하며, 요소가 정수이므로 자동 포인터 감쇠 또는 전체 배열 Copy가 없습니다. 표준 Array 및 Vector 이름을 사용하는 return 소유권의 예입니다. 정상적인 가변 값 매개 변수는 호출자 소유의 배열을 변경합니다; 독점적 인 대여은 확립 된 대여 규칙에 따라 원래 소유자를 변경합니다.

Result<Vector<Vector<i32>>, CollectionError> make_dynamic_grid() {
    i32 rows[][] = [[1, 2], [3, 4, 5]]?;
    return Result.ok(rows);
}

선언은 중첩된 동적 컨텍스트를 제공하므로 중첩된 전체 리터럴에는 하나의 오류 가능한 구성 Result가 있습니다. 표준 return 유형은 Vector<Vector<i32>>를 소유한 것과 동일한 이름을 지정합니다. 이러한 할당은 variadic pack이 아닌 명시적 배열 구성에 속합니다.

접미사는 기본 요소 유형을 래핑합니다. 그 요소 타입이 참조일 때, 접미사는 참조의 배열을 기술한다; 그것은 전체 배열의 대여이 아니다. Whole-Array 대여 사용 &Array<...> 또는 &Vector<...>. Rank-bearing 또는 repeated-empty-bracket 매개 변수 선언자는 초기 함수 문법에서 지원되지 않습니다. 대신 표준 중첩 Vector 유형을 작성하십시오.

정규 선언의 경우, 괄호로 묶인 순위는 양의 컴파일 타임 정수이며, 동적 행 길이는 런타임에 변경될 수 있습니다. 고정 및 동적 브래킷 구성은 재귀적인 Array/Vector 매핑을 따릅니다. 고정 리터럴 범위는 checked입니다. 동적 [ ... ] 건설에는 명시적인 Result 처리가 필요하거나 ? Compatible 기능입니다. 더 보기 배열 및 정적 배열 완전한 문자 및 저장 계약을 위해.

6입니다. 인수를 한 번 준비하고 현재 팩 소유자를 정확히 한 번 청소하십시오.

호출자는 자신의 호출 프레임에 정적으로 카운트된 임시 팩을 준비한다. 팩 스토리지는 숨겨진 힙 할당을 도입하지 않습니다. Copy 요소 복사 및 비 Copy 소유자는 일반적인 가치 규칙에 따라 이동하므로 실제 copy/move 비용은 그대로 유지됩니다. 명시적 인수 구성, 복제 또는 동적 배열 리터럴은 자체 할당 및 오류 비용을 유지합니다.

명시적 인수 표현식은 한 번 실행되며, 왼쪽에서 오른쪽으로 소스 순서로 실행됩니다. 준비 트랙은 요소를 초기화했습니다. 일반 오류 전파가 나머지 인수가 준비되기 전에 호출자를 종료하면 이미 준비된 소유자는 정확히 한 번 정리됩니다. 반환된 Err는 일반적인 인수 값으로만 사용되기 때문에 기존 전파 작업 없이 전파되지 않습니다.

enum PrepareError {
    Failed;
};

Result<string, PrepareError> prepare_second(string input, bool reject_input) {
    if (reject_input) {
        return Result.err(PrepareError.Failed);
    }
    return Result.ok(input);
}

Result<usize, PrepareError> prepare_owned_call(
    string first, string second, bool reject_second
) {
    usize count = count_owned(first, prepare_second(second, reject_second)?);
    return Result.ok(count);
}

먼저 prepare_second 실행 전에 준비된 팩으로 이동합니다. 그 오류 경로에서, 입력 두 번째는 도우미에 의해 정리됩니다. ? 호출자를 종료하고 이미 준비된 첫 번째를 정리합니다. count_owned가 입력되지 않았습니다. 성공시 두 개의 소유 문자열을 관찰하고 나머지 두 팩 소유자는 그 호출 후에 해제됩니다. 이전 부작용은 롤백되지 않습니다.

호출이 정상적으로 완료되면 여전히 소유된 초기화된 팩 요소가 정확히 한 번 청소됩니다. 외부 저장소에 대한 유효한 복사된 참조는 원래 수명 뒤에 따라옵니다. 강제 안전 정지 및 외부 프로세스 종료는 새로운 정리 보증을 얻지 못합니다. 정확한 물리적 배치, 프레임 제한 및 ABI 하강은 숨겨진 힙 폴백 없이 이러한 소스 수준의 의무를 유지해야 합니다.
