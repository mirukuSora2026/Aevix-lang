0.2 구현 현황. 이제 함수 일반 목록은 후행 기본값, const usize 매개변수 및 추론 또는 기본값으로 완료된 부분 명시적 인수 목록을 지원합니다. 더 보기 제네릭 프로파일 Generic Profile.

1입니다. 형식 매개 변수 앞에 함수 이름 지정

T identity<T>(T value) {
    return value;
}

void use_identity() {
    i32 first = identity(10);
    i32 second = identity<i32>(20);
    return;
}

Capital T는 함수의 name-following angle brackets에 의해 선언된 타입 파라미터입니다. 범위에는 return 유형, 매개 변수 유형, 요구 사항 및 바디가 포함됩니다. 호출은 제네릭 인수를 추론하거나, 선두 부분을 명시적으로 제공하거나, 전체 정렬된 목록을 제공할 수 있습니다. 나머지 매개 변수는 인수 정보, 호환 대상 컨텍스트 또는 선언된 후행 기본값으로 해결되어야 합니다. 정상적으로 성공한 return는 여전히 return로 작성되며 신체의 최종 표현은 암시적 return가 아닙니다.

2입니다. 다중 타입 파라미터를 순서대로 일치

T first_of<T, U>(T first, U second) {
    return first;
}

void use_first_of() {
    i32 inferred = first_of(10, true);
    i32 explicit_types = first_of<i32, bool>(20, false);
    i32 partial_types = first_of<i32>(10, true);
    return;
}

T는 첫 번째 명시적 형식 인수에 해당하고 U는 두 번째에 해당합니다. 각 타입 파라미터는 고유하게 결정된 하나의 일관된 타입을 가져야 한다. 두 번째 값 매개 변수는 일반적인 값 인수입니다.이 간단한 함수가 return를 수행하지 않더라도 소유권은 형식을 따릅니다.

다음 상황에서 first_of<i32>(10, true), 명시적 접두사는 T를 i32로 수정하고 두 번째 값 인수는 U를 bool로 추론합니다. 더 짧은 목록을 작성하는 것은 나머지 매개 변수를 해결할 수 있을 때 유효합니다. 와일드카드 자리 표시자와 중간 매개 변수를 건너뛰는 것은 지원되지 않습니다. 추적 일반 기본값도 지원됩니다. 이 기본값은 추론 후 해결되지 않은 채 남아 있는 매개변수를 채웁니다.

T keep<T, Marker = bool>(T value) {
    return value;
}

void use_generic_default() {
    i32 result = keep<i32>(10);
    return;
}

Marker는 이 선언에 value 인수가 없으므로, 선언된 bool 기본값이 호출을 완료합니다. 기본값은 명시적인 인수나 추론으로 수정된 형식을 재정의하지 않습니다.

3입니다. 장소 일반적인 모수 후에 곳에

T copy_value<T>(&T value) where T implements Copy {
    return *value;
}

void use_copy_value() {
    i32 original = 7;
    i32 duplicate = copy_value(&original);
    i32 retained = original;
    return;
}

where 절은 매개 변수 목록의 괄호를 닫은 후 함수 본문 앞에옵니다. Copy는 공유 참조 및 T에만 적용되는 것이 아닙니다. 이것은 빌린 저장에서 그것을 이동하지 않고 복사한 점자를 돌려보내는 허용한다.

리시버 및 매개변수 액세스 계약은 여전히 중요합니다: 요구 사항은 공유 대여을 통해 변경를 부여하거나, 복제 작업을 생성하거나, 소스 수명을 연장하지 않습니다.

4입니다. 모든 쉼표로 구분된 요구사항은 유지되어야 합니다.

interface Leveled {
    public i32 get_level(&Self self);
};

i32 copied_level<T>(&T value)
    where T implements Copy, T implements Leveled {
    T duplicate = *value;
    return duplicate.get_level();
}

T copied_first<T, U>(&T first, &U second)
    where T implements Copy, U implements Copy {
    U inspected = *second;
    return *first;
}

각 요구 사항에 대해 주제를 반복하십시오. where T implements Copy, T implements Leveled또는 T 및 U와 같은 별도의 주제. 콤마 익스프레스 결합; 그들은 대안이 아니며 기본 구현을 의미하지 않습니다. 예제의 Newlines는 where 절을 선택한 위치에서 이동시키지 않습니다.

알려진 것과 동일한 Copy 구분이 일반 컨테이너에 적용됩니다. T에 대한 요구 사항은 포함 구조체 또는 enum Copy를 자동으로 만들지 않습니다. 형식은 다음과 같이 자체 기능 목록을 제약 조건과 결합할 수 있습니다. struct Pair<T> implements Copy where T implements Copy. implements 목록은 where; 두 절은 다른 형식에 적용됩니다.

5입니다. 선언 된 계약서에 대해 시체를 확인하십시오.

제네릭 바디는 허용된 모든 인수에 대해 유효한 연산을 사용할 수 있습니다: 일반 소유권 이전 및 차입, 정적으로 알려진 유형 및 선언된 요구 사항에 의해 보장되는 기능. 그것은 단지 하나의 구체적인 호출자가 그것을 제공하기 때문에 추가 방법에 의존 할 수 없습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: no Leveled requirement makes get_level available on T;
i32 missing_contract<T>(&T value) {
    return value.get_level();
}

AOT 또는 JIT 전문화는 이러한 소스 수준 유효성 규칙을 유지해야 합니다. 하나의 컴파일 경로가 편리한 콘크리트 유형을 알기 때문에 동일한 선언이 합법적이 될 수 없습니다. 0.2 컴파일러는 일반 계약을 확인한 후 표준 콘크리트 전문화를 만듭니다. AOT 및 JIT는 동일한 소스 유효성 검사를 사용하며 전문화는 선언에서 제외된 기능을 제공할 수 없습니다.

6입니다. 리터럴 디폴트 전에 입력된 인자 해결

T first_of_same<T>(T first, T second) {
    return first;
}

void use_typed_evidence() {
    i64 wide = 40;
    i64 first = first_of_same(10, wide);
    i64 second = first_of_same(wide, 20);
    return;
}

입력된 i64 인수는 소스 위치에 T = i64를 제공합니다. 그런 다음 untyped 정수 리터럴은 예상되는 숫자 형식과 일치할 수 있습니다. 컴파일러는 나중에 입력된 인수의 정보를 수집하기 전에 이전 리터럴을 i32로 수정해서는 안 됩니다.

단계규칙
선언된 명시적 형식 인수제공된 선도 또는 전체 정렬된 목록은 이러한 매개 변수를 수정합니다; 다른 증거는 명시적 선택을 대체할 수 없습니다. 인수 및 요구 사항에 대한 결과를 확인하십시오.
입력된 인자 정보입력된 숫자 값을 자동으로 변환하지 않고 호출의 입력으로부터 호환 가능한 형식 제약 조건을 수집합니다.
형식이 없는 리터럴가능한 경우 해결된 매개 변수 컨텍스트를 사용합니다. 그렇지 않으면 설정된 i32 정수 및 f64 실제 기본값을 적용합니다.
선언된 목적지인수 기반 추론 후에 해결되지 않은 형식 매개 변수만 채웁니다.
일반 기본값 추적선언된 기본값을 사용하여 인수와 대상 추론 후에 여전히 해결되지 않은 매개변수를 채웁니다.
완료해결되지 않거나 일관성이 없거나 요구 사항 위반 대체를 거부합니다.

이것은 형식 검사이며 표현식 평가 순서가 아닙니다. 인수 표현식은 여전히 원본 순서로 왼쪽에서 오른쪽으로 실행됩니다. 컴파일러는 나중에 정적 형식을 얻기 위해 인수를 일찍 실행하지 않습니다.

7입니다. 해결되지 않은 매개변수를 채우기 위해서만 대상 사용하기

enum ExampleError {
    Invalid;
};

Result<T, E> success<T, E>(T value) {
    return Result.ok(value);
}

void use_destination() {
    Result<i32, ExampleError> result = success(10);
    return;
}

입력은 T를 i32로 수정합니다. E에는 인수 소스가 없으므로 선언 된 대상 Result<i32, ExampleError>는 ExampleError를 제공합니다. 함수 자체의 선언 return type은 생성자 컨텍스트를 제공합니다. Result.ok; 암시적 래핑은 없습니다. return.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: rsn supplies no destination error type for unresolved E;
void unresolved_error_type() {
    rsn result = success(10);
    return;
}

임의의 디폴트 에러 타입은 발명되지 않는다. 선언된 대상을 완료할 수 있음 success<i32>(10) E = ExampleError를 사용하면 success<i32, ExampleError>(10) 둘 다 명확하게 제공하십시오. 대신 선언은 다음과 같은 후행 기본값을 제공할 수 있습니다. success<T, E = ExampleError>.

8입니다. 대상은 유추된 유형을 대체할 수 없습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: identity(10) has T = i32 before destination checking;
void incompatible_destination() {
    f64 result = identity(10);
    return;
}
void explicit_numeric_context() {
    i64 result = identity<i64>(10);
    return;
}

명시적 i64는 형식화되지 않은 정수 리터럴에 매개변수 컨텍스트를 제공합니다. 이미 입력된 i32 변수의 암시적 변환이 아닙니다. 입력 증거가 이미 유형을 설정한 경우 다른 수신 변수 유형으로 수정할 수 없습니다. 대여 및 이동 수표도 변경되지 않습니다.

9입니다. Copy, 이동 및 대여 유형 의존

string relay_string(string original) {
    string transferred = identity(original);
    return transferred;
}

기존 소유 string 인수는 identity로 이동하고 반환된 값을 통해 다시 이동합니다. 이 예제는 이미 소유한 string를 수신하며, 텍스트 리터럴에서 자동으로 할당되지 않습니다. 텍스트 리터럴은 현재 텍스트 계약에 따라 string_view이며, string를 소유하려면 명시적 오류 생성자가 필요합니다.

Copy 바운드가 없으면 일반 값 전송이 금지되지 않습니다. 이것은 T 가 중복될 수 있다는 것을 가정하는 것을 막는다. 빌린 T 값은 소스 권한과 수명을 유지하며, 일반 코드는 이러한 사실을 지우지 않습니다.

10입니다. 누락된 주장 및 상충되는 증거 거부

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: Missing has no argument source, destination source, or default;
T keep_with_extra<T, Missing>(T value) {
    return value;
}

void unresolved_remaining_parameter() {
    i32 result = keep_with_extra<i32>(10);
    return;
}

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: already typed arguments disagree about the same T;
void conflicting_arguments() {
    i32 narrow = 1;
    i64 wide = 2;
    i32 result = first_of_same(narrow, wide);
    return;
}

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: owning string is not Copy;
string invalid_copy(string original) {
    return copy_value(&original);
}

이 블록은 이 페이지의 이전 선언을 사용합니다. 거부된 경우는 0.2 컴파일러가 있는 checked였으며, 메시지는 명시된 실패 이유를 변경하지 않고 변경될 수 있습니다. 부분적인 리스트는 실수가 아니다: first_of<i32>(10, true) 견적 요청

11입니다. 기능 추론을 유형 구성과 분리

선택된 추론 규칙은 일반 함수 호출에 적용됩니다. 제네릭 타입의 사용은 디폴트를 선언한 후행 인자를 생략할 수 있다. 일반 형식 참조. 이것은 임의의 컨테이너 타입을 named-field initializer 값으로부터 추론하는 것과는 구별된다.

  • 명시적 함수 인수, 추론, 후행 일반 기본값, 그리고 const usize 매개 변수가 사용됩니다. 자세히 보기 0.2 제네릭 프로필.
  • 와일드카드 자리 표시자, 임의 const-파라미터 유형, 셰이프 매개 변수, 수명 매개 변수 구문, 상위 순위 범위 및 관련 형식 제약 조건은 이 프로필 외부에 있습니다.
  • 일반적인 함수와 메서드는 정적으로 전문화됩니다. 일반 메서드는 dyn 보기를 통해 호출할 수 없습니다. 일반적인 FFI 레이아웃과 미래의 공유 코드 전략은 이 구문에 의해 보장되지 않습니다.
