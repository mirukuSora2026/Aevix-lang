1. 문법 문서

Aevix는 표현식·제어 흐름·선언·수명 규칙을 독자적인 언어 설계로 문서화합니다. 각 페이지는 확정된 동작과 미정인 구문·정책을 구분합니다. 파서·최적화기·런타임·GPU 백엔드·진단의 구현을 이 문서 자체가 증명하지는 않습니다.

타입 우선 선언, 불변 기본값, 명시적 mut, rsn의 정적 추론, 명시적 숫자 변환, 소유권을 고려한 대여가 공통 기반입니다. 비교 대상 언어의 규칙으로 빠진 규칙을 조용히 채우지 않습니다.

2. 문서의 열한 가지 분류

값연산자와 표현식

산술·비교·대입·증가/감소·checked 표현식·Result 전파.

실행제어 흐름

조건문, while, 세 가지 for 형태, switch의 case, 제어 흐름의 대상.

영역과 메타데이터스코프와 주석

접근 권한, 이름 가리기 금지, 자원 정리, 일반 문서 주석.

설계 목표언어 기반

열다섯 가지 원칙, AOT와 선택적 JIT, 안전성과 명시적 비용.

값의 구조struct와 메서드

이름을 지정한 필드, private 접근, 팩토리, self receiver, 이동과 Copy.

공통 계약interface와 동적 디스패치

Self, 기본 메서드, override, 대여한 dyn 뷰, 소유하는 동적 Box.

변형 데이터enum과 enum switch

빈 항목과 데이터를 담는 항목, 대여·소비·스코프·빠짐없는 분기.

재사용 가능한 타입제네릭 타입과 제약

꺾쇠의 타입 매개변수와 where T implements Copy.

재사용 가능한 동작함수와 호출

제네릭 추론, 오버로드, 기본값, 이름 지정 인수, 확정된 values[] 가변 인수 표기.

소스 구성모듈과 import

파일 경로, 선택한 이름, 와일드카드, 재공개, 패키지 경계.

프로세스 수명지속 저장소

시작 시 초기화와 첫 사용 초기화, 공유 접근, 정상 종료.

3. 선언부터 시작하기

구문의 기반선언

변수·함수·값/참조 매개변수·명시적 반환·unit·void.

값의 기반자료형

기본 값, 컬렉션, 소유권, 동기화, CPU/GPU 자원 계약.

지역 소유 값, 대여한 참조, 반환한 값의 수명 효과는 서로 다릅니다. 문법 문서는 암묵적 복사·할당을 만들어내는 대신 연결된 타입의 기존 계약을 유지합니다.

4. 문서 전체의 공통 구문

i32 size = 128;
mut i32 count = 0;
rsn inferred = 128;
const i32 LIMIT = 100;
&i32 reference = &size;
i32 observed = *reference;

이 선언 조각들은 세미콜론과 고정된 정적 타입을 사용합니다. 표현식과 제어 흐름에도 같은 소유권·대여 규칙이 적용됩니다. 상세 문서에서는 의도적으로 거부되는 예제에 표시하며 코드를 조용히 고쳐 해석하지 않습니다.

5. 의미의 경계

경계 설계 규칙
이름과 저장소 public 접근 권한은 수명을 늘리거나 지역 값을 프로세스 수명의 저장소로 바꾸지 못합니다.
변경과 별칭 mut이나 쓰기 가능한 참조도 충돌하는 접근을 허용하지 않습니다.
오류와 정상 종료 복구 가능한 Result 전파는 정상 정리를 따릅니다. 일반 안전 정지는 같은 종류의 종료가 아닙니다.
디바이스 작업 이미 수락되어 처리 중인 자원은 계속 유지해야 하며 대여한 지역 저장소는 접근 종료를 확인한 뒤 해제해야 합니다.
문서 메타데이터는 선언을 설명하며 실행 의미를 다시 쓰지 않습니다.

6. 미정 설계와 구현 상태

각 문서는 남은 질문을 표시합니다. 사용자 정의 정리 함수, 그 정리가 있는 타입의 부분 이동, enum 표현, 전체 동적 호출 자격, 반환 참조의 수명 표기, 프로젝트 설정 형식은 아직 열려 있습니다. 모듈 경로·import, 제네릭 함수 호출, 오버로드 선택, 이름/기본값 인수, persist 초기화·정상 종료에는 해당 문서에 확정된 규칙이 있습니다. struct·interface·enum·타입 제네릭·독립적인 switch-case 스코프도 확정된 규칙으로 문서화했습니다. 문서는 설계를 설명하며 그 자체로 컴파일러나 백엔드의 실제 구현을 증명하지는 않습니다.

선언부터 읽은 뒤 연산자, 제어 흐름, 스코프 규칙으로 진행하세요. 연산이 소유권·배치·오류 계약에 의존하면 자료형 문서를 함께 확인하세요.
