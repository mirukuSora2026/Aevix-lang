1입니다. 두 개의 선택된 초기화 시간

선언초기화가 실행될 때다음 실행은 무엇을 하는가
모듈 최상위 persist프로그램의 진입 기능이 시작되기 전에.일반 안전 규칙에 따라 전체 저장된 값에 액세스하십시오.
지역 persist일단 실행이 실제로 선언에 도달하면.이미 초기화된 저장소를 다시 사용합니다.
도달하지 않은 로컬 persistinitializer가 실행되지 않습니다.성공적으로 초기화 된 값이 청소에 존재하지 않습니다.
persist i32 process_revision = 1;

i32 conditional_limit(bool enabled) {
    if (enabled) {
        persist i32 limit = 64;
        return limit;
    }
    return 0;
}

conditional_limit(false)를 호출하는 것은 제한에 도달하지 않으므로 로컬 값을 초기화하지 않습니다. 나중에 진짜 전화가 온다. 프로그램 항목은 필요한 최상위 초기화가 성공적으로 완료된 후에만 도달됩니다.

2입니다. 연결된 모듈 세트의 모든 최상위 persist가 포함되어 있습니다.

항목 모듈에서 시작해서 imports와 explicit reexports를 transitively 따라오세요. 연결된 모듈의 모든 최상위 persist는 일반 프로그램 코드 never가 읽는 개인 선언 및 값을 포함하여 시작 초기화에 속합니다. 엔트리 모듈에서 연결되지 않은 채 기계에 단지 설치된 패키지는 그 존재에 의해 추가되지 않는다.

import math.vector { Point };

이 선택적 가져오기는 Point 및 허용된 경로에 대한 액세스를 허용합니다. 그것은 여전히 시작 대상 세트에서 math.vector의 모든 최상위 persist 값을 포함합니다. 가시성 선택은 해당 모듈의 초기화를 Point 단독으로 필터링하지 않으며, 선택되지 않은 다른 이름에 대한 액세스를 허용하지 않습니다.

재수출을 통해 모듈에 도달하면 동일한 대상 세트 규칙이 적용됩니다. 여러 경로를 따라 도달한 모듈은 하나의 모듈 ID이며, 이니셜라이저를 여러 번 실행하는 것은 아닙니다. 패키지 의존성 사이클은 모듈 선언 사이클이 한 패키지 내에서 허용되는 동안 금지됩니다.

3입니다. 알려진 값 종속성은 종속성보다 먼저 실행됩니다.

persist i32 upper_limit = base_limit + 1;
persist i32 base_limit = 10;

upper_limit는 base_limit의 초기화된 값을 필요로 하기 때문에, base_limit는 나중에 쓰여지더라도 먼저 초기화됩니다. 일단 그 전제 조건이 성공하면, upper_limit은 11가 된다. 선언을 가져오거나 형식 또는 함수 시그니처만 참조하는 것은 그 자체로 이러한 값 종속성을 생성하지 않습니다.

관계효과
다른 모듈을 가져오는 모듈선언을 연결하고 시작 대상 세트를 확장합니다. 가져오기 문에서 이니셜라이저를 실행하는 명령이 아닙니다.
이니셜라이저는 다른 persist를 읽거나 대여합니다대상 값의 초기화 전제 조건을 존중합니다.
두 형식 또는 함수 선언은 서로 참조합니다.모듈 사이클 규칙에 따라 선언을 해결합니다; 값 사이클은 시그니처만으로 수행되지 않습니다.
알려진 이니셜라이저 값은 주기적으로 서로 의존합니다.컴파일 타임에 value-initialization 사이클을 거부한다.

허용되지 않는 예제. 어떤 값도 이 알려진 사이클에서 그것의 전제 조건 이전에 초기화될 수 없다.

persist i32 left = right + 1;
persist i32 right = left + 1;

4입니다. 모듈 경로별로 준비된 값을 선택한 다음 소스 순서 선택

알려진 종속성을 존중한 후 전체 모듈 경로 사전 편찬 순서로 동시에 준비된 최상위 값 중에서 선택합니다. 하나의 모듈 내에서 소스 선언 순서를 사용합니다. 의존성 요구 사항은 항상이 넥타이 규칙을 능가합니다.

준비된 선언선택한 순서이유
alpha.cache.first 그리고 beta.cache.firstbeta.cache.first 전에 alpha.cache.first입니다.alpha.cache는 사전 적으로 beta.cache 앞에 있습니다.
alpha.cache에서 두 개의 준비된 선언이전 선언이 먼저입니다.전체 모듈 경로가 동일하므로 소스 순서가 넥타이를 끊습니다.
alpha.cache.first는 beta.cache.first에 달려 있습니다alpha.cache.first 전에 beta.cache.first입니다.값 종속성은 경로 환경설정보다 우수합니다.

모듈 이름을 바꾸거나 선언을 이동하는 것은 타이 위치를 바꿀 수 있습니다. 따라서 관찰 가능한 I/O 또는 로깅이 포함된 이니셜라이저는 순서 계약을 체결합니다. 이 디자인은 컴파일러가 임의의 병렬 순서로 실행하거나 단순히 값이 사용되지 않기 때문에 부작용을 지울 수 있는 권한을 부여하지 않습니다.

5입니다. 런타임 액세스 검사는 종속성 계획을 완료합니다.

이니셜라이저는 함수를 호출하거나 해당 종속성을 미리 설정하지 않고 다른 persist에 액세스하는 동적 디스패치를 사용할 수 있습니다. 이러한 요청은 허용됩니다. Aevix가 관리하는 persist 액세스는 미완성 대상을 노출하는 대신 초기화하는 동안 checked입니다.

대상 상태필요한 행동
시작하지 않음필요한 대상 초기화를 먼저 수행한 다음 요청 이니셜라이저를 다시 시작합니다.
성공적으로 초기화됨일반 액세스 규칙에 따라 전체 값을 사용합니다.
다른 스레드에서 초기화 중초기화 시도가 완료될 때까지 기다립니다. 주기 감지의 대상이 됩니다.
Access는 초기화 주기를 만듭니다.초기화 오류를 진단하고 프로그램 실행을 중지합니다.

새로 발견된 전제조건은 ready-value tie rule에 의해 선택된 다음 값 이전에 초기화될 수 있다. 즉, 종속성 해상도, 기본 path/source 순서에 대한 변경이 아닙니다. 초기화를 통해 도달한 로컬 persist 값도 자체적인 첫 번째 범위 조정에 참여합니다.

이러한 검사는 Aevix에서 관리하는 persist 액세스에 적용됩니다. 그들은 모든 교착 상태 또는 불투명 한 외국 코드, 외부 잠금 또는 임의의 장치 동작에 숨겨진 종속성을 발견 할 것을 약속하지 않습니다.

6입니다. 완전한 값만 게시됨

persist 이니셜라이저는 사용할 수 없음 ? 또는 값을 구성하기 전에 동봉 함수에서 return로의 또 다른 비로컬 종료. 호출된 함수에서 정상적으로 반환된 Result는 완전한 값으로 저장할 수 있습니다. initializer 종료 제한.

성공적인 초기화는 완전한 값을 설치하고 나중에 허용된 액세스가 성공할 수 있도록 합니다. 초기화 도중 실행 오류가 진단되고 프로그램을 중지합니다; 출판된 부분 초기화 대체는 없습니다. 대신 Err를 포함하는 저장된 Result는 성공적으로 초기화된 값입니다.

종료 순서는 선언 발생 또는 초기화 시작이 아닌 성공적인 초기화 완료를 기록합니다. 로컬 persist never에 도달한 레코드가 성공적으로 완료되지 않았습니다. 더 보기 동시성과 실패 및 정상 종료.

7입니다. 구현 세부사항은 별도로 유지됩니다.

  • 정확한 initializer state representation, synchronization primitives 및 runtime registry는 구현 작업입니다.
  • 진단 문구 및 안전 정지 풀기 또는 중단 메커니즘은 선택되지 않습니다.
  • 함수 호출 의존성 분석은 완벽한 전이 순도 또는 완전한 FFI 가시성을 주장할 필요가 없습니다.
  • 런타임 대기는 never가 완료하는 작업에 의해 여전히 영향을 받을 수 있습니다. 초기화 검사는 범용 종료 증명이 아닙니다.
