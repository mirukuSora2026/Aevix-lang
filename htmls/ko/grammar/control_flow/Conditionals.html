1. if is a statement; 조건부 선택은 표현식입니다.

if 문은 어떤 문이나 블록이 실행될지를 결정합니다. 그것은 가치를 생산하지 않습니다. Aevix는 이니셜라이저, 인수 또는 return 표현식에 대한 값을 선택할 때 삼항 조건 연산자를 사용합니다.

문법은 각각의 if 와 else if 조건 주위에 괄호를 필요로 합니다. 조건에는 bool 유형이 있습니다; 숫자, 포인터 및 Optional 값은 암묵적인 진실성을 획득하지 않습니다.

2입니다. 필수 괄호 및 명시적 return 경로

int maximum(int left, int right) {
    if (left > right) {
        return left;
    } else {
        return right;
    }
}

실행이 이 경우에 도달하면 조건이 한 번 평가됩니다. exactly one branch executes. else 는 statement-form if 에 대해 선택 사항이다; 조건이 false 이고 else 가 없으면 statement 후에 실행이 계속된다.

비 void 값을 반환하는 함수는 모든 일반 완료 경로에 명시적인 return가 필요합니다. 분기를 선택하는 것은 함수에서 return 자체를 선택하지 않습니다.

3입니다. 조건은 bool 여야합니다.

int clamp_negative(int value) {
    bool negative = value < 0;
    if (negative) return 0;
    return value;
}

비교는 bool를 생산합니다. 논리 !, && 및 bool 피연산자에 대한 작업; && 조건 내에서 자신의 단락 동작을 유지 . 숫자 테스트는 숫자를 다른 값과 명시적으로 비교해야 합니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 코드가 아닙니다.

void invalid_numeric_condition() {
    int count = 3;
    if (count) return;
}

거부된 조건은 int 타입이 있고, 그렇지 않습니다. bool. count != 0 와 같은 명시적 조건을 사용합니다.

4입니다. 하나의 실행 가능한 구문에 대해 중괄호를 생략할 수 있음

int normalize(int value) {
    mut int normalized = value;
    if (normalized < 0) normalized = 0;
    else normalized += 1;
    return normalized;
}

하나의 실행가능한 문장은 중괄호가 없는 브랜치 바디를 형성할 수 있다. 여러 문장은 { ... }가 필요합니다. 이것은 소스 라인의 count가 아닌 진술의 count입니다. 모든 선언, 할당, 호출 문 및 return 문은 세미콜론으로 끝납니다. 폐쇄 제어 흐름 또는 기능 보조기는 추가 세미콜론이 필요하지 않습니다.

int record_positive(int value) {
    mut int adjusted = value;
    mut int changes = 0;
    if (adjusted > 0) {
        adjusted += 1;
        changes += 1;
    }
    return adjusted + changes;
}

같은 물리적인 라인에 다른 문장을 넣는다고 해서 그것이 괄호가 없는 브랜치에 추가되는 것은 아니다. 분기 본문으로 사용되는 선언은 유일한 선언인 경우에도 명시적인 블록이 필요합니다. 이 블록은 렉시컬 범위와 정리 경계를 제공한다; 단독의 unbraced 선언은 거부된다.

5. 그렇지 않으면 대안을 순서대로 검사합니다.

int sign_code(int value) {
    if (value < 0) return -1;
    else if (value == 0) return 0;
    else return 1;
}

조건들은 브랜치가 선택될 때까지 소스 순서로 고려된다. 나중에 조건과 그들의 신체는 이전 조건이 성공한 후에 평가되지 않습니다. 각각의 else가 bool 조건의 괄호를 가지고 있다면; else는 조건이 없다.

다음 else 는 가장 가까운 짝 없는 다음 문장에 연결됩니다: if. 에서 if (outer) if (inner) action(); else fallback();다른 하나는 내면의 것이다. 그것을 외부에 부착하기 위해 중괄호를 사용하십시오. 더 보기 구문 분석.

6입니다. ? 사용 : 조건이 값을 선택할 때

int maximum_value(int left, int right) {
    int larger = (left > right) ? left : right;
    return larger;
}
속성확정된 규칙
조건bool 유형이 있어야 합니다.
대체 형식두 대안 모두 동일한 결과 유형을 가지며, 이미 입력된 값에 대한 자동 숫자 프로모션이 없습니다.
평가 방식조건을 평가 한 다음 선택한 대안 만 평가하십시오.
우선순위산술, 비교 및 논리 연산자보다 낮음.
협회중첩된 조건부 선택 연결은 오른쪽에 있습니다.
반환조건식은 명시적 return 키워드를 대체하지 않습니다.
int sign_value(int value) {
    return (value < 0) ? -1 : ((value == 0) ? 0 : 1);
}

조건 주위에 괄호가 조건식의 가독성에 대해 표시됩니다. 이미 선택한 필수 조건 괄호는 if와 while에 적용되며, 삼항 조건에 별도의 필수 부모 규칙을 부과하지 않습니다.

7입니다. 조건부 ? 및 postfix Result ? 다른 연산자입니다

Result<int, IntegerError> select_sum(bool use_left, int left, int right) {
    int selected = use_left ? left : right;
    int sum = checked(selected + 1)?;
    return Result.ok(sum);
}

삼항 연산자는 조건과 콜론으로 구분 된 두 가지 대안이 필요합니다. Postfix ?는 하나의 Result 값으로 동작한다: 현재 Result-returning 함수에서 Ok를 추출하거나 Err를 반환한다. 그들의 의미는 공백에 의존하지 않습니다.

postfix ? 는 enclosing 함수에 의해 선언된 동일한 에러 타입을 전파한다. 그것은 오류를 자동으로 변환하지 않거나, 함수라는 내부 강제 안전 정지를 잡거나, 이미 발생한 효과를 취소하지 않습니다. Result 구성 및 조건부 값 선택은 별도의 작업으로 유지됩니다.

8입니다. 선택된 코드만 실행됩니다. 소유권은 checked입니다.

string choose_text(bool use_first, string first, string second) {
    return use_first ? first : second;
}

선택된 소유 string 반환 값으로 이동합니다. 선택되지 않은 로컬 소유자는 함수가 종료될 때 정리됩니다. string는 조용히 딥 클로닝되지 않습니다. 조건과 부작용은 여전히 선택된 평가 순서를 따르며, 건너뛴 브랜치는 런타임 효과가 없다.

조건부 브랜치 후에, 값은 그 사용에 도달할 수 있는 모든 경로에서 유효한 경우에만 사용될 수 있다. 한 브랜치가 Copy가 아닌 소유자를 옮기고 다른 브랜치가 그것을 유지했다면, 브랜치가 소유권을 유지한 후에 무조건적인 사용은 가정할 수 없다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 코드가 아닙니다.

string invalid_conditional_move(bool take_first, string first, string second) {
    if (take_first) {
        string moved = first;
    }
    return first;
}

거부된 return는 먼저 한 브랜치의 내부 바인딩으로 이동한 후에 도달할 수 있다. 다른 런타임 조건은 컴파일 시간 소유권 요구 사항을 제거하지 않습니다.

9입니다. 지점은 지역 범위 및 정리를 준수합니다.

중괄호가 있는 분기 안에 선언된 로컬은 해당 분기 블록에 속합니다. 중첩된 블록 내에서 볼 수 있으며 분기 블록이 끝난 후 사용할 수 없습니다. 보이는 외부 로컬 바인딩의 이름은 브랜치 내에서 다시 선언할 수 없습니다. 가시성 수정자는 로컬 범위에서 벗어나는 것이 아닙니다.

int branch_scope(int input) {
    mut int output = input;
    if (input > 0) {
        int bonus = 2;
        output += bonus;
    }
    return output;
}

보너스 바인딩은 닫는 분기 중괄호에서 사라집니다. 해당 블록이 소유한 리소스는 역초기화 순서로 정리됩니다. return 또는 Result? 브랜치 내부에 있는 return 페이로드가 발신자를 따라가는 동안, 또한 해당 브랜치가 남긴 클로징 기능 범위를 정리합니다.

10입니다. 거부된 양식은 계속 볼 수 있습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 코드가 아닙니다.

int invalid_if_expression(int left, int right) {
    int larger = if (left > right) left else right;
    return larger;
}

expression-form : 의도적으로 제외된 경우 사용 (왼쪽 > 오른쪽) ? 왼쪽 : 값을 생성하는 오른쪽.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 코드가 아닙니다.

int invalid_missing_parentheses(int value) {
    if value > 0 return value;
    return 0;
}

조건 주위에 필요한 괄호가 없습니다. 이러한 부정적인 예는 선택된 컴파일 타임 거부 규칙을 문서화한다; 컴파일러 실행은 주장되지 않는다.

11입니다. 열린 결정

  • 패턴 바인딩 형태를 포함한 if 조건 안에 선언 또는 조건-로컬 바인딩.
  • never 브랜치, 사용자 정의 변환, 또는 기존 숫자 추론을 넘어서는 문맥적 리터럴 타이핑을 포함하는 조건부 표현식.
  • 미래의 타입 문법과의 추가적인 상호작용; 기존의 postfix Result ? and ternary ? : 파싱 규칙이 이미 선택되어 있습니다.

선택된 파싱 규칙은 다음과 같습니다. 파싱 규칙: else uncomponent if; 선언 본문에 명시적 블록이 필요한 경우; postfix Result ? and ternary ? : 공백과 독립적으로 고유한 구문 해석을 사용합니다. 여러 완전한 해석은 유형 검사의 앞에 괄호를 요구한다. 이 규칙은 공개 결정이 아닙니다.

이 페이지에서 표현, 진실성 변환 또는 자동 복사본을 소개하면 패턴 일치가 없습니다. 계속하기 반복문 iteration 또는 Switch 여러 케이스 브랜치.
