1입니다. 하나의 열거형, 여러 변형

열거형은 선언 된 변형 중 하나 인 값을 가진 형식을 지정합니다. Empty variant와 named-payload variant는 하나의 enum 선언과 하나의 부모 타입을 공유합니다. 변형된 이름은 독립적인 서브타입이 아니다.

이러한 문서는 소유권 인식 스위치 패턴을 포함하여 선택된 Aevix 설계 규칙을 기록합니다. 그들은 구현 된 파서, 컴파일러, ABI 또는 런타임을 주장하지 않습니다. 오픈 레이아웃, 일반 및 정리 세부 사항은 별도로 레이블이 지정됩니다.

3입니다. 간단한 enum 예제

enum Direction implements Copy {
    North;
    South;
};

Direction choose_direction(bool northward) {
    return northward ? Direction.North : Direction.South;
}

빈 변형은 Direction.North와 같은 정규화된 값을 사용합니다. 데이터 변형은 Event.Move { x = 1, y = 2 }와 같은 명명된 이니셜라이저를 사용합니다. 각 필요한 페이로드 필드는 명시적으로 초기화됩니다. 암시적 필드 기본값은 선택되지 않았습니다.

지역확정된 규칙
변형 이름public by default; private은 명시적입니다.
페이로드 필드private by default; 공개 필드는 명시적입니다.
소유권기본적으로 이동; 내장 Copy는 모든 변형과 모든 필드를 검사합니다.
스위치 읽기switch(event)는 읽기를 위해 빌리고 소유자를 보존합니다.
스위치 수정switch(&mut event)는 전용 수정 기능을 제공합니다.
지금 연락switch(move event)는 소유된 enum 소스를 명시적으로 소비합니다.
브랜치 커버리지모든 variant는 case 또는 default로 적용되며, coverage가 없는 것은 compile-time error이다.
케이스 범위각 case/default는 독립적인 암시적 어휘 범위를 가지며 다음과 같이 끝납니다. break;.

4입니다. enum 규칙을 나머지 언어에 연결

열거형은 구조체의 타입 함수 및 셀프 리시버 모델을 재사용합니다. 일반적인 인터페이스 구현은 전체 열거형에 적용되므로 Self는 하나의 변형이 아닌 부모 열거형을 나타냅니다. 정적 디스패치, 기본 구현 및 재정의 규칙은 공통 인터페이스 계약을 따릅니다.

참고: 인터페이스, 일반 유형 및 Copy. 수치 판별, 메모리 레이아웃, 외국 ABI, 파생된 평등, 자동 복제 및 사용자 지정 열거 정리는 열려 있습니다.
