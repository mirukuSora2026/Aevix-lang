1입니다. 읽기, 수정 또는 사용 모드를 명시적으로 선택

헤더모드스위치 후 소스
switch(event)Shared 대여 읽기.소유자 유지됨; 읽기 바인딩을 통한 일반 변경를 사용할 수 없습니다.
switch(&mut event)변제자금 대여소유자 유지; 명시적으로 바인딩된 쓰기 가능한 필드는 변경될 수 있습니다.
switch(move event)소유하지 않은 비 Copy 열거형에 대한 명백한 소모적 파견.소비 후 원본 소스를 사용할 수 없습니다. 필드를 소유하면 바인딩으로 이동할 수 있습니다.

셀렉터는 한 번 평가됩니다. 일치하는 브랜치만 실행됩니다. 모든 case와 모든 written default는 독립적인 렉시컬 스코프를 가지며 다음과 같이 끝난다. break;. implicit fallthrough 는 없습니다. 이전 return, 루프 계속, 발산 및 Result ? 허용되는, 그러나 각 써진 분지는 아직도로 끝난다 break;. 도달 할 수없는 필요한 break는 그 이유만으로 오류 나 경고가 아닙니다. 이것은 일반적인 unreachable-code 정책을 설정하지 않습니다. 더 보기 case 종료.

이동 마커는 enum 스위치 헤더에 대해 승인됩니다. 이것은 언어의 어느 곳에서도 일반적인 이동 표현을 설정하지 않습니다. 명시적인 소비 스위치의 참조 소스 모드 추론, 임시 수명 및 Copy 열거형의 특수 처리는 열려 있습니다.

2입니다. 예제에 대한 공개 페이로드 스키마

public enum Event {
    Quit;
    Move {
        public i32 x;
        public i32 y;
    };
    Message {
        public string text;
    };
};

이러한 필드는 공개되어 있으므로 아래 무료 함수가 바인딩될 수 있습니다. 필드 개인 정보는 이니셜라이저와 패턴에 적용됩니다. Event.Quit는 빈 변형 값이며, Event.Message는 건설을 위해 소유 텍스트 페이로드가 제공 될 때까지 태그 전용 케이스 표기입니다.

참고: enum 시정 및 개인 팩토리 개인 페이로드 데이터를 유지하면서 공개 변형을 노출합니다.

3입니다. 기본 디스패치 로컬 소유자를 읽고 보존

Event inspect_event(Event event) {
    mut i32 code = 0;
    switch (event) {
        case Event.Quit:
            code = 1;
            break;
        case Event.Move { i32 dx = x, i32 dy = y }:
            code = dx + dy;
            break;
        case Event.Message { &string message = &text }:
            bool empty = string.is_empty(message);
            code = empty ? 0 : 2;
            break;
    }
    return event;
}

패턴 이름 dx와 dy는 새로 바인드된 변수이며, 오른쪽 이름 페이로드 필드에는 x와 y가 있습니다. i32 필드는 Copy이므로 읽기 스위치 중에 값이 복사될 수 있습니다. 대신 비 Copy string는 클론을 소유하지 않고 읽기 참조로 바인딩됩니다.

switch(event)는 이벤트 소유자를 보존하여 최종 명시적 return가 이벤트 소유자를 전송할 수 있도록 합니다. by-value 함수 매개 변수는 이미 함수 항목에 대한 호출자 소유권을받습니다. 스위치 자체는 다른 이동을 추가하지 않습니다. 이 예제에서는 호출 소유권과 디스패치 소유권을 구분합니다.

읽기 바인딩은 페이로드 필드에 일반 쓰기를 승인할 수 없습니다. 호환 가능한 별칭과 이스케이프 참조는 소스 출처와 수명에 따라 유지됩니다.

4입니다. 명시적 및 편리성 읽기-대여 바인딩이 모두 지원됩니다.

bool message_empty(Event event) {
    mut bool empty = false;
    switch (event) {
        case Event.Message { &string message = text }:
            empty = string.is_empty(message);
            break;
        case Event.Move:
            empty = false;
            break;
        case Event.Quit:
            empty = false;
            break;
    }
    return empty;
}
패턴 조각의미
i32 dx = xCopy 보이는 i32 필드 x를 불변의 로컬 dx로 만듭니다.
&string message = &text보이는 비 Copy 필드 텍스트를 명시적으로 읽어옵니다.
&string message = textenum 패턴 안에서의 편리한 읽기-대여 표기 지원.
&mut i32 dx = &mut x독점적 인 수정 스위치에서 명시적인 쓰기 가능한 필드 대여.
string message = text소유 필드를 소비 모드로 이동하십시오. 숨겨진 복제본이 없습니다.

공유 수신기 방법은 스위치(*self)와 함께 자신의 열거형 참조자를 명시적으로 선택할 수 있다; This can explicitly select its enum referent with switch (*self); 이것은 참조로부터의 값 이동이 아니라 참조 장소의 읽기 대부를 선택한다. 특수화되지 않은 switch(self) 소스 모드 추론은 열려 있습니다. 읽기 편의 규칙은 열거형 패턴 바인딩에만 적용됩니다. 일반적인 로컬 선언이나 함수 인수에 암시적 읽기 대여을 추가하지 않습니다. 바인딩 선언은 해당 유형으로 시작되며, 그 이름은 보이는 외부 로컬 이름을 숨기지 않을 수 있습니다.

5입니다. 명시적으로 빌린 필드를 수정하는 독점 디스패치

Event shift_event(Event input) {
    mut Event event = input;
    switch (&mut event) {
        case Event.Move { &mut i32 dx = &mut x, &mut i32 dy = &mut y }:
            *dx += 1;
            *dy -= 1;
            break;
        case Event.Message:
            break;
        case Event.Quit:
            break;
    }
    return event;
}

변경 가능한 로컬 이벤트는 독점 기능을 제공합니다. dx와 dy는 활성 Move 페이로드의 별도의 필드에 대한 명시적인 쓰기 가능한 참조입니다. 에넘 소유자는 유지되며 변경 후 반환될 수 있습니다.

활성 대여 충돌은 중복 스토리지에 대한 checked입니다. 이미 빌린 참조를 직접 읽는 것은 다른 &를 삽입하지 않습니다. 독점 스위치는 모든 필드에 대해 쓰기 가능한 참조를 자동으로 노출하지 않습니다.

축약형 &mut i32 dx = x 는 아직 선택되지 않았습니다. 예시는 명시적 &mut 필드 양식을 사용합니다. 필드 대여이 활성 상태로 유지되는 동안 활성 변형을 교체하는 것은 ownership/overlap 검사를 따릅니다.

6입니다. 페이로드 필드 소유 디스패치 이동 소비

usize consume_message_bytes(Event event) {
    mut usize bytes = 0;
    switch (move event) {
        case Event.Message { string message = text }:
            bytes = string.byte_len(&message);
            break;
        case Event.Move:
            bytes = 0;
            break;
        case Event.Quit:
            bytes = 0;
            break;
    }
    return bytes;
}

이벤트가 소유되지 않은 비Copy 값입니다. 스위치는 이를 소비하며, 원래의 이벤트 바인딩은 이후에 사용할 수 없습니다. 메시지의 경우, 소유 텍스트 필드는 메시지로 이동합니다. 읽기 길이 연산은 새 소유자를 명시적으로 대여합니다; 텍스트 클론을 생성하지 않습니다.

case exit에서, 그 case가 그 case의 소유로 남아 있을 경우 메세지는 정리된다. 이동된 바인딩 자체가 다른 유효한 소유자에게 전송된 경우 대신 해당 대상을 정리합니다. 이동되지 않은 활성 페이로드 필드는 정확히 한 번 정리됩니다.

오직 활성 변형만이 라이브 페이로드 자원을 가지고 있습니다. 사용자 정의 정리 구현과 부분 이동과의 호환성은 열려 있습니다. 이 예제에서는 사용자 지정 enum 소멸자를 정의하지 않습니다.

7입니다. 필드의 부분집합이나 변형 태그만 묶기

enum Envelope {
    End;
    Data {
        public string body;
        public string note;
    };
};

usize consume_body_bytes(Envelope envelope) {
    mut usize bytes = 0;
    switch (move envelope) {
        case Envelope.Data { string payload = body }:
            bytes = string.byte_len(&payload);
            break;
        case Envelope.End:
            break;
    }
    return bytes;
}

데이터 패턴은 본문만 바인딩하며 노트는 의도적으로 생략됩니다. 소모 스위치에서 생략된 소유 페이로드는 스위치 정리의 일부로 남아 있으며 정확히 한 번 해제됩니다. 읽기 또는 수정 모드에서 생략된 필드는 암시적으로 이동되거나 복제되지 않고 소스 소유자와 함께 유지됩니다.

메시지에 페이로드 필드가 있더라도 Event.Message:와 같은 태그 전용 케이스가 허용됩니다. 그것은 어떤 페이로드 액세스 권한을 부여하고 그 필드가 개인 보이는 변형과 일치 할 수 있습니다. 소비 모드에서는 모든 언바운드 페이로드 소유자를 정리할 수 있습니다.

태그 전용 케이스 문법은 생성자 철자가 아닙니다: Event.Message 단독은 완전히 초기화된 페이로드 값이 아닙니다.

8입니다. 각 case와 default는 고유의 렉시컬 스코프를 가지고 있습니다.

i32 move_component(Event event) {
    mut i32 component = 0;
    switch (event) {
        case Event.Move { i32 local = x }:
            component = local;
            break;
        case Event.Message:
            i32 local = 0;
            component = local;
            break;
        case Event.Quit:
            i32 local = -1;
            component = local;
            break;
    }
    return component;
}

세 개의 로컬 이름은 독립적인 형제 사례 범위에 속한다. 다른 형제 사건 바인딩이 보이지 않기 때문에 이름을 재사용하는 것이 허용됩니다. 이미 보이는 외부 로컬을 숨기는 패턴이나 바디 바인딩은 여전히 거부됩니다.

패턴 바인딩과 body locals는 브랜치에 렉시컬 스코프를 남긴다. 기존에 있던 소유자들은 역초기화 순서로 정리된다. 중첩 블록 정리는 터미널 break에서 반복되지 않습니다.

대여 수명은 구속력있는 이름 범위와 동일하지 않습니다. 출처 출처와 주변의 대여 규칙이 허용하는 경우 참조는 사건 이후에도 유효할 수 있으며, 사례 로컬 소유 스토리지에 대한 참조는 스토리지 수명에서 벗어날 수 없습니다. break에 도달했기 때문에 모든 소스 대여이 끝나야한다고 가정하지 마십시오.

9입니다. 모든 변형을 덮거나 기본값 제공

i32 event_category(Event event) {
    mut i32 category = 0;
    switch (event) {
        case Event.Quit:
            category = 1;
            break;
        default:
            category = 2;
            break;
    }
    return category;
}

열거형 스위치는 명시적인 경우 또는 기본 분기를 통해 모든 변형을 포함해야 합니다. 기본값 없이 선언된 변형을 생략하는 것은 컴파일 타임 오류입니다. 이전 전체 이벤트 스위치는 각 변형이 적용되기 때문에 기본값이 필요하지 않습니다.

태그 전용 케이스는 모든 페이로드 필드를 바인딩할 필요 없이 해당 변형을 커버합니다. 기본값은 나중에 열거형에 추가된 변형을 포함하여 명시적으로 처리되지 않은 모든 변형을 포함하므로 이러한 추가에 대한 누락된 변형 진단을 억제합니다.

이 보증 계약은 enum 파견에 속합니다. 그것은 일반 스칼라 스위치에 동일한 완전한 유한 도메인 규칙을 자동으로 부과하지 않습니다. 보호 패턴과 그 범위의 의미는 열려 있습니다.

10입니다. 외부 스위치는 숨겨진 변형에 대해 기본값이 필요합니다.

public enum Credential {
    Token {
        string secret;
    };
    private Internal;

    public Credential issue(string initial_secret) {
        return Credential.Token { secret = initial_secret };
    }
};

bool externally_is_token(Credential credential) {
    mut bool token = false;
    switch (credential) {
        case Credential.Token:
            token = true;
            break;
        default:
            token = false;
            break;
    }
    return token;
}

외부 코드는 비공개로 공개 토큰을 태그 일치시킬 수 있습니다. private Internal의 이름을 지정할 수 없으므로 숨겨진 가능성을 커버하려면 기본값이 필요합니다. 개인 정보 보호는 열거형 유형이나 철저한 검사에서 변형을 지우지 않습니다.

열거 안에 액세스 할 수있는 코드는 개인 변형의 이름을 지정할 수 있으며 완전한 명시 적 적용 범위를 제공 할 수 있습니다. 기본 브랜치는 여전히 독립적 인 어휘 범위를 가지고 있으며 break로 끝납니다. 숨겨진 페이로드에 대한 액세스 권한을 부여하지 않습니다.

11입니다. 거부된 범위, 필드 및 소유권 패턴

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 코드가 아닙니다.

void missing_variant(Event event) {
    switch (event) {
        case Event.Quit:
            break;
        case Event.Move:
            break;
    }
}

메시지가 발견되지만 기본값은 없습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 코드가 아닙니다.

void duplicate_field(Event event) {
    switch (event) {
        case Event.Move { i32 first = x, i32 second = x }:
            break;
        default:
            break;
    }
}

소유한 non-Copy 이벤트가 소비되었습니다. 원래의 바인딩을 반환한 후 소유권을 침해합니다. 이러한 예제는 실행된 진단이 아닌 의도된 컴파일 시간 거부를 정의합니다.

12입니다. 오픈 스위치 세부 정보 및 링크된 계약

  • 보호 패턴, 그룹화된 레이블, 와일드카드 표기 및 풍부한 nested/destructuring 패턴.
  • 임시 선택자, 빌린 선택자에 대한 자세한 수명 규칙 및 소스 표현식이 이미 참조일 때의 추론.
  • 명시적 &mut 소스 마커 없이 암시적인 가변 필드 바인딩.
  • 사용자 지정 청소 후크 및 이러한 후크에 의해 부과 부분 이동 제한.
  • 명시적 switch(move ...) 헤더에서 Copy 열거형의 정확한 처리.
  • 일반적으로 도달할 수 없는 코드 처리는 문법적으로 필요한 터미널 break에 대해 선택한 예외를 넘어 열려 있습니다. 정상적인 return/continue/Err 출구는 그들의 정규적인 정리를 적용합니다; nontermination와 강제적인 정지는 정상 출구 보증을 얻지 않습니다.
  • 일반 이동 표현식은 열거형 스위치를 벗어나고 미래 형식 구문에 대한 전체 파서 문법을 사용합니다.

패턴에서 누락된 필드는 이미 허용된 반면, 생성자에서 누락된 필수 필드는 거부됩니다. 일반적인 산술 실패와 전파는 별도의 계약을 유지합니다. 더 보기 Switch, Copy, 인터페이스 및 일반 유형.
