1입니다. 뷰는 빌려; 그것은 소유권을 차지 하지 않습니다.

&dyn Interface 은 구체 구현을 가리키는 명시적 공유 뷰입니다. &mut dyn Interface 은 독점 쓰기 뷰입니다. 구체 소유자는 값과 정리에 대한 책임을 유지하며, 뷰는 실행 중 구체 타입에 따라 호출 가능한 메서드를 선택합니다.

User user = User.new(7);
&dyn Leveled view = &user;
bool beginner = view.is_beginner();

이 예제는 다음 문서의 User·Leveled 선언을 사용합니다: 인터페이스 계약. 선택된 User의 override는 뷰를 통한 호출에도 적용됩니다. 이 공유 뷰를 만들 때 할당·clone·CPU/GPU 전송은 발생하지 않습니다.

2입니다. 수신자 권한은 여전히 호출을 제어

종류대여 능력메서드 접근
&dyn IShared 대여 읽기.적격한 read-receiver 메소드; 독점적인 수신기로의 업그레이드 없음.
&mut dyn I단독 대여입니다.적격한 write-receiver 방법과 borrow 규칙에 따라 호환 가능한 read access.

메서드에 선언된 self 매개변수 타입이 권한을 결정합니다. dyn 은 구현을 선택하는 방식을 바꿉니다. 일반 공유 참조에 수정 권한을 주거나 값 self를 대여 호출로 바꾸지는 않습니다. 직접 소유한 값에서 일반 쓰기 대여를 만들려면 mut 바인딩이 필요합니다.

3입니다. 독점 뷰는 원래 값을 변경합니다.

interface Counter {
    public i32 read(&Self self);
    public void write(&mut Self self, i32 next_value);
};

struct CounterState implements Counter {
    i32 value;

    public CounterState new(i32 initial_value) {
        return CounterState { value = initial_value };
    }

    public i32 read(&CounterState self) {
        return (*self).value;
    }

    public void write(&mut CounterState self, i32 next_value) {
        (*self).value = next_value;
    }
};

mut CounterState counter = CounterState.new(1);
{
    &mut dyn Counter view = &mut counter;
    view.write(2);
}
i32 updated = counter.read();

뷰가 같은 counter 저장소를 수정하므로 updated는 2입니다. 참조 대상에 대한 독점 권한을 사용하기 위해 참조 바인딩 자체가 mut 일 필요는 없습니다. 이 예제에서는 명시적 내부 블록으로 뷰의 범위를 제한하며, 뷰를 사용하는 동안 충돌하는 접근은 하지 않습니다.

4입니다. Concrete Provenance가 살아남는 방법

타입 소거는 호출 위치에서 공개 구체 타입을 숨길 뿐, 대여의 원본을 지우지 않습니다. 뷰는 소유자나 소유자 내부에 저장된 대여 데이터보다 오래 살 수 없습니다. 충돌하는 뷰가 살아 있는 동안 소유자를 이동·소비·정리하면 거부합니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: the view is used after its owner is moved;
User user = User.new(7);
&dyn Leveled view = &user;
User moved = user;
bool beginner = view.is_beginner();

뷰의 마지막 사용은 기존 대여 분석에 반영됩니다. 변수의 스코프와 증명된 대여 범위는 관련이 있지만 다릅니다. 한 분기를 벗어났다고 해서 밖으로 탈출한 참조가 유효해지지는 않습니다. 독점 뷰는 충돌하는 읽기·쓰기를 만드는 겹치는 대여와 공존할 수 없습니다.

5입니다. dyn 뷰는 계약의 일부만 노출할 수 있습니다.

interface Rebuildable {
    public i32 level(&Self self);
    public Self rebuild(&Self self);
};

void inspect(&dyn Rebuildable view) {
    i32 observed = view.level();
}

인터페이스에는 구체 Self를 알아야 하는 메서드가 있을 수 있습니다. 그래도 dyn 뷰는 허용하지만, 뷰에서는 호출 가능한 메서드만 사용할 수 있습니다. rebuild처럼 값으로 반환하는 Self 결과는 선택된 모델에서 구체 타입의 연산으로 유지됩니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: a dyn view cannot produce an erased concrete Self value;
void invalid_rebuild(&dyn Rebuildable view) {
    view.rebuild();
}

사용할 수 없는 메서드를 호출 가능하게 만들기 위해 자동 Box 할당이나 clone을 넣지 않습니다. 컴파일러는 메서드 하나 때문에 인터페이스 뷰 전체를 거부하는 대신 해당 동적 뷰에서 그 호출을 지원하지 않는다고 진단합니다.

6입니다. 기본값과 재정의는 그 의미를 유지합니다.

호출 가능한 기본 메서드는 인터페이스 계약의 동작을 사용합니다. 구현 타입이 override를 제공하면 동적 호출도 이를 사용합니다. 기본 구현이 필수 메서드를 호출하면 구체 구현이 해당 연산을 제공합니다.

공유 동적 뷰는 수신자에 독점 접근이 필요한 기본 메서드를 호출할 수 없습니다. 같은 서명의 기본 구현이 충돌하면 해당 타입이 유효한 구현이 되기 전에 구체 override가 필요합니다. 동적 디스패치는 인터페이스 목록 순서로 우선순위를 만들지 않습니다.

7입니다. 런타임 선택 및 액세스 비용 표시

작동선택한 계약
빌린 시야 만들기새로운 할당, 복제 또는 데이터 전송이 없습니다.
적격 메서드 호출런타임에 구현을 선택하십시오; 메소드 바디 비용은 그대로 유지됩니다.
구체적인 필드 액세스인터페이스 뷰는 임의의 숨겨진 필드 액세스가 아닌 계약을 제공합니다.
보기 끝내기대여금을 끊는 것은 소유자의 페이로드를 파괴하지 않습니다.
장치 사용자동 GPU 지원 또는 전송은 dyn에서 유추되지 않습니다.

백엔드는 구체 구현을 증명할 수 있을 때 동적 호출을 최적화할 수 있습니다. 이는 구현상의 기회일 뿐, 명시적으로 런타임에서 선택하는 언어 모델을 바꾸지 않습니다. 이 문서는 메타데이터 배치, 포인터 개수, 크기를 규정하지 않습니다.

8입니다. 거부된 권한 및 호환성 변경

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: this owner does not grant ordinary write permission;
CounterState counter = CounterState.new(1);
&mut dyn Counter view = &mut counter;
view.write(2);

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: a shared view cannot invoke Counter.write;
mut CounterState counter = CounterState.new(1);
&dyn Counter view = &counter;
view.write(2);

원본은 요청한 인터페이스를 구현해야 합니다. dyn 변환은 누락된 구현을 유효하게 만들거나 private 멤버 접근 제한을 완화하거나 숨겨진 대여의 수명을 늘리거나 대여 중인 소유자의 소비를 허용하지 않습니다.

9입니다. 동적 규칙 및 관련 참조 열기

  • 0.2의 dyn 호출에서는 제네릭 메서드와 구체 Self 인자·결과가 필요한 서명을 제외합니다. 호출 가능한 비제네릭 메서드는 대여한 self 수신자를 사용합니다. 연관 타입과 더 넓은 동적 서명은 이 프로필에 포함되지 않습니다.
  • 동적 소유자를 통한 값 self, 값 추출, 인터페이스 다운캐스팅, 여러 인터페이스를 결합한 동적 타입은 미정입니다.
  • 원본이 Reader<i32>를 구현하면 &dyn Reader<i32>처럼 구체 인터페이스 특수화를 동적으로 대여할 수 있습니다. 그 인터페이스의 제네릭 메서드는 여전히 정적 호출이 필요합니다.
  • 인터페이스 ABI, 메타데이터 표현, FFI 경계, GPU에서 지원할 동적 연산은 미정입니다.
