1입니다. 계약서를 명시적으로 선언

인터페이스는 구체적인 필드 배치 대신 호출 가능한 동작을 묶습니다. 서명은 인수 타입, 반환 타입, 수신자 전달 방식을 명시합니다. 본문이 없는 선언은 필수 메서드이며, 본문이 있는 선언은 사용할 수 있는 기본 구현입니다.

interface Leveled {
    public i32 get_level(&Self self);

    public bool is_beginner(&Self self) {
        return self.get_level() < 10;
    }
};

이 예제의 인터페이스 메서드는 명시적으로 public입니다. 0.2 프로필의 구현 메서드는 명시적으로 public이어야 하며, 예제에서도 이 요구 사항을 드러냅니다. non-void 본문은 일반 함수와 마찬가지로 명시적 return을 사용합니다.

2입니다. Self는 유형입니다; 각자는 모수입니다

선언의미
&Self self실제 구현 유형의 대여 읽기.
&mut Self selfexclusive write는 실제 구현 유형의 대여입니다.
Self selfBy-value receiver: Copy 값이 복사되고 다른 값이 이동됩니다.

대문자 Self 는 구현하는 struct 또는 enum 전체로 해석됩니다. User 구현에서 &Self self 는 다음과 일치합니다: &User self. 소문자 self 는 수신자 변수입니다. 일치 여부는 해석된 인수·반환 타입과 대여 방식을 함께 검사합니다.

수신자가 없는 타입 함수와 self 메서드는 구별됩니다. 인터페이스를 사용해도 self 매개변수를 자동으로 추가하거나 값 수신자를 읽기 대여로 바꾸지 않습니다. 인터페이스 선언 밖에서의 Self 범위는 아직 미정입니다.

3입니다. 필요한 메서드를 정상적으로 구현

struct User implements Leveled {
    i32 level;

    public User new(i32 initial_level) {
        return User { level = initial_level };
    }

    public i32 get_level(&User self) {
        return (*self).level;
    }
};

User user = User.new(7);
bool beginner = user.is_beginner();

이 User는 필수 메서드를 제공하고 기본 구현인 is_beginner를 이어받으므로 여기서는 level 7이 beginner입니다. 필수 메서드는 일반 메서드 선언으로 구현하며, 기존 본문을 대체하지 않으므로 override 가 필요하지 않습니다. 필수 구현 누락이나 수신자·반환 계약 변경은 컴파일 타임 오류입니다.

구체 타입 내부에서는 다음을 통해 private 필드에 접근할 수 있습니다: (*self).field. 호출자는 공개 계약을 사용하며 private 필드에 접근할 권한은 얻지 않습니다.

4입니다. 기본 본체는 계약에 따라 달라집니다.

기본 구현은 필수 메서드를 포함해 해당 인터페이스에 선언된 동작을 호출하고, 매개변수 권한으로 허용되는 값을 사용할 수 있습니다. 특정 구현 struct의 필드가 존재한다고 가정할 수는 없습니다. 이 덕분에 기본 구현은 struct와 enum 모두에서 의미를 유지합니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: an interface has no concrete level field;
interface InvalidDefault {
    public i32 read_level(&Self self) {
        return (*self).level;
    }
};

유효한 Leveled 기본 구현에서 self.get_level() 는 선택된 정적·동적 호출 방식에 따라 실제 구현을 호출합니다. 기본 본문이 override를 우회하거나 수신자를 몰래 복제하지는 않습니다.

5입니다. 기본값을 교체하려면 재정의가 필요합니다.

struct User implements Leveled {
    i32 level;

    public User new(i32 initial_level) {
        return User { level = initial_level };
    }

    public i32 get_level(&User self) {
        return (*self).level;
    }

    public override bool is_beginner(&User self) {
        return self.get_level() < 5;
    }
};

명시적 표시는 대체 의도를 나타냅니다. 일치하는 기본 구현이 있어야 하며, 완전히 해석된 메서드 서명이 일치해야 합니다. 선택된 계약에서는 오타가 있거나 대상과 일치하지 않는 override를 거부해야 합니다. 선택된 대체 구현은 구체 호출과 호출 가능한 동적 호출에 모두 적용됩니다.

0.3 검사 강화: 유효한 기본 구현 override는 이미 0.2에서 동작합니다. 일반 함수·필드·인터페이스 선언에 잘못 붙인 override 표시는 현재 일부 경우 허용됩니다. 0.3 계획 에서는 이런 대상 누락에 대한 진단을 요구합니다. 이는 클래스 상속을 추가하거나 기본 본문 없는 필수 메서드 구현을 바꾸지 않습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: get_level is required but has no default body;
struct InvalidOverride implements Leveled {
    public override i32 get_level(&InvalidOverride self) {
        return 0;
    }
};

이 블록들은 서로 독립적인 설명용 정의입니다. 하나의 모듈에서 User 이름을 반복 선언할 수 있다는 뜻은 아닙니다.

6입니다. 다양한 독립 계약

interface Leveled {
    public i32 get_level(&Self self);
};

interface Enabled {
    public bool is_enabled(&Self self);
};

struct Device implements Leveled, Enabled {
    i32 level;
    bool enabled;

    public Device new(i32 initial_level, bool initial_enabled) {
        return Device { level = initial_level, enabled = initial_enabled };
    }

    public i32 get_level(&Device self) {
        return (*self).level;
    }

    public bool is_enabled(&Device self) {
        return (*self).enabled;
    }
};

목록의 각 인터페이스는 계약을 추가합니다. 먼저 적었다고 우선순위를 얻지는 않습니다. 구현은 선택된 모든 의무를 충족해야 합니다. 서로 다른 메서드는 바로 함께 구성할 수 있으며, 이름이 같은 메서드는 아래의 충돌·서명 규칙을 따라야 합니다.

7입니다. 충돌하는 기본값을 명시적으로 해결

interface Calm {
    public i32 priority(&Self self) {
        return 1;
    }
};

interface Urgent {
    public i32 priority(&Self self) {
        return 9;
    }
};

struct Ticket implements Calm, Urgent {
    public override i32 priority(&Ticket self) {
        return 5;
    }
};

두 기본 구현은 이름과 해석된 서명이 같습니다. Ticket에 명시적 override가 없으면 충돌은 컴파일 타임 오류입니다. 대체 구현은 두 계약의 뷰에 공통 동작을 제공하며, 원래 기본 구현 중 하나를 암묵적으로 호출하지 않습니다.

구현된 0.2 충돌 규칙. 해석된 서명이 같은 필수 선언들은 하나의 구현을 공유할 수 있습니다. 일치하는 기본 구현 하나가 다른 인터페이스의 필수 선언을 충족할 수도 있습니다. 해석된 반환 타입은 일치해야 하며, 제공된 구현은 계약의 제네릭 요구 사항에 따라 검사합니다. 제네릭 where 제약이 서로 다른 충돌에는 더 넓은 계약 결정이 필요합니다. 일치하는 기본 구현이 여러 개면 public override가 필요하며, 매개변수 서명이 다르면 별도의 오버로드로 유지합니다. 경로를 지정해 원래 기본 본문을 호출하는 기능은 이 프로필에 포함되지 않습니다.

8입니다. 열거형은 전체 계약을 구현합니다.

interface Leveled {
    public i32 get_level(&Self self);
};

enum LevelState implements Leveled {
    Beginner;
    Experienced;

    public i32 get_level(&LevelState self) {
        mut i32 result = 0;

        switch (*self) {
            case LevelState.Beginner:
                result = 1;
                break;

            case LevelState.Experienced:
                result = 20;
                break;
        }

        return result;
    }
};

Self 는 여기서 개별 항목이 아니라 LevelState로 해석됩니다. 인터페이스 구현은 enum 전체에 속하며, 각 항목에 독립적인 자동 구현을 주지 않습니다. 기존 enum switch의 대여·모든 항목 처리 검사·명시적 break 규칙은 그대로 적용됩니다. 여기서 switch (*self) 는 기본 읽기 대여를 위한 위치로 enum 참조 대상을 선택하며, enum을 self에서 꺼내 이동하지 않습니다.

enum 메서드 내부에서는 수신자 권한에 따라 해당 타입의 private 페이로드 필드에 접근할 수 있습니다. public 메서드라고 필드를 자동으로 공개하지는 않습니다. private 팩토리와 페이로드 바인딩은 다음 문서를 참조하세요: 열거형 .

9입니다. 콘크리트 호출은 기본적으로 정적 상태로 유지됩니다.

User user = User.new(7);
bool automatic = user.is_beginner();
bool explicit_view = (&user).is_beginner();

이 예제는 override 예제의 User를 사용합니다. 두 호출 모두 선언된 읽기 수신자를 사용합니다. 일반 호출은 자동으로 대여하고, 명시적 참조 형태는 같은 접근을 직접 요청합니다. 수신자 식은 한 번만 평가합니다. 값 수신자를 전달하면 Copy 또는 이동 동작을 따릅니다.

다음 implements 선언만으로 인터페이스 박스를 할당하거나 모든 호출을 런타임 디스패치로 바꾸지는 않습니다. 명시적 dyn 값은 실행 중 구현을 선택합니다. 컴파일러의 최적화·백엔드 전략은 이 기본 의미와 별개입니다.

10입니다. Copy는 checked 내장 기능 남아

implements Copy 는 암묵적 값 복사를 위한 확정된 명시 구문입니다. 인터페이스 본문에서 제공하는 일반 clone 메서드가 아니라 컴파일러가 검사합니다. 모든 struct 필드 또는 모든 enum 항목의 페이로드가 Copy 요구 사항을 충족해야 합니다.

일반 동작 인터페이스를 사용한다고 Copy가 되지는 않습니다. 소유하는 string, Box 와 동적 컬렉션 필드는 일반 이동 동작을 유지합니다. 제네릭 where T implements Copy 는 인자 T를 제약하며 이를 담은 타입을 자동으로 Copy로 만들지 않습니다.

사용자 정의 정리와 Copy의 호환성은 미정입니다. 다음 문서를 참조하세요: struct 소유권 및 타입 제약.

11. 아직 결정되지 않은 사항과 관련 문서

  • 인터페이스 상속, 연관 타입, 인터페이스 상수, 수신자가 없는 인터페이스 의무는 0.2 프로필에 포함되지 않습니다. 문서에 명시된 인스턴스 메서드 계약에서 Self는 구현 타입을 나타냅니다.
  • 메서드 오버로드와 호환되는 중복·혼합 계약은 위에 설명한 구현된 충돌 규칙을 따릅니다. 선택한 원래 기본 본문을 경로 지정으로 호출하는 기능은 이 프로필에 포함되지 않습니다.
  • 제네릭 함수와 호출 추론 은 확정되었습니다. 정적 제네릭 인터페이스 메서드는 구현되어 있으며, 타입 매개변수와 where 요구 사항은 매개변수 이름 변경을 제외하면 계약과 일치해야 합니다. 이 메서드는 dyn 호출에서 제외됩니다. 임의의 필드 값에 기반한 컨테이너 추론과 안정적인 제네릭 ABI 보장은 이 프로필에 포함되지 않습니다.
  • 문서에 명시된 확정 경계를 넘는 동적 호출 가능성은 별도로 다룹니다. ABI·GPU 호환성은 보장하지 않습니다.
