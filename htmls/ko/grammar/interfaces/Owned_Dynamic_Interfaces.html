1입니다. 동적 계약 뒤에 가치를 소유

0.2 제공 범위: 소유 래퍼를 사용하려면 선언 앞에 import memory { Box }; 이 필요합니다. 인터페이스 자체도 일반 모듈 규칙에 따라 보여야 합니다. Box는 자동 제공 타입이 아닙니다. 다음 문서를 참조하세요: 구현된 값 프로필.

Box<dyn Interface> 는 구체 구현 페이로드를 소유합니다. 동적 메서드 선택은 소유권과 별개입니다. 박스가 페이로드를 살아 있게 유지하고, 인터페이스는 보이는 메서드 계약을 제한합니다.

명시적 비용. Box 생성은 Result를 반환하는 생성자로 할당을 드러냅니다. 기존 Box를 dyn으로 변환할 때는 추가 할당이나 페이로드 clone 없이 소유권을 이동합니다.

이는 기존의 Box API를 사용하며, 특별한 실패 없는 할당 구문을 도입하지 않습니다. 페이로드 안에 숨겨진 참조에도 원본 수명 제한이 유지됩니다.

2입니다. 기존 실패 가능한 Box 생성자 사용

Result<Box<dyn Leveled>, InputError<User>> make_user(i32 requested_level) {
    Box<User> concrete = Box.new(User.new(requested_level))?;
    Box<dyn Leveled> owner = Box.into_dyn(concrete);
    return Result.ok(owner);
}

User와 Leveled는 다음 문서의 선언입니다: 인터페이스 계약. Box.new(User.new(...)) 는 다음을 반환합니다: Result<Box<User>, InputError<User>>. 바깥 함수도 정확히 같은 오류 타입을 사용하므로 ? 로 할당 실패를 전파할 수 있습니다. 정상 성공 경로는 Result.ok(owner)를 명시적으로 반환합니다.

문서에 명시된 생성자 실패 시 InputError는 사용되지 않은 User 입력을 보존합니다. 변환은 생성에 성공한 뒤에만 실행됩니다. 소유 할당은 명시적이며, Type.new나 인터페이스 기본 구현이 이를 몰래 도입하지 않습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: Box.new returns Result, not a bare Box;
Box<User> concrete = Box.new(User.new(7));

3입니다. Box.into_dyn 로 명시적으로 변환

속성규칙
출처소유하는 콘크리트 Box<T> 상기 요청된 인터페이스는 The requested interface is
대상선언된 목적지 Box<dyn Interface> 이 선택한 형태로 인터페이스를 제공합니다.
소유권원본 상자가 이동하며 바인딩은 나중에 다시 사용할 수 없습니다.
할당 및 복사추가 할당 또는 페이로드 클론이 도입되지 않습니다.
청소구체적인 페이로드 정리 정보와 소유권은 여전히 유효합니다.
대여 출처숨겨진 페이로드 참조는 원래의 수명 제한을 유지합니다.
// This fragment assumes a valid owned Box<User> named concrete;
Box<dyn Leveled> owner = Box.into_dyn(concrete);

명시적 호출은 암묵적인 대상 타입 변환을 대신합니다. 인터페이스를 구현하지 않는 T를 호환되게 만들지는 않습니다. 이 변환은 자동 CPU/GPU 전송이 아닙니다. 정확한 메타데이터 표현은 이후 ABI 결정으로 남겨 둡니다.

다음처럼 타입을 지정하지 않은 대상은 rsn owner 그 자체로 선택할 인터페이스를 제공하지 않습니다. 여러 인터페이스 중 하나를 고르는 추가 제네릭 인자나 추론 경로는 아직 설계되지 않았습니다.

4입니다. 소유자 또는 명시적 뷰를 통해 호출

// This fragment assumes a valid Box<dyn Leveled> named owner;
bool automatic = owner.is_beginner();

&dyn Leveled view = Box.as_ref(&owner);
bool explicit_view = view.is_beginner();

기본 호출은 소유한 페이로드에 접근하고 메서드의 self 매개변수에 필요한 대여를 만듭니다. 명시적 형태에서는 먼저 Box.as_ref 로 공유 인터페이스 뷰를 얻습니다. 두 방식 모두 owner의 소유권을 유지하며 같은 호출 가능한 동적 구현을 사용합니다.

소유자 식은 한 번만 평가합니다. 숨겨진 clone·소유 값 추출·추가 박스 할당은 없습니다. 자동 페이로드 메서드 접근이 일반 필드 자동 역참조, 래퍼 전달, 이름 충돌 규칙까지 별도로 결정하지는 않습니다.

5입니다. 가변 통화는 전용 페이로드 대여이 필요합니다.

// This fragment assumes Counter and CounterState from the borrowed-view page;
Result<Box<dyn Counter>, InputError<CounterState>> make_counter(i32 initial_value) {
    Box<CounterState> concrete = Box.new(CounterState.new(initial_value))?;
    mut Box<dyn Counter> owner = Box.into_dyn(concrete);

    owner.write(2);
    {
        &mut dyn Counter view = Box.as_mut(&mut owner);
        view.write(3);
    }

    return Result.ok(owner);
}

소유자의 mut 바인딩은 자동 독점 대여와 Box.as_mut에 필요한 일반 쓰기 권한을 제공합니다. 각 호출은 여전히 겹치는 대여 검사를 따릅니다. 뷰는 기존 박스 페이로드를 수정하며, 대여가 끝난다고 페이로드를 파괴하지는 않습니다.

대여한 뷰가 사용 중일 때 뷰를 무효화하는 소유자의 추출·이동·교체는 거부됩니다. 바깥 컨테이너가 쓰기 API를 지원한다는 이유만으로 공유 접근을 쓰기 접근으로 올릴 수 없습니다.

6입니다. 실제 페이로드의 정리 의무를 유지

동적 박스로 이동하면 기존 소유권 의무가 넘어갑니다. 마지막 소유자가 정상적으로 끝나면 실제 구체 페이로드를 정확히 한 번 정리하고 해당 저장소를 해제합니다. 인터페이스 뷰가 이 의무를 정적으로 보이는 인터페이스 메서드만으로 대체하지는 않습니다.

박스를 반환하면 그 책임이 호출자로 넘어갑니다. 대여한 인터페이스 뷰 자체는 정리된 소유자를 살아 있게 유지하지 않습니다. 정상 정리는 Result 오류 반환을 포함하여 현재 소유자의 확정된 역초기화 순서를 따릅니다. 대여 중인 장치 작업도 자원 사용 완료 계약을 충족해야 합니다.

대여한 필드를 포함한 struct를 소유해도 필드가 프로세스 수명의 참조가 되지는 않습니다. 컴파일러는 타입이 소거된 소유자를 통해서도 원본 제약을 유지해야 합니다. Box 소유권은 대여의 수명 이탈 검사를 피하는 방법이 아닙니다.

7입니다. 소유권은 모든 메서드를 동적으로 호출할 수 있게 만들지 않습니다.

Box가 소유한 인터페이스에도 같은 명시적 동적 메서드 제한이 적용됩니다. 페이로드를 소유한다는 이유만으로 Self 값을 반환하는 메서드가 동적 호출 가능해지거나 공유 페이로드 뷰를 통한 값 self 메서드가 허용되지는 않습니다.

구체적인 T에 사용하는 제네릭 Box.into_inner API가 모든 Box<dyn Interface>에서 알 수 없는 소거된 구체 값을 반환한다고 가정할 수는 없습니다. 숨겨진 타입 추출, 다운캐스팅, dyn을 소비하는 self 메서드는 별도 규칙이 필요합니다.

작동현재 상태
적격 페이로드 방법 대여선택된 항목: 자동 소유자 호출 또는 명시적인 as_ref/as_mut 보기.
소유권 상자 반환선택됨: 일반 명시적 return가 소유권을 이동합니다.
값에 따라 지워진 페이로드 소모열기 : 새로운 추출 또는 dyn 값 자체 API가 선택되지 않았습니다.
Shared 또는 Weak 동적 소유자를 변환열기: Box 지원은 다른 래퍼 변환을 정의하지 않습니다.
CPU/GPU 또는 FFI 표현열기 : 숨겨진 전송 또는 표현 약속이 없습니다.

8입니다. 재사용된 이동 상자 거부하기

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반한 예제입니다.

// Rejected: concrete was moved by into_dyn;
Result<Box<dyn Leveled>, InputError<User>> invalid_reuse(i32 requested_level) {
    Box<User> concrete = Box.new(User.new(requested_level))?;
    Box<dyn Leveled> owner = Box.into_dyn(concrete);
    &User stale_view = Box.as_ref(&concrete);
    return Result.ok(owner);
}

인터페이스 구현 누락, 살아 있는 비호환 대여, 독점 뷰에 사용한 가변이 아닌 소유자, Result 오류 타입 불일치, 수명을 벗어나는 참조를 포함한 페이로드 등 일반 오류도 그대로 적용됩니다. 이는 설계 수준의 거부 사유이며, 진단 코드를 주장하는 것은 아닙니다.

9입니다. Open owning-dynamic 규칙 및 관련 참조

  • 구체 메타데이터 배치, 할당자/ABI 표현, 다운캐스트 연산은 미정입니다.
  • 타입이 소거된 페이로드 추출, 소비하는 dyn 수신자, 이들과 부분 이동·사용자 정의 정리의 상호작용은 미정입니다.
  • Shared/Weak 동적 소유권, 래퍼 호출 충돌, 일반화된 자동 전달은 미정입니다.
  • 소유 타입이 해당 특수화를 구현하고 호출할 메서드가 동적 호출 가능하면 구체 제네릭 인터페이스로의 동적 변환을 지원합니다. 장치 사용 가능성과 안정적인 외부 표현은 0.2 프로필에 포함되지 않습니다.
