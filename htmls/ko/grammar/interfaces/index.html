1입니다. 하나의 계약, 여러 가지 구현 유형

다음 interface 는 동작을 선언합니다. struct 또는 enum 는 다음을 선언하여 implements 해당 계약을 충족합니다. 필수 메서드, 공유 기본 본문, 수신자 권한, 명시적 소유권은 소스에 드러납니다.

설계 문서. 이 페이지들은 확정된 Aevix 규칙을 기록합니다. 미정인 언어 정책은 별도로 표시하며, 예제 자체가 구현된 컴파일러나 런타임을 입증하지는 않습니다.

Box<dyn Leveled>콘크리트 페이로드의 정리 정보를 유지하는 동적 인터페이스 값을 소유.

여러 인터페이스의 구현은 쉼표로 구분한 implements Named, Leveled 목록을 사용합니다. 이름과 서명이 같은 기본 메서드가 충돌하면 명시적 대체가 필요하며, 인터페이스 순서가 승자를 고르지는 않습니다.

4입니다. 필수 메서드 및 대체된 기본값

interface Leveled {
    public i32 get_level(&Self self);

    public bool is_beginner(&Self self) {
        return self.get_level() < 10;
    }
};

struct User implements Leveled {
    i32 level;

    public User new(i32 initial_level) {
        return User { level = initial_level };
    }

    public i32 get_level(&User self) {
        return (*self).level;
    }

    public override bool is_beginner(&User self) {
        return self.get_level() < 5;
    }
};

User user = User.new(7);
bool beginner = user.is_beginner();

User 는 필수 읽기 메서드를 구현하고 기본 판별식을 명시적으로 대체합니다. 호출은 구체 User 구현을 사용하므로 level 7에서 beginner 는 false입니다. 메서드 호출은 self 매개변수가 요구하는 공유 대여를 자동으로 만들며, user를 clone하지 않습니다.

5입니다. 액세스 및 전송 모드 선택

수신자 양식발송소유권 및 비용
구체적인 user.method()기본적으로 정적입니다.수신자 선언은 읽기 대여, 쓰기 대여 또는 값 전달을 결정합니다.
&dyn Interface적격 방법에 대한 런타임 선택.Shared 대여; 뷰를 생성하여 도입된 할당 또는 복제본이 없습니다.
&mut dyn Interface적격 방법에 대한 런타임 선택.독점 대여; 일반 가변 스토리지 및 호환 대여이 필요합니다.
Box<dyn Interface>적격 페이로드 방법에 대한 런타임 선택.구체적인 값을 소유합니다. 명시적 Box 구성이 할당을 설명합니다.

정적 디스패치가 언어의 기본값이지만, 모든 인터페이스 추상화가 모든 백엔드에서 비용이 없다는 보장은 아닙니다. 동적 호출은 의도적으로 런타임에서 선택하는 수단입니다. 인터페이스를 구현한다고 CPU/GPU 전송이나 자동 GPU 지원이 생기지는 않습니다.

6입니다. 공개 결정 및 관련 참조

  • 0.2는 정적 제네릭 메서드와 대여 self 수신자를 가진 호출 가능한 비제네릭 메서드의 동적 호출을 지원합니다. 구체 Self 값이 필요한 메서드와 제네릭 메서드는 dyn에서 사용할 수 없습니다. 동적 값 수신자, 연관 타입, 인터페이스 상속은 이 프로필에 포함되지 않습니다.
  • &dyn Reader<i32> 같은 구체 제네릭 인터페이스는 메서드가 동적 호출 가능할 때 지원합니다. 안정적인 인터페이스 ABI, 다운캐스팅, 장치 실행은 이 프로필에 포함되지 않습니다.
  • 제네릭 함수 구문과 쉼표로 구분하는 where 요구 사항은 다음 문서에서 정의합니다: 일반 함수. 0.3 override 계획 은 클래스 상속을 추가하지 않고 잘못된 한정자 위치 검사를 강화합니다.
