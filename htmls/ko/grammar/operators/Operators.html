1입니다. 선택한 표현 규칙

표현식은 값을 계산하거나 저장소의 장소를 식별합니다. statement 는 action 을 수행한다. Aevix는 정규 할당 문을 값 표현식과 분리하고, 접두사 및 postfix 증가 및 감소를 값 표현식으로 명시적으로 허용합니다.

이것은 Aevix 파서, 컴파일러, 대여 검사기 또는 런타임이 이러한 규칙을 구현한다는 주장이 아닌 언어 설계 참조입니다. 각 예제는 세미콜론으로 끝납니다. 로컬 바인딩 예제는 적절한 enclosing 블록을 가정한다; 모듈 배치는 이 페이지에 의해 결정되지 않는다.

  • 이름은 type-first 선언을 따릅니다. i32 value = 3;. 바인딩은 변경할 수 없습니다. mut 있습니다.
  • int 는 다음 표기와 같습니다: i32; float 는 다음 표기와 같습니다: f64. rsn Static Inference를 실행합니다.
  • 모든 일반 non-void 함수 종료에는 명시적 return. 오류 종료는 postfix로 명시적으로 표시될 수 있습니다. ?.

3입니다. 입력된 피연산자는 자동으로 홍보하지 않습니다.

i32 left = 7;
i32 right = 3;
i32 sum = left + right;
f64 ratio = 0.5;
rsn inferred = sum + 1;

이미 입력된 산술 피연산자는 호환되는 형식이 있어야 합니다. 제한되지 않은 정수 리터럴은 기본적으로 i32이고 제한되지 않은 실제 리터럴은 f64입니다. 아직 타입이 없는 리터럴은 주변 타입 컨텍스트를 사용할 수 있다. 결과가 형식 범위를 초과하면 동적으로 확대되지 않습니다.

허용되지 않는 예제. 이 코드는 선택된 규칙을 의도적으로 위반합니다.

// Rejected: no implicit conversion from i32 to f64;
i32 number = 7;
f64 fraction = 0.5;
f64 mixed = number + fraction;

혼합형 산술 전에 문서화된 명시적 변환 API를 사용합니다. 여기서는 cast 연산자 철자가 선택되지 않습니다. 할당 및 return 컨텍스트는 일반 산술을 checked Result 산술로 변환하지 않습니다.

4입니다. 산술은 선택한 실패 모드를 유지합니다.

i32 dividend = 7;
i32 divisor = 3;
i32 quotient = dividend / divisor;
i32 remainder = dividend % divisor;
i32 product = dividend * divisor;

여기의 지수는 2이고 나머지는 1입니다. Integer 부문은 Integer 계약을 0으로 사용합니다. 일반 정수 산술은 스칼라를 반환하고, 정적으로 보장된 산술 실패를 진단하며, 런타임 실패 시 안전하게 실행을 중지합니다. never는 릴리스, AOT 또는 JIT 빌드가 선택 되었기 때문에 자동으로 래핑으로 변경됩니다.

복구 사용 Integer.checked_* 또는 lexical checked(...). 자세한 내용은 검사 산술 실패, 평가 경계 및 미완성 에지 계약. 해당 종료에 대한 런타임 안전 종료 및 정리의 정확한 메커니즘은 열려 있습니다.

5입니다. 비교 및 부울 논리

i32 low = 0;
i32 value = 5;
i32 high = 10;
bool within = low < value && value < high;
bool same = value == high;

관계 연산자는 평등 연산자보다 더 단단히 결합됩니다. 비교는 여전히 두 레벨에 걸쳐 비모범 체인을 형성 할 수 없습니다; 그 결과를 다른 비교 피연산자로 사용할 때 명시적으로 비교를 그룹화하십시오. low < value < high 두 글자로 이루어진 단어 : 2 개 &&. 평등은 순서 계약이없는 유형에 순서을 허용하지 않습니다.

허용되지 않는 예제. 이 코드는 선택된 규칙을 의도적으로 위반합니다.

// Rejected: chained comparisons are not an interval test;
i32 low = 0;
i32 value = 5;
i32 high = 10;
bool within = low < value < high;

Boolean 논리 단락

bool large_ratio(bool enabled, i32 numerator, i32 denominator) {
    return enabled && ((numerator / denominator) > 1);
}

bool acceptable = large_ratio(false, 8, 0);
bool ready = !acceptable;

이 호출에서는 enabled가 false이기 때문에 분할을 건너니다. 좌편의 동료가 있나니 너희는좌편의 동료가 무엇인지 아느뇨 두 피연산자 모두 여전히 유형-checked입니다. 평가되지 않은 분기는 산술, 변경 또는 호출을 수행하지 않습니다.

허용되지 않는 예제. 이 코드는 선택된 규칙을 의도적으로 위반합니다.

// Rejected: an integer is not a boolean condition;
i32 count = 1;
bool active = count && true;

같은 명시 적 비교를 사용하여 count != 0. 모델 번호:Integer & 및 | 비트 연산을 수행하고 lazy boolean logic을 지원하지 않는다.

6입니다. 비트 연산자 및 쉬프트

u8 flags = 0b1010;
u8 mask = 0b0010;
u8 common = flags & mask;
u8 combined = flags | mask;
u8 changed = flags ^ mask;
u8 inverted = ~flags;
bool selected = (flags & mask) != 0;

비트 연산은 정수 폭을 유지합니다. 비교는 비트 연산보다 더 긴밀하게 결합합니다. 마스크 작동을 Parenthesize (flags & mask) != 0 정수를 부울과 결합하지 않고 결과를 테스트합니다.

0.2에서 두 피연산자는 모두 정수여야 하며 너비가 일치할 필요가 없습니다. count 시프트는 음수가 아니어야 하며 왼쪽 피연산자 너비보다 작아야 합니다. 유효하지 않은 상수 count가 진단되고 유효하지 않은 런타임 count가 안전하게 실행을 중지합니다. 왼쪽 시프트는 원래 너비 내에서 높은 비트를 버린다. 부호 있는 오른쪽 시프트는 서명 비트를 전파하고 부호 없는 오른쪽 시프트는 0 비트를 삽입한다. 명명된 checked-shift API는 설계-카탈로그 작업으로 남아 있지만, 구현된 대안은 아니다.

7입니다. 과제, 쓰기 가능한 장소 및 대여

mut i32 total = 0;
i32 delta = 3;
total = delta;
total += delta;
total *= 2;

대상은 쓸 수 있는 장소여야 하며 저장된 값은 해당 유형과 일치해야 합니다. 할당 및 복합 할당은 주변 표현식에 대한 값을 산출하지 않습니다. 헤더에 대한 C 스타일에는 사용할 수 있는 전용 업데이트 동작 슬롯이 있습니다. i += 1 이것을 value expression으로 변환하지 않는다.

허용되지 않는 예제. 이 코드는 선택된 규칙을 의도적으로 위반합니다.

// Rejected: assignment has no expression value;
mut i32 first = 0;
mut i32 second = 0;
i32 saved = (first = second);

목표 위치를 한 번 평가 한 다음 오른쪽을 확인한 다음 결과를 저장합니다. 연결된 산술이 실패하면 실패한 업데이트의 결과가 저장되지 않습니다. 대여 충돌은 오류로 남아 있습니다; 할당 구문은 다른 동시 쓰기 별칭을 허가하지 않습니다. 사용자 정의 장소와의 완전히 지정된 화합물 할당 상호 작용은 열려 있습니다.

대여 및 역참조 권한 유지

void increase(&mut i32 target) {
    (*target)++;
}

i32 apply_increase() {
    mut i32 value = 4;
    increase(&mut value);
    return value;
}

불변 타겟 참조 바인딩은 독점적인 쓰기 능력을 전달하므로, 참조자는 수정될 수 있다. 결합 자체는 가변적일 필요가 없다. 값과 같은 일반 소유자는 독점 대여을 만들기 전에 mut가 필요합니다. 공유 참조는 쓰기 권한을 부여하지 않으며, 역참조는 빌린 저장소에서 Copy가 아닌 페이로드를 소유하는 것을 허용하지 않습니다.

허용되지 않는 예제. 이 코드는 선택된 규칙을 의도적으로 위반합니다.

// Rejected: a shared read borrow does not grant write access;
void change_read_only(&i32 value) {
    (*value)++;
}

유나리 & binary: 이진; 이진 & 정수 비트를 결합합니다. 대여은 중복 지역 및 최종 사용 수표를 준수합니다. 기존의 호환 참조 및 뷰는 자동 추가 참조 계층 없이 함수에 직접 전달됩니다.

8입니다. 접두사와 접두사 ++ / --

형태업데이트 성공반환된 표현식 값
++value하나 추가, 검증, 저장.T 타입의 새로운 값.
value++하나 추가, 검증, 저장.T 타입의 이전 값입니다.
--value1을 빼서, 검증하고, 저장하세요.T 타입의 새로운 값.
value--1을 빼서, 검증하고, 저장하세요.T 타입의 이전 값입니다.
mut i32 value = 4;
i32 previous = value++;
i32 current = ++value;
i32 before_decrement = value--;
i32 after_decrement = --value;

기록된 결과는 4, 6, 6 및 4이며, 최종 저장된 값은 4입니다. 각 목표 위치는 한 번 평가됩니다. 이러한 연산은 쓰기 가능한 정수 위치를 요구하고 쓰기 가능한 참조가 아닌 정수 값을 생성하며 초기 규칙에서 bool, float 또는 복잡한 피연산자를 지원하지 않습니다.

오버플로우 및 부호 없는 언더플로우는 checked 정수 산술을 따릅니다. 유효성 검사는 쓰기 전에 발생합니다. checked(value++) Err 을 실패시 반환하고, 그 타겟은 변경되지 않는다; 증가가 실패할 때 이전 값의 Ok 를 생성하지 않는다.

허용되지 않는 예제. 이 코드는 선택된 규칙을 의도적으로 위반합니다.

// Rejected: immutable integer storage cannot be incremented;
i32 value = 4;
value++;

assignment는 increment가 value expression이더라도 statement로 남는다. 이것은 명백한 언어 선택이다. Postfix increment/decrement는 postfix 체인에 속합니다. 접두사 양식은 단항 레벨을 공유합니다. Parentheses는 복합 대상 주위에 유용합니다. 더 보기 전체 우선 순위 테이블.

9입니다. 3차 값 선택

i32 maximum(i32 first, i32 second) {
    return (first > second) ? first : second;
}

i32 choose_score(bool selected) {
    return selected ? 10 : 20;
}

조건은 bool 여야 합니다. 두 브랜치 모두 이미 입력된 피연산자를 자동으로 변환하지 않고 동일한 값 유형으로 해결해야 합니다. 선택된 branch만 실행한다. 결과는 불변 바인딩을 초기화하거나 명시적으로 반환될 수 있습니다.

허용되지 않는 예제. 이 코드는 선택된 규칙을 의도적으로 위반합니다.

// Rejected: the two already typed branches have different types;
bool selected = true;
i32 integer_value = 10;
f64 float_value = 20.0;
rsn mixed = selected ? integer_value : float_value;

조건부 연산자는 범위 생성 및 논리적 OR 및 연관자 아래에 바인딩됩니다. 명확성을 위해, 그룹 중첩 first ? a : (second ? b : c). 별도의 경우 statement-form이고 never가 값을 생성합니다. 사후 수정 오류 전파 및 삼항 선택은 공백과 독립적으로 구별됩니다. 고유한 완전한 구문 해석을 사용하거나 몇 개가 남아 있을 때 명시적인 괄호가 필요합니다. 더 보기 질문-마크 파싱.

Postfix propagation과 increment/decrement는 postfix chain에서 결합됩니다. 접두사 업데이트는 단항 레벨을 공유합니다. 비연관적 범위 생성은 논리적 OR 및 오른쪽 연관 조건부 선택 아래에 바인딩됩니다. 비교는 명시적인 그룹화 없이 체인화할 수 없습니다. 파싱 규칙 mixed question marks, generic angles, range token boundaries, 그리고 좁은 컴파일 타임 타입 피연산자를 정의합니다. 이것들은 구현 된 문법의 증거가 아닌 미래 파서에 대한 요구 사항입니다.

연산자와 인수는 한 번 왼쪽에서 오른쪽으로 평가합니다.

i32 next_number(&mut i32 number) {
    return ++(*number);
}

i32 combine(i32 first, i32 second) {
    return first * 10 + second;
}

i32 observe_order() {
    mut i32 counter = 0;
    return combine(next_number(&mut counter), next_number(&mut counter));
}

observe_order는 12를 반환합니다: 첫 번째 인수는 1와 두 번째 2를 수신합니다. 인수 계산은 왼쪽에서 오른쪽으로 한 번 발생하며, 완료된 각 호출의 임시 배타적 대여은 다음 호출이 생성되기 전에 끝납니다. 대여을 유지하는 함수는 여전히 대여 규칙을 충족해야합니다.

Precedence는 표현식 트리를 만듭니다. 평가 순서는 어떤 피연산자 작업이 먼저 발생하는지 결정합니다. a + b * c a를 계산한 다음 b를 계산하고 c는 곱셈을 계산한 다음 덧셈을 계산합니다. 단락 부울 연산자, 삼항 선택 및 checked 실패 스킵 작업은 계약에서 제외됩니다. 최적화는 관찰 가능한 값, 돌연변이 및 실패를 보존합니다.

Range<int> half_open = 0..10;

mut int total = 0;

for (int index in half_open) total += index;

범위는 모든 값의 미리 할당된 목록이 아닌 엔드포인트 및 포함 계약을 저장합니다. #현재 Range 참조 지원되는 고정폭 정수, 빈 오름차순 범위, 명시적 descending/strided 생성자 및 최대 끝점을 설명합니다. 이 문자 그대로의 규칙은 부동 소수점 범위나 새로운 내림차를 승인하지 않습니다.

int first = 2;
int last = 6;
Range<int> segment = (first)..(last);

Range 생성은 연관되지 않으며 논리적 OR 이하 및 조건부 선택 이상에 바인딩됩니다. 산술 엔드포인트 표현식이 먼저 바인딩됩니다; 그룹화는 가독성에 유용합니다. 렉서 읽기 0..10 정수, 범위 토큰, 정수로. 더 보기 문자 경계.
