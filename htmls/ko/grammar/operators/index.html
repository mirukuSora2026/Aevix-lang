1입니다. 표현식은 형식과 선언 규칙을 연결합니다.

이 섹션에서는 데이터 유형 및 선언 참조 이후에 Aevix 연산자 선택을 기록합니다. 일반 정수 산술은 결과를 안전하게 확인하고 명시적 checked 산술은 Result를 생성하고 postfix ?는 현재 함수에서 오류를 전달할 수 있습니다.

각 페이지는 선택된 구문을 열린 결정과 분리하고 작업을 유형, 소유권, 비용 및 실패 계약에 연결합니다. 이들은 컴파일러 실행 증거가 아닌 언어 디자인 참조입니다.

2입니다. 4 집중된 언급

가치와 행동연산자와 표현식

산술, 비교, 논리, 비트 작업, 과제, 대여, 증가, 선택, 범위 리터럴 및 평가 순서.

명백한 복구검사 산술

일반 안전 검사, Integer.checked_* API, 어휘 checked 경계, 첫 번째 실패 및 롤백 없음.

명시적 오류 종료오류 전파

소유 Result 페이로드, 정확한 오류 유형 일치, postfix ?, 성공적인 return 및 리소스 정리.

문법 통합파싱 규칙

우선 순위, 물음표, 일반 각도, 유형 피연산자, 문자 경계 및 사례 종료를 완료합니다.

3입니다. 결합된 모델

Result<i32, IntegerError> calculate(i32 first, i32 second, i32 third) {
    i32 sum = checked(first + second)?;
    i32 value = checked(sum * third)?;
    return Result.ok(value);
}

i32 maximum(i32 first, i32 second) {
    return (first > second) ? first : second;
}

checked는 산술 Result를 만든다. 포스트픽은 성공을 추출하거나 오류를 명시적으로 반환합니다. 삼항 연산자는 하나의 동일 형식 값을 선택합니다. 어느 형식도 함수의 최종 표현식이 암시적 return가 되도록 허용하지 않습니다.

4입니다. 한 눈에 보는 규칙 선택

  • 정적 숫자 타입, 문맥 리터럴, 이미 타이핑된 피연산자의 암시적 프로모션이 없습니다.
  • bool 전용 조건; 단락 AND/OR 및 선택된 삼항식 분지.
  • 왼쪽에서 오른쪽으로, 피연산자, 인수 및 쓰기 가능한 대상 위치에 대한 일회성 평가.
  • statement-only assignment + 명시적으로 지원되는 정수 ++ 및 -- 값 표현식.
  • 반쯤 열리고 포괄적인 범위 리터럴은 구체화된 배열이 아닌 Range 객체를 생성합니다.
  • 산술 Result 실패와 ? 종료는 소유권을 보존하고 성공적인 이전 효과를 롤백하지 않습니다.

선언 예제 사용 T name = value;, mut 일반적인 글쓰기 및 rsn static inference 에 대하여 int = i32, float = f64텍스트 형식이 소문자인 경우The text type is lowercase string.

5입니다. 공개 결정이 계속 표시됨

우선 순위 및 파서 통합 정책에 설명되어 있습니다. 파싱 규칙. 0.2 컴파일러와 회귀 테스트는 구현된 운영자 프로파일을 포함하며, 더 넓은 설계 카탈로그는 모든 제안된 API에 대한 지원을 의미하지 않습니다. Result 및 Optional 전파는 명시 적으로 입력 된 폐쇄를 포함하여 구현됩니다. 안전 정지가 해당 프로필 외부에 유지된 후 None-to-error 변환, 추가 전파 캐리어, 사용자 운영자 과부하 및 정리.

현재 0.2 구현 프로필 기록 가능한 Scope. 유형 및 선언 참조는 또한 더 넓은 설계 계약을 설명합니다.
