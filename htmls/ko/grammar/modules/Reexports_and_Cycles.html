관련 레퍼런스

기능 및 과부하영속 저장소로컬 범위 및 가시성구조체열거형제네릭 타입

1입니다. 지정된 공개 선언을 명시적으로 재수출

예시 모듈 · 지오메트리

public import math.vector { Point };

public import는 같은 이름으로 명시적으로 지정된 선언을 전달합니다. 정상적인 import는 자신의 import 모듈에 이름을 사용할 수 있게 한다; 그 자체로는 그 이름을 소비자에게 공개하지 않는다. 원본 선언은 공개적이고 접근 가능해야 합니다.

재수출 지점은 math.vector의 다른 모든 구성원을 재수출하지 않습니다. 명시적 목록은 공개 서페이스를 의도적으로 기록합니다. Reexport 이름은 별칭일 수 없습니다.

2입니다. 고객이 실제로 가져온 경로를 사용합니다.

예 CONSUMER · 지오메트리 공개 재수출 Point

import geometry { Point };

geometry.Point make_origin() {
    Point value = Point { x = 0.0, y = 0.0 };
    return value;
}

포인트와 geometry.Point는 허용됩니다. 소비자가 math.vector.Point를 가져오지 않았기 때문에 컴파일러가 Point를 원래 선언으로 해결하더라도 원래 정의 경로가 자동으로 승인되지 않습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import geometry { Point };

math.vector.Point unimported_original_path() {
    return Point { x = 0.0, y = 0.0 };
}

원본 경로는 자체 가져오기가 필요합니다. Canonical identity와 source-level access paths는 다른 문제를 해결한다: 선언이 어디에서 시작되었는지 아는 것은 프로그래머에게 다른 룩업 경로를 부여하지 않는다.

3입니다. 하나의 원점에 대한 중복된 경로는 하나의 선언으로 남음

import math.vector { Point };
import geometry { Point };

Point merged_origin() {
    return Point { x = 0.0, y = 0.0 };
}

두 개의 import는 동일한 원래 포인트 선언으로 이어집니다. 그들은 캐논 정체성에 의해 병합, 그래서 짧은 이름은 두 번 도착 하기 때문에만 모호 하지 않습니다. 선언은 두 개의 관련 없는 유형, 두 개의 과부하 원본 또는 두 개의 저장소 소유 복사본이 되지 않습니다.

명시적으로 가져온 경로는 허용된 액세스만 유지합니다. 이 예제에서는 두 경로의 이름을 명시적으로 지정합니다. 지오메트리만 가져오면 중복 제거의 부작용으로 math.vector를 얻을 수 없습니다. 추가 경로는 재수출 체인에서 합성 된 never입니다.

동일한 ID 원칙이 함수와 상수에도 적용됩니다. 동일 원본 오버로드 세트는 이름이 일치하기 때문에 다른 모듈의 관련 없는 오버로드와 결합되지 않습니다.

4입니다. 와일드카드 포워딩 또는 별칭 포워딩 없음

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

public import math.vector { * };

와일드카드 재수출은 금지되어 있습니다. 모듈은 노출하려는 이름을 나열해야 합니다. 일반 가져오기 math.vector { * };는 해당 모듈의 자체 액세스에 허용되므로 이 두 양식을 병합해서는 안 됩니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

public import math.vector { Point as Vec2 };

전달된 선언의 이름을 바꾸는 것은 허용되지 않습니다. 전체 모듈 형식 public import math.vector;가 결정되지 않았습니다. 이 참조는 유효한 것으로 제시하지 않습니다. 다른 import와 마찬가지로, 선택된 public import는 선언 앞에 나타납니다.

5입니다. 단위 선언 주기는 1개의 포장 안쪽에 허용됩니다

예 파일 · src/cycle/alpha.avx · 모듈 cycle.alpha

import cycle.beta { odd };

public bool even(i32 count) {
    if (count <= 0) return true;
    return odd(count - 1);
}

예 파일 · src/cycle/beta.avx · 모듈 cycle.beta

import cycle.alpha { even };

public bool odd(i32 count) {
    if (count <= 0) return false;
    return even(count - 1);
}

파일은 서로의 공개 선언을 참조합니다. 이 동일 패키지 모듈 사이클은 허용된다; 선언은 단지 다른 파일이 여전히 연결되어 있기 때문에 사용할 수 없게 될 필요는 없다. 그럼에도 불구하고 수입 및 액세스 제한은 모든 가장자리에서 checked입니다.

이 예제는 임의의 재귀 호출이 종료되거나 컴파일러가 이를 실행했다는 보장이 아닌 상호 선언 참조를 보여줍니다. 패키지에 대한 종속성 사이클은 모듈이 그렇지 않으면 유효한 선언 사이클이 될 때에도 금지됩니다.

6입니다. 선언 연결이 값 초기화와 분리됨

모듈을 연결하면 어떤 선언 이름이 계약을 참조하고 검사하는지 설정됩니다. 부분적으로 초기화된 값을 노출할 필요가 없습니다. 선언 주기를 허용하면 persist 값이 초기화되기 전에 읽을 수 없습니다.

엔트리 모듈로부터의 import와 reexport에 따라 모듈내의 모든 최상위 persist 선언은 프로그램 진입 전에 초기화 대상이다. 확인된 값 의존관계는 초기화 계획을 주도한다; 실행 중에 발견된 관리된 의존관계는 다음과 같은 준비상태와 사이클 규칙을 따른다. 지속 저장소.

Import line order는 초기화 순서가 아니며, 모듈에서 이름을 선택하는 것은 선언의 초기화가 관련이 있다는 것을 의미하지 않습니다. 개인 최상위 레벨 persist 선언은 포함된 모듈의 대상 집합의 일부로 남아 있습니다.

의존성 그래프선택한 치료
Same-package 모듈 선언 주기일반 이름 및 가시성 검사와 함께 허용됩니다.
재귀적 레이아웃 주기 By-value recursive layout cycle값이 유한 레이아웃을 가져야 하기 때문에 거부되었습니다.
Rootless 재수출 리디렉션 주기원본 선언이 해결되지 않았기 때문에 거부되었습니다.
상수 초기화 주기자리 표시자 값을 할당하는 대신 거부되었습니다.
persist 값 초기화 주기별도로 선택한 초기화 오류 규칙을 따릅니다.
패키지 의존성 주기한 작업 공간을 포함하여 거부되었습니다.

7입니다. 재귀 형식 선언은 여전히 유한 레이아웃이 필요합니다.

enum ListNode {
    End;
    Next {
        public i32 value;
        public Box<ListNode> next;
    };
};

간접성은 Box<ListNode>에서 명시적입니다. 그것은 안정적인 ABI, 자동 권투 또는 열거형 선언 자체에 의해 할당을 주장 하지 않습니다. 힙 소유자를 만드는 것은 해당 명시적 Box API와 failure/cost 계약을 사용합니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

struct Endless {
    public Endless next;
};

by-value 재귀 필드는 끝없이 확장되는 레이아웃을 필요로 하며 거부됩니다. by-value 사이클이 파일을 교차할 때도 동일한 요구 사항이 적용됩니다. 가져오기 주기는 허용됩니다; 무한대 크기의 값 레이아웃은 허용되지 않습니다. 컴파일러가 자동으로 Box를 삽입하여 선언을 복구하지 않습니다.

8입니다. 재수출 주기는 실제 정의 선언이 필요합니다.

거부된 예제 모듈 · redirects.first

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

public import redirects.second { Point };

거부된 예제 모듈 · redirects.second

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

public import redirects.first { Point };

종합하면, 이 모듈들은 닫힌 리다이렉션 사이클을 통해서만 포인트를 전달합니다. 원론적인 정의도 제시하지 않는다. 이는 해결되지 않은 재수출 주기이며 위치 지정자 포인트 유형을 제조하는 대신 거부됩니다.

모듈 그래프는 사이클을 가질 수 있지만 특정 재수출은 여전히 실제 원래 선언으로 해결됩니다. 모듈이 한 번 방문되었는지 여부뿐만 아니라 요청된 이름과 원래의 ID를 추적합니다. 비공개 선언은 순환 전달 체인에 의해 추진 될 수 없습니다.

9입니다. 상수 초기화 주기는 오류입니다

거부된 예제 모듈 · constants.left

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import constants.right { RIGHT };

public const i32 LEFT = RIGHT + 1;

거부된 예제 모듈 · constants.right

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import constants.left { LEFT };

public const i32 RIGHT = LEFT - 1;

각 const는 자신의 값을 계산하기 전에 다른 값을 요구한다. 초기화된 시작 값이 없습니다. 컴파일러는 동시 방정식을 해결하거나, 0을 대체하거나, 무해한 선언 재귀로 취급하는 대신 상수 이니셜라이저 주기를 거부합니다.

persist 초기화에는 초기화되지 않은 액세스의 방지 및 초기화 주기의 진단을 포함하여 자체 종속성 및 런타임 준비 규칙이 있습니다. 이러한 규칙은 해결되지 않은 const 값을 유효한 런타임 폴백으로 전환하지 않습니다.

10입니다. 모든 사이클에서 생존하는 개인 정보 보호 및 선택

한 사이클의 모듈은 그 임포트에 의해 부여된 이름만 본다. Point를 선택하면 동일한 대상 모듈에 있는 Dot에 대한 액세스 권한이 부여되지 않습니다. Point의 공개 재수출은 원본의 개인 헬퍼를 공개하거나 원래 모듈 경로를 통해 액세스 권한을 부여하지 않습니다.

parent/child 파일 이름 접두사는 이러한 검사를 약화시키지 않습니다. math.vector.ops는 math.vector와 독립적이며 필요할 경우 각각 다른 공개 선언을 가져와야 합니다. 주기는 파일 간의 우정 관계가 아닙니다.

마찬가지로, 패키지 의존성 사이클은 선언들이 연결될 수 있다는 사실에 의해 합법화되지 않는다. 더 보기 패키지 사이클 경계.

11입니다. SCC 컬렉션은 가능한 컴파일러 조직입니다.

강력히 연결된 구성 요소에서 선언을 수집하는 것은 허용된 모듈 사이클을 위해 컴파일러를 구성하는 권장 방법입니다. 값 초기화 분석에서 name/type 연결을 분리하는 데 도움이 될 수 있습니다.

이것은 기존 파서, 링커 또는 SCC 패스의 증거가 아니라 구현 지침이며 모든 백엔드가 동일한 내부 알고리즘을 사용해야 한다는 요구 사항이 아닙니다. AOT 및 JIT는 선택한 이름 ID, 액세스 및 초기화 시맨틱을 보존해야 합니다.

Canonical Declaration Identity는 재수출 경로에서 생존해야합니다. 컴파일러는 다른 모듈이 동일한 선언을 전달하기 때문에 추가 유형이나 추가 일반 함수 저장소 인스턴스를 만들어서는 안 됩니다. 정확한 내부 표현은 여기에 명시되어 있지 않습니다.

12입니다. 포워딩 및 사이클 세부 정보 열기

  • 전체 모듈의 public import form; named explicit reexports가 선택된 형식입니다.
  • 길거나 모호한 전달 체인에 대한 정확한 진단 및 소스 위치 보고.
  • 전체 모듈 loading/build 구현, 생성 된 모듈 및 증분 컴파일 메커니즘.
  • 파일 시스템 간접화 및 패키지 구성 세부 정보는 선택한 경로 규칙을 초과합니다.
