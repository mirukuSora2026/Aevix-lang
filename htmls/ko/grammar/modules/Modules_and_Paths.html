모듈 및 패키지

개요모듈 및 경로수입 및 가시성재수출 및 사이클패키지 경계

관련 레퍼런스

기능 및 과부하영속 저장소로컬 범위 및 가시성구조체열거형제네릭 타입

1입니다. 하나의 .avx 파일은 하나의 모듈을 정의합니다

소스 파일은 모듈 경계입니다. .avx 확장자는 source-file 확장자입니다. 모듈 이름은 소스 내부의 모듈 선언에서 반복되지 않고 파일 경로에서 파생됩니다.

이 설계는 논리적 소스 ID 및 액세스에 대해 설명합니다. 구현된 파일시스템 리졸버를 규정하거나 모든 미래의 빌드 환경이 물리적 로컬 디렉토리를 사용한다는 것을 약속하지 않는다. 여기에서 매핑 예제는 선택한 기본 소스 루트를 사용합니다.

2입니다. 원본 루트에서 전체 경로 추출

기본 루트 아래의 소스 파일전체 모듈 경로
src/math/vector.avxmath.vector
src/math/vector/ops.avxmath.vector.ops
src/app/start.avxapp.start

src/는 일반적인 소스 루트입니다. 0.2에서, aevixc --source-root DIR entry.avx 이를 명시적으로 선택한다; 그렇지 않으면 로더는 가장 가까운 src ancestance를 사용하여 엔트리 파일의 디렉토리로 되돌아간다. 프로젝트 구성 파일 형식은 향후 작업으로 유지됩니다. 소스-루트 접두사와 .avx 확장자는 논리 가져오기 경로에 포함되지 않습니다.

별도의 모듈 경로 구성 요소를 점. 전체 경로는 인용된 운영 체제 파일 이름이 아닌 논리적 모듈 경로입니다. 일반 가져오기와 일반 가져오기는 동일한 전체 경로 표기을 사용합니다.

3입니다. 파일에서 모듈 이름을 반복하지 마십시오

예 파일 · src/math/vector.avx

public struct Point {
    public f64 x;
    public f64 y;
};

public f64 dot(&Point left, &Point right) {
    return (*left).x * (*right).x + (*left).y * (*right).y;
}

f64 square(f64 value) {
    return value * value;
}

경로는 math.vector을 제공합니다. 점과 점은 공개 선언입니다; square는 비공개입니다. 왜냐하면 공개 수정자가 작성되지 않았기 때문입니다. 그들의 모듈 아이덴티티는 모듈 math.vector를 필요로하지 않는다; 헤더.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

module math.vector;

public const i32 DIMENSIONS = 2;

별도의 모듈 선언은 선택한 모델의 일부가 아닙니다. 파일 경로와 추가 헤더를 두 개의 경쟁하는 모듈 ID 소스로 취급하지 마십시오.

4입니다. 가져오기는 주변 파일 사이에서도 전체 경로를 사용합니다.

예제 모듈 · app.start

import math.vector { Point, dot };

f64 projection(&Point value) {
    return dot(value, value);
}

전체 math.vector 경로는 모듈 루트에서 작성됩니다. 가져오기 파일을 다른 디렉터리로 이동해도 이 표기이 상대 경로로 전환되지 않습니다. 이미 빌린 매개 변수는 추가 참조 계층없이 점으로 직접 전달됩니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import .vector { Point };

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import ../math/vector.avx;

선행 도트 가져오기와 상위 디렉터리 가져오기는 거부됩니다. 가져오기 경로는 상대 파일시스템 순회를 사용하지 않거나 .avx 확장자를 포함합니다.

5입니다. 모듈 파일 및 동일 접두사 디렉토리가 공존할 수 있음

파일모듈관계
src/math/vector.avxmath.vector독립적인 파일 모듈.
src/math/vector/ops.avxmath.vector.ops다른 독립적인 파일 모듈.

두 파일이 동시에 허용됩니다. 각각은 자신의 모듈을 정의합니다. 디렉토리 경로 접두사는 파일 모듈의 선언을 대체하거나 병합하거나 상속하지 않습니다.

예 파일 · src/math/vector/ops.avx

import math.vector { Point, dot };

public f64 length_squared(&Point value) {
    return dot(value, value);
}

child-path 모듈은 점과 점을 명시적으로 가져옵니다. 접두사는 이러한 선언을 자동으로 표시하지 않습니다. 파일 모듈은 동일한 접두사 디렉토리로 모든 모듈을 자동으로 다시 내보내지 않습니다.

6입니다. 부모 및 자식 경로는 별도의 개인 정보 보호 및 가져 오기를 유지합니다.

import math.vector { Point };
import math.vector.ops { length_squared };

f64 use_operations() {
    Point value = Point { x = 3.0, y = 4.0 };
    return length_squared(&value);
}

소비자는 math.vector에서 포인트 선언과 math.vector.ops에서 함수를 선택합니다. 한 모듈을 가져오면 어느 방향으로든 다른 모듈에 대한 액세스가 자동으로 승인되지 않습니다. 각 파일에는 자체 개인 선언 경계가 있습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import math.vector;

f64 child_is_not_imported() {
    math.vector.Point value = math.vector.Point { x = 3.0, y = 4.0 };
    return math.vector.ops.length_squared(&value);
}

전체 모듈 가져오기는 math.vector의 공개 이름에 대한 액세스 권한을 부여합니다. math.vector.ops를 가져오지 않습니다. 더 긴 철자는 누락된 자식 가져오기를 합성할 수 없습니다.

7입니다. 논리 및 실제 파일 케이싱 모두 일치

상황선택된 결과
만 src/math/vector.avx exists; 가져오기 math.vector.케이싱 경기.
같은 파일이 요청됨 Math.Vector.케이싱 불일치를 거부합니다. 파일시스템 케이스 폴딩을 사용하지 마십시오.
1개의 포장은 포함합니다 math.vector 및 Math.vector.경로가 사례별로 다를 뿐인 모듈을 거부합니다.
디스크의 경로 구성 요소에는 가져오기와 다른 케이싱이 있습니다.대소문자를 구분하지 않는 호스트 파일 시스템에서도 불일치가 발생합니다.

모듈 경로는 대소문자를 구분하며, 기록된 경로는 실제 파일 및 디렉터리 케이스와 일치해야 합니다. 패키지는 오직 케이스에 따라 다른 두 개의 모듈을 배치할 수 없습니다. 이러한 검사는 호스트 파일시스템의 동작이 어떤 소스를 선택했는지를 자동으로 변경하는 것을 방지합니다.

0.2 로더는 ASCII 모듈 구성 요소를 일치시킵니다. [A-Za-z_][A-Za-z0-9_]*. Unicode 모듈 identifiers/normalization 및 광범위한 파일 시스템 인디렉션 정책은 해당 프로필 외부에 남아 있습니다. 대소문자 구분 일치 자체는 이미 선택되어 있습니다.

8입니다. 표준 및 외부 경로는 실제 뿌리를 사용합니다.

import math;
import io;
import pixel.filters;

이 선은 경로 형태를 설명하고, 그 단위에 의해 공급된 특정한 기능에 관하여 약속 아닙니다. 표준 라이브러리 모듈은 수학 및 io와 같은 최상위 경로를 사용합니다. std 접두사는 자동으로 추가되지 않습니다. STD가 예약되어 있는지 여부는 결정되지 않았습니다.

외부 패키지에는 패키지 픽셀의 필터 모듈에 대한 pixel.filters와 같은 실제 패키지 이름이 포함됩니다. 별칭을 사용할 수 없습니다. 더 보기 패키지 경계 패키지 ID 및 오버랩 규칙.

9입니다. 전체 경로 충돌은 오류입니다

두 개 이상의 후보가 동일한 전체 모듈 경로를 제공하는 경우, 선호하는 소스를 선택하는 대신 해결에 실패합니다. 예를 들어 프로젝트 수학 모듈과 표준 라이브러리 수학 모듈은 프로젝트 우선 규칙 또는 표준 우선 규칙으로 해결할 수 없습니다.

이 오류는 각각 Point와 같은 짧은 이름을 노출하는 별개의 모듈을 가져오는 것과는 다릅니다. 전체 경로 충돌은 모듈을 식별하는 것을 방지합니다. 짧은 이름 충돌은 사용되지 않고 모호한 짧은 이름이 사용될 때 진단 될 수 있습니다. 모호함 가져오기.

10입니다. 필요한 경로 거부

조건필요한 결과
상대적인 가져오기 표기.import를 거부합니다.
실제 파일 케이싱이 일치하지 않습니다.모듈 경로를 거부합니다.
하나의 패키지에 케이스 전용 모듈 쌍.패키지 원본 배열을 거부합니다.
하나의 전체 모듈 경로에 대한 여러 후보.reject resolution; 우선 순위가 없습니다.
자신의 수입없이 Child-path 액세스.가져 오지 않은 모듈에 대한 액세스를 거부합니다.
추가 모듈 선언.선택한 파일 파생 모델 외부의 문법을 거부합니다.

이는 컴파일러 오류 코드 또는 확인된 출력이 아닌 소스 수준 거부 요구 사항입니다. 유효한 예제는 실행된 Aevix 컴파일을 주장하지 않고 선택된 문법을 설명합니다.

11입니다. 경로 상세 정보 열기

  • CLI는 이미 --source-root DIR, --module-root DIR 및 --package NAME=DIR을 제공합니다. 프로젝트 매니페스트, 패키지 버전 및 빌드 메타데이터는 향후 작업으로 유지됩니다.
  • 전체 모듈 식별자 문자 집합, 이스케이프 및 Unicode 정규화 규칙.
  • Symlink, generated-source 및 기타 파일 시스템 간접 정책
  • 위치 입력 파일은 이미 입력 모듈을 선택합니다. 매니페스트 기반 기본 항목과 플랫폼별 source/build-target 선택은 향후 작업으로 남아 있습니다.
  • 식별자 std 가 예약되어 있는지 여부; 현재 std 접두사는 필요하지 않습니다.

전체 경로, .avx 파일, 개인 모듈 경계 및 동시 math.vector/math.vector.ops 모듈이 이미 선택되어 있습니다. 모듈 ID 및 개인 정보 보호 경계는 열린 구성 세부 사항과 독립적입니다.
