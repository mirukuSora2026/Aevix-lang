모듈 및 패키지

개요모듈 및 경로수입 및 가시성재수출 및 사이클패키지 경계

관련 레퍼런스

기능 및 과부하영속 저장소로컬 범위 및 가시성구조체열거형제네릭 타입

1입니다. 패키지는 모듈을 포함하지만 자체 종속성 경계가 있습니다.

모듈은 하나의 .avx 파일입니다. 패키지는 소스 모듈을 그룹화하고 패키지 종속성 그래프에 참여합니다. 작업 공간을 공유하는 것은 패키지 ID, 개인 범위 또는 종속성 규칙을 병합하지 않습니다.

이 페이지는 소스 레벨 패키지와 경로 경계를 기록합니다. 완성된 패키지 매니페스트, 레지스트리 프로토콜, 버전 솔버, 패키지 게시 프로세스 또는 작업 공간 구성 파일을 정의하지 않습니다.

2입니다. 외부 모듈에는 실제 패키지 이름이 포함됩니다.

import pixel.filters;
import pixel.filters { apply };

경로는 실제로 픽셀이라는 외부 패키지의 필터 모듈을 식별합니다. 두 번째 줄은 그 예제 모듈이 제공하는 공개 이름을 선택하는 것을 예시한다; 표준 픽셀 패키지 또는 구현된 apply API가 존재한다고 주장하지 않는다.

패키지 ID는 원본 가져오기 별칭으로 대체되지 않습니다. 가져오기 별칭과 선택한 이름 별칭은 허용되지 않습니다. 가져온 경로는 적격 액세스를 제어합니다: 재수출은 원래 패키지 경로를 자동으로 승인하지 않습니다.

3입니다. 표준 모듈에는 최상위 경로가 있습니다

import math;
import io;

표준 라이브러리 모듈은 math 및 io와 같은 경로를 사용합니다. 필요한 std 접두사가 없습니다. std가 예약되어 있는지 여부는 여전히 열려 있으므로이 페이지는 사용자 패키지가 그 아래의 모든 철자를 자유롭게 주장 할 수 있다고 약속하지 않습니다.

이 라인은 모듈 경로 표기을 보여 주며, 수학이나 io의 상세한 API는 아닙니다. 가시성 및 selected/whole-module 가져오기 규칙은 해결된 모듈에서 제공하는 공개 선언에 적용됩니다.

4입니다. 원본 범주가 전체 경로 충돌을 이기지 못함

지원자격선택된 결과
프로젝트 math 모듈 및 표준 math 모듈.해결 오류: 프로젝트 우선 또는 표준 우선 폴백 없음.
2개의 유효한 근원은 둘 다 제공합니다 pixel.filters.해결 오류; dependency/source-order 승자가 없습니다.
서로 다른 모듈은 각각 짧은 이름을 노출 Point.전체 경로 충돌이 아니라 애매모호한 짧은 사용은 가져오기 조회 규칙을 따릅니다.

전체 경로는 하나의 모듈 후보를 식별해야합니다. 명시적으로 명명된 import는 모듈 경로 자체에서 충돌을 해결하지 않습니다: 선택한 이름을 해결하기 전에 대상 모듈을 식별해야 합니다.

구성 가능한 원본 뿌리를 이 규칙을 자동으로 재정의하는 우선 순위 목록으로 해석하지 마십시오. 구성 구문이 열려 있습니다. 우선 순위 충돌 결과가 아닙니다.

5입니다. 패키지 간의 종속성은 비순환적이어야 합니다.

그래프확정된 규칙
여러 모듈이 하나의 패키지 안에 들어 있습니다.Declaration/import 주기는 단위 규칙의 밑에 허용될지도 모릅니다.
패키지 A는 B에 따라 다르며 B는 A에 따라 다릅니다.패키지 의존성 사이클을 거부합니다.
A는 B, B는 C, C는 A에 의존한다.간접 패키지 종속성 사이클을 거부합니다.
동일한 순환 패키지는 하나의 작업 공간의 멤버입니다.여전히 거부; 작업 공간 멤버십은 면제가 아닙니다.

패키지 종속성 그래프와 모듈 선언 그래프는 서로 다릅니다. 패키지 내에서 상호 참조하는 소스 파일을 지원한다고 해서 독립적으로 식별된 패키지 간에 순환 종속성이 합법화되는 것은 아닙니다.

따라서 두 개의 패키지를 하나의 작업 공간으로 옮기는 것은 순환 해상도 메커니즘이 아닙니다. 이 시맨틱 제약을 명시하기 위해 패키지 매니페스트 구문이 필요하지 않으며 패키지 관리자 구현이 주장되지 않습니다.

6입니다. 패키지 멤버십이 파일 개인정보 보호를 우회하지 않음

모듈 수준 유형, 함수 및 상수는 공개가 아닌 경우 선언 파일 모듈에 비공개입니다. 같은 패키지에 있는 다른 모듈은 같은 패키지에 속해 있기 때문에 개인 도우미를 가져올 수 없습니다. 더 긴 경로 접두사를 가진 모듈도 별도의 경계입니다.

패키지마다 동일한 공개 액세스 요구 사항이 유지됩니다. 공개 형식은 필드 및 페이로드 액세스 규칙을 유지하며, 선언을 가져올 수 있게 만들면 개인 내부가 노출되거나 쓰기 가능한 참조가 생성되지 않습니다.

패키지 종속성은 모든 종속성 이름을 범위에 포함시키지 않습니다. 각 파일은 여전히 필요한 전체 경로 가져오기 및 명시적 선택을 기록합니다.

7입니다. 공개 전달은 선언 된 공개 경로 만 만듭니다.

예제 모듈 · graphics.api

public import pixel.filters { Filter };

예 를 들어 본 소비자

import graphics.api { Filter };

소비자는 필터와 graphics.api.Filter의 이름을 지정할 수 있습니다. 그것은 원래 경로의 다른 가져 오기없이 pixel.filters.Filter을 얻을 수 없습니다. 기본 선언은 새로운 복사 형식이 아닌 동일한 표준 필터로 유지됩니다.

이 예제에서는 가상 모듈에서 제공하는 공개 이름을 보여 줍니다. 구현 파일은 HTML 링크나 새로 생성된 소스 아티팩트가 아닙니다. 와일드카드 공개 포워딩은 금지되어 있으며 never 포워딩은 소스 선언의 공개 요구 사항을 우회합니다.

8입니다. 가져오기는 또한 사전 항목 초기화 대상 집합을 연결합니다.

엔트리 모듈에서 시작하여, imports 와 reexports 를 따라 연결된 모듈로 갑니다. 해당 모듈의 모든 최상위 persist 선언은 포함된 모듈의 비공개 또는 사용되지 않는 최상위 persist 선언을 포함하여 사전 입력 초기화 대상입니다.

하나의 선언을 선택하는 것은 선언이 초기화된다는 것을 의미하지 않습니다. 이 대상 세트 규칙은 파일이 사용할 수 있는 이름과는 별개입니다. 허용된 선언 주기는 실행 순서가 아닙니다. 확인된 값 종속성과 영구 저장소 준비 규칙이 초기화를 결정합니다.

Unimported 관련 없는 소스 파일은 디렉토리에 존재하기 때문에 추가되지 않습니다. 0.2에서, 입력 경로는 aevixc entry.avx 엔트리 모듈을 선택, which supplies i32 main() 실행을 위해. 프로젝트는 일반적으로 src/main.avx를 사용할 수 있으며 매니페스트 기반 기본값과 완전한 빌드 구성은 향후 작업으로 유지됩니다. 더 보기 지속 저장소 초기 설정 및 종료 계약.

9입니다. 이름을 사용 가능한 것으로 취급하기 전에 ID 및 액세스 확인

확인경계
하나의 전체 경로가 여러 공급자에게 해결됩니다.제공자를 선택하는 대신 모듈 해상도를 거부합니다.
패키지 사이클이 존재합니다.심지어 작업 공간에서도 거부합니다.
케이싱은 하나의 패키지에서 모듈 간에만 다릅니다.충돌하는 원본 배열을 거부합니다.
비공개 선언이 다른 파일에서 선택됩니다.패키지 멤버쉽에 관계없이 선택 거부.
소비자는 수입되지 않은 원래의 재수출 경로를 명명합니다.승인되지 않은 경로를 거부합니다.

이 언어는 패키지 위치에서 초기화 안전, 가시성 또는 메모리 레이아웃을 유도하지 않습니다. 모든 예제는 명시적 세미콜론과 함께 선택한 문법을 사용하고 일반적인 정적 타이핑을 유지합니다.

10입니다. 패키지 구성 및 툴링 열기

  • 패키지 manifest/workspace 구성 형식과 구성 가능한 소스 루트의 표기.
  • 매니페스트 기반 항목 기본값, 버전 해상도, 종속성 획득 및 패키지 게시. CLI는 이미 항목 경로를 선택하고 --package NAME=DIR을 통해 명시적인 패키지 루트를 허용합니다.
  • Generated/platform-specific 모듈 검색 및 파일 시스템 간접 정보.
  • 완전한 식별자 문법과 std와 같은 예약된 이름 결정.

이러한 열린 툴링 세부 정보는 상대적인 가져오기, 가져오기 별칭, 패키지 주기 또는 우선 순위 기반 전체 경로 섀도잉을 허용하지 않습니다. 계속하기 모듈 및 경로, Import와 접근 권한, 및 재수출 및 사이클.
