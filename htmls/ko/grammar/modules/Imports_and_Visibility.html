1입니다. 선언 전에 모든 가져오기

import math.vector { Point, dot };

f64 squared_length(&Point value) {
    return dot(value, value);
}

형식, 함수, 상수 및 기타 선언 전에 가져오기가 파일 맨 위에 배치됩니다. 여기에는 public import 선언이 포함됩니다. 임포트는 함수 내부나 선언 후에 이름 확인이나 초기화를 지연시키기 위해 이동할 수 없습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

const i32 VERSION = 1;
import math.vector { Point };

가져오기는 선언을 따르고 거부됩니다. 모든 import 예제는 전체 경로를 사용하고 세미콜론으로 끝납니다.

기본 전주곡과 명시적 라이브러리 가져오기

기본 전주곡은 선택한 기본 및 자주 사용되는 핵심 유형 이름을 모든 모듈에서 사용할 수 있도록 합니다. 이것은 name-availability 규칙이다: Vector와 같은 라이브러리 정의 타입은 어휘 키워드나 컴파일러 프리미티브가 되지 않고 prelude를 통해 사용할 수 있다.

분류사용 가능한 이름규칙 가져오기
원시 스칼라 종류선택된 정수와 부동소수점 스칼라 타입 int 및 float 별칭; bool, char, byte, unit, never자동 사용 가능. 선택한 언어 유형에 대해 숫자 형식 초안이 적용되지 않습니다.
반환 마커voidreturn 위치에서 자동으로 사용 가능; 일반적인 저장 가능 값 유형이 아닙니다.
텍스트 및 일반 컬렉션string, string_view, Array, Vector, Slice, MutSlice, Tuple, Range기본 전주곡을 통해 자동으로 사용할 수 있습니다.
부재와 실패Optional, Result기본 전주곡을 통해 자동으로 사용할 수 있습니다.
다른 도서관들예를 들어 Tensor, Map, Set, Box, Shared, Weak 및 동기화 유형명시적으로 허용된 가져오기 경로가 필요합니다.

예를 들어 import tensor { Tensor }; 선택된 Tensor 이름과 허용된 적격 경로를 부여합니다. Standard-library 모듈은 예약된 std 접두사 없이 일반적인 전체 경로를 유지합니다. 카탈로그에 나타나는 형식은 자체적으로 해당 이름에 대한 액세스를 부여하지 않으며 가져오기는 Tensor 값을 할당하거나 컨테이너를 인스턴스화하지 않습니다.

자동 가용성을 제한하면 모듈 로더가 관련 없는 전문가 모듈을 열심히 분석하지 않아도 되지만 컴파일러 메모리 및 빌드 시간 개선에는 구현 및 측정이 필요합니다. 선택된 가시성, 충돌, 재수출 및 영구 초기화 규칙은 연결된 모듈에 계속 적용됩니다. Compiler import enforcement는 모듈 로딩 및 이름 확인에 속합니다. 카탈로그는 설계 참조입니다.

2입니다. 전체 모듈 가져오기를 통해 적격한 공개 액세스 권한 부여

import math.vector;

f64 qualified_projection() {
    math.vector.Point value = math.vector.Point { x = 2.0, y = 3.0 };
    math.vector.Point axis = math.vector.Point { x = 1.0, y = 0.0 };
    return math.vector.dot(&value, &axis);
}

전체 모듈 가져오기는 모듈의 공개 선언에 대한 완전한 액세스 권한을 허용합니다. 그것은 포인트 또는 점 짧은 이름을 소개 하지 않습니다. 자격은 모듈을 식별하고 여전히 public/private 액세스의 적용을받습니다.

모듈 네임스페이스는 동적으로 할당된 객체가 아닌 이름-해상도 경계입니다. 함수 호출의 자격은 그 값을 변경하거나 매개 변수 모드를 빌려주지 않습니다.

3입니다. 노출할 이름을 정확하게 선택

import math.vector { Point, dot };

f64 selected_projection() {
    Point value = Point { x = 2.0, y = 3.0 };
    Point axis = Point { x = 1.0, y = 0.0 };
    return math.vector.dot(&value, &axis);
}

선택한 이름은 짧은 철자와 함께 사용되거나 명시적으로 가져온 경로를 통해 자격을 얻을 수 있습니다. 이 예제에서는 Point, math.vector.Point, dot 및 math.vector.dot를 사용할 수 있습니다. 선택 항목은 이름을 변경하지 않습니다.

다음 모듈을 import하세요:짧은 이름자격 있는 이름
import math.vector;이 import에는 아무것도 들어있지 않습니다.math.vector의 공개 선언.
import math.vector { Point };포인트 ONLYmath.vector.Point 전용.
import math.vector { Point, dot };점과 점.math.vector에서 선택한 동일한 이름입니다.
import math.vector { * };모듈의 공개 이름입니다.math.vector에서 그 공개 이름.

4입니다. 선택되지 않은 이름은 복구할 수 없습니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import math.vector { Point };

f64 unselected_function() {
    Point value = Point { x = 2.0, y = 3.0 };
    return math.vector.dot(&value, &value);
}

포인트가 선택되었지만 점은 선택되지 않았습니다. 전체 모듈 경로는 이러한 제한을 우회하지 않습니다. 명시 적으로 가져 오기 점, 전체 모듈 가져 오기를 사용하거나 모든 공용 이름이 의도 될 때 와일드 카드 가져 오기를 사용하십시오.

동일한 규칙이 상수, 유형 및 호출 가능한 과부하 세트에 적용됩니다. 선택한 선언의 시그니처 안에 언급된 형식은 자동으로 다른 가져온 짧은 이름이나 적격 이름이 되지 않습니다.

5입니다. 와일드카드 가져오기로 우선 순위 없이 공개 이름 노출

import math.vector { * };

f64 wildcard_projection() {
    Point value = Point { x = 2.0, y = 3.0 };
    return dot(&value, &value);
}

와일드카드는 명시적으로 재수출된 이름을 포함하여 해당 모듈에서 제공하는 모든 공개 이름을 가져옵니다. 이것은 private 선언을 가져오거나, 자동으로 같은 접두사 자식 모듈을 가져오거나, 모듈의 의존성의 모든 이름을 노출하지 않습니다.

명시적 수입은 와일드카드 수입을 능가하지 않습니다. 임포트 순서도 우선 순위가 없습니다. 고유한 고유한 선언이 동일한 짧은 철자에 기여하는 경우, 그 짧은 이름을 사용할 때 모호성이 처리됩니다. 와일드카드 재수출은 다른 작업이며 금지됩니다.

6입니다. 모듈 수준의 선언은 기본적으로 비공개입니다.

예제 모듈 · math.vector

public struct Point {
    public f64 x;
    public f64 y;
};

public const i32 DIMENSIONS = 2;
const i32 INTERNAL_REVISION = 1;

f64 square(f64 value) {
    return value * value;
}

public f64 dot(&Point left, &Point right) {
    return (*left).x * (*right).x + (*left).y * (*right).y;
}

점, 차원 및 점은 수입될지도 모릅니다. INTERNAL_REVISION과 square는 이 파일 모듈에 비공개입니다. 개인 기본값은 모듈 수준 유형, 함수 및 상수에 적용되며 공개 수정자가 이를 노출해야 합니다.

공개 형식은 여전히 자체 필드 및 방법 가시성을 적용합니다. 유형을 가져오는 것은 개인 필드 또는 개인 페이로드에 대한 액세스를 승인할 수 없습니다. 로컬 변수는 어휘 블록 범위를 유지한다; public/private는 이들을 전역적으로 접근 가능한 이름으로 바꾸지 않는다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import math.vector { square };

명시적 선택은 개인 함수를 가져올 수 없으며 와일드 카드는 이를 포함하지 않습니다. Same-prefix 자식 모듈은 특별한 예외를 받지 않는다.

7입니다. 직접 유형, 함수 및 상수는 하나의 이름 공간을 공유합니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

struct Item {
    public i32 value;
};

const i32 Item = 1;

이것들은 하나의 모듈에서 두 개의 직접 선언이며, 수입 된 후보자와 경쟁하지 않습니다. 이름 충돌은 선언 수준에서 거부됩니다. 타입, 함수 및 상수는 별도의 모듈 레벨 이름 공간을 사용하지 않습니다.

예외는 동일한 모듈에 선언된 허용된 과부하 함수 집합입니다. 함수 오버로드는 매개 변수 유형이나 개수에 따라 다를 수 있지만 return-type-only 차이는 거부됩니다. 이러한 함수는 가져오기를 위한 하나의 명명된 과부하 세트로 남아 있습니다.

public i32 add(i32 left, i32 right) {
    return left + right;
}

public f64 add(f64 left, f64 right) {
    return left + right;
}

이 두 함수는 동일한 모듈에서 직접 선언되며 매개 변수 유형에 따라 다릅니다. 허용된 한 세트의 오버로드를 형성합니다. return 유형만 변경해도 다른 과부하가 발생하지 않습니다.

자세한 통화 순위, 일반 환경 설정 및 기본 인수에 설명되어 있습니다 함수수입 조회는 다른 과부하 시스템을 발명해서는 안됩니다.

8입니다. 모호한 짧은 이름은 사용할 때 실패합니다.

예제 가져오기 · 두 소스 모듈 모두 별개의 포인트 유형을 내보냅니다

import drawing.left { Point };
import drawing.right { Point };

i32 unaffected() {
    return 1;
}

경쟁 수입은 포인트가 짧은 이름으로 사용되지 않을 때 공존 할 수 있습니다. 출처 순서 승자는 없습니다. 완전히 자격을 갖춘 선택된 이름 drawing.left.Point 및 drawing.right.Point는 두 개의 원래 선언을 구별합니다.

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import drawing.left { Point };
import drawing.right { * };

Point ambiguous_point() {
    return Point { x = 0.0, y = 0.0 };
}

짧은 이름 포인트는 모호합니다. 명시적 왼쪽 선택에는 오른쪽 와일드카드보다 우선 순위가 없습니다. 오류는 두 수입의 단순한 존재보다는 모호한 짧은 사용이다.

9입니다. 로컬 선언은 가져오기를 능가하거나 원격 과부하를 병합하지 않습니다.

예 모듈 · app.settings · config.remote는 별도의 공개 LIMIT를 수출

import config.remote { LIMIT };

const i32 LIMIT = 3;

i32 selected_remote_limit() {
    return config.remote.LIMIT;
}

로컬 선언과 가져온 선언은 서로 다른 기원입니다. 어느 쪽도 우선순위를 받지 않는다. 그들의 공존은 애매모호한 짧은 용도가 아니다; 선택된 먼 자격이 된 경로는 그것의 선언을 확인하는 그러나, LIMIT를 혼자 참조하는 것은 애매모호할 것입니다.

예제 소스 계약 · text.integer 내보내기 파싱(i32); text.real 내보내기 파싱(f64)

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import text.integer { parse };
import text.real { parse };

i32 ambiguous_parse() {
    return parse(1);
}

다른 원래 모듈의 과부하가 결합되지 않습니다. 짧은 이름 파싱은 인수 기반 오버로드 순위가 원격 출처를 선택할 수 있기 전에 모호합니다. 일치하는 인수 유형이 병합된 호출을 구출하지 않습니다. 허용된 정규화된 경로를 사용하십시오.

두 경로가 실제로 동일한 원래 선언으로 연결되면, canonical identity가 대신 복제를 병합합니다. 더 보기 canonical 재수출 신원.

전체 경로는 액세스 가능한 선언 하나를 식별해야 합니다.

적격한 사용을 해결하기 전에 가져오기 경로 부여 및 가시성을 적용합니다. 부모 모듈의 type/member 체인과 독립적으로 가져온 자식 모듈이 동일한 기록된 전체 경로에서 별개의 접근 가능한 선언을 산출하는 경우, 그 사용에 대해 모호함을 보고합니다. 자동으로 모듈, 멤버 또는 가장 긴 모듈 접두사를 선호하지 마십시오. 부모 파일과 자식 모듈은 공존할 수 있습니다. 프로그래머는 전체 경로 자체가 선언을 구별할 수 없을 때 경쟁 경로를 제거하거나 노출된 이름을 변경해야 합니다.

10입니다. 이름을 변경하지 않고 유지

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import math.vector { Point as Vec2 };

허용되지 않는 예제. 확정된 규칙을 의도적으로 위반하므로 유효한 Aevix 소스가 아닙니다.

import math.vector as vectors;

선택한 이름 별칭이나 전체 모듈 별칭이 선택되지 않습니다. 같은 짧은 이름을 가진 독특한 기원은 import precedence나 renaming보다는 허용된 전체 모듈 경로를 사용하여 구별된다.

공개 재수출은 또한 선언 된 이름을 보존합니다. 가져온 값은 단순히 이름이 도입되었기 때문에 복사되거나 이동되지 않습니다. 후속 일반 통화 또는 값 작업은 자체 소유권 및 비용 계약을 따릅니다.
