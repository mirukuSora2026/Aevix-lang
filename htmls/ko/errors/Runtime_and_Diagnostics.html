1입니다. 감시된 실행 중지

작동실패 조건결과
일반 정수 +, -, *, 단항 마이너스, ++, --표현 가능한 결과가 오버플로우되거나 언더플로우됩니다.유효하지 않은 결과를 사용하기 전에 보호된 종료입니다.
Integer / 그리고 %0인 나눗수 또는 부호 있는 최솟값을 -1로 나누는 경우.위험한 지시를 하기 전에 미리 대비해야 한다.
Integer 시프트네거티브 시프트 count 또는 count가 피연산자 너비 밖에 있습니다.종료를 경계합니다. Bitwise shift 결과는 지정된 비트 의미론을 따릅니다.
고정 Array 및 최소 Vector/Slice 인덱싱[0, length] 외부의 런타임 인덱스; 상수 유효하지 않은 인덱스는 컴파일 중에 진단됩니다.메모리 액세스 전에 종료를 보호합니다.
유효하지 않은 런타임Corrupt/unreachable 태그 또는 백엔드 런타임 전제 조건.안전 정지; 진단 정밀도는 가동에 달려 있습니다.

이 표는 고정 Array와 구현된 Vector/Slice 프로필을 다루며, 설계 카탈로그의 모든 컬렉션을 다루지는 않습니다. 0.2 구현 프로필 현재 플랫폼 지원 및 실행 제한을 기록합니다. checked 서브슬라이스 API return BoundsError; 일반 인덱싱은 여전히 여기에 나열된 가드 스톱 동작을 사용합니다. 생성 된 경비원은 LLVM 트랩 의미론을 사용합니다. OS는 신호 또는 예외를 보고할 수 있으며, 숫자 코드는 플랫폼에 따라 다릅니다. IntegerError 또는 BoundsError 값이 아니며 Result ?가 복구할 수 없습니다. 검사-산술 라이브러리 API와 어휘 checked는 별도의 design/implementation 스코프로 유지됩니다.

2입니다. 초기화 및 종료 지속

초기화는 동기화됩니다: 하나의 스레드가 초기화되고 다른 스레드는 기다립니다. 감지된 재귀 또는 크로스 스레드 초기화 주기가 Aevix persist 초기화 오류 진단으로 중단됩니다. 닫힌 도메인 읽기, 정리 중 금지된 persist 액세스, 런타임 레지스트리 메타데이터 할당, synchronization/cleanup 부기 설정 실패도 중단할 수 있습니다. 일반 저장된 Result.err는 성공적으로 초기화된 값이며 이 정책을 트리거하지 않습니다.

지원되는 persist 값에 성공하면 일반적으로 런타임 관리 초기화 작업이 완료된 후 역 초기화-완료 순서로 정리됩니다. 구현된 The 모델 번호: parallel.for_each call은 반환하기 전에 이름지어진 검증된 스칼라 워커를 조인합니다; persist 종료가 기다리는 백그라운드 작업을 떠나지 않습니다. 일반 Task 및 애플리케이션 스레드 수명 주기 API, Tensor 및 GPU 실행은 0.2 작업 프로필에서 지원되지 않습니다. 중단되거나 강제 종료 된 실행에는 정상적인 정리 보증이 없습니다. 정확한 런타임 진단 원인은 아래 소스 인벤토리에 보관됩니다.

출처계약
모델 번호:PersistRuntime.cppruntime fail(reason, name)는 stderr에 기록되고 호출은 중단됩니다.
초기화 참조선택된 eager/lazy 초기화 및 사이클 정책.
종료 참조정상적인 종료, 의존성 접근 및 정리 순서.

  • cannot unlock initialization registry
  • cannot update cleanup TLS slot
  • cannot update initialization TLS slot
  • cannot wait for initialization
  • cyclic initialization across threads
  • cyclic initialization on the current thread
  • guard belongs to a different module

  • missing module registry slot
  • missing persist guard slot

  • persist access from cleanup is forbidden

3입니다. 단계별 컴파일러 진단

구현체는 진단(Diagnostic)을 SourceRange와 메시지 string로 저장하고 벡터로 진단을 수집합니다. 현재 안정적인 번호가 매겨진 공개 진단 열거형, 심각도 계층 구조 또는 잡을 수 있는 Aevix 예외 개체를 노출하지 않습니다. 메시지에는 선언 이름과 유형이 포함될 수 있습니다.

아래 소스 링크는 저장소에 공개된 main 브랜치를 엽니다. 릴리스 이후의 변경 사항이 포함될 수 있습니다. 0.2 구현 프로필 지원되는 릴리스 동작을 식별합니다. 소스 링크는 해당 프로필에 대한 향후 로드맵 계약을 홍보하지 않습니다.

C++ 구현 유형목적Aevix 가시성
Failure (Parser.cpp internal)토큰 위치와 메시지를 전달하는 파서 복구.내부; 소스 진단으로 변환.

std::invalid_argument유효하지 않은 파서 API/token-stream 사전 조건입니다.Aevix 오류 열거형이 아닌 C++ API 계약을 호스트합니다.

std::out_of_rangeSourceManager API에서 유효하지 않은 소스 ID 또는 소스 오프셋입니다.호스트 컴파일러 API misuse/failure.
std::ios_base::failure소스 입력 I/O 실패가 모듈 로딩에 의해 포착되었습니다.컴파일러 I/O 진단을 통해 보고되었습니다.
std::bad_alloc새 컨테이너나 표준 컨테이너에 의한 컴파일러-호스트 할당이 실패할 수 있다; 이것은 생성된 프로그램의 명시적 할당 Result와는 별개이다.호스트 C++ 실패; Aevix 오류 값으로의 보편적인 변환이 구현되지 않았습니다. 잡히지 않은 실패는 컴파일러를 종료할 수 있습니다.
std::exception프로세스 지원에 의해 포착된 임시 디렉터리 호스트 실패입니다.오류가 발생한 string로 변환됩니다.
AOTResult / JITInvocationResult / ProcessResultBackend/process 성공, 메시지, exit/signal/timeout 상태.소스 언어 Result가 아닌 컴파일러 드라이버 레코드.
TypeLayoutResult / OwnershipResult / TypeCheckResult분석 성공, layout/ownership 메타 데이터 및 진단 상태.컴파일러 분석 레코드.

C++ 할당 실패 또는 타사 LLVM/OS 진단이 완전히 새로운 Aevix 예외 계층 구조로 변환되지는 않습니다. 외국 C++ 예외는 지원되는 C ABI를 통해 풀리지 않아야 합니다. 소스 프로그램은 컴파일러 호스트 예외에 대한 try/catch 액세스를 얻지 못합니다.

5입니다. 명령줄 결과

상태의미
0성공적인 check/build/package 작업; 실행된 프로그램은 자신의 주 return 상태를 사용합니다.
1드라이버 경로에서 컴파일, 분석, AOT/JIT 또는 백엔드 실패.
2드라이버 경로에서 사용, 경로, 입력, 환경, 실행 또는 지원되지 않는 실행 모드 실패.
아동 결과Run/JIT 작업자가 정상적인 프로그램 종료를 전달하거나 비정상적인 종료를 보고합니다. 모든 0이 아닌 자식 종료를 컴파일러 유형 오류로 해석하지 마십시오.

AOT 실행은 자식 프로세스입니다. JIT 호출은 작업자 프로세스에서 격리되므로 프로그램 트랩이 부모 컴파일러를 통해 풀리지 않습니다. 진단 문구, 하위 프로세스 신호 매핑 및 OS 오류는 안정적인 휴대용 열거형이 아닙니다.
