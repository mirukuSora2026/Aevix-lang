This table covers fixed Array and the implemented Vector/Slice profile, not every collection in the design catalog. The 0.2 implementation profile records current platform support and execution limits. The checked subslice APIs return BoundsError; ordinary indexing still uses the guarded-stop behavior listed here. Generated guards use LLVM trap semantics. The OS may report a signal or exception; its numeric code is platform-dependent. These are not IntegerError or BoundsError values, and Result ? cannot recover from them. Checked-arithmetic library APIs and lexical checked remain separate design/implementation scope.

2. Persist initialization and shutdown

Initialization is synchronized: one thread initializes and others wait. A detected recursive or cross-thread initialization cycle aborts with an Aevix persist initialization error diagnostic. Reading a closed domain, forbidden persist access during cleanup, allocation of runtime registry metadata, and failure to establish synchronization/cleanup bookkeeping can also abort. An ordinary stored Result.err is a successfully initialized value and does not trigger this policy.

Successful supported persist values normally clean up in reverse initialization-completion order after runtime-managed initialization activity is complete. The implemented CPU parallel.for_each call joins its named, validated scalar workers before returning; it does not leave background work for persist shutdown to await. General Task and application-thread lifecycle APIs, Tensor and GPU execution remain unsupported in the 0.2 working profile. Aborted or forcibly terminated execution has no normal cleanup guarantee. 3. Compiler diagnostics by phase

The implementation stores a Diagnostic as SourceRange plus a message string, and collects Diagnostics in a vector. It does not currently expose a stable numbered public diagnostic enum, severity hierarchy or catchable Aevix exception object. Messages may embed declaration names and types.

Source links below open the repository's published main branch, which can advance beyond a release. The 0.2 implementation profile identifies supported release behavior; a source link does not promote a future roadmap contract into that profile.

C++ allocation failures or third-party LLVM/OS diagnostics are not exhaustively converted into a new Aevix exception hierarchy. Foreign C++ exceptions must not unwind through the supported C ABI. Source programs do not get try/catch access to compiler host exceptions.

5. Command-line outcomes

StatusMeaning
0Successful check/build/package action; executed programs use their own main return status.
1Compilation, analysis, AOT/JIT or backend failure in the driver paths.
2Usage, path, input, environment, launch or unsupported execution-mode failure in driver paths.
Child outcomeRun/JIT workers forward normal program exit or report abnormal termination; do not interpret every nonzero child exit as a compiler type error.

AOT execution is a child process. JIT invocation is isolated in a worker process so a program trap does not unwind through the parent compiler. Diagnostic wording, subprocess signal mapping and OS errors are not a stable portable enum.
