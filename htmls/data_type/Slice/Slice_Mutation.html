1. One Exclusive View, No New Owner

MutSlice<T> describes an exclusive writable borrow of initialized contiguous values. It does not own an allocation and does not free the source when the descriptor ends. Creating it requires an existing exclusive capability over the owner or source view. Moving a descriptor transfers that borrow capability; copying arbitrary mutable descriptors is not permitted. Ordinary read Slice<T> descriptors can be copied only while their inherited lifetime remains valid.

Passing an existing view directly to a known MutSlice<U> or &mut U parameter forms a temporary reborrow under the chosen function rule. Its source capability is suspended while derived references, views or iterators remain live, including loans inside Optional or Result and any cleanup that may access their referent. Ending the call alone does not end such a returned loan. Reborrowing uses the existing exclusive capability and does not require a mut binding for the descriptor itself.

Ordinary assignment, initialization, return and a generic T value argument still move a non-Copy descriptor. T being instantiated as MutSlice does not make a generic value parameter borrowing. All current mutable Slice catalog inputs are borrowing inputs; see the common parameter modes for the distinction. No general move expression or implicit capability copy is added.

2. Disjointness Is an Actual Range Proof

Splitting an exclusive view produces nonoverlapping child ranges. The parent capability is suspended while children live, so it cannot access overlapping elements concurrently. Empty ranges can share a boundary without denoting a shared element. Implementations validate indices before producing references; they must not create invalid references and test bounds afterward. Scalar count arithmetic and target element layout limits still apply.

3. Copying, Moving, and Overlap

A separate read source and writable destination must satisfy the normal aliasing rules. Overlapping ranges cannot be smuggled in by constructing two independent mutable descriptors. Where the common catalog offers an overlap-safe within-view operation, one exclusive parent capability supplies the proof and the algorithm states its move or copy requirements. Byte movement does not license duplicating arbitrary resource-owning T values.

4. Callbacks and Partial Failure

Sorts, mutation callbacks, and fallible transforms retain initialized storage even when callbacks fail or unwind under the selected runtime profile. The basic guarantee may leave a permutation or completed element updates; external side effects are not rolled back. A consistent total comparator is required for ordered algorithms. Floating-point input needs an explicit NaN ordering rather than ordinary partial comparison. Allocation-bearing stable sorts publish scratch and failure behavior.

5. Borrowed Results and Escaping Handles

Returning a slice, reference, iterator, or mapped view preserves the original owner’s lifetime dependency. Packing the descriptor into Shared does not lengthen that dependency or turn borrowed data into owned storage. Safe FFI adapters must validate the external owner, initialized count, alignment, access permissions, and mutation exclusion. A release callback belongs to a separately owning adapter, not an ordinary slice destructor.

6. Parallel Disjointness and Suspension

Disjoint element ranges are useful for host parallelism only when element and capture bounds also permit transfer. Internal references in T may still connect to shared resources; splitting indices is not proof against every internal data race. Scoped jobs finish before borrowed ranges expire. Device access needs explicit placement and Pending lifetime management. Holding an exclusive host view does not make that memory kernel-addressable or synchronized.

7. Read Example and Related Contracts 

mut Array<i32, 4> values = [1, 2, 3, 4];
MutSlice<i32> writable = Slice.from_array_mut(&mut values);
Slice.reverse(writable);
Slice<i32> view = Slice.from_array(&values);
Result<Slice<i32>, BoundsError> middle = Slice.subslice(view, 1, 3);
Optional<&i32> first = Slice.first(view);

The owner is mut before its exclusive borrow is created. The writable view is passed directly; its final use ends before the later shared owner borrow. See the existing complete Slice catalog for individual mutable functions and Vector Growth for owner invalidation. A numeric slice is not validated UTF-8 text; raw byte and Unicode boundaries remain explicit.
