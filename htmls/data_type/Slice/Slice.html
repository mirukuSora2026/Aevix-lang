1. Borrowed Contiguous Views

Language design draft. Slice<T> is a read view; MutSlice<T> is an exclusive writable borrowed view. These descriptors do not own or allocate the backing elements.

A slice names an initialized contiguous element range owned elsewhere. It stores enough metadata to identify its range and length, but does not own or release those elements. A shorter slice changes what is visible; it never changes the backing Array or Vector length.

Read views may be duplicated as borrow metadata when lifetime rules permit. Writable capabilities cannot be duplicated into overlapping writers. Reborrowing a MutSlice suspends conflicting use of the original view for the derived borrow’s lifetime.

2. Owner Lifetime & Invalidation

Every view remains tied to its originating owner or explicit foreign lifetime. It cannot escape a local owner, survive owner destruction, or keep a Vector buffer valid across an invalidating reallocation. Safe code rejects conflicting owner moves and structural mutation while the borrow remains live.

Length and contiguity are not ownership. Constructing a Slice from an arbitrary address would require provenance, alignment, initialized-element, extent, and permission proofs. This catalog deliberately exposes safe owner-based construction instead of raw-pointer adoption.

A view into a fixed array is subject to the same lifetime rules as one into a Vector. Fixed capacity does not permit aliases that violate exclusive access. Borrow shortening may be inferred, but no algorithm may rely on a dangling view merely because its length metadata still exists.

3. Exclusive Access & Disjoint Regions

Write algorithms need both an exclusive writable capability and an explicitly permitted mutable access at the call site. Default immutable declarations remain immutable; holding a read Slice never grants writing permission.

Checked split functions validate the split point, then create nonoverlapping borrowed regions. Two write halves can coexist because they cover disjoint slots; the original overlapping write capability is suspended. Mutable iterators and chunk iterators enforce the same separation for yielded elements.

Overlapping windows are read-only in this catalog. General writable overlapping windows would require a lending/short-lived access protocol rather than unrestricted independent MutSlice results. Interior-mutability types and callback captures still need their own concurrency constraints.

4. Bounds, Empty Views & Chunks

Ranges are half-open and use usize endpoints: 0 <= start <= end <= length. Empty ranges are valid, including an empty suffix at length. Out-of-bounds access returns Optional or Result according to the selected API; no unchecked read is implied.

Chunk and window widths must be positive. Width greater than length yields one short chunk or no full window, according to the named operation. Exact chunk functions separate full chunks from a leftover tail. Mutation never changes the backing collection’s element count.

Zero-sized T can have many logical elements while byte_len is zero. Bounds, borrow exclusivity, callback counts, and element Drop obligations still follow logical length. A zero-length view has no first element and must not be dereferenced even when a raw FFI address is present.

5. Copy, Clone & Error Atomicity

Copying a read view duplicates only metadata and retains the borrow. Explicit to_vector/to_array functions create owned values and require Copy or Clone as named. An owned resource is not deep-cloned by reinterpreting its bytes.

copy_from and clone_from require equal lengths and compatible disjoint borrows. copy_within is the explicit overlap-permitting Copy operation. Bounds checks occur before mutation. Clone-based overwrite can leave a replaced prefix on error, while every slot remains initialized.

Returned allocation errors from output construction clean the partial output and preserve the borrowed source. In-place callback side effects are not rolled back. A future unwind path must preserve valid initialization; process termination does not guarantee cleanup. All error and iterator protocol names remain proposed.

6. Algorithm Requirements & Cost

Search positions are relative to the view’s beginning, not the owner’s full buffer. Binary search needs sorted input under the supplied consistent total comparator. partition_point needs a true prefix followed by a false suffix. These semantic preconditions do not permit memory unsafety when violated.

Sorting floating values needs an explicit total comparator with a chosen NaN order. Stable sort may allocate scratch; unstable sort avoids heap scratch. Interrupted comparison can change order while preserving ownership. Eq comparisons use element semantics, never uninitialized padding.

Creating or splitting a view is O(1) metadata work. Traversal, copy, clone, reverse, and rotation remain proportional to affected elements. Element size, comparator work, Clone, and Drop add their own costs; no copy or device transfer becomes free because its input was a view.

7. Complete Proposed Slice API

Canonical Slice catalog. Maintain signatures, reborrow guarantees, returned errors, and costs here. The Array-family Slice guide links to these rows instead of maintaining duplicate contracts.

All rows use the Slice. namespace, including operations on MutSlice. Owner parameters use &T or &mut T borrows; Slice<T> and MutSlice<T> view parameters are passed directly. Callback aliases, borrowed iterator types, and returned-reference lifetime descriptions remain proposed library contracts. Core access and error handling are explicit in each row.

Declared view parameters reborrow

The chosen parameter rule distinguishes a known borrowed parameter from an ordinary value parameter. A formal MutSlice<U> or &mut U parameter reborrows a compatible existing exclusive capability after type normalization; U may be generic. Shared references and read Slice descriptors keep their source lifetime and compatible read permissions. No exclusive capability becomes Copy.

Every MutSlice input in this Slice catalog is a borrowing input, including mutable algorithms and view, split, chunk and iterator constructors. Ordinary algorithms end their derived loan when their access is finished. A returned reference, read view, writable view or iterator retains the parent relationship, including when wrapped in Optional, Result or a tuple. Conflicting parent access stays suspended until all derived loans end, including any referent access during cleanup; the call returning is not sufficient.

Moving a descriptor by ordinary value assignment, initialization or return still transfers its capability. A generic T value parameter also moves a non-Copy descriptor, even if T is instantiated as MutSlice or an exclusive reference. Generic containers such as Optional.some and Result.ok use their value contracts. No current Slice row consumes the caller's original descriptor through a known MutSlice parameter. A future consuming API must state that different contract explicitly; this page introduces no force-move argument syntax. Reborrowing an existing writable view does not require a mut descriptor binding, while rebinding the descriptor does.

8. Type-First Examples

Assume values is an existing Array<i32, 4> owner. Each declaration is type first, and every executable statement ends with a semicolon. These read views must end before a conflicting owner mutation or move. 

Array<i32, 4> values = [1, 2, 3, 4];
Slice<i32> view = Slice.from_array(&values);
usize count = Slice.len(view);
Optional<&i32> first = Slice.first(view);
Result<Slice<i32>, BoundsError> middle = Slice.subslice(view, 1, 3);
Result<Vector<i32>, CollectionError> owned_copy = Slice.to_vector_copy(view);

Owned_copy’s Ok value has separate storage. View and middle remain borrows; copying their descriptors would not extend the owner’s lifetime or produce owned elements.

9. Parallelism, GPU Work & FFI

Read sharing requires T to support safe shared access. Disjoint write ranges can support parallel processing only with compatible element traits and callback captures. A split is an aliasing proof, not universal race-safety for arbitrary internal references.

A slice is not a device pointer. Borrowing CPU storage does not perform an upload, synchronize GPU work, or make that storage kernel-accessible. Explicit transfer and asynchronous lifetime rules belong to the execution and Tensor design.

Foreign borrowed buffers need a duration, initialized element count, alignment, access permission, and external-mutation contract. The owner must not free or reallocate during the borrow. Release callbacks belong to the owning adapter, not to an ordinary Slice destructor.

10. Text, Bytes & Related Collections

Slice<char> indexes Unicode scalar values. It is not a UTF-8 string_view, and a numeric or raw-byte slice is not validated text. See the lowercase string reference for encoding boundaries.

byte is distinct from u8; a slice cast must not silently substitute one element type for the other. Endianness, serialization, and FFI layout also need explicit conversion.

Use Array for common family rules, Static Array for fixed ownership, and Vector for dynamic ownership. The primary sources inform this proposal; no compiler, allocator, ABI, or device implementation is claimed.
