1. Overview

Design draft. These are proposed Aevix APIs, not claims that a compiler or standard library implements them. Parameter modes are chosen: T value, &T value, and &mut T value. Type-pack notation, callable types, explicit returned-reference lifetime spelling, and error enums remain descriptive where marked. Namespace functions are used throughout; there are no value-method aliases.

bool represents exactly false and true. It is the type of conditions and predicates. Integers, strings, pointers, and Optional values do not implicitly become conditions. A presence check uses Optional.is_some(value); integer truth conversion names its policy explicitly.

2. Declarations and literals

Declarations put the type first and are immutable by default. The tokens true and false have type bool independently of the default integer alias. A bool scalar is Copy; copying it does not allocate or share mutable state. 

bool ready = true;
bool blocked = false;
bool allowed = Boolean.and(ready, Boolean.not(blocked));

3. Eager calls and short circuiting

Ordinary function arguments are evaluated before a function call. Boolean.and(expensive_a(), expensive_b()) therefore evaluates both calls. The chosen language operators && and || take bool operands and evaluate the right operand only when required. The ternary condition ? a : b likewise evaluates only the selected branch. See Operators and Expressions.

Boolean.then accepts a callable and invokes it conditionally. Boolean.select receives two already constructed values. Neither name implies a hardware branch, constant-time execution, or a security timing guarantee.

4. Representation and valid values

The semantic domain has two values. This draft proposes one addressable byte for a stored standalone bool, subject to a target ABI definition; it does not promise the same layout for vectors, tensor masks, packed records, or foreign booleans. Arbitrary byte patterns cannot be reinterpreted as valid bool values in safe code.

A packed-bit container would be a separately specified representation with proxy and concurrency costs. Vector<bool> follows the ordinary contiguous-element model unless a distinct packed type is introduced.

5. Numeric and text conversion

There is no implicit bool-to-integer or integer-to-bool conversion. Boolean.from_integer validates an encoded logical value; Boolean.from_nonzero requests a different policy. The distinction prevents a corrupt flag value such as 2 from silently passing strict decoding.

Formatting uses lowercase ASCII and no locale. Parsing does not trim whitespace. Caller-controlled trimming must happen before parsing if the input format allows it. UTF-8 text and raw byte storage remain distinct.

6. Function reference

T value passes a value: Copy types are copied, and owning non-Copy values move without a deep clone. &T value is a shared read borrow; &mut T value is an exclusive modification borrow. Calls use x, &x, or &mut x respectively. Already borrowed references and view values are passed directly; adding another & changes the type. *ref accesses the referent. Ordinary &mut x requires a mut owner; mut T value alone makes a by-value parameter locally mutable and does not modify the caller. Overlapping active borrows are checked until last use; disjoint regions may be split safely and no borrow outlives its source. Synchronized interior mutation follows its own type contract. Fn(A) -> B describes a callable; returned-reference lifetime relationships remain documented in prose.

7. Errors and buffer atomicity

BooleanError is a proposed error enum covering InvalidRepresentation and InvalidText. BufferError includes required and available byte counts. The formatting buffer is unchanged when capacity validation fails; no partially encoded logical token is exposed as success.

The pure scalar operations cannot overflow. A callback failure is governed by that callback contract. No Boolean helper turns an allocation failure into false.

8. Parallel and device use

Immutable bool values can be copied into independent work. Concurrent writes to the same bool still require an exclusive borrow, a lock, or a supported Atomic<bool> operation. Copy does not make unsynchronized shared writes safe.

A CPU bool is not automatically a SIMD lane mask or GPU predicate register. Conversion to those representations is explicit in the corresponding APIs. Moving a bool value has no device-transfer semantics.

9. Foreign interfaces

C _Bool, C++ bool, Python bool, and foreign integer flags have different binding rules. A binding validates and converts values using the foreign ABI; a raw address does not establish the representation contract. Python object reference management belongs to the Python boundary, not Boolean scalar storage.

See byte storage rules and atomic capabilities before exposing mutable foreign flags.

10. Examples and boundary cases 

Result<bool, BooleanError> valid = Boolean.from_integer(1);
Result<bool, BooleanError> invalid = Boolean.from_integer(2);
Result<bool, BooleanError> token = Boolean.parse("true");
bool nonzero = Boolean.from_nonzero(-3);
i32 encoded = Boolean.to_integer<i32>(ready);

These examples distinguish strict validation from intentional nonzero conversion. A malformed input returns an error value; an already evaluated argument is never retroactively made lazy.
