1. Owned UTF-8 Text

Language design draft. Contracts, helper types, and function spellings below are proposals. They do not claim an implemented compiler, finalized grammar, or validated runtime. Examples use type-first declarations, default immutability, and semicolon-terminated statements.

Implemented 0.2 subset. The 0.2 profile lists byte_len, scalar_count, is_empty, view, as_bytes, equals, from_view, from_utf8, slice_bytes, append, push_char, and clear. Core fallible text operations return TextError. Other rows below, including owning-byte adoption and advanced algorithms, remain proposals. A text input s means a string_view or an explicit borrow of an owned string.

string owns a contiguous, well-formed UTF-8 buffer. Moving it transfers ownership; duplicating its contents uses an explicit fallible copy. Values are immutable by default. Mutable operations require an exclusive write borrow. Empty text is a valid value; absence uses Optional<string>. Embedded U+0000 is valid text and does not terminate the buffer.

A char is one Unicode scalar, not one display character. A byte is an opaque eight-bit storage unit, distinct from the numeric u8 type. UTF-8 text exposes read-only bytes without turning arbitrary byte offsets into text indices. Basic ownership follows the memory model; no automatic reference counting or copy-on-write is implied.

2. Ownership, Failure & Explicit Cost

s, needle, and other text inputs in the catalog accept a read borrow of an owner or string_view. A view retains the source lifetime; it cannot outlive an owner or survive a conflicting mutation. Returned search offsets refer to the unchanged source. Reallocation, removal, replacement, or mutation can invalidate saved positions even when their integer values remain in bounds.

dst denotes an exclusive mutable owner. Existing read views block writes to overlapping storage. Self-append and overlapping replacement require an explicit temporary copy unless a separately specified alias-safe operation is used. All mutators validate ranges and reserve required capacity before committing; a reported error leaves the original contents unchanged. This does not promise that capacities never change after a successful operation.

TextError, BoundaryError, PatternError, OwnedUtf8Error, FormatArgs, and Iterator<T> are proposed library support types, not new primitives. Errors cover invalid encoding, boundary or range errors, empty patterns where forbidden, capacity overflow, allocation failure, and formatting failure. Failed ownership-taking UTF-8 validation returns the rejected byte buffer inside OwnedUtf8Error. Every operation that may allocate returns a Result.

Costs are proposed upper-level behavior: n is source bytes, k output bytes, and p pattern size. “Scan” makes no universal linear-time search guarantee; callback and pattern-preparation costs are additional. Iterators borrow their source and any stored pattern. Clearing or shrinking text is not a secure memory erase.

3. Indices, Matching & Execution Targets

Ranges are half-open byte ranges. Safe byte slicing checks both bounds and UTF-8 scalar boundaries. Scalar ordinals require traversal; grapheme ordinals additionally require segmentation. There is no default s[i] operation returning a character. Byte inspection uses as_bytes; producing another text view requires validation. Adjusting a scalar boundary can still split a grapheme cluster.

Default equality and ordering compare UTF-8 bytes, with no normalization, locale tailoring, or case folding. A successful literal-text match returns scalar-aligned byte offsets. Empty needles are allowed for contains, find, and rfind: the first two match at zero and reverse search matches at byte length. Count, match iteration, replacement, and delimiter splitting reject empty patterns to keep progress explicit. Missing separators and empty fields have the per-function meanings below.

ASCII case and whitespace helpers are deliberately restricted. Unicode normalization, grapheme segmentation, locale casing, and collation belong to the optional Unicode module. Encoding import and export belong to Encoding. CPU library support does not imply native GPU support. AOT and JIT preserve validation and lifetime rules; device text operations require declared capabilities and explicit data transfers.

Comparison references include Rust UTF-8 views, Go text operations, and Java’s contrasting text API. Their indexing and allocation policies are not adopted automatically.

11. Explicit Owner Mutation

Mutators require a write borrow. Positions are checked UTF-8 byte offsets. No safe operation exposes unrestricted writable encoded bytes. Capacity-changing calls can invalidate addresses; all textual edits invalidate previously derived offsets unless a separate contract proves otherwise.

13. Examples & Design Boundaries 

string_view text = "café";
Result<string_view, TextError> word = string.slice_bytes(text, 0, 5);
Result<string_view, TextError> invalid = string.slice_bytes(text, 4, 5); // Err(TextError.InvalidBoundary);
bool same = string.equals(text, "café");

Future catalog examples. The search, repeat, and iterator calls below are proposed APIs, not part of the 0.2 implementation.

Optional<usize> hit = string.find(text, "fé"); // Byte offset 2;
Result<string, TextError> repeated = string.repeat(text, 2);
Result<Iterator<string_view>, PatternError> fields = string.split("a,,b", ",");

Under this draft, text literals borrow immutable static UTF-8 storage as string_view without allocation. Creating an owned string from literal text requires an explicit fallible owning constructor. This gives the draft one consistent allocation rule while the complete grammar remains under design. The language spelling and namespace are always lowercase string.

Planned 0.3 syntax: print/println output composition with + joins borrowed text and printable values without requiring an intermediate owned string. This applies to recognized output calls, not general string-valued expressions. Owned concatenation remains an explicit fallible operation; the catalog above does not by itself claim implementation. The raw string literal plan likewise produces a string_view, not an implicit string allocation.

Normalization does not happen during construction, comparison, or concatenation. C-compatible NUL termination is an explicit encoding operation. Regex engines, parsers, file paths, locale resource loading, and secure erasure are separate APIs; a general text escape cannot substitute for context-specific HTML, SQL, shell, or JSON handling.
