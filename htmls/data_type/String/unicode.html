1. Optional Unicode Text Services

Language design draft. Contracts, helper types, and function spellings below are proposals. They do not claim an implemented compiler, finalized grammar, or validated runtime. Examples use type-first declarations, default immutability, and semicolon-terminated statements.

unicode. is an optional library namespace operating on valid UTF-8 text. It adds normalization, grapheme segmentation, full casing, locale collation, and security analysis without changing the representation of string. Scalar property helpers remain in the char reference; this page describes algorithms over text sequences.

A UnicodeProfile identifies pinned algorithm and data versions. It is a proposed library descriptor, not a primitive or a promise to use the operating system’s current tables. Requested profiles must be available explicitly; silently substituting a different version would change observable results.

2. Normalization & Equality

NFC and NFD perform canonical normalization, while NFKC and NFKD additionally apply compatibility mappings. Compatibility normalization can remove meaningful distinctions and is never an implicit constructor or comparison step. Concatenating two normalized strings does not guarantee the concatenation remains normalized at their boundary.

Default string equality remains byte equality. Applications choose canonical comparison or normalize keys at a documented boundary. Case folding is a separate transformation and does not make arbitrary normalization steps interchangeable. UAX #15 defines the normalization algorithms and conformance expectations; Aevix still needs a tested implementation.

3. Scalars, Graphemes & Words

Extended grapheme clusters approximate user-perceived text units; they are not guaranteed glyph counts, terminal-cell widths, or application cursor positions. Segmentation returns source-relative byte ranges that remain valid UTF-8. Word and sentence boundaries use named profiles and optional tailoring rather than an English-only split on spaces.

Combining sequences and emoji may require looking beyond a single scalar. Random grapheme access therefore requires traversal or an explicit index structure. A streaming segmenter may need deferred context; a fixed small look-behind is not promised for arbitrary Unicode input. The comparison algorithm is specified by UAX #29.

6. Locale, Collation & Security

Full case mapping can change the number of scalars and bytes. Locale-specific dotted-I behavior illustrates why ASCII folding, default Unicode folding, and locale casing are different APIs. Unicode White_Space also differs from ASCII whitespace; zero-width format characters are not automatically removed. ICU case mapping documents these distinctions.

Collation uses an explicit locale, options, and data profile. Sort keys are comparable only under the same collator configuration and version; storing them requires that metadata. Confusable detection is an optional review signal, not proof that two identifiers belong to the same person or that text is safe. Normalization alone cannot prevent spoofing.

8. Examples, Versions & Execution Targets 

string_view decomposed = "e\u{0301}";
Result<string, UnicodeError> composed = unicode.nfc(decomposed, profile);
usize groups = unicode.grapheme_count(decomposed, profile); // One extended grapheme cluster;
Result<bool, UnicodeError> same = unicode.canonical_equal("é", decomposed, profile);

The profile variable represents an already selected immutable library resource. Unicode escape notation is illustrative pending final literal grammar. Allocation failure, unavailable data versions, invalid options, and resource limits are recoverable errors. The infallible iterators cover only default rules supported without fallible workspace allocation after profile setup. Dictionary-based or tailored segmentation requires a separate fallible setup API; it is not silently substituted.

CPU Unicode support is not native GPU support. Device algorithms require explicitly transferred tables, supported operations, and equivalent versioned semantics. Regression checks must include normalization and segmentation conformance data for the pinned version, lifetime cases, expansion limits, and locale-specific examples. A published source reference does not establish Aevix conformance.
