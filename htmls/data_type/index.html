Chosen language rules

Chosen declaration rules. Type first: i32 size = 128;. Immutable by default; write mut i32 count = 0; for a mutable binding. rsn requests static inference, as in rsn size = 128;. The inferred type is fixed. Unconstrained integer and real literals default to i32 and f64. const i32 LIMIT = 100; declares an immutable compile-time constant; const rsn SCALE = 2.0; infers its fixed type. Combining const and mut is invalid. An ordinary immutable binding may initialize at runtime. The chosen persist keyword denotes per-declaration process-lifetime storage; module-level values initialize before entry, local values initialize on first reach, and generic local storage is distinct per concrete type-argument combination. AOT and JIT code versions for the same declaration and concrete arguments share that storage. At normal shutdown, tracked resource uses finish before successfully initialized values are cleaned in reverse initialization-completion order; cleanup may not access another persist. See storage identity, initialization, and normal shutdown for the chosen rules. Thread-local storage, generic type-member persist and custom cleanup syntax remain separate open topics. It does not mean disk persistence or a static type member.

Chosen default prelude. Selected integer and floating-point scalar types and their int/float aliases, bool, char, byte, unit, and never are automatically available; void remains a return-position marker. The default prelude also provides string, string_view, Array, Vector, Slice, MutSlice, Tuple, Range, Optional, and Result. Automatic availability does not make every one of these a compiler primitive. Other library types require explicit imports, such as import tensor { Tensor };; catalog membership alone does not grant access. See the chosen prelude and import boundary.

Chosen parameter rules. T value passes by value: Copy types are copied and owning non-Copy values move, with no implicit deep clone. &T value is a shared read borrow; &mut T value is an exclusive modification borrow. Calls explicitly pass x, &x, or &mut x; an already borrowed reference or a view value such as Slice<T>, MutSlice<T>, or string_view is passed directly without another &. *ref accesses the referent. Ordinary mutable borrowing requires a mut owner. A mut T value parameter only makes its local by-value binding mutable; &mut T value permits changing the caller’s original. Active borrow conflicts are checked by overlapping memory region until last use, allowing proven disjoint regions; no borrow outlives its source. Synchronized interior mutation follows its own type contract. Explicit returned-reference lifetime annotations remain under review.

Chosen return rules. Ordinary returns from a non-void function explicitly return a value. A Result-returning function may additionally use postfix ? to explicitly propagate an Err with the same error type. Successful returns still use return; no final expression is an implicit return. A unit-returning function explicitly returns its unit value. Return-position void permits fallthrough or a bare return; diverging paths do not need impossible returns.

Cost and safety. Owning containers move by default. Cloning, allocation, device transfers, and asynchronous completion are explicit. Borrowed views require their owners to remain valid for all uses, and mutable views require exclusive access. Ordinary integer operator failures stop execution safely; checked(expression) and the named checked APIs return explicit Result values. See Checked Arithmetic. Draft labels apply to proposed catalog signatures and genuinely unselected topics, not to this chosen failure policy.

Chosen control and scope rules. if and while require parenthesized bool conditions; a single executable body statement may omit braces, while a declaration body requires an explicit block. An else attaches to the nearest unmatched if. See statement-body parsing. Three for forms support Range values, C-style control, and enhanced iteration. Switch cases require explicit terminating break;. Local variables have lexical scope and may not shadow visible variables. Module/type declarations support public/private, and normal scope exits clean up initialized current owners in reverse order. Full rules, documentation tags and open boundaries are in the Grammar reference.

Chosen user-defined type rules. Structs use access-checked named-field initialization, private fields by default, typed self methods, and explicit type factories. Structs and enums move by default and may explicitly implement Copy when all fields qualify. Enum variant names are public by default and payload fields private by default. Interfaces support multiple implementations, default methods, required override for replaced defaults, and static dispatch with explicit dyn views or Box<dyn Interface> ownership. Generic types use <T> and where T implements Copy; a parameter constraint does not automatically mark its container Copy. Every case/default has an independent scope, and enum switch must cover every variant or provide default.
