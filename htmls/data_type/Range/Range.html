1. Overview

Design draft. These are proposed Aevix APIs, not claims that a compiler or standard library implements them. Parameter modes are chosen: T value, &T value, and &mut T value. Type-pack notation, callable types, explicit returned-reference lifetime spelling, and error enums remain descriptive where marked. Namespace functions are used throughout; there are no value-method aliases.

Range is a non-owning value descriptor, not an allocated container or a borrow of a collection. The chosen range literal 0..10 creates the descriptor represented by Range.new(0, 10), while 0..=10 corresponds to Range.closed(0, 10). Both literals and existing Range values are accepted by the range-form for; see Loops. This first design supports integer primitives and target-sized integers. Floating-point ranges, Unicode traversal, unbounded endpoints, and arbitrary user-defined stepping require separate contracts.

2. Bounds and declarations

Range.new(start, end) includes start and excludes end. The closed constructor allows a reachable end value. Descending constructors express direction independently of signedness, so unsigned countdowns do not require a negative unsigned integer. 

Range<i32> indices = Range.new(0, 5);
Range<i32> closed = Range.closed(0, 5);
u8 countdown_start = 3;
u8 countdown_end = 0;
Range<u8> countdown = Range.descending_closed(countdown_start, countdown_end);

3. Stepping and exact membership

Every step magnitude is a same-width unsigned U corresponding to T and must be positive. Starting at 0 with end 6 inclusive and magnitude 4 yields 0 and 4; 6 is eligible as an inclusive bound but is not reachable. Contains checks the stride as well as the bounds.

A directionally reversed start/end pair is empty, not automatically normalized. Stepping past the last eligible value terminates using checked comparisons; the iterator never performs an overflowing increment to discover that it is done.

4. Cardinality and target bounds

A representable pair of endpoints can describe more values than usize can count. The full inclusive u64 domain has 2^64 values, so even a 64-bit usize cannot represent its length. Range.len returns CountOverflow in that case; the descriptor and an independently advancing iterator remain meaningful.

Arithmetic computes mathematical distances using checked or sufficiently wide intermediates, including signed minimum-to-maximum spans. It must not first subtract endpoints in T and overflow. Collection creation additionally validates byte size, address-space and allocator limits.

5. Value semantics and iterator state

An integer range descriptor is a Copy value with no owned allocation. Creating an iterator creates separate cursor state; consuming one iterator does not secretly mutate another copy of the descriptor. Range.end describes a bound, while Range.last describes the final actual element.

Take, skip, split and reverse may normalize endpoint spelling while preserving their documented sequence. Range.equal compares descriptor fields. Range.sequence_equal handles empty and singleton cases by sequence meaning rather than by spelling.

6. Function reference

T value passes a value: Copy types are copied, and owning non-Copy values move without a deep clone. &T value is a shared read borrow; &mut T value is an exclusive modification borrow. Calls use x, &x, or &mut x respectively. Already borrowed references and view values are passed directly; adding another & changes the type. *ref accesses the referent. Ordinary &mut x requires a mut owner; mut T value alone makes a by-value parameter locally mutable and does not modify the caller. Overlapping active borrows are checked until last use; disjoint regions may be split safely and no borrow outlives its source. Synchronized interior mutation follows its own type contract. Fn(A) -> B describes a callable; returned-reference lifetime relationships remain documented in prose.

U means the unsigned integer of the same bit width as T. RangeDirection, RangeError, and RangeIterator<T> are proposed library support types, not additional primitive numeric types.

7. Ranges and collection indexing

A numeric Range is not permission to access an owner. Collection slicing validates its own bounds against the current length and creates a lifetime-checked Slice or MutSlice. A stride greater than one is not a contiguous Slice; use an iterator or an explicitly strided view instead.

Indexes count elements, not bytes or Unicode grapheme clusters. A Range of usize can describe collection positions, but a range of i32 is not implicitly converted to it. Negative or overflowing conversions fail explicitly.

8. Error values and materialization

RangeError covers InvalidStep, StepOverflow, CountOverflow, OutOfBounds and LengthMismatch. Infallible descriptor construction accepts reversed bounds as an empty sequence. Materialization uses CollectionError to preserve size and allocation failures.

Error returns do not leave a partially initialized Array or Vector visible. If construction has initialized a prefix before an unrelated element-generation failure in a future extension, that prefix must be destroyed safely. The current integer sequence itself has no fallible element callback.

9. Parallel partitioning and devices

Finite integer descriptors can be copied into CPU or supported GPU work, but collecting them on a host does not place data on a GPU. Parallel partitioning must partition ordinals without overlaps or gaps and check arithmetic at boundaries.

A range describing disjoint indexes does not alone prove disjoint memory borrows. The borrow-producing collection API validates and records the actual regions. Reduction order, integer overflow and reproducibility follow the operation contract.

10. Examples and boundary cases 

Result<Range<i32>, RangeError> strided = Range.with_step(Range.closed(0, 6), 4);
u64 smallest = 0;
u64 largest = 18446744073709551615;
Range<u64> full = Range.closed(smallest, largest);
Result<usize, RangeError> too_many = Range.len(&full);
Optional<u8> last = Range.last(&countdown);
Result<Vector<i32>, CollectionError> values = Range.collect_vector(indices);

The full-domain count fails because the count exceeds target usize on supported 32- and 64-bit targets. The descending unsigned range ends at zero without wrapping to 255. Type-first declarations give each large literal an explicit integer context.
