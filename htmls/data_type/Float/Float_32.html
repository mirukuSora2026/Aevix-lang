1. Basic Information

0.2 implementation scope. The automatically available formats are f16, bf16, f32 and f64; float aliases f64. Numeric suffixes, scalar arithmetic and comparisons are implemented. The implemented namespace calls are Float.convert<D>(value), Float.convert_exact<D>(value) and Float.to_integer_exact<I>(value). The first two accept an integer or float and require a floating destination; the last accepts a float and requires an integer destination. They return Result with FloatError and take no rounding-mode argument. Classification, bit/byte codecs and the math-function catalog below are not implemented 0.2 APIs. See the 0.2 implementation profile; other catalog entries remain design contracts.

f32 is a 32-bit binary floating-point value with 24 bits of normal significand precision. This type is selected explicitly or inferred from a typed context; the default float alias remains f64.

2. Bit Representation

The high bit stores the sign, followed by 8 exponent bits and 23 fraction bits. A normal value is (−1)sign × (1 + fraction / 223) × 2exponent − 127. Zero/subnormal encodings use a zero exponent; an all-one exponent represents infinity or NaN.

Use Float.to_bits and Float.from_bits for representation access. NaN payload preservation is a storage/bit-conversion contract, not a guarantee for the results of arithmetic.

3. Literals & Type Inference

A literal in a f32 context is rounded directly to that target format. An untyped decimal real literal defaults to f64. A previously typed value is not implicitly converted. Constant parsing must avoid an unintended intermediate rounding through another format. 

f32 value = 1.5;
// Declaration syntax is illustrative.
Float.to_bits(value);
Float.is_finite(value);

Decimal fractions such as 0.1 generally have no exact finite binary representation. The literal is a correctly rounded value, not an exact decimal rational. Values outside the finite range require an explicitly documented conversion or literal diagnostic policy.

4. Precision & Rounding Boundaries

Normal values have 24 significant binary digits. The spacing changes with magnitude; epsilon is the gap immediately above 1 and is not a universal comparison tolerance. 

// Round-to-nearest, ties-to-even at a precision boundary.
f32 a = 16777216;
a + 1;   // rounds back to 16777216

Float.next_up(a); // adjacent representable value

Every integer with magnitude at most 16777216 is exact. Beyond that boundary, some integers remain exact and others do not. Choose exact conversion when preserving an integer value matters. Default scalar rounding is round-to-nearest, ties-to-even; other policies require explicit API selection.

5. Zero, Infinity, NaN & Subnormals

Positive and negative zero compare numerically equal but have different sign bits. NaN is unordered in ordinary comparisons, including equality with itself. Infinity is a distinct numeric value, not the largest finite value.

Subnormal values fill the interval between zero and the smallest normal magnitude. The strict execution profile preserves these values. A target that flushes them to zero must expose that behavior as a separate opt-in capability, not silently change the document contract.

Use classification functions before applying application-specific finite-value constraints. Checked arithmetic is an explicit alternative when division by zero, invalid domains, or non-finite results must become Result errors.

6. Type Conversion

Float.convert_exact reports whether the mathematical value is representable in the destination format. Float.convert uses an explicit rounding policy and may lose precision. Narrowing does not silently become a bitcast.

Float.to_integer_exact<I>(value) requires a finite integral input in the destination integer range. A fractional value returns FloatError.NonExact; NaN/infinity return NonFinite, and a range failure returns OutOfRange. Rounded integer conversion is a separate proposed API.

NaN payloads and signed zero need a separate representation-preservation policy when converting between formats.

7. Arithmetic & Common Function Bindings

Arithmetic returns f32 under the common Float contract. A smaller storage type does not imply that transcendental operations have native hardware instructions. Backend promotion/emulation must preserve the requested rounding points and expose its cost.

8. Comparison & Adjacent Values

Ordinary comparison follows numerical ordering with NaN unordered. Float.total_compare provides the explicit total-order path for sorting raw floating-point values, including signed zero and NaN encodings.

Approximate comparison must specify absolute/relative tolerances or an explicit ULP policy. Never use this format’s epsilon as a universal tolerance. next_up, next_down, and next_after navigate the format’s representable grid and follow the special-value rules in Float.

9. string & Byte Representation

Raw serialization uses byte, the opaque octet type documented in Byte, rather than the numeric integer u8. There is no implicit conversion between them: use Byte.from_u8 or Byte.to_u8 explicitly for each octet when a numeric value is needed. Numeric bit-word APIs retain their documented unsigned integer types.

The raw storage is 4 bytes. Explicit little-endian and big-endian conversion produces Array<byte, 4>; byte order does not change the floating-point format. Dynamic buffer reads and writes validate the whole range.

A shortest round-trip formatter emits decimal text that parses back to the same finite value under the documented parser. NaN text does not preserve an arbitrary payload. Exact payload transport uses bit or byte APIs. 

f32 value = 1.5;
Array<byte, 4> bytes = Float.to_be_bytes(value);
f32 decoded = Float.from_be_bytes(f32, bytes);
Float.parse(f32, "1.5");
Float.format_into(value, buffer, options);

Formatting into an existing buffer avoids a new output allocation. A string-producing formatter has an explicit allocation-failure path.

10. Arrays, Tensors & Execution Targets

Array<f32, N>, Vector<f32>, and Tensor<f32, Shape, Place> store values of this format. Value copying requires no per-scalar heap allocation; owning collections follow their own move/copy rules.

Storage, arithmetic, conversion, special-function, and atomic support are checked separately for each target. Strict AOT and JIT execution use the same format meaning. FMA contraction, fast-math reassociation, and subnormal flushing require explicit policy.

A reduction’s accumulator format and evaluation order must be visible. Wider accumulation is a distinct choice and can produce different results from repeated rounding in the storage format. FFI must verify the external format and ABI rather than matching type names alone.

11. Float32-Specific Functions

No separate format-only function namespace is defined. All common operations remain under Float.; the format-specific metadata and conversion conditions above specialize that common contract.

See the complete Float function catalog for signatures, result types, numerical domains, and target availability. This specification is a design draft, not a claim that the compiler or math runtime already implements the catalog.
