1. A Safe Box Is Not a Foreign Pointer Contract

An address alone does not establish a Box owner. Foreign memory may use a different allocator, representation, alignment, or destruction protocol. The safe Box constructors do not silently adopt arbitrary addresses or pretend that a C allocation contains a valid T. Any future adoption interface is a separately marked unsafe or audited FFI facility with a documented proof obligation.

2. Size, Alignment, and Valid Values

The adapter must establish target size, required alignment, initialized bytes, valid discriminants, and any nested ownership or reference invariants. Equal byte width is insufficient for compatibility. A byte buffer can carry raw representations without containing valid values of an arbitrary T. Native field layout and padding are not portable wire formats. Use explicit Byte codecs when serializing values.

3. Matching Allocation and Deallocation

Allocation and release must agree on allocator identity, exact allocation base, layout, and ownership count. Adopting an interior pointer or freeing the same allocation twice violates the adapter contract. A foreign release callback may have thread-affinity or runtime requirements that a generic Box destructor cannot infer. Moving a handle across threads is permitted only when the complete resource contract supports it.

4. Foreign Borrows Need a Duration

A borrowed export does not transfer ownership. The foreign side must stop reading or writing before the borrow ends, and the owner must remain alive and unmodified as required. A read export forbids external mutation during the borrow; a writable export excludes every conflicting alias. If a foreign callback stores an address for later, a synchronous call boundary is not a sufficient lifetime proof.

5. Asynchronous Retention and Completion

For delayed foreign work, either move the actual owner into a completion-managed adapter or use a structured scope that tracks completion independently of an optional user handle. Cancelling a request does not prove the foreign operation has stopped. Dropping or leaking a notification token cannot permit early release of borrowed memory. Device completion and host visibility may also require different synchronization steps.

6. Failure and Partial Adoption

Preflight failure leaves the original owner with its caller. Once an external library takes ownership, an adapter must state whether errors return that owner, destroy it, or transfer it to another resource record. Avoid APIs that can both run a foreign release callback and then return an allegedly intact Box. Errors and unwinding must preserve a single, unambiguous owner for every initialized resource.

7. Excluded Shortcuts and Related References

This page deliberately defines no safe from_raw or arbitrary set-initialized-length shortcut. The common Box API remains safe by construction. Shared thread bounds and Slice describe related restrictions. A documented FFI contract identifies what must be audited; neither a successful build nor a pointer-sized wrapper verifies the external implementation.

Native allocation and size metadata do not transfer this owner to a foreign allocator or define a wire representation. 

Result<Box<i32>, InputError<i32>> native_owner = Box.new(42);
usize payload_bytes = Box.payload_size(i32);
