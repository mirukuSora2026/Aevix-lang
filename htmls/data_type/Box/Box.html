1. Unique Initialized Heap Ownership

Box<T> uniquely owns one initialized T and its associated allocation. Moving a box transfers that ownership; it does not clone T or turn the allocation into shared storage. Ordinary destruction runs T’s finalization and releases matching storage. The allocation can be absent for zero-sized payloads while logical ownership and destructor obligations remain real. A box is not a raw address and does not make a self-referential value automatically pinned.

Design draft. Functions, traits, error carriers, and callback notation specify intended contracts, not implemented APIs. Variables and parameters are type first; bindings are immutable by default. Parameters use T value by value, &T value for a shared borrow, and &mut T value for an exclusive borrow. Calls pass owners as x, &x, or &mut x; taking &mut owner requires a mut binding. Existing references and borrowed views are passed directly. Callback aliases, error records, and returned-reference lifetime notation remain design descriptions. unit is a value type, distinct from return-position void.

2. Fallible Construction and Recovery

Allocation checks native layout, alignment, and target object bounds before value installation. A constructor consuming T returns the unused input on a returned preflight failure. Builder forms reserve first and call the builder exactly once; if a fallible builder fails, only initialized output is finalized. This is not a promise to reverse external callback effects or recover from process termination. Constructors do not expose uninitialized memory as a safe T value.

3. Borrows and Movement

Read access can coexist with other reads; writing requires one exclusive capability. A borrow is tied to both owner lifetime and the relevant initialized value. Moving the box handle does not move its heap payload physically, but the language still rejects owner operations that conflict with live borrows. Replacing or extracting T can move that value. Use a separately specified pinning abstraction when code relies on stronger address-stability guarantees.

Chosen dynamic-interface integration. Box<dyn Interface> owns its concrete payload and supports explicit Box.into_dyn conversion. Calls to eligible borrowed-self methods may use owner.method(...) with automatic payload access and borrowing; Box.as_ref(&owner) and Box.as_mut(&mut owner) expose explicit views. Ownership and exclusive access remain checked. Value-self extraction, name collisions and dynamic payload extraction through Box.into_inner remain open. The Box.new allocation result must still be handled explicitly.

4. Copy, Clone, and Mapping

Copy and Clone describe the pointee operation, not implicit box duplication. Both explicit duplication calls allocate separate unique storage. A cloned T may itself contain a Shared handle, so cloning does not imply deep isolation. Mapping must preallocate before consuming a recoverable source when it promises an owner-returning allocation error. A callback that consumes T and then fails has a different error carrier and cannot honestly promise the original T back.

5. Destruction, Resources, and Threads

A normal owning drop destroys initialized payload exactly once, subject to the runtime’s termination policy. This is not absolute leak prevention: intentionally unreachable ownership, process exit, or a leaked surrounding graph can prevent resource cleanup. Transfer to another host thread requires T: Send; shared read references require T: Sync. These names describe safety traits, not a guarantee that arbitrary foreign resources are thread-compatible. GPU access needs separate placement and completion contracts.

6. Complete Proposed Box API

All fallible allocation paths below return explicit errors. InputError and OwnerError retain moved inputs on the documented preflight failures. By-value owning arguments move, Copy arguments copy, and reference arguments borrow; returned references remain bounded by their source loans. Complexity includes T-sized moves, Clone, Drop, comparison, and callbacks rather than treating every pointee operation as one instruction.

7. Arrays and Foreign Interfaces

A box containing an Array owns that array’s inline elements; a box containing a Vector owns its vector handle, whose buffer follows Vector rules. A box containing Slice merely owns a borrowed descriptor and does not acquire its referent. See Boxed Arrays and Views. Foreign adoption and release require allocator, lifetime, and finalization contracts; Box and FFI explicitly keeps unchecked adoption outside safe constructors.

The result’s Ok branch owns the new box; its Err branch owns the rejected input. For chosen borrowing, ownership and enum branch syntax, see the grammar reference. Other function-specific API syntax remains draft. See Shared for refcounted ownership and Vector for growable storage. The primary reference informs this independent proposal; no allocator implementation or physical ABI is claimed.
