1. An axis selects the scale entry

A per-axis scheme associates every integer tensor element with a scale and zero point selected by one logical coordinate. For tensor shape [D0,...,Dr-1] and axis a, both metadata arrays have length Da. Every scale is finite and positive; every zero point is representable in the storage type. Rank-zero payloads cannot carry a per-axis scheme because they have no axis.

A zero selected extent permits empty metadata arrays. Such a tensor has no elements that need a scale entry, but axis validity and the rest of its shape still require validation. Calibration on empty channels reports an explicit missing-data error instead of manufacturing a scale. Fixed-rank static constraints can reject known metadata mismatches during compilation; runtime metadata lengths remain checked.

2. One metadata owner, many element codes

The scheme owns its scale and zero-point arrays or is an explicitly named borrowed SchemeView tied to their owner. A quantized tensor does not repeat those arrays in every element. Cloning the full value deep-copies payload and owned metadata; making a view only borrows them. Queued device work retains both leases until quiescence, including after handle abandonment.

Metadata is immutable while values use it. A mutable slice to scales cannot coexist with a quantized read view or an in-flight kernel that interprets those scales. Constructing a new scheme validates it independently. Shared metadata requires a real Shared owner with the same ownership rules as any other allocation; a copied pointer is not ownership.

3. Axis-aware shape transformations

Transposing tensor axes changes the scheme axis to its new logical position. Slicing along that axis slices metadata with the same start, length and step; slicing another axis keeps the metadata coordinate unchanged. A reshape is valid without numeric conversion only when it preserves a provable mapping from every new logical element to the same channel parameter. Equal element count alone is insufficient.

Broadcasting the quantized axis requires special care: a singleton channel may repeat the same metadata logically, but an arbitrary new channel size cannot gain new independent scales. Concatenating along the quantized axis concatenates metadata in the same order as codes. Concatenating another axis requires identical parameter meaning or explicit requantization first.

4. Kernel and contraction constraints

A per-axis matmul backend may support only selected axis positions and operand roles. The adapter checks this capability before submission; it does not silently collapse channel scales into one scalar. The dot/matmul contract names accumulator precision and how scale products apply to contraction and output axes. A scale varying along the contracted dimension generally cannot be factored out as one multiplier.

Raw code sums require corresponding zero-point and scale accounting. A backend using a narrower accumulator or another saturation rule must be selected through an explicit alternative profile. Portable semantics do not guarantee a native per-channel instruction sequence. Error reports distinguish a mathematically valid scheme from a backend-unsupported layout.

5. Foreign descriptors and packed data

Interchange records include rank, selected logical axis, metadata lengths, scale type, integer signedness and ownership. Negative-axis conventions are normalized by the adapter using checked arithmetic and the external schema version. Packed 4-bit or 2-bit payloads require an explicit bit order, padding policy and logical element count; they are optional encodings, not standard Array<i8> memory.

Exporting raw bytes alone loses quantization meaning. Native object layout, pointer width and metadata structure are not stable serialization. Imported buffers must prove allocation span, alignment and lifetime, or be explicitly copied into owned storage. Device-only metadata cannot be read on the host through a descriptor without an explicit transfer.

6. Per-axis metadata construction 

Vector<f32> scales = prepared_scales;
Vector<i8> zeros = prepared_zero_points;
Result<PerAxis<i8, f32>, QuantizationInputError<(Vector<f32>, Vector<i8>)>> channels = Quantized.per_axis<i8, f32>(1, scales, zeros, tensor_shape);

The input vectors move into the validated scheme on success; the proposed error payload retains them when ownership was accepted before validation failed. Their lengths must equal dimension 1. A successful scheme does not copy or move the tensor element buffer.

8. Interchange boundary

These are proposed library contracts. The source operators inform comparison and interchange; they do not define Aevix behavior automatically. An adapter must test ties, negative values, saturation, zero points and scale precision against the exact external schema version. The common Quantized reference owns the rounding order and nonfinite-input policy.
