1. One meaning for every code

An affine scheme stores a positive finite scale s and integer zero point z. Integer code q reconstructs as (q-z)*s in the selected computation type. A per-tensor scheme applies the same mapping to every element, so an owning tensor stores the scheme once. Affine<I, F> is a proposed library record; I fixes code range and F fixes scale/division precision, without changing the primitive integer type itself.

The code z reconstructs exact real zero before any floating multiplication. Other values generally form a finite grid in mathematical real arithmetic. Floating reconstruction can round or overflow, so the mathematical grid and an F-valued dequantized tensor are distinct. Re-encoding a reconstructed value need not preserve a code after scale conversion or computation-type changes.

2. The rounding operation has a location

The proposed pipeline divides x by s in F, rounds that ratio according to the named mode, adds z in an exact integer domain, then checks or saturates to I. TiesEven chooses the even integer for a halfway ratio; TiesAway chooses the integer farther from zero; TowardZero truncates; Floor and Ceil follow mathematical direction. No rounding mode depends on the ambient host floating environment.

An odd zero point can expose the difference between rounding before and after translation. For ratio 0.5 and z=1, TiesEven produces code 1 here. This order is part of serialized scheme-operation metadata and compiled kernel identity. A kernel that uses another ordering requires an explicit conversion profile rather than silently substituting results.

3. Checking and saturation

Checked conversion fails whenever the rounded translated code is outside I. Saturating conversion clamps to I endpoints. Both reject NaN and infinite input by default. A finite ratio computation that overflows F can be clamped in the saturating path by sign, but must not invoke an undefined conversion to an implementation integer. The metadata remains valid even if the full reconstructed endpoint range exceeds F; checked endpoint queries report that limitation.

Saturation changes value and is never an overflow exception substitute for unrelated arithmetic. A report can count clamped elements when the operation requests it. It cannot recover that count from an arbitrary raw payload later: a code at the minimum may be a natural endpoint or the result of saturation.

4. Calibration is a separate lossy policy

Min/max calibration observes finite nonempty samples and derives a candidate scale and zero point under an explicit range-coverage policy. A constant-valued sample set has zero observed range and needs a named minimum-scale policy or an error. The library never inserts a hidden arbitrary epsilon. Symmetric calibration uses signed codes and zero point zero; its asymmetric endpoint range must still be considered when choosing scale.

Calibration data is an input, not a retained hidden owner. Computing statistics may require a floating accumulator and a specific traversal order. Percentile or histogram calibration belongs to an optional library because its accuracy and memory costs differ from simple min/max. Calibration on Cpu and device work share policies but require explicit execution placement.

5. Metadata replacement and raw payloads

A scalar Affine record can be copied without heap allocation. A quantized owner with a tensor payload still moves its storage. Returning raw_view borrows codes read-only; it does not expose mutable metadata or authorize an untracked foreign pointer. into_raw consumes the wrapper and discards numerical interpretation only after all loans and queued leases permit ownership transfer.

reinterpret_scheme deliberately changes the meaning of unchanged codes. requantize attempts to preserve reconstructed meaning through a named lossy conversion. Keeping these operations separate prevents an inexpensive metadata update from masquerading as a numeric conversion. Failed consuming conversions retain their original owner inside the error payload.

6. A rounding-sensitive example 

Result<Affine<u8, f32>, QuantizationError> parameters = Quantized.affine<u8, f32>(2.0, 1);
// After validating parameters as scheme_value: ratio 1.0 / 2.0 is 0.5.
Result<Quantized<u8, Affine<u8, f32>>, QuantizationError> encoded = Quantized.quantize_checked<u8, f32>(1.0, scheme_value, RoundingMode.TiesEven);

The successful code is 1 under this draft contract, and its reconstructed value is 0.0. The example illustrates intentional precision loss. It does not unwrap Result or assume a final match syntax.

8. Interchange boundary

These are proposed library contracts. The source operators inform comparison and interchange; they do not define Aevix behavior automatically. An adapter must test ties, negative values, saturation, zero points and scale precision against the exact external schema version. The common Quantized reference owns the rounding order and nonfinite-input policy.
