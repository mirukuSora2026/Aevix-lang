1. Integer payload with validated numeric meaning

Quantized<Storage, Scheme> is a proposed library value pairing an integer payload with immutable quantization metadata. Storage can be one integer or an owning Tensor of integers. Scheme describes how integer codes correspond to real values. Metadata is attached once to the payload owner, not duplicated beside every tensor element. Copy and move behavior follows both payload and metadata ownership; a tensor payload is not implicitly deep-copied.

The initial affine profile proposes i8, u8, i16 and u16 integer storage with f32 or f64 scales. Wider accumulators, packed low-bit formats and backend extensions require explicit capabilities. FP8 formats remain floating-point formats with their own exponent and NaN rules; they are not aliases for scaled integers. The generic parameter spelling and support records are draft library design, not implemented ABI.

2. Schemes, records and errors

Affine<I, F> stores one validated positive scale of F and a zero point representable in I. PerAxis<I, F> stores an axis plus owned scale and zero-point arrays. I is an integer storage type and F is a floating computation type. In signatures Q is a catalog variable for an already shared-borrowed quantized input: &Quantized<Storage, Scheme> or QuantizedView. R denotes the corresponding real scalar or real tensor view/input, S is the raw payload type, and I/F retain these meanings. An owning quantized input uses &owner at the call; an existing QuantizedView is passed directly. Tensor outputs preserve logical shape and use explicit placement rules from Tensor.

QuantizationError is a proposed tagged error record with InvalidScale, InvalidZeroPoint, NonFiniteInput, Range, Axis, MetadataLength, Shape, Overflow, Allocation, Unsupported and InvalidEncoding cases. ConversionError<Owner> preserves a consumed owner on failed representation conversion. RoundingMode, QuantizationPolicy, PackedFormat and QuantizationReport are proposed library records. Methods named _into reuse caller storage and validate all metadata and prohibited aliasing before writes; late arithmetic/device failure is not rollback.

QuantizationInputError<Input> is a proposed validation error carrying consumed input owners. It is used when the contract promises that rejected metadata arrays remain recoverable. QuantizationError alone carries no implicit type-erased owner.

QuantizedView, SchemeView, ShapeLike, real tensor input views and MutRawView/MutRealView are already borrowed descriptors; no extra & is added when passing those values. A real scalar input is Copy. Concrete owning parameters passed by value move their owners, including metadata vectors. Parameter forms are settled; the exact syntax for naming returned-reference lifetimes is still conceptual.

3. A precise order for affine rounding

For a finite real input x, scale s and integer zero point z, the proposed integer formula is q = clamp_I(round_mode(x / s) + z). The division is evaluated in explicitly selected computation type F; rounding applies to that ratio before exact integer-domain zero-point addition. The default named mode is TiesEven. The checked variant errors when the rounded code plus z is outside I; the saturating variant clamps to the integer endpoints. Integer-domain intermediates must not overflow an implementation integer.

Rounding the ratio and then adding an odd zero point is not interchangeable with rounding the shifted ratio. With x/s = 0.5 and z = 1, this contract gives 1 under TiesEven, whereas rounding 1.5 gives 2. Import/export adapters must verify the selected external operator version and its reference behavior rather than assume every quantization convention is equivalent.

4. Reconstruction and finite-value policy

Real reconstruction is (q - z) * s. The code subtraction is performed exactly before conversion to the declared floating computation type; subtracting in i8 or u8 and wrapping is forbidden. Dequantization returns the floating result under the strict scalar profile, which may overflow to infinity if the selected output type cannot represent the reconstructed value. checked_dequantize instead requires a finite result and reports Range.

Default quantization rejects NaN and both infinities. For a finite x whose computed ratio overflows F, saturating conversion maps the sign to the appropriate integer endpoint; checked conversion reports Range. A ratio rounded to a finite integer is translated in an exact integer domain and then range-checked. No success path relies on undefined float-to-integer conversion. Changing F or rounding mode can change codes and must be explicit.

5. Scale, zero point and per-axis ownership

Each scale must be finite and strictly greater than zero; negative zero, positive zero, NaN and infinity are invalid. Every zero point lies in the storage type range. Per-axis arrays have identical length equal to the selected tensor extent. Axis validation is rank-aware and does not silently normalize a negative axis. Empty selected axes allow empty metadata arrays; no element accesses them. Calibration of an empty sample set still errors.

Validated metadata is immutable while associated payload views or queued operations use it. A metadata update constructs a new validated scheme and explicitly requantizes values, or reinterprets numeric meaning through a separately named operation. Exported ABI descriptors retain metadata ownership or a scoped borrow. Device submission retains both payload and metadata leases until quiescence, without an implicit CPU copy of the payload.

6. Quantized arithmetic is not raw byte arithmetic

Adding or multiplying integer codes does not in general add or multiply their reconstructed real values. The library therefore names input schemes, accumulator type, output scheme and rounding policy in every arithmetic operation. Dot products subtract zero points before multiplication and use an explicitly selected accumulator. Accumulator overflow is checked unless a separately named saturating policy is requested. Requantization is an intentional lossy conversion.

A backend may implement an integer kernel only when its scale layout, rounding, accumulator and saturation semantics match the operation contract. AOT and JIT cannot silently select a different quantization meaning. An explicit approximate kernel belongs to an optional numeric profile and must report its error/rounding assumptions. No native matrix or SIMD throughput is promised by this reference.

Every ready function that reads, transforms, copies or compares payload elements is Cpu-only in this profile, including quantize, dequantize, requantize, clone and same_encoding. Metadata-only operations and views can retain device placement without reading device elements on the host. GPU equivalents use an explicit Quantized.submit operation descriptor and return Pending; no ready conversion inserts a hidden wait or transfer.

10. Scale and rounding remain visible 

Result<Affine<i8, f32>, QuantizationError> scheme = Quantized.affine<i8, f32>(0.5, 0);
// Given a validated scheme named parameters.
Result<Quantized<i8, Affine<i8, f32>>, QuantizationError> code_value = Quantized.quantize_checked<i8, f32>(1.25, parameters, RoundingMode.TiesEven);

A literal real defaults to f64 when unconstrained; the explicit generic and parameter context above constrain the computation to f32. rsn can infer a fixed static type, but it does not turn a validated affine scheme into a dynamic numeric type or erase a Result. Mutable buffers require explicit mut declarations and exclusive borrows.

11. Interchange and cost boundary

A payload byte dump is not a complete quantized value: storage width, integer signedness, axis meaning, scale precision, zero points, rounding order and packing convention are required. Device layouts and compiled kernels may depend on these facts. Interchange adapters must preserve or explicitly convert them. Serialization uses a versioned explicit format, not native object memory.
