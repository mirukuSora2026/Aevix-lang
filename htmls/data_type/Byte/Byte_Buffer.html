1. Owners and Borrowed Views

The 0.3 imported bytes.copy_within source API performs checked overlap-safe copying with no allocation. It accepts open or closed ascending unit-step extents, rejects reversed endpoints separately, validates a closed endpoint before adding one and leaves the entire buffer unchanged on error. Empty half-open ranges at length are valid. Other catalog allocation, growth and lazy iterator operations below still require individual implementations.

0.2 implementation scope. Raw storage uses the implemented Array/Vector/Slice types with byte elements. Byte.from_u8/Byte.to_u8 convert one element explicitly; string.as_bytes borrows valid text bytes, and string.from_utf8 validates bytes into a fallible owned string. The Byte. allocation/search/codec functions cataloged here are not implemented 0.2 APIs. See the 0.2 implementation profile; other catalog entries remain design contracts.

A byte buffer uses ordinary Vector<byte> ownership, not a new scalar primitive. Slice<byte> borrows an initialized range, while MutSlice<byte> carries exclusive write permission. Views neither own nor extend storage lifetime. Fixed Array<byte, N> follows the Array contract. Bytes remain raw until an explicit decoder or field schema assigns meaning.

Design draft. Names, support records, and conceptual syntax describe proposed Aevix contracts. They do not claim implementation or measured performance. Declarations put the type first and bindings are immutable by default. MutSlice<T> denotes an exclusive writable view; mut, &T, and &mut T follow the chosen declaration and borrow rules. Catalog-specific support records and signatures remain proposals.

2. Allocation and Initialized Length

Allocations are visible in the signatures and Result contracts. New logical elements are initialized; reserving capacity does not expose uninitialized bytes for safe reading. Length and capacity use usize with checked additions and products before requesting memory. A failure cannot leave a usable vector with a fictitious initialized length. Returned owners are independent unless an explicitly moving operation says otherwise. Copying one byte is not equivalent in cost or ownership to copying a vector.

Signature Returns Contract and cost
Byte.allocate(usize length) Result<Vector<byte>, ByteError> Allocate length zero-initialized bytes; reject size overflow and allocation failure.
Byte.with_capacity(usize capacity) Result<Vector<byte>, ByteError> Allocate logical length zero; spare capacity is not readable initialized data.
Byte.from_slice(Slice<byte> input) Result<Vector<byte>, ByteError> Allocate an independent copy of all source bytes.
Byte.len(Slice<byte> input) usize Return initialized logical length; no allocation.
Byte.is_empty(Slice<byte> input) bool Test logical length zero.
Byte.capacity(&Vector<byte> input) usize Return reserved storage capacity without moving ownership.

3. Growth, Movement, and Failure

Structural mutation needs exclusive ownership access and must not invalidate a live borrowed view. Reserve, append, insert, and resize may allocate or relocate storage; removing can shift a suffix even without allocation. Failed range checks precede modification. Allocating structural operations preserve the original owner on allocation failure. Clear and truncate release logical contents but make no cryptographic erasure promise. Writable owners use the chosen &mut Vector<byte> parameter form. Callers pass &mut buffer from an ordinary mut owner. MutSlice<byte> is already an exclusive view and is passed directly.

Known MutSlice<byte> parameters in Byte buffer and byte-order operations borrow the existing writable capability for the call. Returned byte subviews retain that derived loan, including a subview inside Result, so conflicting parent access remains suspended through its last possible use or cleanup. These calls do not consume the original descriptor. Ordinary value moves and generic T value arguments still transfer a non-Copy view. Reborrowing an existing view does not require rebinding its descriptor; creating a fresh write borrow from an owner still requires the owner's mut permission. See the shared Slice contract.

Signature Returns Contract and cost
Byte.reserve(&mut Vector<byte> buffer, usize additional) Result<unit, ByteError> Check length plus additional; may relocate storage, requiring no invalidated live views.
Byte.resize(&mut Vector<byte> buffer, usize length, byte fill) Result<unit, ByteError> Grow with initialized fill bytes or truncate; may allocate.
Byte.clear(&mut Vector<byte> buffer) unit Set length to zero, retain capacity; no secure-erasure guarantee.
Byte.truncate(&mut Vector<byte> buffer, usize length) Result<unit, ByteError> Require length no greater than logical length; no allocation.
Byte.push(&mut Vector<byte> buffer, byte value) Result<unit, ByteError> Append one initialized byte; may allocate.
Byte.pop(&mut Vector<byte> buffer) Optional<byte> Remove the last byte or return None without allocation.
Byte.extend(&mut Vector<byte> buffer, Slice<byte> input) Result<unit, ByteError> Append copied bytes; check length and allocation first; borrows cannot conflict.
Byte.insert(&mut Vector<byte> buffer, usize offset, byte value) Result<unit, ByteError> Allow offsets through length; shift suffix and possibly allocate.
Byte.remove(&mut Vector<byte> buffer, usize offset) Result<byte, ByteError> Require offset below length; shift suffix without allocation.
Byte.split_off(&mut Vector<byte> buffer, usize offset) Result<Vector<byte>, ByteError> Allocate an owning tail; retain the prefix; validate before changing either.
Byte.append(&mut Vector<byte> destination, &mut Vector<byte> source) Result<unit, ByteError> Move source contents into destination; source becomes empty after success; may allocate.

4. Bounds and Borrowed Slices

Ranges are half-open. Start may equal end, including an empty range at length; element access still requires an offset strictly below length. Bounds arithmetic must not wrap. Subviews inherit lifetime and exclusivity rather than escaping through an unrelated owner handle. Conflicting read/write aliases are rejected. A single exclusive copy_within call can deliberately support overlap using movement semantics. Fixed-size copy_from requires equal lengths, keeping partial-copy policies out of its contract.

Signature Returns Contract and cost
Byte.slice(Slice<byte> input, Range<usize> range) Result<Slice<byte>, ByteError> Borrow a checked half-open range with inherited lifetime; no allocation.
Byte.slice_mut(MutSlice<byte> input, Range<usize> range) Result<MutSlice<byte>, ByteError> Create an exclusive sub-borrow; parent access cannot conflict while it lives.
Byte.get(Slice<byte> input, usize offset) Optional<byte> Copy one byte or return None when out of range.
Byte.set(MutSlice<byte> output, usize offset, byte value) Result<unit, ByteError> Validate offset before modifying one initialized byte.
Byte.copy_from(MutSlice<byte> destination, Slice<byte> source) Result<unit, ByteError> Require equal lengths and nonconflicting borrows; copy initialized bytes.
Byte.copy_within(MutSlice<byte> buffer, Range<usize> source, usize destination) Result<unit, ByteError> Checked overlap-safe movement within one exclusive buffer; no allocation.
Byte.fill(MutSlice<byte> output, byte value) unit Write all initialized elements through one exclusive borrow.

5. Searching and Iteration

Search compares raw patterns and can match a UTF-8 continuation byte or the middle of an integer field. An offset therefore counts bytes, not scalars or graphemes. Lazy split and chunk descriptors borrow input and allocate no output collection. They cannot outlive that input or coexist with structural mutation that invalidates it. Collecting their results into an owning vector is a separate allocating action. Search algorithm complexity must be published rather than hidden behind a universal speed claim.

Signature Returns Contract and cost
Byte.compare_lexicographic(Slice<byte> left, Slice<byte> right) Ordering Compare unsigned byte values and then lengths; no text collation or allocation.
Byte.starts_with(Slice<byte> input, Slice<byte> prefix) bool Test a byte prefix without text-boundary assumptions.
Byte.ends_with(Slice<byte> input, Slice<byte> suffix) bool Test a byte suffix without allocation.
Byte.find(Slice<byte> input, byte value) Optional<usize> Return the first matching byte offset; linear scan.
Byte.find_subsequence(Slice<byte> input, Slice<byte> needle) Optional<usize> Return the first match; empty needle matches zero; publish algorithm bounds.
Byte.split(Slice<byte> input, byte separator) ByteSplit Borrow a lazy separator iterator including empty fields; no result collection allocation.
Byte.chunks(Slice<byte> input, usize width) Result<ByteChunks, ByteError> Require nonzero width; borrow chunks including a shorter tail.

6. Text and Hex Codecs

Strict validation differs from explicitly lossy decoding. A replacement result is useful text, not proof that original bytes were valid or reversible. Unicode maximal-subpart replacement avoids swallowing a following valid sequence into an error. Hex uses its own fixed ASCII grammar. Whole-input codecs reject malformed trailing data. Incremental streaming must separately retain partial-sequence state; callers cannot safely decode arbitrary transport chunks independently and assume boundaries align with scalars.

Signature Returns Contract and cost
Byte.utf8_validate(Slice<byte> input) Result<unit, ByteError> Strictly validate the whole sequence; report byte offsets; no output allocation.
Byte.decode_utf8(Slice<byte> input) Result<string, ByteError> Strictly validate and allocate owned UTF-8 text; malformed input is an error.
Byte.decode_utf8_lossy(Slice<byte> input) Result<string, ByteError> Allocate text, replacing each maximal ill-formed subpart with U+FFFD.
Byte.encode_utf8(string_view input) Result<Vector<byte>, ByteError> Allocate a byte copy of validated UTF-8 text; no normalization.
Byte.encode_hex(Slice<byte> input, bool uppercase) Result<string, ByteError> Allocate two ASCII digits per byte; check length multiplication.
Byte.decode_hex(string_view input) Result<Vector<byte>, ByteError> Require an even number of ASCII hex digits; no prefix or whitespace; allocate bytes.

7. Wider Fields and Execution Places

A numeric field needs width, signedness, and byte order; see Byte Order. Decoding never authorizes alignment assumptions or pointer alias casts. CPU/GPU buffers retain their placement rules: a view cannot silently migrate memory, and submitted work keeps resources until actual completion. Host-readable output additionally needs the appropriate transfer and visibility synchronization. Raw ownership is not an exception to lifetime checks. Buffer growth cannot proceed through an active conflicting GPU borrow.

8. Examples and Related Types

Byte.with_capacity(16); // Result with logical length zero
byte separator = Byte.from_u8(0x00);
Byte.decode_hex("41ff"); // allocating byte decoder
Byte.encode_utf8("A"); // allocating UTF-8 copy

See Byte for scalar bits, Unicode Scalar for exact-one decoding, and string for text sequences. ByteError and borrowed iterators are proposed support records. References motivate independent contracts, not a specific allocator, native library, or measured performance result.
