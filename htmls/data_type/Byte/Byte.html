1. An Opaque Eight-Bit Value

0.2 implementation scope. The byte primitive is automatically available and distinct from u8. Byte.from_u8(value) and Byte.to_u8(value) are implemented allocation-free scalar conversions. No implicit numeric or whole-buffer reinterpretation is added. The named bit, parsing, formatting and codec helpers below remain proposals. See the 0.2 implementation profile; other catalog entries remain design contracts.

The byte type stores an opaque eight-bit pattern and is distinct from u8. It represents raw files, memory buffers, network frames, or encoded text whose interpretation has not yet been established. A byte alone does not identify a Unicode character, signed integer, or protocol field. All 256 patterns are valid, including zero and 0xff. Scalar assignment copies the pattern without heap allocation.

Design draft. Names, support records, and conceptual syntax describe proposed Aevix contracts. They do not claim implementation or measured performance. Declarations put the type first and bindings are immutable by default. MutSlice<T> denotes an exclusive writable view; mut, &T, and &mut T follow the chosen declaration and borrow rules. Catalog-specific support records and signatures remain proposals.

2. Explicit Numeric Boundary

Numeric addition, subtraction, multiplication, and division are not directly defined on byte. Convert explicitly through Byte.to_u8 before using Integer arithmetic; conversion does not authorize unchecked overflow or unchecked indexing. Converting a numeric u8 result back is also explicit. Named bitwise operations preserve the raw-pattern interpretation. Physical packing, register usage, and foreign alignment remain separate from the value’s one-byte representation. There is no implicit character or text conversion.

Numeric serialization boundary. Raw representation APIs in Integer and Float use Array<byte, N>, Slice<byte>, and MutSlice<byte>. Numeric Array<u8, N> values remain ordinary unsigned-integer collections. Equal element width does not make those collection types interchangeable: use Byte.from_u8 and Byte.to_u8 explicitly for element conversions. This rule introduces neither an implicit whole-buffer cast nor a hidden copy.

3. Bitwise and Shift Operations

Bit positions start at zero at the least significant position. Strict shifts accept counts 0…7 rather than silently inheriting hardware count masking. Left shift is explicitly a bit operation that discards high bits, not checked numeric multiplication. Rotation accepts an unsigned count and reduces it modulo eight. Reversing bits differs from swapping bytes: a one-byte value has no alternate byte order. Every operation here returns an independent scalar value.

4. Counts and Pattern Queries

Counts return numeric u32 values from zero through eight, not opaque byte values. All positions of a zero byte count as leading and trailing zeros. Queries require no heap storage. Constant complexity with a bounded value width does not certify cryptographic constant-time machine code or side-channel resistance. The explicit pattern comparator provides deterministic ordering without granting general numeric operators to the type; equality remains exact pattern equality.

5. Checked Fields and Nibbles

A field must satisfy start ≤ 8 and width ≤ 8 − start, using checked arithmetic. Zero-width extraction returns zero; zero-width deposit requires a zero field and leaves the value unchanged. Other field arguments must fit the selected width. Returning a modified copy avoids a hidden mutation through aliases. Nibble helpers work with exactly four positions and reject oversized components instead of truncating their high bits.

6. Hexadecimal and Binary Text

Hexadecimal text represents a byte but does not prove that the represented byte is text. Scalar parsers consume the whole fixed ASCII grammar. Formatters allocate an explicitly returned string or write ASCII bytes into an exclusive output view. Capacity failures precede a fixed-size write. No operation infers a decimal number, Unicode scalar, locale, or source-language escape from a raw byte. Binary and hexadecimal spellings remain distinct from an encoded protocol field.

7. Scalar Copies, Buffers, and Text

Owning Vector<byte> storage normally moves. Slice<byte> borrows initialized storage; MutSlice<byte> additionally requires exclusive write access. Neither copying bytes nor checking their bounds establishes UTF-8 validity. Multi-byte numbers require width, signedness, and byte order. See Byte Buffer for collection operations and Byte Order for field codecs. Those pages individually define their additional functions rather than repeating this core catalog.

8. Examples and Guarantees 

byte raw = Byte.from_u8(0xff);
u8 number = Byte.to_u8(raw);
Byte.count_ones(raw); // 8
Byte.shift_left(raw, 8); // count error
Byte.rotate_left(raw, 8); // unchanged
Byte.parse_hex("ff"); // Result containing the all-one byte

ByteError distinguishes invalid indices, fields, text, capacity, and allocation failures. Error names and example grammar remain draft proposals. No helper transfers a buffer between execution places, creates an invalid byte, or authorizes conflicting mutable views. See string for text semantics. External references explain established concepts, not implemented Aevix performance.
