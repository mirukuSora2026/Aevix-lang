1. A Width and an Order

Endianness orders bytes inside a multi-byte value. It does not reverse bits within each byte, determine signedness, or specify a complete file format. A one-byte field needs no byte-order distinction. This page defines Byte namespace operations over raw slices instead of unchecked native pointer casts. All offsets and returned write lengths count bytes. The caller still chooses an application-level field schema.

Design draft. Names, support records, and conceptual syntax describe proposed Aevix contracts. They do not claim implementation or measured performance. Declarations put the type first and bindings are immutable by default. MutSlice<T> denotes an exclusive writable view; mut, &T, and &mut T follow the chosen declaration and borrow rules. Catalog-specific support records and signatures remain proposals.

2. Portable Layout and Native Interop

Little-endian places the least significant byte first, while big-endian places it last. Thus u16 value 0x1234 encodes as [0x34, 0x12] in little-endian and [0x12, 0x34] in big-endian. Native order means the executing target’s documented representation, not a universal host convention. Native-order fields are unsuitable as an unspecified portable file format. A schema separately declares field order, widths, padding, tags, lengths, and versioning.

The common Integer representation APIs and Float representation APIs use the same raw byte element type as this page. A fixed codec produces or consumes Array<byte, N>; dynamic codecs borrow Slice<byte> or MutSlice<byte>. A numeric u8 array requires explicit element conversion rather than implicit reinterpretation. Float to_bits/from_bits instead use unsigned integer words and remain distinct from byte serialization.

3. Bounds, Signedness, and Cost

A read requires offset ≤ length and width ≤ length − offset. This avoids overflowing offset plus width. Reads use initialized bytes without native alignment requirements and allocate no heap memory. Signed decoding uses the chosen fixed-width two’s-complement interpretation: ff ff gives −1 as i16, but 65535 as u16. This is decoding a declared representation, not a numeric cast silently ignoring a conversion error. Fixed widths do not change with usize.

4. Sixteen-Bit Fields

Each function below consumes or writes exactly two bytes. Its spelling fixes the result type and byte order; data never chooses its own encoding. The caller keeps the source owner and the result is an independent scalar. Writes need MutSlice exclusivity. A failed capacity check leaves output unchanged, and a write never grows the owner implicitly. Protocol semantic constraints, such as allowed value ranges, remain separate after successful field decoding.

5. Thirty-Two-Bit Fields

These functions use exactly four bytes, not the platform width of a C int or pointer-sized integer. Native-order variants remain fixed-width. Application code can perform an explicit checked conversion after decoding when a narrower value or usize is required. A valid decoded integer is not automatically a valid index, allocation length, Unicode scalar, or trustworthy protocol tag. Byte order alone does not validate those meanings or authenticate the message.

6. Sixty-Four-Bit Fields

Eight-byte codecs preserve all integer bits, including the high unsigned bit. No floating intermediate is allowed because f64 cannot exactly represent every 64-bit integer. Implementations can assemble the result without an aligned load; native acceleration must preserve the same bounds and representation contract. Supporting eight-byte storage does not promise native GPU arithmetic, atomics, or a particular speed. Tensor placement and in-flight access permissions remain in force.

7. Single Bytes and Floating Representations

Single-byte functions distinguish u8 and i8 numeric interpretation without redundant endian suffixes. Floating codecs transport f32/f64 representations rather than integer-to-float numeric conversions. Transport preserves signed zero and NaN payload bits; later arithmetic follows Float rules and may transform NaNs. Use the Float byte APIs for f16 and bf16 instead of redefining those codecs here. A raw floating decode does not establish finiteness or a valid application-domain value.

8. Writes, Ownership, and Examples

Validate then write means bounds failure leaves output unchanged; it does not promise a hardware atomic transaction, synchronization, or durable storage. Borrow rules forbid conflicting source and output aliases. Numeric scalar inputs do not alias destination bytes. Writes never allocate hidden storage. Use Byte Buffer to grow an owner and Integer for arithmetic. 

Array<byte, 2> data = [Byte.from_u8(0x34), Byte.from_u8(0x12)];
Slice<byte> view = Slice.from_array(&data);
Byte.read_u16_le(view, 0); // Result containing 4660
Byte.read_u16_be(view, 0); // Result containing 13330
Byte.read_u16_le(view, 1); // bounds error

Text streams need their own UTF-16/UTF-32 codec and BOM policy; UTF-8 has no endian alternatives. See string and Unicode Scalar. API names and support records remain proposals; primary references do not certify an Aevix implementation.
