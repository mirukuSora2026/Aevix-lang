1. Hashed set

Set<T> owns one representative per equivalence class. It provides membership and uniqueness without associating a separate value. The default is randomized hashing with unspecified iteration order; OrderedSet is a separate sorted collection. The set handle moves its allocation and members rather than copying each element. Empty storage is permitted, and every stored member remains initialized.

Design draft. Function names, callbacks, iterators, traits, and error carriers define proposed Aevix contracts. Parameters use T value by value, &T value for a shared borrow, and &mut T value for an exclusive borrow. Calls pass owners as x, &x, or &mut x; taking &mut owner requires a mut binding. Existing references and borrowed views are passed directly. Callback aliases, error records, and returned-reference lifetime notation remain design descriptions. Bindings are immutable unless declared mut; unit is a value type. No implementation or device-support claim follows from this catalog.

2. Stable membership semantics

Equality must be an equivalence relation, and equal members must hash equally under the chosen policy. Those meanings remain stable while a member is stored. Public APIs never yield &mut T for a member: editing a value that determines its bucket would break lookup. For intentional changes, take the owner, edit it outside the set, then reinsert with explicit failure handling. Interior state and custom callbacks remain subject to the same rule.

3. Canonical representatives

An equal query can differ from the stored object in metadata excluded by equality. get borrows the stored representative; take transfers it. insert preserves it and destroys a successful duplicate input, whereas replace returns the previous owner and installs the incoming one. try_insert rejects duplicates with input recovery. These differences avoid accidental destruction of meaningful external-resource owners or silent replacement of canonical data.

4. Errors and borrowing

InputError retains unused incoming ownership on duplicate rejection or growth preflight failure. CollectionError covers checked size, allocation, seed initialization, and fallible clone errors. Borrowed construction leaves its source intact; partial output is destroyed on failure. Rehash cannot occur while a member reference or iterator is live, even if spare capacity exists. Callback unwind keeps safe initialization but does not undo previous removals or external effects. Broken user equality/hash logic may produce incorrect results, but safe implementations must not create out-of-bounds access or aliased mutable references.

6. Algebra and complexity

Relations and lazy union/intersection/difference live on the set algebra page. Lazy views borrow inputs without allocating a result; owned output uses explicitly named copy or clone operations and Result. Expected constant-time membership is not a collision-proof worst-case guarantee. Full iteration may scan capacity, and hashing, equality, cloning, and finalizers add costs beyond bucket operations. No fixed hash algorithm, reproducible seed, or cryptographic guarantee is implied.

7. Examples 

Result<Set<i32>, CollectionError> identifiers = Set.with_capacity(i32, 64);
Array<i32, 4> repeated = [3, 1, 3, 2];
Result<Set<i32>, CollectionError> unique = Set.from_values(Slice.from_array(&repeated));

Construction returns Result, so the caller must handle failure before applying membership operations. Duplicate source values do not turn a set into a multiset. The array remains the owner of its original four integers.

8. Targets and related collections

A set is a host owning collection. Shared thread access requires appropriate synchronization and payload bounds; hashing is not a concurrency primitive. GPU code needs explicit device-compatible storage or a supported specialized collection. Host bucket pointers, capacity, and random seed do not define a portable byte encoding. See OrderedSet, Map, Vector, Array, and string.
