1. Ordered membership

OrderedSet<T> is the explicit sorted alternative to hashed Set. It owns one representative for each comparator-equivalent member and yields increasing order. This enables minimum/maximum operations and bounded traversal. Its balanced-tree contract has no hash policy or bucket capacity. Empty construction is allocation-free; adding nodes is fallible.

Design draft. Function names, callbacks, iterators, traits, and error carriers define proposed Aevix contracts. Parameters use T value by value, &T value for a shared borrow, and &mut T value for an exclusive borrow. Calls pass owners as x, &x, or &mut x; taking &mut owner requires a mut binding. Existing references and borrowed views are passed directly. Callback aliases, error records, and returned-reference lifetime notation remain design descriptions. Bindings are immutable unless declared mut; unit is a value type. No implementation or device-support claim follows from this catalog.

2. Stable total ordering

The element relation must be total and transitive, and remain stable while a member is stored. Comparator equivalence must agree with the chosen equality contract. NaN-bearing numeric keys need an explicit total-order wrapper or policy. Query ordering must agree with stored ordering. A comparator’s changing external state is a logic error; it must not let a safe collection manufacture invalid references or access freed storage.

3. Members and borrows

Members are borrowed only immutably. To change ordering-relevant data, remove or take the member before modifying it, then reinsert while handling possible node allocation failure. insert keeps an existing equivalent representative; replace swaps the owner explicitly. Iterators hold the set borrow; balancing, removal, insertion, and destruction cannot invalidate live references through another safe alias.

4. Failure boundaries

InputError returns the unused incoming member when duplicate rejection or preflight node allocation fails. The set remains unchanged on a documented preflight failure. CollectionError includes checked size, allocation, and clone failure. User callbacks and finalizers are not rollback transactions: callback unwind preserves initialized memory while prior removals and external effects may remain. No stable node address, allocator layout, or zeroing guarantee is offered.

6. Sorted ranges and examples

range is half-open: lower is included, upper excluded. Equal bounds produce no values; reversed bounds return RangeError before yielding. Bounds locate the traversal and need not outlive construction; yielded member references remain tied to the set. A range visits k matching elements after logarithmic setup. 

OrderedSet<i32> empty = OrderedSet.new(i32);
usize count = OrderedSet.len(&empty);
Optional<&i32> least = OrderedSet.first(&empty);

7. Algebra and related types

The algebra catalog defines sorted merge iterators for ordered sets. They borrow both sets, need no output allocation, and preserve increasing order. Owned results require explicit copying or cloning and fallible storage construction. Logarithmic key search still includes comparison cost, and destruction is linear in removed members plus finalizers. See Set, OrderedMap, and Slice.
