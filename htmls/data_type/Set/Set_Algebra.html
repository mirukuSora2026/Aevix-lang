1. Set algebra

Relations answer membership questions; lazy algebra iterators describe selections without owning new members. Owned materialization is separately named copy or clone and returns Result. The same mathematical operation therefore does not hide allocation, cloning, or ownership transfer. Set.equal remains on the common Set page rather than being redefined here.

Design draft. Function names, callbacks, iterators, traits, and error carriers define proposed Aevix contracts. Parameters use T value by value, &T value for a shared borrow, and &mut T value for an exclusive borrow. Calls pass owners as x, &x, or &mut x; taking &mut owner requires a mut binding. Existing references and borrowed views are passed directly. Callback aliases, error records, and returned-reference lifetime notation remain design descriptions. Bindings are immutable unless declared mut; unit is a value type. No implementation or device-support claim follows from this catalog.

2. Compatible equality and order

Both hashed sets must implement the same member equivalence relation, even if their seeds differ. Each lookup uses the queried set’s own hash policy. Ordered sets must agree on a stable total ordering. Combining inconsistent policies is a logic error, not a license for memory unsafety. A set is not a multiset; duplicate counts and original insertion positions do not affect these relations.

3. Borrowed iterators and representatives

Lazy algebra borrows both inputs until the iterator and all yielded references are released. Neither input may be structurally modified through another alias. The union and intersection contracts deliberately prefer the left stored representative for equal classes; metadata excluded from equality can therefore be selected predictably. Hash iteration order remains unspecified despite that representative choice. No iterator extends the lifetime of its source owners.

5. Ordered set algebra functions

These seven ordered operations are merge views and relations. Owned ordered output is built explicitly through OrderedSet.from_values or application-controlled insertion; no hidden clone or generic collection conversion is implied. Double-ended traversal must honor left-representative preference consistently from either end.

6. Materialization and cost

The *_copy family is available only for Copy members; *_clone calls the member’s fallible Clone contract. CollectionError includes clone failure for those variants. Result construction initializes each selected owner once, cleans partial output on failure, and leaves both inputs unchanged. Lazy iterators allocate no result buckets, but user hashing, equality, comparison, and captured state may have their own costs. Worst-case hashed membership can make a full algebra operation quadratic. Ordered merge work is linear in the two lengths plus comparator cost.

7. Examples and related ownership 

OrderedSet<i32> left = OrderedSet.new(i32);
OrderedSet<i32> right = OrderedSet.new(i32);
bool separate = OrderedSet.is_disjoint(&left, &right);
DoubleEndedIterator<&i32> merged = OrderedSet.union(&left, &right);

The empty sets make the relation true and the iterator empty; both source owners remain alive for the merged view. For populated sets, the same lifetime rule applies. See hashed Set, OrderedSet, and exclusive mutation.
