Implemented 0.2 CPU profile

Read the implemented SIMD profile for the exact imports, supported lane counts, checked operations, masks, and fixed-array access available in 0.2. The broader API catalog below remains a design draft; it is not a list of compiler-supported functions.

1. One logical predicate per lane

Mask<N> contains N logical truth values and matches the lane count of an associated Simd value. It is a proposed library type, not an alias for bool, Array<bool, N>, an integer vector or a hardware predicate register. Logical operations specify results per lane while leaving native representation to the target. A backend may use bit packing, full-width lane bits or another valid internal format.

The positive lane count is a compile-time constraint. A mask can be copied as a value without heap allocation, but that does not guarantee a single register or stable memory layout. Numeric comparison creates masks. A mask cannot be passed to a C bool array pointer through a bitcast; explicit logical array conversion is required.

2. Logical operations and reductions

Conjunction, disjunction, exclusive-or and negation apply independently to each lane. all is true only when every lane is true; any is true when at least one lane is true; count returns the number of true lanes. first_set and last_set return Optional<usize>, avoiding an invalid sentinel index for an all-false mask.

Because N is positive, an all-true mask contains at least one active lane. A future zero-lane extension would need explicit reduction identities and does not follow automatically from ordinary empty-array behavior. Mask equality means identical logical truth values, not identical padding or register bits.

3. Selecting values and guarding effects

select receives two already evaluated vector values. It chooses lanes but cannot suppress computation of those inputs. Guarding a zero divisor requires a masked arithmetic function whose contract excludes inactive arithmetic, or a proven-safe replacement divisor before regular division. Guarding a load requires the masked load/gather functions, not a selection after an invalid load.

Masked memory functions validate and access only active indices. They do not form an address for an inactive invalid index. Masked scatter also rejects duplicates among active destinations before writing; duplicates solely among inactive lanes are irrelevant. The borrow checker still requires legal source and destination loans even if every lane is inactive.

4. Explicit bitset conversion

Portable bitset conversion assigns lane i to bit i, with bit zero the least-significant logical bit of word zero. Bitset<N> is a library record containing enough u64 words; unused high bits in the final word must be zero when constructing a mask. A compact u64 conversion is available only when N <= 64. These are value conversions and do not expose native mask object memory.

Endianness matters only when that bitset is serialized into bytes, through an explicitly named little-endian or big-endian encoding. N=64 must not be implemented with an invalid shift by 64. A safe adapter validates unused bits using width-aware arithmetic rather than relying on CPU shift masking.

5. Masks do not grant memory rights

A mask is a value predicate, not a proof that a buffer is uniquely borrowed or that a GPU producer has finished. A masked store still requires MutSlice ownership and bounds proof for active lanes. A copied mask does not retain a source buffer or extend a borrowed task lifetime. Queued work captures masks by value or retains their owning memory explicitly if they are stored in buffers.

Whether a mask operation is native is a compile capability. A compiler can combine masks or remove redundant checks when it proves the same active-access set and error behavior, but cannot turn a checked operation into poison on inactive lanes. AOT and JIT share these semantic requirements.

6. A logical array is an explicit conversion 

Mask<4> active = Simd.mask_from_array<4>([true, false, true, false]);
Array<bool, 4> flags = Simd.mask_to_array(active);
usize enabled = Simd.mask_count(active);
Optional<usize> first = Simd.mask_first_set(active);

The values flags and active have different abstract types and no shared native layout guarantee. The example allocates no dynamic Vector and makes no implicit conversion to a numeric lane type.

8. Reference scope

All interfaces here are proposals. Rust portable SIMD documentation is explicitly experimental and is used only as an official comparison source. LLVM vector IR is a lowering vocabulary; its poison and undefined-behavior preconditions are not safe Aevix contracts. The language must validate every condition required by its own observable semantics.
