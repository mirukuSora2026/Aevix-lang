1. Overview

Design draft. These are proposed Aevix APIs, not claims that a compiler or standard library implements them. Parameter modes are chosen: T value, &T value, and &mut T value. Type-pack notation, callable types, explicit returned-reference lifetime spelling, and error enums remain descriptive where marked. Namespace functions are used throughout; there are no value-method aliases.

Optional represents a value that may be absent. Absence is expected data, not an error payload. A failed parse with a diagnostic belongs in Result; an optional search can return None. Uninitialized storage is neither None nor Some and is never exposed as a valid Optional.

2. Declarations and variants

Use namespace constructors with a type-first declaration. A None constructor needs an expected T or an explicit type argument. Some consumes an owning payload; it does not implicitly clone it. 

Optional<i32> present = Optional.some(12);
Optional<i32> absent = Optional.none<i32>();
bool found = Optional.is_some(&present);

3. Safe inspection and extraction

Reading a variant tag does not move its payload. Shared and exclusive borrowed projections preserve the owner lifetime and prevent replacing the owner while a projected reference remains live. The chosen enum branching form is switch with case patterns. This catalog does not yet specify Optional's complete public variant-pattern representation; its named inspection and extraction APIs remain available under their stated contracts.

The proposed catalog has no panic-on-None unwrap, unchecked access, or implicit truth conversion. Use a fallback, a Result conversion, or an exhaustive branch. A diagnostic convenience must not silently change recoverable absence into an unmodeled abort.

4. Ownership and in-place updates

Optional of an owning T moves by default. Explicit copy requires T: Copy; explicit clone follows T Clone semantics and can fail. Taking a value leaves a valid None state, so an owner is never temporarily left uninitialized.

Insert and replacement require exclusive access. Insert destroys a previous payload before returning a borrow of the new one; replace returns the previous payload to the caller. No mutation can occur through a simultaneous shared borrow.

5. Lazy and eager alternatives

Functions ending in _else or _with accept a callback and state exactly when it runs. Ordinary fallback values, and/or arguments, and zip inputs are already evaluated before the call; unselected owned payloads are destroyed once.

Map and and_then consume a present payload. Map_ref borrows it. Inspect borrows for observation and then returns ownership unchanged. Callback return types remain explicit, including unit for observers.

6. Function reference

T value passes a value: Copy types are copied, and owning non-Copy values move without a deep clone. &T value is a shared read borrow; &mut T value is an exclusive modification borrow. Calls use x, &x, or &mut x respectively. Already borrowed references and view values are passed directly; adding another & changes the type. *ref accesses the referent. Ordinary &mut x requires a mut owner; mut T value alone makes a by-value parameter locally mutable and does not modify the caller. Overlapping active borrows are checked until last use; disjoint regions may be split safely and no borrow outlives its source. Synchronized interior mutation follows its own type contract. Fn(A) -> B describes a callable; returned-reference lifetime relationships remain documented in prose.

7. Nested optionals and Result

Optional<Optional<T>> has distinct outer absence and present-inner-absence states until flatten deliberately merges them. Optional.transpose preserves an error inside a present Result and treats outer absence as a successful absence.

Optional<unit> is a presence flag with two semantic states. Optional<never> can only be None. These are type-level meanings; this document does not require a particular byte layout for either.

8. Failures, layout, and drop rules

Constructing an Optional wrapper requires no allocation. A payload factory, payload clone, or payload destructor can have costs inherited from T. Clone failure leaves a borrowed source valid and destroys any partially created clone.

A compiler may encode absence in a payload niche only when every bit pattern and ABI rule permits it. No universal null-pointer optimization, tag size, or C-compatible layout is promised. Raw bytes require a decoder that validates the active payload.

9. Parallel, device, and foreign boundaries

Optional is transferable to another task or device only when its payload and representation contract support that boundary. A shared Optional does not permit concurrent mutation of its payload. Atomic Optional storage is not implied by an atomic payload type.

A C nullable pointer, C++ optional, and Python None require explicit adapters. An Optional borrowed reference cannot outlive a foreign object or pinning guard. Opaque Python ownership remains in the binding layer.

10. Examples and explicit cost 

i32 chosen = Optional.unwrap_or(Optional.some(7), 99);
Result<i32, i32> required = Optional.ok_or(Optional.none<i32>(), 404);
Optional<Optional<i32>> nested = Optional.some(Optional.some(3));
Optional<i32> flat = Optional.flatten(nested);

The fallback 99 is evaluated even when the Some payload is used. A callback form is needed to defer an expensive allocation. Ordinary borrow expressions are already chosen: &owner reads, &mut owner requests exclusive access to a mutable owner, and *reference accesses the referent. The function declaration reference defines these modes. Callback type spelling and explicit returned-reference lifetime notation remain separate open details.
