1. Borrowed Contiguous Views

Array-family guide. The Slice reference is the single canonical catalog for Slice signatures, returned errors, borrowing, and costs. This page preserves Array-family navigation and existing links; it does not define a second API.

Slice<T> is a shared read view and MutSlice<T> is an exclusive writable view of an initialized contiguous range. Neither view owns or allocates its backing elements.

2. Owner Lifetime & Invalidation

A view cannot outlive its owner or survive an invalidating move, reallocation, or cleanup. Metadata alone does not keep a buffer alive. See owner lifetimes and invalidation.

3. Exclusive Access & Disjoint Regions

Exclusive access rules apply to the backing elements. Checked splits can create disjoint writable subranges; unrestricted overlapping writable views are not allowed. See exclusive access and disjoint regions.

4. Bounds, Empty Views & Chunks

View ranges are half-open, including valid empty ranges at the end. Chunk and window widths must be positive, and access returns the Optional or Result specified by its API. See bounds, empty views, and chunks.

5. Copy, Clone & Error Atomicity

Duplicating a shared view copies metadata, not elements or ownership. Owned copies and clones are explicit; clone-based mutation can keep a valid replaced prefix after failure. See copy, clone, and failure guarantees.

6. Algorithm Requirements & Cost

Search indices are relative to the view. Sorted searches require a consistent comparator and sorted input; stable sorting may allocate scratch storage. See algorithm requirements and costs.

7. Canonical Slice API Links

The complete signatures, return types, borrow or ownership guarantees, and costs live only in the canonical Slice API catalog. The entries below preserve every former function anchor and link to its authoritative row.

Known view inputs are reborrowed

Known MutSlice<U> and &mut U parameters reborrow compatible exclusive capabilities; a generic by-value T parameter still moves a non-Copy view. Derived results retain their parent loan until all uses and cleanup accesses end. Read the Slice parameter contract and function reborrow rule.

8. Type-First Examples

A Slice borrows its owner. Creating an owned Vector copy has a separate, fallible allocation.

Array<i32, 4> values = [1, 2, 3, 4];
Slice<i32> view = Slice.from_array(&values);
usize count = Slice.len(view);
Result<Vector<i32>, CollectionError> owned_copy = Slice.to_vector_copy(view);

See canonical examples and exclusive Slice views.

9. Parallelism, GPU Work & FFI

Read sharing requires T to support safe shared access. Disjoint write ranges can support parallel processing only with compatible element traits and callback captures. A split is an aliasing proof, not universal race-safety for arbitrary internal references.

A slice is not a device pointer. Borrowing CPU storage does not perform an upload, synchronize GPU work, or make that storage kernel-accessible. Explicit transfer and asynchronous lifetime rules belong to the execution and Tensor design.

Foreign borrowed buffers need a duration, initialized element count, alignment, access permission, and external-mutation contract. The owner must not free or reallocate during the borrow. Release callbacks belong to the owning adapter, not to an ordinary Slice destructor.

10. Text, Bytes & Related Collections

Slice<char> indexes Unicode scalar values. It is not a UTF-8 string_view, and a numeric or raw-byte slice is not validated text. See the lowercase string reference for encoding boundaries.

byte is distinct from u8; a slice cast must not silently substitute one element type for the other. Endianness, serialization, and FFI layout also need explicit conversion.

Use Array for common family rules, Static Array for fixed ownership, and Vector for dynamic ownership. The primary sources inform this proposal; no compiler, allocator, ABI, or device implementation is claimed.
