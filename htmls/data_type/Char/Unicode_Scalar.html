1. What Counts as a Scalar

A Unicode scalar lies in U+0000…U+D7FF or U+E000…U+10FFFF. The surrogate interval U+D800…U+DFFF is excluded. There are 1,112,064 possible scalar values, including assigned and unassigned values. Validity does not require a font, visible glyph, name, or permission in a protocol. This page specializes the Char contract without duplicating its constructors or property catalog.

Design draft. Names, support records, and conceptual syntax describe proposed Aevix contracts. They do not claim implementation or measured performance. Declarations put the type first and bindings are immutable by default. MutSlice<T> denotes an exclusive writable view; mut, &T, and &mut T follow the chosen declaration and borrow rules. Catalog-specific support records and signatures remain proposals.

2. Surrogates and Numeric Input

A UTF-16 high surrogate lies in D800…DBFF; a low surrogate lies in DC00…DFFF. Neither code unit is a char alone. A valid pair represents one supplementary scalar. u8, u16, and u32 remain numeric or encoded-unit storage types, not alternate character primitives. Validate at the boundary rather than reinterpreting arbitrary integers. NUL and noncharacters can still be valid scalars.

3. Encoding Width Is Not Scalar Width

UTF-8 needs one through four byte units for a scalar; UTF-16 needs one or two u16 units; UTF-32 needs one validated u32 unit. These counts are not an ABI promise about a char variable. UTF-16 and UTF-32 byte streams additionally need declared byte order. Numeric code-unit slices have already resolved that byte representation. Stream codecs must state their BOM policy instead of inferring a whole protocol from a scalar.

4. Strict Decoding and Error Positions

Strict decoders reject overlong UTF-8, invalid continuation bytes, encoded surrogates, values above U+10FFFF, truncated sequences, and unpaired UTF-16 surrogates. Errors distinguish incomplete input from invalid input and report offsets in the documented unit. Exact-one decoders reject leftovers. Prefix and offset functions report consumption and make no assertion that the suffix is valid. They never silently replace malformed input or skip a following valid sequence.

5. Buffer Encoding and Borrowing

Destination encoders need an exclusive MutSlice<T> borrow and initialized capacity. They validate the whole fixed-size write before modifying output. A view cannot outlive its owner, and storage cannot be reallocated while a live view would be invalidated. Encoding performs no normalization and does not allocate. U+0000 legitimately writes a zero unit; it becomes a terminator only when an explicitly selected external protocol says so.

Signature Returns Contract and cost
Char.encode_utf8_into(char c, MutSlice<byte> output) Result<usize, CharError> Validate capacity before writing one to four bytes; no allocation.
Char.encode_utf16_into(char c, MutSlice<u16> output) Result<usize, CharError> Validate exclusive capacity before writing one or two units.
Char.validate_utf8_prefix(Slice<byte> units) Result<usize, CharError> Validate one complete leading scalar and return its byte count.
Char.validate_utf16_prefix(Slice<u16> units) Result<usize, CharError> Validate one complete leading scalar and return its unit count.

6. Normalization and Grapheme Boundaries

A valid scalar can form only part of a grapheme cluster. Canonical equivalence relates sequences; it does not make their scalar counts or bytes identical. Validation, property lookup, normalization, and segmentation are separate operations. Successful UTF decoding does not establish NFC, a single grapheme, an identifier, or safe display. Whole-sequence algorithms belong to string; combining marks must not be discarded merely to simplify indexing.

7. Pinned Properties and Independent Validity

Scalar range and surrogate exclusion do not depend on whether the selected Unicode database assigns a value. Property-driven behavior records the compiler artifact’s exact version and fingerprint. A later toolchain can recognize new names without changing UTF encodings of existing scalars. The cited Unicode release is a comparison source, not a newly selected Aevix version. AOT and JIT share validation contracts; an operating-system update must not silently replace their tables.

8. Boundary Examples 

Char.from_u32(0x10ffff); // valid noncharacter scalar
Char.from_u32(0xd800); // surrogate error
Char.from_u32(0x110000); // out-of-range error
char zero = '\0';
Char.utf16_length('😀'); // 2 units
Char.utf8_length('😀'); // 4 bytes

See Byte Buffer for raw storage and explicit replacement decoding, and Byte Order for wide fields. A lossy result is not evidence that the original bytes were valid or preserved. Error record names and parsing grammar remain draft decisions, not claims about an existing Aevix decoder.
