1. ASCII Is a Subset of char

ASCII covers U+0000 through U+007F. An ASCII scalar remains char; this page creates no char8 primitive and no permissive eight-bit text encoding. The 128 code points include controls and DEL. Their UTF-8 spelling is one byte, but a high-bit byte is not ASCII and does not independently establish a UTF-8 character. The subset does not imply that every control is suitable in a message.

Design draft. Names, support records, and conceptual syntax describe proposed Aevix contracts. They do not claim implementation or measured performance. Declarations put the type first and bindings are immutable by default. MutSlice<T> denotes an exclusive writable view; mut, &T, and &mut T follow the chosen declaration and borrow rules. Catalog-specific support records and signatures remain proposals.

2. Fixed Classification Rules

The Char.ascii_* predicates use explicit numeric rules and never consult process locale. Non-ASCII input is false rather than falling back to Unicode classification. This draft chooses five whitespace characters: tab, line feed, form feed, carriage return, and space. Vertical tab is false here even though Unicode White_Space includes it. Printable includes space, while graphic excludes it; neither property is a protocol validator or a terminal safety guarantee.

Char.ascii_is_alphabetic(char c) bool A–Z or a–z; non-ASCII returns false, without allocation.
Char.ascii_is_alphanumeric(char c) bool ASCII letter or decimal digit; non-ASCII returns false, without allocation.
Char.ascii_is_uppercase(char c) bool A–Z; non-ASCII returns false, without allocation.
Char.ascii_is_lowercase(char c) bool a–z; non-ASCII returns false, without allocation.
Char.ascii_is_digit(char c) bool 0–9; non-ASCII returns false, without allocation.
Char.ascii_is_hex_digit(char c) bool 0–9, A–F, or a–f; non-ASCII returns false, without allocation.
Char.ascii_is_octal_digit(char c) bool 0–7; non-ASCII returns false, without allocation.
Char.ascii_is_binary_digit(char c) bool 0 or 1; non-ASCII returns false, without allocation.
Char.ascii_is_whitespace(char c) bool HT, LF, FF, CR, or SPACE; VT excluded; non-ASCII returns false, without allocation.
Char.ascii_is_control(char c) bool U+0000…U+001F or U+007F; non-ASCII returns false, without allocation.
Char.ascii_is_graphic(char c) bool U+0021…U+007E; non-ASCII returns false, without allocation.

3. ASCII Case Mapping

Case transforms change only the 26 basic Latin letters. Their scalar results never expand and require no allocation. Non-ASCII input remains unchanged, so comparing é with É ignores no distinction. The helpers do not perform international folding, normalization, or locale-sensitive sorting. A comparator can still order unchanged non-ASCII scalars numerically: ASCII folding names the transformation, not a precondition that both inputs are ASCII. Whole-text matching belongs to the string contract.

Signature Returns Contract and cost
Char.ascii_to_lowercase(char c) char Map A–Z to a–z; all other scalars remain unchanged.
Char.ascii_to_uppercase(char c) char Map a–z to A–Z; all other scalars remain unchanged.
Char.ascii_equal_ignore_case(char left, char right) bool Compare after ASCII folding; never Unicode-fold non-ASCII scalars.
Char.ascii_compare_ignore_case(char left, char right) Ordering Compare scalar values after ASCII folding; no locale or allocation.

4. Digit Parsing and Radix

ASCII decimal digits are 0 through 9. Radix helpers additionally recognize basic Latin letters, with uppercase and lowercase denoting the same value. A radix outside 2…36 is an error; an allowed radix with a non-digit produces None. Arabic-Indic and fullwidth decimal digits remain valid Unicode scalars but fail ASCII digit tests. Whole numeric strings need explicit sign, separators, range, and consumption rules beyond this one-scalar helper.

Signature Returns Contract and cost
Char.ascii_digit_value(char c, u32 radix) Result<Optional<u32>, CharError> Require radix 2…36; accept ASCII digits and letters only.

5. Checked Encoding and Decoding

Encoding bridges a scalar and an opaque byte only after range validation. A valid byte such as 0xff cannot be ASCII-decoded. U+00FF also does not become ASCII merely because its numeric value fits in u8. NUL is valid ASCII rather than an automatic end marker. Whole-input parsing rejects trailing text after a valid prefix. Scalar and byte results are independent value copies; their constructors do not establish ownership of a surrounding buffer.

Signature Returns Contract and cost
Char.ascii_from_u8(u8 value) Result<char, CharError> Accept 0…127, including NUL and controls; reject high-bit input.
Char.ascii_encode(char c) Result<byte, CharError> Encode one ASCII scalar as one byte; reject non-ASCII values.
Char.ascii_decode(byte value) Result<char, CharError> Decode one seven-bit byte; reject values 128…255.
Char.ascii_parse(string_view text) Result<char, CharError> Require exactly one ASCII scalar and consume the whole input.
Char.ascii_escape(char c) Result<string, CharError> Allocate an ASCII diagnostic escape; reject non-ASCII input.

6. Different Unicode Answers

Use Char for Unicode properties and full mapping proposals. A Unicode letter can lie outside ASCII, a numeric property can denote a fraction, and a decimal digit need not have an ASCII byte spelling. ASCII-only rules are useful for a protocol grammar, but that grammar must also define delimiters, escaping, length, and validation. No function automatically turns a scalar into a valid identifier or validates a complete request.

7. Ownership and Cost

Classification and single-scalar ASCII transformations allocate no heap storage. This bounded complexity does not certify one native instruction or cryptographic timing. Diagnostic string output allocates through an explicit Result path. Input views retain their owner’s lifetime, while returned scalar values are independent. Vector<char> need not have the same representation as Vector<byte>. Choose text and raw storage deliberately; scalar copying is not copying an owning container.

8. Examples and Related References 

char letter = 'A';
Char.ascii_is_alphabetic(letter); // true
Char.ascii_to_lowercase(letter); // a
Char.ascii_is_digit('９'); // false
Char.ascii_equal_ignore_case('é', 'É'); // false
Char.ascii_from_u8(0xff); // error

See Byte for raw patterns and string for text sequences. Unicode versioning affects property tables, but these ASCII numeric ranges remain explicit in the Aevix contract. Sources explain comparison behavior; the proposed namespace and error types do not claim an already implemented compiler or standard library.
