1. Scalar Identity

The char type denotes one Unicode scalar value. A scalar is a code point excluding the surrogate range; it is not a UTF-8 byte, a UTF-16 unit, a glyph, or necessarily a user-perceived character. This page introduces no char8, char16, or char32 primitive. Scalars copy without per-value heap allocation. Their physical ABI remains a separate target contract.

Design draft. Names, support records, and conceptual syntax describe proposed Aevix contracts. They do not claim implementation or measured performance. Declarations put the type first and bindings are immutable by default. MutSlice<T> denotes an exclusive writable view; mut, &T, and &mut T follow the chosen declaration and borrow rules. Catalog-specific support records and signatures remain proposals.

Destination-buffer encoders with a known MutSlice<byte> or MutSlice<u16> parameter reborrow an existing writable view for their access. They do not consume that descriptor or copy its exclusive capability; it can be reused after the derived loan ends. The descriptor need not be a mut binding merely to lend its existing permission. Ordinary value moves and a generic T value parameter still transfer non-Copy capabilities. Returned borrowed data, where offered, keeps its source loan through its last possible use or cleanup. See the Slice parameter contract.

2. Versioned Data, Not Ambient Locale

Property answers depend on a compiler-supplied Unicode data artifact. A build records an exact version, contributing data files, and fingerprint; AOT and JIT use that same artifact. This draft selects no release number merely because a reference website has one. Updating tables is a visible toolchain change. Neither the operating-system locale nor a downloaded runtime table may silently change classification. ASCII-only helpers use fixed numeric rules on their dedicated page.

3. Construction and Metadata

Validate numeric input before constructing char. Surrogates and out-of-range integers fail without creating an invalid scalar. Assignment status, private use, NUL, and noncharacter status do not alter scalar validity. Applications may impose stricter interchange policies separately; constructors do not silently replace or drop data. CharError is a proposed tagged error record, and allocating calls expose allocation failure.

Char.min_value() char Return U+0000; constant, no allocation.

4. Classification Predicates

Predicates inspect one scalar through bounded property-table lookup. No allocation does not promise one machine instruction or identical latency on every target. Alphabetic, numeric, and whitespace properties differ from ASCII classification. Identifier properties are useful lexer inputs, but keywords, normalization, script restrictions, and security profiles belong to the language identifier specification. A successful property test is never proof of safe display or a valid complete token.

5. Property and Name Queries

Property result records are draft support descriptors, not additional scalar primitives. A property can have a default even when a scalar has no displayable name. Script, block, directionality, width, and segmentation answer different questions; none independently provides rendering. Allocating vectors and strings have explicit Result contracts. Quick-check values are hints for a complete normalization algorithm, not substitutes for inspecting a sequence. Exact rational numeric properties avoid silently treating a fraction as a decimal digit.

6. Simple Mapping and Full Expansion

Simple mappings return one scalar, applying identity when no simple mapping exists. Full mappings may expand, so they return string through an allocating operation. A scalar has no neighboring context: these functions cannot implement final-sigma selection, arbitrary word title-casing, or locale-sensitive whole-text transforms. Default non-Turkic case folding is locale-independent and does not normalize canonically equivalent sequences. Context-sensitive and locale-aware whole-text operations belong to unicode., including unicode.lower and unicode.lower_locale.

Signature Returns Contract and cost
Char.simple_lowercase(char c) char Apply the simple mapping or identity; no allocation or neighboring context.
Char.simple_uppercase(char c) char Apply the simple mapping or identity; never truncate an expansion.
Char.simple_titlecase(char c) char Apply the simple title mapping or identity; no word-boundary inference.
Char.simple_case_fold(char c) char Apply the default non-Turkic simple fold or identity; no allocation.
Char.to_lowercase(char c) Result<string, CharError> Allocate the default isolated-scalar lowercase mapping; it may expand.
Char.to_uppercase(char c) Result<string, CharError> Allocate the full uppercase mapping; multiple scalars are possible.
Char.to_titlecase(char c) Result<string, CharError> Allocate the isolated-scalar full title mapping; not word title-casing.
Char.case_fold(char c) Result<string, CharError> Allocate full default non-Turkic folding; normalization is separate.

7. Encoding and Escapes

UTF encoders consume a valid scalar and produce code units, never another character primitive. Fixed arrays contain initialized temporary storage; the used length matters because trailing padding is not extra text. Source escapes and diagnostic output differ from binary transport, and debug spelling is not a stable external protocol. Explicit decoders and destination-buffer encoders live on the Unicode Scalar page. No encoder infers a BOM policy, surrounding string normalization, or a locale.

Signature Returns Contract and cost
Char.utf8_length(char c) u32 Return one through four encoded bytes; no allocation.
Char.utf16_length(char c) u32 Return one or two UTF-16 code units; no allocation.
Char.to_utf8(char c) (Array<byte, 4>, u32) Return zero-padded storage and used length; only its prefix is encoded text.
Char.to_utf16(char c) (Array<u16, 2>, u32) Return zero-padded code-unit storage and used length; no allocation.
Char.to_string(char c) Result<string, CharError> Allocate valid UTF-8 text containing exactly this scalar.
Char.escape_unicode(char c) Result<string, CharError> Allocate a scalar escape containing an explicit hexadecimal value.
Char.escape_default(char c) Result<string, CharError> Allocate the versioned draft source-literal escape.
Char.escape_debug(char c) Result<string, CharError> Allocate a diagnostic spelling, not a portable serialization format.

8. Scalars, Graphemes, and Ownership

An e followed by a combining acute accent contains two scalars and can form one grapheme cluster. Emoji sequences may contain several scalars. Counting, indexing, or deleting one scalar is therefore not necessarily editing one displayed character. Borrowed string_view and Slice<char> retain their owners’ lifetimes. Array<T, N> and Vector<T> follow their normal copy or move contracts; scalar copying does not duplicate surrounding owning storage.

9. Examples and Related References 

char letter = 'A';
u32 value = Char.to_u32(letter);
Char.is_valid_scalar(0xd800); // false
Char.to_uppercase('ß'); // Result containing SS
Char.utf8_length('한'); // 3
Char.to_string(letter); // explicitly allocating Result
