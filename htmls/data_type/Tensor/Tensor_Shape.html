1. Shape is a constraint, not storage

A shape describes the number and extent of logical axes. Shape<2, 3> proves a rank-two, six-element layout-independent fact. It does not choose row-major order, alignment, ownership or device placement. A dynamic shape value stores validated runtime extents. DynamicShape<R> is a proposed library descriptor for known rank R with runtime sizes; it does not create a new numeric primitive or allow runtime values as arbitrary compile-time parameters.

A symbolic static dimension such as N is a compile-time generic parameter. A caller cannot satisfy Shape<N, 3> by passing an unrelated runtime integer with the same spelling. When input constraints cannot be proved, checked constructors return ShapeError. A successful refinement produces a descriptor tied to the actual validated value, not a globally trusted assertion.

2. Products and representability

Each extent is a nonnegative usize value. Axis count, element count, output extent sums, reshape inference and byte-size calculations must use checked arithmetic. Rank-zero has one element. Zero extents produce no logical accesses, but do not exempt metadata from validation. Constructors may impose explicit rank and allocation limits; exceeding them is a normal resource or shape error rather than integer wraparound.

An inferred reshape extent is permitted only through the explicitly named inference function. The product of known extents must divide the element count. A zero known product makes inference ambiguous when total count is also zero, so that case returns an inference error instead of guessing a dimension. A nonzero count cannot be reshaped to a zero-product shape.

3. Broadcast evidence

Trailing dimensions align. Equal extents match, and an extent of one expands to the other extent. Missing leading axes are singleton axes. The result of 0 with 1 is 0; the result of 0 with 0 is 0; 0 with 2 is invalid. This rule is stated directly because a numeric maximum implementation mishandles empty dimensions.

A static broadcast produces compile-time output dimensions where known. Runtime compatibility is checked before an operation allocates or writes. A broadcast proof certifies dimensions only: a repeated-address read view cannot use that proof to become mutable. Device operations consume the same validated shape constraints as CPU operations.

4. Axes and permutations

Core axis arguments are unsigned, zero-based indices. Insertion permits axis equal to rank; access and reduction do not. Optional adapters may accept negative axes, but must normalize explicitly and reject arithmetic overflow. A permutation contains every axis exactly once. Repeated reduction axes are rejected instead of silently deduplicated, so the requested operation has a single meaning.

Squeeze accepts only axes with extent one; an empty axis is not a singleton. Expanding inserts one without copying elements. Concatenation checks every non-concatenated extent and the checked sum of concatenated extents. Batched matrix multiplication keeps these rules separate from its inner contraction constraint.

5. Shape refinement and ownership

A successful shape check does not borrow elements unless its returned descriptor references owner metadata. A metadata view cannot outlive its owner or a mutation that would replace that metadata. Owned DynamicShape values copy only their own small descriptor storage, and any allocation required for unbounded rank is fallible. A fixed-rank descriptor may live inline without a heap allocation.

Refining a tensor from dynamic dimensions to a static target consumes the tensor or returns a borrowed refined view, as named by the API. Failure of an ownership-consuming refinement returns the original owner inside a proposed ShapeConversionError<T>. This keeps a recoverable error from accidentally losing expensive storage.

6. Explicit dynamic checks 

Result<DynamicShape<2>, ShapeError> dimensions = Tensor.make_shape<2>([2, 3]);
// Given Slice<usize> dimensions_view and borrowed ShapeLike descriptors left_shape/right_shape.
Result<usize, ShapeError> count = Tensor.checked_element_count(dimensions_view);
Result<DynamicShape<2>, ShapeError> compatible = Tensor.broadcast_shape(left_shape, right_shape);

The owning fixed array passed to make_shape is a value input; dimensions_view and ShapeLike descriptors are existing borrowed views passed directly. No implicit Array-to-Slice coercion is assumed. Every Result remains explicit; a failing shape check cannot be ignored and then used as evidence for unchecked access.

8. Design boundary and related pages

All signatures are proposed library contracts. AOT and JIT preserve the same validation, lifetime and numeric semantics. An optimization may remove a proven redundant operation, but must preserve observable errors and synchronization boundaries. Supporting descriptor types and generic shape spellings remain design candidates; parameter passing uses the approved value, &T and &mut T forms. Returned-reference lifetime notation remains conceptual.
