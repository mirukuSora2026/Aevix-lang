1. Entry capability

Map.entry performs lookup once and returns a linear capability for a particular key. The capability exclusively borrows the whole map, tracks occupied or vacant state, and owns the incoming key until a terminal operation chooses what happens to it. It is not a separately allocated key/value container and cannot outlive its map.

Design draft. This is an Aevix contract proposal, not an implementation claim. Callback, iterator, trait, and error-carrier names are descriptive. Parameters use T value by value, &T value for a shared borrow, and &mut T value for an exclusive borrow. Calls pass owners as x, &x, or &mut x; taking &mut owner requires a mut binding. Existing references and borrowed views are passed directly. Callback aliases, error records, and returned-reference lifetime notation remain design descriptions. Bindings are immutable unless declared mut; unit is a value type.

2. Stored and incoming keys

For occupied entries, the original stored key remains canonical while an equal incoming key may still be owned by the capability. key exposes the stored key in this state; into_incoming_key recovers the original incoming key in either state. Dropping an unused entry capability destroys its incoming key and releases the borrow. No stored key becomes mutable.

3. Exclusive scope

Every entry operation requires the same live map lease. A returned mutable value reference extends that lease and prevents unrelated map mutation until it ends. Callbacks may edit their value but cannot structurally access the map, capture an escaping value borrow, or reenter it through another alias. Occupied/vacant status cannot race with another safe writer during this scope.

4. Recovery carriers

EntryInputError contains a still-live entry capability and the unused replacement value; EntryBuildError contains the entry plus either preflight failure or callback error. These carriers retain the map borrow until handled or dropped. On allocation preflight failure no input is silently destroyed. Ordinary callback error leaves the key vacant; callback unwind releases initialized captures and the entry lease, while external side effects remain. The notation describes an error contract rather than fixing record syntax.

6. Lazy value construction

A lazy builder runs only for a vacant entry, so occupied access does not allocate an unused replacement value. Capacity preflight occurs first. A builder can still allocate or fail according to its own return type; a successful builder produces one owner for insertion. These entry APIs are synchronous and never suspend while holding the map’s mutable capability.

7. Examples and related contracts

Entry capabilities begin with the common Map.entry operation. The example below constructs a fallible owning map; actual entry access follows explicit success handling, so an allocation error cannot be confused with an empty map. 

Result<Map<i32, i32>, CollectionError> counts = Map.with_capacity(i32, i32, 8);
Result<Map<i32, i32>, CollectionError> sparse = Map.new(i32, i32);

See Map.entry for lookup and exclusive view rules for non-overlapping borrows. An entry operation preserves memory safety under user logic errors; it does not promise transactional application rollback.
