1. Ordered map

OrderedMap<K, V> is the explicit sorted alternative to the default hashed Map. It owns keys and values and traverses entries in increasing key order. A balanced search-tree representation supports key ranges without scanning an entire hash capacity. This is a distinct collection choice, not a flag that silently changes Map iteration.

Design draft. This is an Aevix contract proposal, not an implementation claim. Callback, iterator, trait, and error-carrier names are descriptive. Parameters use T value by value, &T value for a shared borrow, and &mut T value for an exclusive borrow. Calls pass owners as x, &x, or &mut x; taking &mut owner requires a mut binding. Existing references and borrowed views are passed directly. Callback aliases, error records, and returned-reference lifetime notation remain design descriptions. Bindings are immutable unless declared mut; unit is a value type.

2. Total ordering

The key relation must be total, transitive, and stable while stored. Comparator equivalence determines uniqueness, and must agree with the chosen key equality contract. No API returns a mutable key. Ordinary floating NaN comparison is not a suitable total order without an explicit wrapper or policy. Query keys must preserve the stored ordering; changing a comparator’s external state is a logic error whose containment cannot permit unsafe aliasing.

3. Nodes and invalidation

Tree nodes may split, merge, or rebalance. An ordered map does not promise stable addresses for keys or values. A borrow or iterator constrains structural mutation even if the next operation could reuse an existing node. There is no hashed capacity, reserve, seed, or bucket-layout API on this type. Empty construction performs no node allocation; insertion is fallible whenever new nodes may be needed.

4. Allocation and callback errors

InsertError returns both unused incoming owners if checked node preallocation fails before modification. Replacement keeps the stored equal key and returns the previous value. CollectionError includes clone failure as well as allocation and checked size failure. Destruction and user comparison costs remain observable. Callback unwind preserves initialized values but does not undo earlier callbacks, edits, or removals.

6. Ranges and examples

range and range_mut use a half-open interval: the lower bound is included and the upper bound excluded. Reversed bounds return RangeError; equal bounds produce an empty iterator. Bounds are borrowed only while constructing the search, while yielded references borrow the map itself. This page deliberately does not depend on an unapproved generic Range representation. 

OrderedMap<i32, i32> timeline = OrderedMap.new(i32, i32);
usize count = OrderedMap.len(&timeline);
Optional<(&i32, &i32)> earliest = OrderedMap.first_key_value(&timeline);

7. Cost and related types

Lookup and single-key mutation use logarithmic comparisons in the balanced-tree contract. A range initializes in logarithmic time and then visits its k entries in linear traversal work; comparisons, moves, and finalizers add their own costs. Ordered traversal is deterministic for fixed keys and a stable ordering, but pointer identity and node layout are not portable. See Map, OrderedSet, and Array.
