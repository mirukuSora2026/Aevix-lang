1. Values and implementation

i128 is a built-in 128-bit integer with Copy semantics. Its exact range is -170141183460469231731687303715884105728 through 170141183460469231731687303715884105727. It is available without an import.

This page documents the implemented 0.2 subset. The broader Integer API catalog also contains planned functions; those entries are not enabled merely by selecting a 128-bit type. See the 0.2 implementation profile for the release-wide boundary.

2. Literals and constants

Use the suffix i128 to fix a literal’s type, or supply a matching declaration context. Decimal, 0x hexadecimal, 0b binary, and 0o octal spellings are supported. A suffix is part of the literal; it does not request a conversion to a different declared type.

const i128 MINIMUM = -170141183460469231731687303715884105728i128;
i128 large = 1267650600228229401496703205376i128;
i128 contextual = 1267650600228229401496703205376;

The sign and literal magnitude are checked together, so the minimum signed literal is valid. Negating an already typed minimum is a separate arithmetic operation and safely stops on overflow. A positive hexadecimal value with its highest bit set does not silently become negative.

Compile-time arithmetic uses the same typed bounds as runtime arithmetic. Out-of-range literals and failing constant expressions are compilation errors. This is fixed-width arithmetic, not an arbitrary-precision runtime integer.

3. Operators and failure boundaries

The implemented operators are +, -, *, /, %, unary +, unary -, comparisons, &, |, ^, ~, <<, and >>. Arithmetic requires matching operand types. Mutable bindings also support the existing compound assignments and increment/decrement rules.

Ordinary arithmetic safely stops before overflow, unsigned underflow, or division by zero. It does not wrap and does not return a Result. The same checks apply with -O0, -O2, AOT, and JIT.

Division truncates toward zero, and a nonzero remainder has the dividend’s sign. Both minimum divided by -1i128 and minimum remainder -1i128 safely stop. Signed right shift extends the sign bit.

A shift count must be in 0..128, so its largest valid value is 127. A valid left shift discards bits beyond the 128-bit representation. Count validation is separate from checked arithmetic overflow.

i128 value = -1267650600228229401496703205376i128;
i128 quotient = value / 3i128;
i128 remainder = value % 3i128;
bool identity = quotient * 3i128 + remainder == value;

4. Explicit numeric conversions

Already typed numbers do not convert implicitly. Use the destination type as the explicit generic argument. Successful integer conversion preserves the mathematical value; a value outside the destination’s range returns IntegerError.OutOfRange.

Result<i128, IntegerError> widened = Integer.convert<i128>(18446744073709551615u64);
Result<u64, IntegerError> negative = Integer.convert<u64>(-1i128);
FunctionMeaning
Integer.convert<D>(value)Checked integer-to-integer conversion, including signed and unsigned 128-bit destinations.
Float.convert<F>(value)Explicit conversion to a floating type; finite rounding is permitted.
Float.convert_exact<F>(value)Returns FloatError.NonExact when the mathematical value cannot be represented exactly.
Float.to_integer_exact<D>(value)Requires a finite, integral input inside the destination range.

The floating functions return Result<D, FloatError> and distinguish OutOfRange, NonFinite, and NonExact. A 128-bit integer may fit a floating type’s magnitude range and still lose precision. Handle the Result or propagate a matching error type with ?.

5. Range iteration and counts

Range<i128> and Range<u128> support ordinary iteration, including short ranges adjacent to the minimum or maximum. Advancing past a type boundary ends the range instead of wrapping its cursor.

Range<i128> edge = Range.closed(-170141183460469231731687303715884105728i128, -170141183460469231731687303715884105726i128);
mut usize count = 0;
for (i128 value in edge) count++;
Result<usize, RangeError> length = Range.len(&edge);

The example visits three values. Range.len returns a checked usize count. If the mathematical number of values exceeds usize, it returns RangeError.CountOverflow. A closed range spanning every unsigned 128-bit value contains 2128 values, so its length cannot be returned as a 64-bit count.

6. Storage, aggregates, and ABI

128-bit integers work as scalar values, function arguments and return values, struct fields, generic arguments, fixed-array elements, and Result payloads. Scalar copies do not allocate. Owning arrays and other containers keep their own move and borrow rules.

The current backend stores these values as LLVM i128. Portable runtime helpers pass two 64-bit words across their private C boundary for checked arithmetic, conversion, and large range counts. This avoids requiring an external 128-bit compiler-helper ABI. It does not promise that every operation is one CPU instruction.

Direct C FFI parameters and return values of type i128 or u128 are rejected in 0.2. A foreign ABI and aggregate layout contract must be designed before those signatures can be supported.

7. Verification scope

The 0.2 tests exercise minimum and maximum literals, compile-time arithmetic, checked runtime operations, bit shifts, numeric conversions, range boundaries and length errors, struct/array layout, generic calls, and Result payloads. AOT and ORC JIT execute the same semantic cases at -O0 and -O2.

The portable runtime also has deterministic boundary tests and comparisons over the 64-bit subdomain. These are correctness checks. No throughput comparison with C++, Rust, or another language is established by this page.
