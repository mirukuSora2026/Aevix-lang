1. Overview

Design draft. These are proposed Aevix APIs, not claims that a compiler or standard library implements them. Parameter modes are chosen: T value, &T value, and &mut T value. Type-pack notation, callable types, explicit returned-reference lifetime spelling, and error enums remain descriptive where marked. Namespace functions are used throughout; there are no value-method aliases.

unit has one value. It models successful completion with no additional data, rather than absence or an impossible outcome. Optional<unit> still distinguishes None from Some(unit); Result<unit, E> still distinguishes success from an error.

2. Declaring a unit value

Use the Unit. namespace to construct the value without depending on an unfinished literal grammar. The type is lowercase; the namespace retains its capital letter. Unit scalars are Copy. 

unit completed = Unit.value();
Result<unit, i32> success = Result.ok(Unit.value());
Optional<unit> present = Optional.some(Unit.value());

3. unit values and return-position void

unit is an ordinary value type usable inside generic containers. void is a return-position marker under the current function design; it is not a container element type or an alias for unit.

A function declared to return unit is non-void and must explicitly return Unit.value(); on every normally terminating path. A void function may fall through or use return;. A value expression at the end of a function does not implicitly become a return.

4. Product and variant meanings

A unit field carries no data but can preserve a generic interface shape. A Result of unit is useful for validation, resource closing, or mutation that can fail. Dropping the unit value does not perform the operation again.

This draft does not silently equate every empty user-defined struct or an empty tuple with unit. Any empty-tuple spelling or alias must be documented by the grammar. Equal storage size alone does not establish type identity.

5. Function reference

T value passes a value: Copy types are copied, and owning non-Copy values move without a deep clone. &T value is a shared read borrow; &mut T value is an exclusive modification borrow. Calls use x, &x, or &mut x respectively. Already borrowed references and view values are passed directly; adding another & changes the type. *ref accesses the referent. Ordinary &mut x requires a mut owner; mut T value alone makes a by-value parameter locally mutable and does not modify the caller. Overlapping active borrows are checked until last use; disjoint regions may be split safely and no borrow outlives its source. Synchronized interior mutation follows its own type contract. Fn(A) -> B describes a callable; returned-reference lifetime relationships remain documented in prose.

6. Storage and layout

The unit payload needs zero data bytes. A container may still require a discriminator, a length, padding, or alignment. An Array of N unit values has N logical elements even when no element data bytes are allocated.

Distinct unit values need not have distinct addresses. Pointer arithmetic, unique-address assumptions, or serialized padding cannot be inferred from zero-sized storage. Foreign ABIs may represent a no-payload result differently.

7. Errors and cleanup

Unit.value and Unit.equal do not fail. Formatting can fail because an owning string allocation or caller buffer is required. A Result of unit retains its error even though the success payload is zero-sized. Discarding a Result expression warns under the shared Result policy; its payload is not implicitly unwrapped.

Resource cleanup lives in the owning resource contract. Replacing an owner with unit is not permission to leak it; moving or destroying the owner remains tracked. Recoverable close errors belong to an explicit close operation.

8. FFI and callback adaptation

C void and a C++ void return require a binding adapter to or from unit when used by generic Aevix code. The adapter does not claim that C has a value of type void. Python None is a managed object/sentinel, not the binary layout of unit.

A callback returning unit must follow Aevix explicit-return rules. A void callback uses its own return-position contract. Bindings must preserve the foreign calling convention even when no data payload crosses the boundary.

9. Parallel and device behavior

Copying unit has no data-transfer payload, but executing work that returns unit can still require synchronization and produce errors. A Pending of unit may represent unfinished GPU work whose completion must be observed before borrowed buffers can be reused.

The lack of a payload is not evidence that an operation is free, complete, or safe to reorder. Effects, resource borrows, and task lifetimes remain part of the operation contract.

10. Examples and boundaries 

unit marker = Unit.value();
bool same = Unit.equal(marker, Unit.value());
Result<string, AllocError> text = Unit.format(marker);
Optional<unit> absent = Optional.none<unit>();

Some(unit) and None remain different values. Ignoring a Result does not convert its error into unit or propagate it. A standalone discarded Result expression warns; explicit processing and propagation retain the ordinary Result contract.
