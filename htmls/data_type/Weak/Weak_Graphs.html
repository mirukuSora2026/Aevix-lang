1. Choose Ownership Direction

A tree commonly owns children strongly and observes its parent weakly. A graph does not automatically have one correct strong direction: ownership must reflect which component is responsible for keeping nodes alive. Weak edges can disappear even when the observer itself remains alive. The graph API must document that absence and how callers recover, rather than assume every edge always upgrades.

2. A Weak Edge Breaks Only Its Own Cycle

Replacing a participating strong back-edge with Weak can break that known ownership cycle. It does not inspect the whole heap, remove other cycles, or release an object retained by an external registry. Closures stored in an object can strongly capture the same object indirectly. The default no-tracing-collector model does not promise absolute prevention of memory or external-resource leaks.

3. Acquire an Owner Before Borrowing

Upgrade returns a strong owner or an absent result. Retain that actual owner while borrowing fields or passing references to callbacks. A previous successful upgrade does not validate a later raw address or diagnostic count. Refcount overflow is separate from expiration. Repeated upgrades can be wasteful or observe different application states even when each lifetime operation is individually safe.

4. Observers and Registrations

A callback can capture a Weak observer to avoid a strong registration cycle, then upgrade each time it runs. If the object has gone away, the callback needs a defined no-op, unsubscribe, or error behavior. A foreign event source might retain callback state beyond a scope, so a weak edge alone is insufficient to validate the foreign callback ABI or its release protocol.

5. Cyclic Construction Is Not Partial Access

Shared.new_cyclic supplies a weak construction handle before the payload becomes initialized. During that stage promotion returns no value. The builder can store a weak self-observer but cannot obtain a safe read of partially initialized T. Builder failure releases initialized state under its error contract. Escaping strong references during initialization must not be enabled by a raw-count shortcut.

6. Stable Identity and Replacement

Explicit Shared copy-on-write changes the requesting handle’s allocation identity. Existing weak observers continue to refer to the old allocation and may expire if it loses its last strong owner. Replacing a value behind a Mutex instead keeps the Shared allocation identity, but observers then see whatever synchronized application state the replacement establishes. These are distinct policies and need deliberate selection.

7. Common Functions and Lifetime Boundaries

The full callable API is defined once in Weak. Shared Mutation documents clone costs and Box and FFI explains external ownership. AOT/JIT correctness and safe weak access do not establish eventual cleanup, callback fairness, or externally audited thread affinity.

An empty non-owning graph edge cannot keep a payload alive. Promotion is fallible and returns no strong owner here. 

Weak<i32> parent = Weak.new(i32);
bool absent_edge = Weak.is_empty(&parent);
Result<Optional<Shared<i32>>, RefCountError> retained = Weak.upgrade(&parent);
