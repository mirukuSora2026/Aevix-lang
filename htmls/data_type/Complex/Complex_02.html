Import and construction

This page lists the implemented 0.2 profile. The larger design catalog includes future APIs. Complex values are ordinary generic library structs, loaded only when imported.

import complex { Complex, complex, ComplexError };

i32 main() {
    complex value = complex.new(3.0, 4.0);
    Complex<f32> single = Complex<f32>.new(3.0f32, 4.0f32);
    return complex.magnitude(value) == 5.0 ? 42 : 1;
}

Complex<T = f64> has public T real and T imag fields. The transparent alias complex means Complex<f64>. With a whole-module import complex;, use complex.Complex<f64>. No ambiguous c-width aliases or imaginary literal suffixes are assigned.

Available type functions

In the table, C means the chosen concrete type, such as Complex<f32>. Call functions through that type. Arguments are values; the two-component struct implements Copy.

Numerical behavior

Each component has its own format and rounding. Ordinary arithmetic uses that component format. Stable magnitude and division promote the already rounded input components to f64 and round each final result back to T. They do not create extra input precision.

Magnitude uses a scaled standard numerical implementation, avoiding an unnecessary overflow from explicitly forming real² + imag². Infinity dominates a NaN component in magnitude; otherwise a NaN component produces NaN. A zero magnitude is positive zero.

Finite division keeps product mantissas and binary exponents separate before forming each output component. This avoids unnecessary overflow in a product and preserves a tiny imaginary component beside a huge real component. Nonfinite inputs use the platform standard complex recovery rules. No correctly rounded result, NaN payload preservation, or identical last bit across all platform math libraries is promised.

NaN and infinity are numerical values, not automatic Result errors. Complex numbers have no implicit ordering and no new operator overloads in this profile.

Errors and ownership

A denominator with both components equal to zero, including signed zeros, returns ComplexError.ZeroDivisor. Check the Result or propagate it with ?. ComplexError implements Copy.

import complex { complex, ComplexError };

Result<complex, ComplexError> quotient() {
    complex a = complex.new(3.0, 4.0);
    complex b = complex.new(1.0, -2.0);
    complex result = complex.div(a, b)?;
    return Result.ok(result);
}

Complex values contain no owned heap allocation. A value copy copies two components. Runtime numerical helpers use scalar arguments and caller-provided output storage; they do not allocate memory or throw exceptions. Private implementation helpers are inaccessible from user modules.

Formats and scope

Supported component formats are f16, bf16, f32, and f64, including transparent aliases of those types. The struct requires the sealed numeric.Floating contract. Integer, user-defined, and unrelated same-named interfaces do not satisfy it.

AOT and JIT use the same checked language pipeline. Runtime support must match the target platform. Transcendental complex functions, polar conversions, complex SIMD, and GPU execution remain future work.
