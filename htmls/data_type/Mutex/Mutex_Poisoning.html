1. The Selected Default Is Advisory

PoisonOnUnwind is the default Aevix lock policy proposed here. It records an unwind crossing a protected exclusive operation, rather than treating every returned Result error as an exception. Unwinding while an exclusive guard is held marks the default poison state. Returning an ordinary Result error without unwinding does not automatically poison the lock. An explicitly selected non-poisoning profile must be visible in metadata. Poison state is not a type validity check or a mechanism that proves application-level consistency.

2. A Poison Error Can Own Access

When acquisition succeeds on poisoned storage, the error carries the acquired guard. Ignoring or dropping that error releases the guard normally. Explicit recovery retains its access while preserving the poison flag. Other system failures need not contain a guard; tagged error inspection distinguishes them. Unique into_inner extraction returns a Poisoned<T> payload on poison so the consumed data remains recoverable rather than being silently discarded.

3. Repair Is Application Work

The caller can inspect protected fields, restore invariants, replace contents, or choose to abandon the owner. Clearing poison is only an acknowledgement after that work; the library cannot know that a financial balance, graph relation, file protocol, or external state has been repaired. Clearing requires an exclusive guard in this draft. Read access cannot claim to repair unrelated protected state.

5. Returned Errors and External Effects

An ordinary callback Result error can leave completed mutations visible without automatically marking poison. User code may explicitly mark the state if its invariant is known to be damaged. External effects, such as emitted messages or foreign API calls, are not rolled back by lock release or a poison flag. A recovery path must not treat a failed side effect as if it were undone.

6. No Soundness or Deadlock Shortcut

Poisoning must never be the sole mechanism that prevents memory unsafety. Safe references remain valid even when the application ignores advisory poison. Fairness, reentrancy, priority inversion, and deadlocks are separate properties and are not fixed by clearing a flag. Unwinding or finalization can be unavailable in some termination profiles; the target must declare those limitations instead of promising every failed operation poisons and releases correctly.

7. Common Guards and Reference Scope

See Mutex for acquisition and Guards for lifetimes. The source lock documentation informs a deliberately specified Aevix policy rather than silently importing another runtime’s exact panic behavior. No operating-system lock ABI, destructor delivery on process exit, or automatic invariant restoration is claimed.

A poison snapshot is advisory. It does not repair an invariant or replace acquisition of the guard required by clear_poison. 

Mutex<i32> gate = Mutex.with_policy(0, PoisonPolicy.PoisonOnUnwind);
bool observed_poison = Mutex.is_poisoned(&gate);
